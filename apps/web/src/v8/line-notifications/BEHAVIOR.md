# 運用者へのお知らせを作る・なおす（★V8 gjUz3・hiBO8・公開前の確認 sDXNy）

画面：`operator-edit.tsx`。入口：`app/line-notifications/operator/new/page.tsx`（V8 だけ。v7 の作成画面は 2026-10-04 に捨てた）。
今まで動いていた画面 `app/line-notifications/operator/new/operator-new-v8.tsx` から、データの口と動きを写した。

## 受け付ける URL と指定
- `/line-notifications/operator/new`：作る（題「運用者へのお知らせを作る」、板 gjUz3）
- `/line-notifications/operator/new?id=<お知らせのID>`：なおす（題「「〇〇」を編集する」、板 hiBO8）。保存ずみの全項目を戻す

## 呼ぶ API（今と同じ）
- 読む：`GET /api/line-notifications/operator-rules/:id`、`POST …/recipients-preview`、`GET /api/notifications/teams`
- 書く：下書きの作成・更新（版 `expectedVersion` つき、409 はサーバーの文をそのまま出す）、公開、テスト送信、チームの作成・更新

## 動き
- 作るときは受け取れる人を全員選んでおく。なおすときは保存ずみの宛先のまま（全選択で上書きしない）
- 受け取るスタッフの箱：1人ずつ「LINE／LINE 未ログイン」「管理画面」の札。選ぶと「選択 N人／LINEで受け取れる N人／管理画面で受け取れる N人」が変わる
- 絵に無い「チームを作る」は、箱の右上「この顔ぶれをチームにする…」で開く（チーム名＋チームを作る）
- 公開は下書きを保存してから確認の窓（sDXNy）で、選んだ人と LINE が届く人数を確かめる
- 未保存のまま離れると確認が出る（保存・公開のあとは出ない）
- 閲覧のみ（owner・admin 以外）：帯を出し、下書きを保存・公開・テスト送信・チームを作るのボタンは置かない（2026-10-06 オーナー決定）。キャンセルは残す

## 絵と違うところ
- 「テスト受信者に送る」（hiBO8）は、今の口が自分にだけ送るので「自分にテストを送る」のまま
- 見本の吹き出しの2行目は、きっかけ・重ねない時間（絵は予約の中身の例）。3行目はきっかけごとの開く先（予約管理・一斉配信 など）
- つながる先は 受信箱・ログインユーザー・顧客へのお知らせ（絵は 予約台帳・受信箱・ログインユーザー）
- 設定の中のメニューの「プール管理」は、機能設定で店舗のまとまりがオンのときだけ出る（共通部品の決まり）
