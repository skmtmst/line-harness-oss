# マイペット（専用機能）の動き（BEHAVIOR.md）

対象：今までの V8 のマイペット（`app/nen/pets/pets-v8.tsx`）と v7（`pets-tab.tsx`・`feeding-tab.tsx`・`pet-editor.tsx`）。動きを写して、`pets.tsx`（外枠）・`list.tsx`（登録ペット）・`editor.tsx`（ペットの情報を直す）・`feeding.tsx`（ごはんの目安）を一から書いた。見た目は型（ListPage）と部品で組み直した。板は 一覧 `wTIej`・一覧 1152 `t2SMXX`・ペットの情報を直す `eLjeQ`・ごはんの目安 `h7A2F`。

## 入口
- `app/nen/pets/page.tsx`：V8 のときだけ `@/v8/nen-pets/pets` を出す。v7 の画面と `pets-v8.tsx` は切り替えの日まで残す。

## 受け付ける URL と指定（今までと同じ名前・同じ意味）
- `?tab=feeding`：ごはんの目安。無い・ほかの値は登録ペット。
- タブを替えると `router.replace`（`/nen/pets` か `/nen/pets?tab=feeding`）。
- 探す・種別・主食・体重更新・並び・件数・ページは URL に残さない（今までどおり画面の中だけ）。

## 読み込み（API・今までと同じ口）
- `GET /api/nen/pets?accountId&q&species&product&weight&sort&page&pageSize`：一覧と数の帯（`kpis`）・主食の選択肢（`products`）。古い返事は番号で捨てる。数の帯は一覧の返事から読む（ごはんの目安のタブでは `pageSize=1` で1件だけ取って数を読む）。
- 一覧の取得は、絞り込み・ページ・件数が変わったときだけ（今までの V8 は親の関数を毎回作り直して、取得が止まらなかった。試験で見張る）。
- 探す欄は打ち終わってから 0.3 秒で取り直す。
- `GET /api/nen/feeding-products?accountId`：主食と然の商品・おやつの上限。

## CSV
- 板の頭の「CSV で書き出す」と、数の帯の「…」の「CSV で書き出す」は同じ動き。いまの絞り込みのまま `pageSize=all` で取り直し、BOM 付きの CSV（列は今までと同じ17列）。先頭が `=+-@` のセルには `'` を付ける（共通の csvCell）。閲覧のみでも使える。

## 一覧（wTIej・t2SMXX）
- 列：ペット（名前・種類・品種）・飼い主（名前・EC会員）・年齢・体重・今日の目安（g／日と kcal・鹿肉）・避妊去勢・運動量・主食・体重の更新・行の「…」。
- 1152（白い板が 1100 未満）では 年齢・避妊去勢・運動量 を隠し、年齢は種類の後ろへ（「犬・柴・4歳」）。補足は2行に折れてよい（行は中身なりに伸びる）。道具の段は探す欄だけで1段目。
- 今日の目安：主食が未設定なら「約○kcal・主食が未設定」、体重が無ければ「体重が未登録」、犬・猫以外は「犬・猫以外は目安の計算対象外」（#999 DEEP-24：犬の式で出した数を見せない）。鹿肉の目安が無いときは、子犬・子猫・シニアの段階だけ添える。
- 体重が 90 日更新されていないペットは、体重の更新の日付を琥珀の札で出す。体重が無ければ「—」。
- 行の「…」：ペットの情報を直す（管理者だけ）・飼い主を開く（`/friends/detail?id=…`）・マイページで更新を促す（受信箱でその飼い主とのトーク `/chats?friend=…` を開く。自動で送る口は無いので、担当者がトークで頼む）。

## ペットの情報を直す（eLjeQ）
- 窓（幅 560・上から 170）。対象のペット（名前・飼い主・EC会員）→ 種別（犬・猫・その他）→ ペットの名前・品種 → 性別（男の子・女の子・わからない）→ 誕生日・体重 → 補足。
- 保存：`PUT /api/nen-campaigns/pets/:id?lineAccountId`（`api.nenCampaigns.updatePet`）。版（`expectedUpdatedAt`）つき。名前が空・誕生日が「2020-03-15」か「03-15」でない・体重が 0.01〜200kg でないときは送らずに知らせる。体重の「kg」は外して数で送る。
- 409 `VERSION_CONFLICT`：止めて知らせ、入力は残す。一覧は読み直し、次の保存は最新の版で送る。
- 誕生日を変えると、予約済みの誕生日クーポン配信は新しい誕生日で組み直される（Worker 側）。

## ごはんの目安（h7A2F）
- 左に「主食（お客さまが選ぶ、ふだんのごはん）」「然の商品（おやつ・トッピング）＋おやつの上限（%）」、右に「今日の目安の計算」（式と係数。係数は Worker の ENERGY_FACTORS と同じ）。
- 行は文字で見せ、商品名を押すとその行だけ入力欄になる（足した行は最初から入力欄）。既定（主食）・目安に使う（然の商品）は種類ごとに1つだけ。消すと、その種類の先頭が既定になる。20 行まで。
- 保存は下の帯（中央・画面の下に追従）：`PUT /api/nen/feeding-products`（`products`・`treatLimitPercent`）。商品名が空・kcal が数でない行は送らずに知らせる。保存できたら、計算し直したペットの数を知らせる。
- 保存していない変更があるまま画面を離れると、確かめの窓（`useUnsavedGuard`）。

## 権限
- 役割はサーバ（`/api/staff/me`、`useStaffRole`）。管理者（owner・admin）でない人は「閲覧のみで見ています。…」の帯（数の帯の上）。
- 閲覧のみには、ペットの情報を直す・既定にする・これを使う・削除・追加・保存・キャンセルを出さない（押せない飾りを置かない。2026-10-06 オーナー決定）。おやつの上限は読むだけ。CSV・飼い主を開く・マイページで更新を促すは使える。役割が読めるまでは、変える操作を出さない。

## 今までと変えたところ
- 一覧の取得が止まらなかった（親が `onTotal` を毎回作り直していた）のを、取得の条件が変わったときだけにした。
- 表の行末は「…」だけ（行の右端は「…」の決まり）。CSV のボタンは道具の段から板の頭へ（絵どおり）。
- ごはんの目安の表は、最初から全部を入力欄にせず文字で見せ、押した行だけ入力欄にする（絵は文字）。削除は「削除」の文字ではなくごみ箱の印。
- 体重の入力は「9.2 kg」の形で見せ、保存の前に数へ直す。
