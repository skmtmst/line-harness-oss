# 業種ダッシュボード（飲食・サロン・面談・教室）の動き

絵：V8.pen 修正案 DIHFx の列 XBkC2（NqAvL 飲食・mOAX5 サロン・R0FFqz 面談・k2MBw 教室／分析 KcRVI・hqQLV・UTxFu・tMIuZ／カレンダー UtmIg・R28Jqt／開いた状態 wFmQa・wXOm6）。決まり：B-294・B-304・B-305・B-309・B-318・B-319。

## 入口
- `/`（ホーム）：`GET /api/dashboard/style` で所属を確かめた業種を読み、4業種は業種ダッシュボード、標準・ECは共通ダッシュボードを出す。端末の古い業種を正本にせず、未取得・失敗は読込と再読込を出す。別アカウントの返事は使わない。標準ではEC・出荷を出さず、ECでは既存EC集計とT01の期間集計を組み合わせる。
- `/?setup=0`・`/?setup=summary` は選択中の業種のホームに共通の質問・まとめを重ねる。`?qr=base`・`?qr=<経路ID>`も同じホームで共通のQRを開く。業種を読めない間は標準の画面で代用しない。閉じてもその業種のホームを保つ。初回未選択・明示的な後回しの区別は既存の保存条件を使う。
- `/restaurant-test/dashboard`：飲食の業種ダッシュボード（前の「今日のお店」hKRRF を置き換え・B-319）。`?view=stores` は全店の一覧（CHz31・`restaurant/dashboard/stores.tsx`）のまま。

- 「はじめにやること」の共通カードに、標準・ECと同じ「選んだ機能の設定」を出す。`useStyleSetup`が同じアカウントのスタイル・警告・初期セットの状態を読み、`SetupTasks`が業種に合う言葉と操作を組み立てる。取得失敗は未設定にせず読み直しを出す。質問は共通の`useSetupWizard`でそのホームに開き、URL指定でも同じ窓を使う。閉じる時はsetup指定だけを外し、期間や表示は残す。カードの数と進み線は基本の手順の1つだけにし、質問の案内と操作は残す。使い方の設定を変更できない人も入口は隠さず、共通の灰色と理由で残す。

## 受け付ける URL と指定
- `?tab=`：`today`（1枚目・省略時）・`bookings`・`people`・`analytics`。
- `?view=`：`board`（盤）・`floor`（座席表・飲食だけ）・`list`（一覧）・`calendar`。省くと業種の初期（飲食・面談・教室は一覧、サロンは盤）。
- `?range=`：`week`・`month`（省くと今日）。カレンダーは 1か月なら月の形、ほかは週の形。
- 分析：`?sub=`（小タブ）・`?days=`（7・30・90）。

## 読む口（API 組4 `lib/api-styles.ts` の styleApi・API-CONTRACT-4。生の値は `adapter.ts` が画面の形 `model.ts` へ組み立てる）
- スタイル：`styleApi.get`（GET `/api/dashboard/style`）。読めないときはホームを前に読んだ表示（初めは標準）のまま。
- 数の帯・新着予約：`styleApi.summary`（metrics・previous・newBookings）。率は 0〜1 を %、null は「—」と理由（数が少ない・未設定）、0 は実測の 0。前との比べは previous から（無断率・取消率は下がると緑）。
- サロンの数の帯は `styles.md`・SM21 に従い、予約（見込み額を補足）・対応待ち・次回予約率・呼び戻し待ち・無断キャンセル率を既存の5枠へ接続する。呼び戻しは人数、無断率はAPIの分子・分母・対象期間を使う。未取得・分母不足を0にしない。保存済みPencilの同じ5枠は旧項目の入金・新着を含むため、配置は変えず、この項目差は設計図の未同期として残す。
- 盤・一覧・週／月：`styleApi.schedule`（columns・entries・days・closures・availability）。担当の候補は columns、空きは availability.slots、担当の休みは closures。飲食の盤は `axis=table`。
- 分析：`styleApi.analytics`（日数→ from/to、timeZone、担当の絞り込み）。日別グラフは正規の `dailyComparison.current/previous` を同じ日順で比べ、0は実測値、未取得・権限なし等は欠測として描く。前の期間の日付は元の日付を保持する。
- 支払いの小タブは予約の集計と分け、同じ選択期間を示す `payments.period` と一致した入金額・件数、返金額・件数、未入金・期限切れを表示する。APIは日時の半開区間と店舗・担当の条件を照合する。実測値がないものを0にせず、日別の支払いグラフや詳細のAPIがない部分は取得可能なデータとして表示しない。
- ［表示を変える］：`styleApi.get` の cards と版 → `saveCards`・`resetCards`（配列の順が上から下。接続の異常・媒体の知らせは隠せない）。
- ［休みを入れる］：飲食は既存の `restaurantTestApi.createClosure`（卓は tableIds）、ほかは `styleApi.closeHours` を担当 1 人ずつ（途中の失敗をまとめて成功にしない）。既存の予約は取り消さない。
- 教室の名簿：既存の `eventsApi.listBookings`（回＝slot_id）、出席は `eventsApi.updateBooking(status=attended)`。
- 飲食：口が読めないときは今の飲食の口から組み立てる（`restaurant-today.ts`）。異常の帯は今の「枠を閉じる知らせ」。
- 口が無い物（支払いの札・今日の入金・支払いのリンク・返金・お支払いのカード）は値を作らず、押すと共通の準備中の窓（`preparing-dialog.tsx`・B-314）。

## 操作
- 頭：［ウォークイン］（飲食だけ・今の窓）［LINE を送る］（一斉配信へ）［休みを入れる］［表示を変える］［主ボタン］（飲食＝電話予約の引き出し、サロン・面談＝予約を入れる、教室＝イベント予約へ）。
- 日付の段：［今日｜1週間｜1か月］・日付・担当（席・担当・講師）・比べる・更新時刻・［読み直す］。分析では［7日｜30日｜90日］・CSV・毎朝メール（口ができるまで理由つきで押せない）。
- 行：［来店］（飲食は `postSeatVisitMark`）・［取り消す］（`deleteSeatVisitMark`）・［Meet に入る］［場所を開く］（URL があるとき）。「…」は業種ごとの並び。支払いのリンク・返金は Stripe をつなぐまで理由つきで押せない（B-305）。
- 盤：予約の箱を押すと同じ並びの操作。空き（＋入れる）を押すと予約を入れる。今の時刻に赤い線。
- サロン・面談の通常予約の空きは既存の `/booking/bookings/new` へ日付・時刻・担当IDを渡す（週の空きは日付・時刻と担当の絞り込み）。受け側は店舗・メニューの担当候補と実際の空きに存在するときだけ選ぶ。詳細・コピーは台帳表示用IDではなく実予約IDを `?booking=` へ渡す。閲覧のみの頭の作成操作は隠さず灰色と共通の理由で残す。権限未確認は理由を付けず無効にする。通常予約に属さない旧Meet相談は、受信箱の「次の予定」と同じく相談者の友だち詳細へ渡す。相談者IDが欠けた場合は架空の予約を開かず失敗を知らせる。旧Meetの専用日程・担当変更画面は未接続であり、通常予約の変更完了には数えない。
- 教室：回を押すと右に名簿（出席・この回の人に LINE・支払いのリンク・休講にする）。
- 異常の帯の［閉じた］は `completeChannelCloseTask`（飲食）。

- 週カレンダーの重なる予約は共通部品で並べ、3件以上が同時に重なる区間は残り件数から全予約を開く。予約と空きは別の列で、担当や収容数が不明なときに予約数から空きを推測しない。複数の空きは一覧から選べる。閲覧のみは追加と空きの操作を出さず、予約の詳細を開ける。

- 週と日の空き操作は、取得状態がavailableで残りが正数、または明示的なnull（定員なし）の枠だけに出す。満席0・未取得の枠を空きに数えない。満席の回本体、×の表示、回IDと詳細は残す。
- 週の時間軸は表示する予約と空きの早朝・夜間まで広げ、15分などの短い箱も文字と操作が収まる共通の時間尺度を使う。日をまたぐ区間は店舗の時差で分け、続きの空き操作でも元の予約開始日時を保持する。

## 印・確かめの窓（B-338）
- ［無断にする］（面談は［欠席にする］）は開始の時刻を過ぎた予約にだけ出す（行の主ボタン［来店｜無断］と「…」の両方）。あとで戻せる。飲食は `postSeatVisitMark(no_show)`、人の予約は `bookingApi.postVisitMark(no_show)`、Meet は `styleApi.saveMeetResult(attendance=no_show)`。
- サロンの承認待ちは主ボタン［承認する］（`bookingApi.decideRequest(approve)`）。面談の実施済みで結果が無い物は［結果を付ける］（`saveBooking`・`saveMeetResult` の outcome）と「結果待ち」タブ（件数つき）。
- 教室の名簿は［出席｜欠席］（欠席は回が始まった後だけ）、7 人を超えたら［ほか N人を表示する］。
- 取り消す（h2lHCH）・返金（Y8MWGs、2 段）・休講（Md9O3）・休みの重なる予約（s8BwT8）は共通の確かめの窓（`components/shared/booking-confirm-dialogs.tsx`）。取り消しは理由を口へ。返金・休講・重なる予約への LINE は口が無いので、押すと共通の準備中の窓。
- 試験モードの印は `TestModeNote`（`bookingApi.getPaymentConfig().testMode`）。支払いの札の言葉は `payment-status.ts` の 1 か所。
- 閲覧のみは上に閲覧のみの帯、異常の帯は外の管理画面を開く物だけ残す。［表示を変える］に［型を変える］（`styleApi.save` の style）。

## 狭い板
- 白い板が 1100 未満では右の列を畳み、［新着・お支払いを見る］で開く（2 列で下に出す）。分析の右の列は下に並べる。日付の段は折り返す。数の帯は数と比べの札を折り返す（`KpiBand layout="link-row"`）。

## 閲覧のみ
- 全業種の頭の操作（LINEを送る・休み・表示変更・予約作成・飲食のウォークイン）は、閲覧のみでも隠さず灰色と共通の理由で残す。役割が分からない間は理由なしの無効表示。書込みのhandlerも権限を確かめる。予約URLのコピーは閲覧のみでも使える。行・名簿・右の列の既存の権限制御はそれぞれの部品が持つ。

- サロンと面談の今日が空なら、一覧・盤・日カレンダーに共通の案内と［予約を入れる］を1回だけ出す。日付移動・時間軸・空き・休みは残す。主操作を案内へ移した時は頭に重ねない。検索0は検索を外す案内にし、取得失敗は予約なしにしない。閲覧のみの主操作は灰色と共通の理由、権限未確認は無効、handlerでも拒否する。

- 開いている日が今日でない時は「この日の予約はありません」と出す。取消などの記録だけの日は有効な予約がないことを案内し、記録の行・箱は残す。読み込み中は頭の主ボタンを出さず、読み込み完了後に頭か空状態の1か所へ出す。

- 教室の今日の案内はクラスと会員予約を分ける。クラスがなければ［クラスを作る］から `/events/new`、クラスがあり実集計の会員予約が0件なら［会員を予約する］から `/events` へ進む。会員予約数は summary の available の値のみを使い、未取得を0件にしない。クラスの行・盤・日カレンダー・名簿の回IDは残し、本文へ主操作を移すときは頭に重ねない。閲覧のみは共通の灰色と理由、役割未取得は理由なしの無効で、handlerでも拒否する。

- 教室の日・週カレンダーの日付下は、その日にクラスも空き枠もない場合だけ「クラスなし」と示す。クラスがあって空きがない日は「満」、他業種の補足・休業日・空き数は既存どおり。日をまたぐ回は各日にあるものとして判定する。

- 基本手順と選んだ機能の行は同じ共通行を使い、高さ60px以上・行間8px以上で表示する。閲覧のみ・staffにも選んだ機能の欄を残し、変更操作を灰色と理由で止める。中身を見る操作もオーナー・管理者の理由を表示して止める。既存の一覧GETは閲覧用に名前・種類・状態等だけを返し、本文は渡さない。

## 教室名簿の欠席受付

- 開始前の確定/承認待ちの欠席はeventsの共通窓を使い、最新設定・理由・二重操作・権限・結果を同じ形で扱う。開始後は無断欠席として区別する。予約IDで送り、成功後は名簿とホームを再読取する。欠席の案内は名簿が0件になっても残る。

## 予約の名前と割り当て

- 一覧の名前は顧客、コース・メニューは予約に結び付いた内容、卓は同じ店舗の割り当てを使う。担当軸でも卓名を担当名に置き換えず、結合卓は全卓を示す。停止した卓の既存予約も割り当てた名前を保ち、空き候補には戻さない。未配席は「—」、コースなしは「席のみ」、参照できない内容は「—」で、顧客名を代用しない。盤・カレンダーも同じメニュー名を使う。

教室の一覧・盤・日週・月選択日の行は開催回を単位とし、受講者は回の名簿で読む。KPIと日セルの予約件数は予約の実数を維持する。

率はAPIの「割合」と分母を使い百分率へ変換し、差分はpt。既存の小数1桁の丸めと、分母のない%の表示値は維持する。

- 飲食の空席の注記には、同じ集計で取得した有効卓の総数を表示する。停止卓を除き、時間を閉じた有効卓は総数に含める。
- 説明用の総数は任意の `totalTables` で受け取り、欠けた旧応答では未取得と示す。最低標本数による率の抑止・空席の値・状態・計算式・対象の店舗は変えない。
- 飲食の旧APIから組み立てるfallbackは従来の総卓数表示を維持する。

飲食店のヘッダーは読み込み開始からウォークインと予約の操作を同じ並びで置く。取得元の記録が現在アカウント・現在snapshotと一致し、選択店がそのsnapshotに含まれ、取得中でも失敗中でもないときだけ操作を許可する。予約の操作は現在scopeの予約情報も待つ。再読込や切替の間は同じ場所で理由を示して止める。組織内の店のLINEアカウントと選択アカウントの一致は要求せず、既存の組織・店舗の許容範囲を保つ。
