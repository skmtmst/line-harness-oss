# 友だち追加時の配信の実行結果（V8）の動き

入口：`app/friend-add-settings/runs/page.tsx`（V8 のときだけ `src/v8/friend-add-runs/runs.tsx`、それ以外は今の v7 の画面）。
絵：実行結果 `REIxB`。写し元（動き）：`app/friend-add-settings/runs/runs-v8.tsx`・`run-status.ts`・`csv.ts`（import はしない）。

## 受け付ける URL と指定（今と同じ）
- `/friend-add-settings/runs`：すべての記録
- `?rule_id=<設定のID>`：その設定の記録だけ（「すべての記録へ戻る」を出す）
- `?kind=first_time|returning`・`?attribution=captured|unavailable`・`?status=pending|completed|failed|suppressed|partial_failed`：絞り込み
- `?pages=<カーソル>,<カーソル>…`：今のページまでのカーソルの束（詳細から戻ったとき同じページに戻る）
- 詳細へは `/friend-add-settings/runs/detail?id=<実行のID>` に、上の絞り込みと `pages` をそのまま付けて渡す

## 呼ぶ口（今と同じ）
- 一覧：`api.friendAddRules.runs(accountId, { limit, cursor, status, kind, attribution, ruleId })`。古い返事は捨てる（後から出した読み込みだけを使う）
- 設定の状態：`api.friendAddRules.get(accountId, ruleId)`（一時停止中か・二重送信を防ぐ時間）。`rule_id` が無いときは表の最初の行の設定
- 一時停止：確かめの窓 →`get` で最新の版を読み →`stop(accountId, ruleId, version)` → 一覧と設定の状態を読み直す
- もう一度実行：`retryRun(accountId, runId)`。行の「…」から1件、失敗の帯の「失敗した処理をもう一度」は今のページの失敗を順に
- CSV：同じ絞り込みで 100件ずつ最大 50ページ（5,000件）まで読み、超えたら「新しい順に N件まで」と知らせる。先頭に BOM、式に見える値は無害にする

## 画面の並び（REIxB）
- 頭：戻る（友だち追加時の配信へ）・題・説明／右に「一時停止する」「設定の一覧へ」「CSVで書き出す」
- 数の帯：直近28日の友だち追加（人・追加の記録 N件）／送った案内（通・成功率）／失敗した処理（通）／シナリオを始めた（件）
- 失敗があるときだけ赤い帯：「失敗だけ見る」（札を「失敗」にする）・「失敗した処理をもう一度」
- 記録：探す（今のページの中で、友だちの名前と経路）・札（すべて N／失敗 N／テスト待ち／再追加）・件数（10・20・50）／表（日時・友だち・来た経路・結果・行ったこと・時間・…）／ページ送り
- 下の2枚：経路ごとの内訳（今のページの記録から数える）／二重送信を防ぐ・知らせ（有効・無効、最後に送った時刻）・「流入リンクを見る」

## 札と言葉
- 札は種類と結果を1つずつ：「失敗」「テスト待ち」は `status`、「再追加」は `kind=returning`。押すと他方を外し、1ページ目へ戻る
- 結果：以前からの友だちで案内を送らなかった記録は「再追加」。それ以外は今と同じ（成功・失敗・テスト待ち・配信なし・再送待ち・送達不明）
- 行ったこと：案内は届いたがシナリオを始められなかった失敗は「案内は届いた・シナリオを始められなかった」。再追加は「以前からの友だち（再追加）→ 案内なし（・処理だけ）」

## 権限
- 閲覧のみの人には「一時停止する」「失敗した処理をもう一度」「もう一度実行」を出さない（押せない形でも置かない）。閲覧のみの帯を出す。確認・CSV・詳細はそのまま使える
- 顧客名が隠された記録（`friend.redacted`）は「トークを開く」を出さない（友だちの ID へ進ませない）

## 失敗の扱い
- 読み込みの失敗は理由と「もう一度読み込む」。403 は権限の案内
- 一時停止の失敗は窓の中に「配信を停止できませんでした。状態を読み直してください。」

## 口が無いもの（司令塔へ報告済み）
- 絵の「今月」（期間で絞る）：期間の指定が口に無いので置いていない
- 絵の「経路が取れた N人」：数が無いので「追加の記録 N件」
- 絵の「テスト待ち 1」「再追加 12」の数：数が無いので札は名前だけ
- 絵の「失敗の知らせ：Slack（接続済み）」：口が無いので「—」
- ページ送りはカーソル式なので、次のページまでしか番号を出さない（絵は 1 2 3 … 11）

# 実行の詳細（V8）の動き

入口：`app/friend-add-settings/runs/detail/page.tsx`（V8 のときだけ `src/v8/friend-add-runs/detail.tsx`）。
絵：実行の詳細（失敗あり）`N43uVX`。写し元（動き）：`app/friend-add-settings/runs/detail/detail-v8.tsx`（import はしない）。

## 受け付ける URL と指定（今と同じ）
- `/friend-add-settings/runs/detail?id=<実行のID>`
- `kind`・`status`・`attribution`・`rule_id`・`pages` は「実行結果へ」の戻り先にそのまま付ける（R268）

## 呼ぶ口（今と同じ）
- 詳細：`api.friendAddRules.runDetail(accountId, runId)`。古い返事は捨てる。アカウントを切り替えたら前の詳細を消す
- もう一度実行：`retryRun(accountId, runId)`。成功したら件数を知らせて読み直す。409 は先に読み直してから文を出す（M011）

## 画面の並び（N43uVX）
- 頭：戻る（実行結果へ）・「〇〇さんの友だち追加」・「9月7日（月）10:14 に追加・はじめて」
- 左：失敗の帯（「Nつ目の処理を完了できませんでした」「案内は届いています。〇〇ところで止まりました。」・もう一度）／行ったこと（1 案内を送った → 処理を行った順。成功は緑の印、失敗は赤い地に理由）
- 右の欄（380）：この追加について（友だち・追加の種類・来た経路・動いた設定と版・受けた日時・処理した日時・記録ID）／トークを開く・設定を開く
- 白い板が 1100px を切ったら、右の欄を左の下へ畳む

## 言葉
- 処理の名前は、`stableId` の末尾の番号の設定の処理（`configuredActions`）の言葉を使う。種類が同じ仲間（タグ・シナリオ）のときだけ。合わないとき・閲覧のみで設定が返らないときは種類の名前（タグ操作など）
- 成功した処理は終わった形（付ける→付けた、開始する→開始した）、失敗・待ちはそのまま
- 案内を送らなかった記録（配信なし・送れなかった・送達不明）は「案内を送った」を出さず、番号は処理から数える
- 記録ID は頭7字…末尾3字（全文は title）

## 権限
- 閲覧のみの人には「失敗した処理をもう一度」を出さない（帯は出す）
- 顧客名が隠された記録は「トークを開く」を出さない

## 失敗の扱い
- ID なし・見つからない（404）・権限なし（403）・読み込み失敗を分けて出す（U098・M010）
- 処理の失敗が無い失敗（案内を送れなかった）は、相手に新しく届くので確かめの窓を出してから再試行する。送達不明は自動で送り直さない（ボタンを出さない）

## 口が無いもの（司令塔へ報告済み）
- 絵の失敗の理由「シナリオが停止中のため…」：口は理由を `action_failed` の1種類しか返さないので、決まった文を出す
- 撮影の指定：今の対応表は成功の記録（`friend-add-run-1`）を撮る。絵は失敗の記録なので、写しの対応表で `friend-add-run-4` を撮って測った
