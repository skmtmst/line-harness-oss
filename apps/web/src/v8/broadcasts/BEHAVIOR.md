# 一斉配信一覧の動き（BEHAVIOR.md）

対象：現役の `list.tsx`。ファイルの案内は [README](README.md)。見た目は型（ListPage）と共通部品（KpiBand・KpiCard・FolderPanel・FilterChip・DataTable）で組み直した。

## 入口
- `app/broadcasts/page.tsx`：`@/v8/broadcasts/list` を直接表示する。管理画面はV8に固定。

## 受け付ける URL と指定
- 今までどおり URL の指定は読まない（絞り込み・フォルダ・件数・並びは画面の中だけ）。
- 行き先：詳細 `/broadcasts/detail?id=<ID>`、編集を続ける `/broadcasts/new?draft=<ID>`、複製 `/broadcasts/new?duplicateFrom=<ID>`（今までと同じ）。

## 読み込み（API）
- `api.broadcasts.list({ accountId, limit, cursor, displayStatus, folderId, sort, from, to })`：一覧・数の帯（`kpis`）・札の件数（`statusCounts`）・総数。条件を変えたら1ページ目へ戻し、この口だけ取り直す。
- `api.tags.list`・`api.scenarios.list`：宛先の名前解決だけ。アカウントが変わったときだけ。失敗しても一覧は止めない。
- `api.dashboard.overview`：今月の送信枠（quotaLimit・quotaUsed）。
- `api.broadcasts.savedViews.list / create`：保存した検索。保存の形（filters・sortKey `scheduled`・pageSize 20）は今までと同じ。
- `api.broadcasts.getInsight(id)`：一覧に集計が同梱されていない送信済みだけ1回ずつ。
- `useManagedFolders('broadcast', accountId)` から `api.folders.list('broadcast', accountId)`：一覧と同じ店舗のフォルダ件数。店舗切替時に前の件数を捨て、古い応答では上書きしない。`swapOrder`・`delete`：フォルダ。`api.broadcasts.update(id, { folderId, expectedVersion })`：フォルダへ移す（押した瞬間に移した形を見せ、失敗したら戻して「もう一度」）。
- `api.broadcasts.delete(id)`：削除（確認の窓のあと）。
- 一覧の選択からまとめてフォルダへ移す。選ぶ窓で確定するまで送らず、各配信の版を照合する。失敗した配信と未送信の配信だけ再試行する。閲覧のみでも選ぶ欄と選択の印を残し、理由付きで変更を拒む。統括からの配信は店の移動対象にしない。

## 権限
- 役割と項目の鍵は本人APIの控えから読み、本人・代理モードの変更に追従する。本人が未確認の間は操作を隠さず理由なしのdisabledにし、権限の帯は出さない。初期読み込み失敗を権限拒否と同じ扱いにしない。
- 配信の定義を変えるには `/broadcasts` と `broadcast.definition.edit` が必要。オーナー・管理者と両方を持つ運用担当が変えられる。手元の役割保存値では昇格させない。
- フォルダの作成・名前・色・並び・削除と検索条件の保存は、配信の編集鍵とは別にオーナー・管理者だけ。保存済み検索の読取・適用、絞り込み、詳細を見る操作は止めない。
- 変えられない人にも、作成・選択欄・行メニュー・詳細パネルの同じ操作を灰色と共通の理由付きで残す。理由はTab・hover・タップで確認できる。入力や状態の不足は、権限の理由と分けて通常のdisabledと1行で示す。
- 閲覧者・専用の編集鍵が無い担当者・閲覧代理の帯は、共通Noticeで1本だけ出す。閲覧代理では、元の役割がオーナーでも変更しない。
- 開いていた確認窓と入力は権限が変わっても残す。書込は実行直前にも現在の本人・鍵・代理モードで拒む。行の遅延保存と一括移動は本人の世代・控え・セッションの変化を照合し、readからwriteへ戻っても古い処理を自動再開しない。途中停止では残りを送らず理由を示し、正規の明示再試行では成功分を再送しない。

## 検索と再試行の補足（2026-10-08）
- タイトル・内容の検索APIはないため、条件に合う配信を100件ずつ全件取得して検索し、その結果をページに分ける。上限は10,000件。超過時は部分的な結果を表示せず、状態・フォルダ・配信日で絞るよう案内する。
- 保存した検索は状態・検索語・日付・フォルダ・並び順・表示件数を復元する。
- かんたん送信は作成済みIDを再利用する。再試行前に状態を読み、送信中・送信済み・承認待ちなら再送しない。作成後の本文・対象・予約日時は固定し、失敗した処理を再開する。

### かんたんに送る窓の権限と途中の切替

同じ本文・相手・日時の欄を残し、閲覧のみは灰色と共通の理由、本人確認前は理由なしの無効にする。タグ・承認候補・承認設定の読み取りは続ける。定義の作成は配信の編集鍵、人数確認と承認依頼は送信鍵を実行直前にも確認する。代理ログイン中の直接送信は、書き込みモードでも灰色と「代理ログイン中は配信をすぐには送れません。代理ログインを終了してから送ってください。」の理由で止める。書き込み代理の予約と承認依頼は既存APIどおり通す。

作成・人数再確認・保存済み配信の照合の待機中に本人や代理モードが変われば、残りの処理を止めて理由を1行出す。同じ窓で作成済みならIDは保持し、新しい明示操作で状態を読み直して同じ配信を再試行する。自動再開・二重作成はしない。別アカウントや閉じて開いた窓へ古い応答・通知・busy解除を持ち込まない。すでに要求を出した後の停止は、その要求まで無かったとは扱わず、一覧で状態を確認するよう伝える。

## 作成フォームの入力と失敗表示

保存・確認・テスト送信の入口で示した入力検証の失敗は、現在の検証結果と一致する間だけ残す。別の欄を編集しても同じ不備なら消さず、配信名を有効に直した時は次の不備が残っていても古い配信名の失敗を消す。新しい不備は自動で赤くせず、段の既存の押せない理由と次の明示操作で知らせる。入力と段の状態は保持し、保存・通信・配信前チェックなどの処理の失敗は入力変更だけでは消さない。自動再試行や保存・送信の可否の変更は行わない。

## 配信前チェックの窓の状態

各行と件数は同じ確認一覧から出す。未確認の行が残る時と送信枠が不足する時は、窓の題を警告の印にし、全行済みの時だけ成功の印を出す。送信枠を未取得・取得不可の場合は、選択中のLINEアカウントの接続設定への文字リンクを窓内に置く。アカウントが無い時は一覧へ移る。切替には現在の選択だけを使い、未保存の変更があれば既存の移動確認で入力を守る。本文の確認結果・行・件数、保存・送信・承認の可否は変えない。
