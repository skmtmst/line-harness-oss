# シナリオを作る②：1通目を設定（V8）の動き

入口：`app/scenarios/first-step/page.tsx`（V8 のときだけ `src/v8/scenario-first-step/first-step.tsx`、それ以外は今の v7 の画面）。
絵：`V6xAo`（1440）・`U5rxyH`（1152）。

## 受け付ける URL と指定（今と同じ）
- `/scenarios/first-step?id=<シナリオ>`：そのシナリオの1通目を作る・直す（1通目があれば読み直して出す）
- `id` が無い → 「指定されていません」、404 → 「見つかりません」、通信の失敗 → 「読み込めませんでした」＋もう一度

## 呼ぶ口（今と同じ）
- 読む：`scenarioReferenceData.scenario(id)`・`tags(accountId)`・`templates(accountId)`（候補はシナリオのアカウントだけ）
- 保存：1通目があれば `api.scenarios.updateStep(id, stepId, …)`、無ければ `addStep(id, …)`。送る形は v7 と同じ（`first-step-form.ts` を写した）
- 保存できたら知らせを出して `/scenarios/detail?id=…` へ。「1通目はあとで書く」は保存せずに同じ行き先へ

## 今の V8 画面（app/scenarios/first-step-v8.tsx）と違うところ
- 「いつ」は「1通目の内容」の段の1行目（購読開始から［日］日後の［時刻］）。時刻は30分きざみの選択（保存済みの半端な時刻・大きい日数は候補に足して残す）。「時刻を消す」は無くした（時刻は必ず選ばれている）
- 届く日時の例は、配信側（packages/db の `computeNextDeliveryAt`）と同じ決まりで出す：時刻で指定は「始めた日＋N日後のその時刻。過ぎていたらすぐ」。例の始めた時刻は今日の 14:00 に固定
- だれに送るかは3枚の選ぶカード。「詳細条件で絞る」のカードは押すたびに条件の窓を開き、カードの下の文に「N 個の条件」。タグのときだけカードの下にタグの選択
- 送るものの種類は札の並び（紹介は押せない・理由は title）。1152 ではカルーセルのあとで2段目へ折る
- 右の列は本物のスマホ（共通の `LinePreview`）。1152 では「LINEでの見え方を見る」で窓に開く
- 閲覧のみ（staff）には「作って編集へ」を置かない。閲覧のみの帯を出す（役割が読めるまでは出す。最後の守りはサーバ）

## 書きかけの自動保存（シナリオの下書きの口・API-9）
- 1通目の書きかけを `api.scenarioDrafts`（本物の通とは別の行・配信に使わない・30日で消える）へ残す。キーは `scenario:<id>:first-step`、`scenarioId`（1通目があれば `stepId` も）を添える
- 入力が止まって2秒で `PUT`（新規は `expectedVersion: 0`、以降は返った UUID の版）。下の帯の左に「下書き保存済み・n秒前」。失敗は帯に出し、同じ入力で繰り返さない（打ち直すと送る）
- 開き直したとき、保存済みの形と違う下書きがあれば「前の入力を戻す」の帯（閉じると下書きを消す）。決めるまで上書きしない
- 409（ほかのタブ・人が先に保存）：最新を1回読み、競合の帯「最新の下書きを読み込む」。閉じると自分の入力で上書きする。どちらかを選ぶまで送らない
- 以前このブラウザ（localStorage）に残した書きかけは、一度だけ下書きの口へ移して消す（移せなければ残し、次に開いたときにもう一度）
- 保存済みの形に戻ったら下書きを消す。閲覧のみ・アカウントが決まらないときは読みも書きもしない
- 共通（アカウントなし）のシナリオは本物に紐づけられないので、選択中のアカウントにキーだけで置く
- 作って編集へ（保存できた）・キャンセルで下書きを消す。「1通目はあとで書く」は消さない（戻ってきたら続きから）
