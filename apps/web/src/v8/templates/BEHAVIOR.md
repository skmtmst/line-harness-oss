# テンプレート一覧の動き（BEHAVIOR.md）

対象：`app/templates/list-v8.tsx`（今までの V8 一覧）。このファイルの動きを写して `list.tsx` を一から書いた。見た目は型（ListPage）と部品で組み直した。

## 入口
- `app/templates/page.tsx`：`theme === 'v8'` のときだけ `@/v8/templates/list` を出す。v7 の一覧（TemplatesPageV7）と v7 の試験は触らない。

## 受け付ける URL と指定
- `?row=<テンプレートID>`：右の詳細パネルで開く行（`useDetailPanelUrl('row')`、今までと同じ）。
- ほかの指定（タブ・フォルダ・絞り込み・件数）は今までどおり URL に残さない（画面の中だけ）。

## 読み込み（API）
- `api.templates.list(undefined, accountId)`：一覧。アカウントが替わったら前の行・選択・窓を消してから読み直す（古い返事は世代で捨てる）。
- `api.broadcastMessageAssets.counts({ accountId })`：種類タブ（カルーセル・リッチメッセージ・クーポン・リサーチ）の件数。取れなくても一覧は出す。
- `api.folders.list('template', accountId)`：フォルダと件数（`itemCount`）・未分類の件数（`unfiledCount`）。取れないときはフォルダの列に1行だけ出す。
- 削除できない窓を開いたとき `api.templates.usages(id)`：使っている所の明細。

## 権限
- 作る・編集・複製・移す・削除はオーナーと管理者だけ。役割はサーバ（`/api/staff/me`、`useStaffRole`）で決め、答えが来るまでは手元の値（`isOwnerOrAdmin`）で決める。
- 変えられない人には、タブの上に「閲覧のみで見ています。…」の帯（`hEDTK`）。操作は押せない形で残す（理由は title）。

## タブ・絞り込み・並び
- タブ：メッセージ・カルーセル・リッチメッセージ・質問・クーポン・リサーチ。メッセージ／質問は同じ一覧を中身（question の有無）で分ける。ほかの4つは既存の素材一覧（`BroadcastAssetManager`、見るだけの人は `StaffAssetList`）。
- 探す：名前・本文・下書きの本文（NFKC・大小文字・空白をそろえる。索引は一覧が替わったときだけ作る）。
- 札：1通のみ・複数通（同時に選べない）・差し込みあり・使っていない。
- よく使う絞り込み（栞のボタン → メニュー）：使っている所がある・未公開の変更あり・下書きだけ。もう一度押すと外す。
- フォルダ：左の列（1152 の板では道具の段の「フォルダ：すべて」）。`folderId` で絞る。未分類は `folderId === null`。
- 件数：10・20・50件。ページ送りは表の下（「26件中 1〜20件」と頁）。

## 一覧の行
- □ 選ぶ／名前（詳細画面へのリンク）＋本文の抜粋（下書きがあれば下書き）／種類（テキスト・画像・カード型…）／公開の札（公開中・未公開の変更・下書きだけ）／使っている所（0は「なし」）／今月送った数（title に累計）／更新（M月D日、title に日時）／「…」。
- 行を押す・Enter で右の詳細パネル（名前のその場の書き換え・抜粋・公開・使っている所・移す・前後移動）。右クリックは「…」と同じ項目。
- 「…」：編集する・使っている所を見る・一斉配信で使う・複製する・フォルダへ移す・削除する。
- 1152 の板では 使っている所・今月送った数・更新 の列を出さない（絵 `L7zA7C`）。

## まとめて
- 選ぶと表の下に帯：フォルダへ移す・まとめて削除（使っていないものだけ。使用中が混ざると理由を出して押せない）・選択を外す。

## 窓
- 作る：種類を選ぶ窓（`R9XUMr`、6種類）。行き先は今ある作る画面。
- 削除（使っていない）：`V6JFnd`「「〇〇」を削除する」。危ないボタンは左端、キャンセルは真ん中。アカウントが替わったら消さない。
- 削除できない（使っている）：`Z0g3si`「「〇〇」はまだ消せません」。使っている所を2行（種類・名前・開いて差し替える）＋「ほか N か所」、下に 閉じる・使っている所をすべて見る（詳細画面へ）。明細が読めないときは消させず理由だけ。
- フォルダ：追加・名前の変更・並び替え（隣と交換）・削除（中身は未分類に残る）。
- 複製：下書きで「（コピー）」を作る。フォルダへ移す：1件でもまとめてでも同じ窓（詳細パネルからはパネルの中で選ぶ）。

## 読み込みの状態（`susGP`）
- 読込中・アカウント未選択・見る権限が無い・読み込めない（もう一度試す）・まだ無い・条件に合うものが無い（条件を外す）を分ける。数の帯は読めるまで「—」。

## 質問を作る・編集（question-new.tsx・絵 l87p1J）
今の V8（`app/templates/questions/question-v8.tsx`）と同じ口と動き：`api.folders.list('template')`・`api.templates.get/create/update`
（`question` と `questionStatus`）、使用先がある質問の公開は確認の窓（cuR8I）、離れるときの確認、オーナー・管理者だけが作れる。
- 入口：`app/templates/questions/new/page.tsx`（`/templates/questions/new`・`?id=`）
- 見せ方：段「名前とフォルダ」「質問」（前文・質問文・答え方）「選択肢」（横に並ぶカード：ボタンの文字・押されたら・押したときの返信、最大4つ）
- 「押されたら」は1行の要約（タグ・シナリオは名前。`api.tags.list`・`api.scenarios.list` で読む）。押すと今の質問の部品（QuestionEditor）を窓で開き、タグ・友だち情報・シナリオ・URL・代替テキストなど全部の設定をそこで直す
- 右の列：この質問を使う場所・届き方（本物のスマホ）

## カルーセルを作る・編集（carousel.tsx・絵 J60utH）
今の V8（`app/templates/carousel/carousel-v8.tsx`）と同じ口と動き：読み込み（壊れた中身は知らせて上書き保存）、保存（`saveCarousel`：
作成だけ済んだあとのやり直しは作り直さない）、公開（使用先があれば確認の窓 cuR8I・409 は止める）、押せる回数、離れる確認。組み立てと保存は carousel-core の写し。
- 受け付ける URL：`/templates/carousel`・`?id=`・`?visual=1`（見本の3枚で開く。撮影用。見本は絵の3枚にした）
- 見せ方：段「カード」は札（タイトルの（）書きを外した短い名前）で選び、つまんで並べ替え（Alt＋← → でも）。段「カード N の中身」は画像の枠（ファイル選択・ドラッグ・登録メディア・URL）・タイトル・本文・ボタンの行（文字・押したら・中身）
- 手元の画像（2026-10-08夜）：JPEG・PNG、10MBまで。形式・拡張子・空のファイル・容量を送信前に検査。登録メディアの `prepareUploads → putMediaFile → completeUpload → detail` で登録し、完了後のURLを選んだカードへ入れる。失敗時は本文・元の画像・選んだファイルを残して同じファイルで再試行できる。
- 受け取り中は画像選択・保存・公開・離れる操作・カード選択／追加／複製／削除／並べ替えを止める。アカウントや編集先が変わって遅れた画像は反映しない。店・統括とも、一部のカードだけに画像がある状態での保存を止める。
- 統括は `host.uploadCarouselImage` からメッセージの画像と同じ口へ送る。受け取りを先に記録（R568）、使用中の画像情報も保存へ渡す。統括の既存口は8MBまでのため、絵の10MBとの違いは司令塔の判断待ち（APIは変更していない）。店の登録メディアは統括では出さない。
- 「動きを実行する」の中身は1行の要約。押すと今の部品（InlineActionList）を窓で開いて決める
- 絵に無い「押せる回数」は段のいちばん下に残した

## 種類を選ぶ窓（R9XUMr）・見本から作る（F-5・2026-10-07）
- 窓は絵の幅 840・上から 200。6つの種類を3つずつ2段（高さ 184 のカード）、その下に「見本から作る」、いちばん下に真ん中のキャンセル（線なし）。
- 見本：窓を初めて開いたときに `GET /api/templates/examples`（`examples.ts` の `loadTemplateExamples`）を1回読む。形の合う4件まで並べる。読めない・0件なら段を出さない（種類のカードはそのまま）。
- 見本を押す → `/templates/edit?example=<見本の番号>`（メッセージを作るに名前と本文を入れて開く。口は保存・送信をしないので、保存は利用者が押す）。
- 見本の種類の文字は「メッセージ」（口が返すのは名前・本文だけで、どれも文字のメッセージ。絵の「リッチメッセージ・質問・クーポン」は口に無い）。
- カードの説明文は絵の文言に合わせた（「→ リッチ」「満足度の調査に」「答えですぐタグを付ける」）。
