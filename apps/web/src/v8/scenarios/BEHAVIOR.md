# シナリオ配信一覧の動き（BEHAVIOR.md）

対象：`list.tsx`（★V8 一覧 `axFrW`・1152 `wjfLe`・閲覧のみ `X0QrW0`・複製の窓 `Al4Ek`）。
今までの一覧 [現役の入口・本体](README.md) から動きを写し、見た目だけを型（ListPage）で絵どおりに組み直した。

## 入口
- `app/scenarios/page.tsx` がこの一覧だけを出す。

## 受け付ける URL と指定
- 検索・状態・フォルダ・ページ・表示件数をURLに残す。戻る操作で同じ条件へ戻る。右の詳細はscenarioで指定する。

## 読み込み（API）
- 一覧：`api.scenarios.listPage`（サーバーでページ送り。`query`・`active`・`createdFrom`・`folderId`・`page`・`limit`）。
- 「すべて」の件数：`listPage({ limit: 1 })` の `total`。フォルダ：`api.folders.list('scenario')`（`unfiledCount` つき）。
- 数の帯：`api.listStats.get` の `scenarios`（合計・稼働中・購読中・読み終えた・今週送った数）。取れないときは「—」。
- アカウントを切り替えたら、フォルダ・件数・帯・選択を空にし、前のアカウント宛の遅い返事は捨てる。
- 一覧の配信中と最後まで配信は別々に並記する。人数集計が失敗しても行を残し、読めない人数はnull（表示は「—」）。片側が既知ならその側は保持する。一覧と詳細パネルは同じ人数を示す。
- 割合の分母は配信中＋最後まで配信。両方が既知で合計が1人以上のときだけ棒と割合を出し、欠測や合計0人では出さない。実0人は人数の「0」と補足「登録した0人」で示し、未取得を0へ置き換えたり0/0を表示したりしない。「—」は欠測に限る。
- 欠測の「—」には「人」を付けない。実0人の補足は棒がある行の補足と右端をそろえ、棒自体は出さない。

## 絞り込み
- 検索（300ms 待ってから・長さは `clampSearchQuery`）／停止中のみ（`active=0`）／今月作った（日本時間の今月1日から）／よく使う絞り込み「稼働中のみ」（`active=1`、停止中のみと同時には掛けない）／フォルダ（列または 1152 の選ぶ欄）／20・50・100件表示。

## 行と操作
- 行を押すと詳細パネル（前後移動・開く・配信結果・複製・削除・名前のその場の書き換え）。名前のリンクは詳細へ。
- 「…」と右クリック：複製する・配信結果を見る・削除する。
- □ で選ぶと表の下に帯：止める・再開（押した瞬間に描き換え、5秒は「元に戻す」）・フォルダへ移す（窓で行き先を選ぶ）。
- つまみ（ドラッグ・キーボード）で並び替え → `api.scenarios.reorder`（5秒は「元に戻す」）。
- 削除：確認の窓。引き直して一覧から外れた対象は消さず、選び直してもらう。
- 複製：「元の名前のコピー」で共通の手順を呼び、成功時は一覧を読み直して作成した行を示す。途中で権限が変わった時も作成済みのコピーを消さず、止まった段と一覧での確認を案内する。

## 書きかけの自動保存（シナリオの下書きの口・API-9）
- 名前・フォルダ・方式の書きかけを `api.scenarioDrafts`（本物のシナリオとは別の行・配信に使わない・30日で消える）へ残す。名前と方式を決めるまで本物のシナリオの行は作らない（N-055）
- キー：id なし → 画面が作る `new:<UUID>`（開き直して同じ下書きへ戻れるよう、キーだけをこのブラウザに覚える）、id あり → `scenario:<id>:info`
- 入力が止まって2秒で `PUT`（新規は `expectedVersion: 0`、以降は返った UUID の版）。下の帯の左に「下書き保存済み・n秒前」。失敗は帯に出し、同じ入力で繰り返さない（打ち直すと送る）
- 開き直したとき、保存済みの形と違う下書きがあれば「前の入力を戻す」の帯（閉じると下書きを消す）。決めるまで上書きしない
- 409（ほかのタブ・人が先に保存）：最新を1回読み、競合の帯「最新の下書きを読み込む」。閉じると自分の入力で上書きする。どちらかを選ぶまで送らない
- 以前このブラウザ（localStorage）に残した書きかけは、一度だけ下書きの口へ移して消す（移せなければ残し、次に開いたときにもう一度）
- 保存済みの形に戻ったら下書きを消す。閲覧のみ・アカウントが決まらないときは読みも書きもしない
- 共通（アカウントなし）のシナリオは本物に紐づけられないので、選択中のアカウントにキーだけで置く
- 作った（この方式で保存する・あとで決める）・キャンセルで下書きを消す。キャンセルは一覧へ戻る

## 閲覧と変更の権限
- 本人APIの控えと代理モードを購読し、閲覧の人にも作る・複製・削除・選択・並べ替え・名前変更を同じ形の灰色と共通理由で残す。本人未確定の間は理由や帯を出さず普通の無効にする。既知の変更不可時だけ帯を1本出す。
- 定義の変更はシナリオの編集鍵、開始・停止はowner/admin、フォルダ管理もowner/admin。編集鍵のあるstaffへ開始・停止や管理を広げない。閲覧GET・検索・絞り込み・配信結果はそのまま使える。
- 実行直前、取り消し待ちの実行前、並べ替えの全件GET後、一括の各書込前、複製の各待機後に本人・世代・セッション・アカウントを確認する。切替後の古い処理は許可が戻っても勝手に再開しない。
- 開いた移動・削除・フォルダの窓と入力は役割の切替で消さず、確定だけを理由付きで拒否する。アカウントが替わった窓は権限不足と決めつけず、状態の理由で止めて選び直してもらう。名前の編集中も入力を保ち、Escapeで取り消せる。
- 一括処理は順に送る。権限喪失では保存を確認した数と残りの未送信を知らせる。API失敗では保存確認数・止まった位置・未送信数・日本語の理由を知らせ、残りを送らない。失敗した1件の保存結果は通信によって未確認の場合があるため成功に数えない。
- 削除が成功した直後に役割が替わった場合は、削除の成功を知らせて窓を閉じ、変更後の権限で一覧を読み直す。代理切替の認証読直し中も共通の保留snapshotで書込を拒み、代理閲覧の理由を使う。API・権限キー・Workerは変えない。

## 権限なし（2026-10-07）
- 一覧の口（`GET /api/scenarios`）が 403 のときは、画面ごと権限なしの板（★V8 O5tUeE、`src/v8/no-permission`）にする。500 などは今までどおり「読み込めませんでした」

# シナリオを作る①：シナリオ情報・配信方式（create.tsx）の動き

対象：`create.tsx`（★V8 `dnzqC`）。型（CreatePage）で絵どおりに組み直した。

## 入口
- `app/scenarios/mode/page.tsx`：このV8画面を直接表示する。
- `app/scenarios/new/page.tsx`：このV8画面を直接表示する。`?id=` の意味を保つ。

## 受け付ける URL と指定（今と同じ）
- `?id=<シナリオ>`：あれば既存の下書きを読み、名前・フォルダ・方式を出す（「下書きを作りました」の帯）。無ければ「これから作る」（まだ行を作らない）。

## 呼ぶ口（今と同じ）
- 読む：`scenarioReferenceData.scenario(id)`・`api.folders.list('scenario', シナリオのアカウント)`
- 名前・フォルダ（id あり）：欄を離れたとき・フォルダを選んだときに `api.scenarios.update(id, { name, folderId })`
- この方式で保存する：id なし → `api.scenarios.create(…deliveryMode)`、id あり → `api.scenarios.update(id, { name, folderId, deliveryMode })`。どちらも `/scenarios/first-step?id=…` へ
- あとで決める（下書きとして保存）：id なし → 「時刻で指定」で作って first-step へ、id あり → 名前・フォルダを保存して first-step へ
- 名前が空：欄の下にも理由を出し、欄へ移す（R172）

## 今の V8 画面と違うところ（見せ方）
- 題は id の有無にかかわらず「シナリオを作る」。主ボタンは「この方式で保存する」（絵どおり）
- はじめから「時刻で指定」を選んでおく（絵どおり。既存の下書きは保存済みの方式）。そのため主ボタンは最初から押せる
- 方式のカードは共通の選ぶカード（RadioCard）。G-5 採用案（2026-10-08）の説明1行と、2人がいつ受け取るかの図を各カードに入れる
- 2つの図は常に横に並べ、選んだ方式の線・札・吹き出しは緑、もう一方は灰。図の上も押せる。中の札は読み上げず、各図を要約1文で伝える
- 「作ったあとは変えられません」は配信方式の題の横の「？」に入れる。カードの下の見本の表は置かない（図に入ったため・絵 R83uvQ）

## 閲覧のみ（staff）
- 「あとで決める」「この方式で保存する」を置かない。欄・カードは触れない形。閲覧のみの帯を出す（役割が読めるまでは出す。最後の守りはサーバー）

# シナリオの配信結果（results.tsx）の動き

対象：`results.tsx`（★V8 `X4STXS`）。今までの V8（[現役の入口・本体](README.md)）から動きを写し、型（DetailPage）で絵どおりに組み直した。

## 入口
- `app/scenarios/results/page.tsx`：このV8画面を直接表示する。

## 受け付ける URL と指定（今と同じ）
- `?id=<シナリオ>`：無い → 「指定されていません」、404・空 → 「見つかりません」、通信の失敗 → 「読み込めませんでした」＋もう一度

## 呼ぶ口（今と同じ）
- 本体と集計：`scenarioReferenceData.scenario(id)`・`stats(id)`（操作のあとは `stats(id, true)` で取り直す。失敗しても前の値は残す）
- 参加中の友だち：`api.scenarios.runs(id, アカウント, { limit: 50, status, cursor })`。状態の絞り込みはサーバーへ渡す。続きは「さらに読み込む」
- 行の「…」：止める `subscriptionOps.pause`・再開する `resume`・失敗を再送 `retry`（配信失敗で止まった行だけ）・別のシナリオへ移す `move`（稼働中の別シナリオを窓で選ぶ）。確認キーは同じ操作の再試行で使い回す
- 予定を見る／友だちを選んで配信予定を見る：`FriendPlanDialog`（送信・登録は起きない）
- CSV：`scenario-results-<id>.csv`（列・分母は今と同じ）
- 画面（id）・アカウントを切り替えたら、遅れて返った古い返事は捨てる

## 数の帯（絵の4つ）
- 始まった＝参加した人（集計の enrolledTotal）・読み終えた＝全部届いた人（割合つき）・途中＝いま途中の人（配信中＋送信中＋止まっている）・離れた＝参加 − 読み終えた − 途中
- 「〇通目で多い」と通の行の「ここで N人（x%）離れた」は、届いた人数が次の通で最も減った通。離れた人がいるときだけ出す

## 今の V8 画面と違うところ（見せ方）
- 題は「配信結果：シナリオ名」と説明1行。右上は「シナリオの編集へ」「CSVで書き出す」
- 通ごとの行は1行（何通目・いつ・N人に届いた・届いた率・開いた・押した）＋届いた率の棒
- 上の2本の帯（送れずに止まった・いま送っています）は絵に無いので、段の題の行の右に小さく出す（「止まっている人だけを見る」で絞り込む動きは同じ）
- 表の列は「友だち・状態・いま（何通目まで）・次に届く・予定を見る・…」。状態の札は 途中・送信中・止まっている・送れずに止まった・読み終えた
- 絵の「足す状態と「…」の中身」の箱は、作る人への注記（足す札と「…」の中身の説明）なので画面には出さない。札は表の状態、「…」の中身は行のメニューで出す

## 閲覧のみ（staff）
- 行の「…」（止める・再開・再送・移す）を置かない。予定を見る・CSV・編集へ（見るだけ）は出す
