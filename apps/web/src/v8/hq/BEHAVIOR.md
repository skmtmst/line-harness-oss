## 入口
- 各 `app/hq/**/page.tsx` は `@/v8/hq/*` を直接出す。統括のタグ・テンプレート・リッチメニュー・回答フォームもV8に統一する。

## 受け付ける URL と指定（今までと同じ）
- `/hq?return=…`：アカウントへ入ったあとに戻る店舗画面（`resolveStoreReturnPath` で店舗画面のパスだけ受け付ける：NEXT-07）。
- `/hq/billing?checkout=success|cancel`：Stripe から戻ったときの知らせ。`success` は 4 秒後に読み直す。
- `/hq/support/detail?id=…`：開くお問い合わせ。無い・見つからない・読めないを分ける（U099）。
- 絞り込み・並び・表示件数・カード／表は URL に残さない（画面の中だけ）。

## 読み込み（API）
- 統括の情報（`/hq/settings`・板 `K7HYu`）：統括名は従来の `GET/PATCH /api/tenants/me`。会社と連絡先は別の `GET/PATCH /api/tenants/me/company-contact`。表示用の統括名と正式な会社名は混ぜない。
  - 会社と連絡先はサーバで判定したオーナー・管理者だけが読み取る。通常メンバー・閲覧のみの画面にはカードと読み口を出さない。閲覧のみには保存・住所検索のボタンを出さない。
  - 保存時に必須6欄・郵便番号7桁・電話番号・メールを検査する。任意の建物名・請求書の宛名は空ならNULL。既存の統括の8欄はNULLのまま。
  - 読み込んだ `revision` を `expectedRevision` として送る。既存の会社表示設定の版を共用し、ほかの人の先行保存は409。同じ保存の再送では版・監査を増やさない。失敗時に入力を消したり自動で読み直したりしない。
  - `GET /api/postal-code/search?code=` を再利用。複数候補と既に手入力した住所は、候補を選んだときだけ住所へ入れる。未取得・検索失敗では手入力を保つ。検索中の郵便番号・住所の編集には古い返信を適用しない。
- ホーム：`GET /api/line-accounts`（タグ・接続状態・数を含む）・`GET /api/line-account-tags`・`GET /api/tenants/me`（説明の統括名）・運営のお知らせ（`PlatformNotices`）。
- メンバー：`GET /api/staff/me` → 担当範囲が限られる人は一覧を呼ばない（M025）→ `GET /api/staff`・`GET /api/line-accounts`・最終ログイン。
- 請求：`GET /api/hq/billing/summary`・`GET /api/hq/billing/invoices`（履歴だけの失敗は概要と分ける：R118、502 は決済サービスの案内：M023）。
- お問い合わせ：`GET /api/hq/support/context`・`GET /api/hq/support/requests`。やり取り：`GET /api/hq/support/requests/:id` と、送信者・一覧・店舗名のために `staff/me`・`tenants/me`・`requests`・`context`。

## 書き込み（今までと同じ口・同じ形）
- ホーム：接続情報の更新（各アカウントへ `POST /api/line-accounts/:id/connection-checks`、`Idempotency-Key`・`expectedRevision`）・タグの追加（色つき）・タグの削除（確認の窓を挟む）・設定の窓（名前・フォルダの付け替え。未使用の親アカウントは表示・変更しない）・アーカイブ／戻す（6桁の本人確認 `line_account.archive`）。
- メンバー：招待（`api.staff.create`）・変更（確認の窓 `M4jS9` を挟んで `api.staff.update`、`STEP_UP_REQUIRED` は本人確認してやり直す）・招待メールの再送。
- 請求：申込（Stripe Checkout へ）・支払い方法の管理（ポータルへ）。
- お問い合わせ：送信（添付は PNG・JPEG 3枚まで）・続きを送る。

## 権限
- 役割はサーバ（`/api/staff/me`）から読む。手元の保存値（`lh_staff_role`）は使わない。
- 閲覧のみ・変える権限が無い人には、押せないボタンを置かずに隠す（2026-10-06 オーナー決定）。
  - ホーム：「アカウントを登録」「タグを追加」「設定」「LINE ID・接続状態を更新する」はオーナー・管理者だけ。「戻す」はオーナーだけ。
  - メンバー：「権限者を招待」「変更」「再送」はオーナー・管理者だけ。見るだけの人には「閲覧のみで見ています…」の帯。
  - 請求：「このプランにする」はオーナーだけ。「支払い方法を管理」はオーナー・管理者だけ。担当者（staff）は見られない（今までどおり）。
  - 請求（2026-10-08 オーナー）：いま使っているプランのカードに「利用中」と押せない［いまのプラン］。ほかのカードの［このプランに変える］（今のプランが無いときは［このプランにする］）はオーナーだけ。「いま使っているプラン」は、契約中は API の `current`、課金の対象外は API の `planKey`（返さなければ印なし）。契約中に変えるときは確認の窓→今ある「支払い方法を管理」（Stripe の画面。差額と適用日はそこで確かめる）、課金の対象外・支払いの管理画面が無いときは確認の窓→お問い合わせ（`/hq/support`）。お金が動く口は新しく作らない。周期の切り替えは、最初に読めたとき契約中の周期に合わせる。

## 今までと変えたところ
- ホームの「設定」「戻す」の可否を、アカウントの `role`（アカウントの説明の欄で、人の役割ではない）からサーバの役割に直した。
- 言葉を絵に合わせた：メンバーの役割「スタッフ」→「担当者」、状態「無効」→「停止中」、担当範囲「全アカウント」→「すべて」。請求の未払い「未払い」→「請求中」、日付は「2026/10/01」。お問い合わせの状態「受付済み」→「対応中」・「解決」→「解決済み」、日時は「9/30 11:00」。
- 請求の注（料金は Stripe の価格です…）は、押せない理由があるとき（決済の設定がまだ・オーナー以外）だけ出す。「次回の更新日」は括弧の外に出した（絵の文面）。
- お問い合わせの「必須」札と「任意」の注は絵に無いので出さない（送れない理由は今までどおり送信の上に出る）。「運営からの大事なお知らせを LINE で受け取る」は送信者の帯の右端へ。
- やり取りの画面は、自分の送ったものを右（緑）、運営を左（灰）に並べる（絵どおり）。下に固定した帯（一覧へ戻る・送る）はやめ、「送る」は続きを送るカードの中へ（一覧へは左の列の「お問い合わせ」で戻る）。
- 運営通知専用LINEの窓は、PCで読むQR・2つの手順・6桁コード・紐づける理由をPen `musubo-notice-line-design-v01.pen` に合わせて出す。スマートフォンで開くボタンは置かない。窓を開いたまま5秒ごとに本人の連携状態だけを照会し、成功時はコードを消して連携済み表示へ切り替える。24時間のコード期限が切れたら更新操作を示し、読み込み・状態確認の失敗は別に示す。登録完了直後の自動表示も同じ窓を使う。
- メンバーの窓（招待 `yLKwV`・変更 `BHEl9`・確認 `M4jS9`）を `member-dialog.tsx` に一から書いた（2026-10-07）。
  - 担当範囲と状態は行内のラジオ。担当範囲を「指定したアカウントだけ」にした場合は、対象を別の窓で選ぶ。アーカイブしたアカウントは選ばせない（今の担当範囲に入っているものは残す）。
  - 統括の招待は「閲覧のみ」から始め、担当範囲は全アカウントとする。「最初に表示するアカウント」は選ばせない。
  - 変更で役割を変えないときは、役割を送らない。担当者の人には選ぶ欄に「担当者」を出す（新しく担当者にするのはログインユーザーの画面）。
  - 確認の窓を出す間は変更の窓を閉じ、確認をやめたら入れた中身のまま戻る。確認の窓に「請求の画面 見られる→見られない」の行を足し、状態は変わるときだけ出す。管理者を外す・止めるときは「確認コードを入れて変える」（サーバが本人確認を求める）。

- WEB-214（2026-10-09 オーナー決定）：ホームは現在、タグに代わってアカウントのフォルダで絞り込む。「絞り込みを外す」は検索・状態・フォルダの選択をすべて外す。

## 2026-10-24 細部の直し C
- 設定の4画面（メンバー・統括の情報・請求・お問い合わせ）は、左に「統括の設定」の列、右に中身を置く形にそろえた。請求の数の帯も左の列より上へ張り出さず、右の中身の先頭に置く（メンバーと同じ）。
- 請求：値が無い数のマスは「— 件」のように単位だけを出さない（共通の数の帯）。「課金の対象外です」と本文の間に句点を入れる。プランのカードは中身の高さでそろえ、ボタンが無いカードの下の余白は24にする。
- 入力欄の説明と文字数は同じ1行（説明は左・文字数は右）にし、欄との間を6にする。統括名の説明も欄の部品へ渡す。

## 2周目の調整（2026-10-09）
- 会社・連絡先の必須表示は薄い文字。入力誤りは該当欄の赤枠と理由で示し、最初の誤りへフォーカスする。通信・権限・競合の失敗は従来の案内を残す。

## 接続と期限の表示
- 接続は一覧・単体・ヘルス・運用確認で同じ保存記録の集計を使う。bot と Webhook の両方が成功した場合だけ正常にする。記録なしは未確認、停止中・アーカイブは別の状態として扱う。
- Webhook の24時間以上の無受信は、受信不要の指定がない場合だけ要確認とする。通知・一覧で同じ日時の判定を使い、未確認を正常や故障へ読み替えない。
- トークンの期限と自動更新の失敗は接続と別に表示する。時差の無い保存日時はJSTとして読み、残りの日数と期限の状態は共有の関数から得る。
- ヘルスのログは履歴。現在の接続状態が不明なとき、過去のログで補わない。

統括表は「LINE接続」と「お支払い」を独立して表示する。お支払いは既存の設定の読取だけを使い、未取得・失敗は「—」、実値の接続済み・試験モード・未接続を区別する。名前横に接続の札を重ねない。

期限が近いことの予告は14日前から表示する。運用確認の注意は、期限切れ・自動交換の失敗・残り7日未満でも交換されない場合に分け、正常な自動交換を予告だけで異常にしない。
