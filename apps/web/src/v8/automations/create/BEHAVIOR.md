# オートメーション ルールを作る（V8）の動き

入口：`app/automations/new/page.tsx`（V8 のときだけ `src/v8/automations/create/create.tsx`、それ以外は今の v7 の画面）。
絵：`M4torY`（ルールを作る）・`tJqST`（保存が先にされていた＝競合）。
下書きを仕上げる（`J1VA8`・`/automations/drafts`）は `app/automations/drafts` のまま（この担当の外）。

## 受け付ける URL と指定（今と同じ）
- `/automations/new`：白紙から作る
- `/automations/new?draft=<下書き>`（`?id=` も同じ）：保存した下書きを開いて続きを直す。保存すると URL に番号を載せる
- 前にこのアカウントで保存した下書きがあれば「保存した下書きを開く」を出す（sessionStorage の控え `lh-automation-new-draft-v1`）

## 呼ぶ口（今と同じ。app/automations/new/new-v8.tsx から写した）
- 読む：`automations.draftResources`（タグ・シナリオ・共通アクション）・`automations.list`（同じきっかけのルールがあるか）・`getDraft`
- 下書きを保存：初めては `createDraftFromTemplate('received-message-tag', アカウント, 冪等の鍵)` → `updateDraft`（版の札つき）→ `getDraft` で版を確かめる
- 版が重なった（409・または読み直しで版が違う）→ 競合の帯（tJqST）。「違いを比べる」「最新を読み込んで続ける」、主ボタンは「比べてから保存」（承知の上書き）
- つくって動かす：確かめの窓 → 保存 → `publishDraft(…, activate=true, 'draft')` → 一覧（`?highlight=`）
- 人数：保存のあと `audiencePreview`（失敗しても保存は失敗にしない。「人数をもう一度数える」）
- 1人で試す：保存済みの下書きを読み直して送る内容を窓で確かめる → `automations.test` → 実行の状態（`getRun`）
- アカウントを切り替えたら入力ごと切り替え、前のアカウントの入力は控えに残す（DETAIL-14）

## 今の V8 画面（app/automations/new/new-v8.tsx）と違うところ
- 型（CreatePage）に載せた。右の列は「文章にすると・人数・1人で試す・気をつけること・つながる先」
- きっかけは代表3件の選ぶカード。「ほかのきっかけもすべて見る」で全10件と探す欄を出す（選んでいるのが代表外なら最初から全件）
- 「含まれる言葉」は、メッセージを受け取ったときだけ、きっかけの段の中
- だれに：「動かす相手」の選ぶ欄の形のボタン（条件の要約・無ければ「すべての友だち」）と「＋「いずれか1つ以上を満たす」条件（or 条件）を足す」。どちらも条件の窓（共通の ConditionBuilder）を開く
- 何をするか：1行＝番号・何を・どれを・「…」。「…」から「中身を直す（窓）・上へ・下へ・削除（最後の1つは消せない）」。「＋ すること を足す」「共通アクションから選ぶ」は行を足して中身の窓を開く
- することの種類から「担当へ知らせる（notify_staff）」を外した。この画面には知らせのルールを選ぶ口が無く、選ぶと文面の送信として保存されてしまうため（写し元も同じ不具合）
- 文章にすると：「〜したら、（条件の人に、）〜して、〜します。」の1文。保存に送るのと同じ値から作る
- 人数の段は「友だち全体」「人数」（数えた下書き・アカウントと同じときだけ全体の数を出す）
- 済んだことの知らせ（保存した・読み込んだ・テストを受け付けた）は本文の帯ではなく右下の知らせ（帯だと段が下へずれる）
- 閲覧のみ（権限なし）には「下書きを保存」「つくって動かす」「…」「＋ すること を足す」「共通アクションから選ぶ」「1人で試す」を置かない。閲覧のみの帯を出す
