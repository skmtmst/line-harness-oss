# 回答フォームの編集の動き（BEHAVIOR.md）

対象：`app/form-submissions/edit/page.tsx` から表示するV8の `edit.tsx`。見た目は作る型（CreatePage）と共通部品で組んだ。
板：中身 `m1cWEy`・1152 `ITBAB`・予約を入れるブロック `ijxur`・答え終わったあと `XXFT4`・受付と見た目 `tpRRT`・競合 `J1pdB`・この版を公開 `Z9wXm`。

## 入口
- `app/form-submissions/edit/page.tsx`：V8専用で `@/v8/form-edit/edit` を出す。テーマによる切り替えと旧表示のための契約は使わない。保存・権限・失敗時の動作の試験を保つ。

## 受け付ける URL と指定
- `?id=`：編集するフォーム（必須。無ければ「指定されていません」）。
- `?tab=`：`content`（中身・既定）・`after`（答え終わったあと）・`appearance`（受付と見た目）。今までの名前も受ける：`basic`→中身、`options`→答え終わったあと、`design`→受付と見た目。タブを替えると `?tab=` を書き換える（画面の中の移動なので離脱の確認は出さない）。
- `?page=`：開くページ（1から）。範囲外は1ページ目。
- `?block=`：設定を開いておくブロックの ID。無ければ、そのページの最初の質問を開く（質問が無ければ閉じたまま）。

## 読み込み（API）
- `api.forms.get(id, accountId)`：名前・覚え書き・受付中か・回答数・回答時のタグ・リンクのカード（見出し・説明・画像）・中身（layout）・編集の版（contentRevision）・公開中の版（publishedVersionId・publishedContentRevision）。
- 参照：タグ（`/api/tags?lineAccountId=`）・友だち情報の項目・シナリオ・リマインダ・テンプレート（アカウントで絞る）。予約のメニュー（`bookingApi.listMenus`、本体を待たせない）と、メニューごとの担当（`bookingApi.listMenuStaff`、予約を入れる欄のメニューが決まったものだけ）。
- 失敗：404 は「見つかりません」、403 は「開く権限がありません」（再試行なし）、そのほかは「読み込めませんでした」＋もう一度。

## 保存と公開
- 「下書きを保存」：`api.forms.update(..., expectedContentRevision)`。名前が空・タイトルが空の質問・回答キーの重なり・中身の形（`validateFormLayoutForSave`）・カード画像が https でない・文字と背景の差 4.5:1 未満は送らずに理由を出す。未公開の下書きは受付中にしない（`isActive: publishedVersionId ? isActive : false`）。
- 「この版を公開」：確かめの窓（Z9wXm・幅 640・上から 220）を出す。窓の中の「この版を公開」で、公開前の検査（`validateFormForPublish`）→保存→`api.forms.publish(id, accountId, 保存で返った版)`。「変わること」は、**公開中の版**と画面の今の中身の違い（足した・消した・変えた）。公開中の版は窓を開いたときに `GET /api/forms/:id?view=published`（account_id なし＝お客さまに見えている版を返す。`view` は印だけ）で読む。読めないとき（未公開・受付停止・通信失敗）は、保存してある下書きとの違いに戻す。題は「変わること（版{公開中の版} → 版{編集の版}）」、2行目の注意は「いまの版{公開中の版}がそのまま使われます」。
- 409（ほかの人が先に保存）：送った中身と保存されている中身が同じなら自分の再送として成功扱い（M003）。違えば入力を残したまま上に帯（J1pdB）。「違いを比べる」で最新との違いを窓に出し、「最新を読み込んで続ける」で読み直す。帯が出ている間、下の帯の主のボタンは「比べてから保存」（違いの窓を開く）。
- 公開前に試す：`api.forms.issueTestToken` で試しのURLを作る（保存済みの下書きが出る。試しの回答は集計に入らない）。
- 回答用URL：`https://liff.line.me/<LIFF ID>/forms/<id>`。見せるのは短い形、コピーは全文。LIFF を登録していないアカウントでは案内だけ出す。
- 未保存の変更があるときの離脱は、共通の番兵（`useUnsavedGuard`）で止める。「保存せずに移る」で読み込んだ姿に戻す。

## 中身のタブ
- ページの札（押すとそのページ）・「ページを足す」・右上の「…」（名前を変える・複製する・このページを消す）。空のページも消す前に確かめ、元に戻す操作は付けない。そのページへ飛ばしていた選択肢は「次へ進む」に戻す。
- ブロックの行：つまみ（矢印キーで上下・つかんで落とす）・印・題と種類・「…」（設定を開く・複製する・上へ・下へ・消す）。押すと設定が開く（1つだけ）。
- 開いた設定：種類・必須のつまみ（文字を押しても動く）・「…」（設定を閉じる・詳しい設定・複製・上へ・下へ・消す）。質問文、選択肢（並べ替え・消す・足す）、答えを保存する先（友だち情報の項目。本名・表示名・メモへの保存は詳しい設定）。予約を入れる欄はメニュー・担当・選べる期間（今日から 7・14・30・60日）と「予約の設定を開く」（`/booking/menus`）。飾り（見出し・本文・画像・ボタン）はその中身。
- 「詳しい設定」：今までのブロックの設定（分岐・選んだときの動き・入力の形・説明・初期値ほか）を窓で開く（`components/forms/block-editor`）。
- ブロックを足す：4組 17種（時刻は1行の欄に形「時刻」、メールは形「メール」、電話は形「電話」を付けて作る。質問文は「メールアドレス」「電話番号」が入っている）。足すと設定が開く。

## 編集を離れる時
- 店のフォームは共通の離脱確認から下書きに保存して移れる。成功を待って移り、失敗なら入力を残して編集へ戻る。
- このタブで自動作成した店・ID・版の記録がある未公開フォームは、未変更でもキャンセル時に下書きを残すか消すか聞く。自分の自動保存の版だけ追い、手の保存が通れば通常のフォームとして扱う。
- 消す前は実行中の自動保存を待ち、同じ店・IDの削除影響を読む。公開・利用先・他の版への変更があれば消さない。確認した削除の版を送る。失敗は窓内に出し入力を残す。店を切り替えた後の古い確認結果で削除や移動をしない。
- 既存フォームの未保存変更を破棄してもフォーム本体は消さない。統括の埋め込みも保存結果を待ち、成功した場合だけ離れる。失敗・結果未確定なら入力を残す。店の保存・削除APIは呼ばない。
- 統括の通常保存が通れば保存済みの控えを更新する。「保存して配る」の成功後は親が配布先の段へ進むため、編集部品から追加の画面移動は行わない。

## 新しいフォームの最初の保存
- `new` に作成操作の番号があり、IDがない場合は保存前の編集を開く。最初は名前・入力が空で、回答用URLは最初の保存後に表示する。指定が何もない既存の編集URLは従来どおり対象未指定の案内を出す。
- 最初の有効な自動保存・手の保存・離脱の保存で下書きを作り、そのIDと版で内容を保存する。自動保存は2秒のまま。作成には同じ操作番号を送るので、作成応答を失って再送しても同じフォームになる。
- 作成後の内容保存が失敗しても、IDと版・入力は保持して同じ対象へ再試行する。自分のIDへの切替で入力を読み込み直さず、保存中に追記があれば画面に残す。追記がない保存成功後にID付きURLへ移る。離脱の保存では予定していた移動を優先する。
- 作成元の店・ID・版は最初の作成成功時に記録する。自動保存は記録の版を進め、手の保存は通常のフォームとして扱う。別の店に移った後の応答で現在の入力や移動を変えない。
- 作成APIの任意の `Idempotency-Key` は16〜128文字の英数・ハイフン・下線。店・操作者・操作番号で分け、同じ内容は作成時のIDと版、別の内容は競合、削除・保管後は利用不可を返す。下書き・所属・操作記録は同じ処理で確定する。番号なしの既存の呼び出しは互換動作を保つ。
- 自動作成した下書きの削除はオーナーか管理者だけ。編集を任されたスタッフにも削除操作は灰色と理由で表示し、下書きを保存して残す操作は使える。
- 自動保存に失敗したときは、下の帯の主操作を「下書きを保存」にし、同じ帯から入力を保存し直せる。「この版を公開」は副操作にする。手の保存に成功すると失敗の表示を消して通常の操作へ戻す。保存状態は最新の1つを表示し、公開・配布の状態の説明は横の「？」で読める。
- ボタンの言葉の「前へ・次へ・送る」は、それぞれの入力欄と共通のラベルで1組にする。狭い幅で欄が縦に積まれても、ラベルだけが横並びにならない。値と保存先、閲覧だけの文字表示は変えない。
