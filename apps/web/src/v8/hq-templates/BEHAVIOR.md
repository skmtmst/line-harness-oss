## 受け付ける URL と指定

## 読み書き（API：`hqTemplatesApi`）
- 一覧 `list(type)`・目録 `list()`（参照先の候補と種類ごとの数。失敗しても一覧は出す）・配り先 `accounts()`・所属先 `context()`（`/api/staff/me` の tenantId）・分類 `folders.*`。
- 作る・直す：`create(input, requestId)`（POST の前に依頼を残す。応答不明は同じ依頼を固定し「前回の保存を再確認」、確定した拒否だけ解く）・`update(id, {expectedRevision})`（版の衝突は「最新の内容を読み込む」）。画像 `uploadImage`、使われなかった画像は `deleteImage` で後片付け（R568）。
- 複製 `duplicate`（同じ版への依頼IDを使い回す）・削除 `remove`（確認の窓）。
- 配る：選んだアカウント → `preflight`（選んだ集合と一致しない確認は使わない・期限切れは再確認）→ 重複は未選択から（一括の配布方法・アカウントごと・参照先ごとに選ぶ。上書きできないものは選べない）→ `distribute`（配布番号＝preflightId。応答不達は `result` で戻し、送り直さない）→ 失敗したアカウントだけ再確認。テキストのひな形はアカウントごとの本文（textOverrides）を付けられる。

## G-3：保存のあとに配るか選ぶ（2026-10-08 夜）
- 統括のすべての作る・編集画面の保存操作は「キャンセル」「下書きを保存」「保存する」。リッチメニューの途中は従来の手順移動を保ち、最後の保存も同じ操作。タグの統括用下書き口だけを追加し、店の保存・連続作成は保持。
- 「下書きを保存」は保存して一覧へ。「保存する」は保存の成功後に選択窓 d8CL4g を開く。拒否・版の衝突・結果不明なら開かない。結果不明の同一依頼再確認でも元の保存意図を保持する。
- 窓の「あとで」・×・Escapeは保存済みの一覧へ戻り、配布APIは呼ばない。下書き保存や確認の通信失敗でも再保存しない。

- 配った版は `receivedVersions` からだけ読む。未取得・取得失敗は未配布に読み替えない。前の読み込み結果が別の保存版を上書きしないよう、最新の読み込みだけを反映する。

- 一覧と保存済み定義は `/api/hq/templates?type=friend_field|mark` と `/:id`、フォルダは既存の `/folders`。分類フォルダと配布先に作るフォルダの定義を混同しない。
- 作成は利用者・所属・種類ごとの sessionStorage に依頼ID・入力・保存後の意図を記録し、応答不明時も同じ依頼を再確認する。編集・削除・順序変更は読んだ revision を渡す。順序変更は既存の PATCH で displayOrder を順に保存し、途中の失敗でも必ず一覧を読み直す（専用の一括順序APIはない）。
- 下書き保存は一覧へ。保存するは成功後に共通の配布先選択窓へ。キャンセル・あとで・×・Escapeでは配布しない。選択→preflight→許された重複解決→配る→進み具合・結果。期限切れ・未選択・権限不足では配布しない。
- 配布番号は sessionStorage に残す。POSTの応答が不明なら結果GETだけで復元し、失敗したアカウントだけ新たに確認できる。進行中の配布は一覧から同じひな形の「配る」を開き直すと復元する。
- 閲覧のみは作る・編集・削除・並べ替え・配るを隠す。未取得の人数と使用先は「—」。項目の重複・入力不足は欄で知らせて最初の誤りへ移動する。
- 統括APIにないもの：情報欄の種類の移行、回答フォームの使用数・出す場所・入力済みの友だちの重複除外集計・月内変更数、対応マーク別の状態集計・過去7日の変更数・詳細な自動変更ルール、分類フォルダの順序変更。別の値で代用しない。対応マークの初期値・受信時変更は保存済み定義が持つ項目だけ使う。
- 1440の絵の文字位置は指定2枚で照合する。1152の対応板は未提供なので、1152では列の畳み・切れ・右端越えを画像で確認する（1440の座標との一致率は合格の根拠にしない）。

## フォルダの「…」からまとめて配る（G-7・2026-10-09）
- タグ・テンプレート（種類タブをまたぐ）・リッチメニュー・回答フォームの作ったフォルダと未分類に「このフォルダを配る」。すべて・0件・閲覧のみには出さない。検索・種類タブで配布対象を狭めず、開く直前に種類全体の一覧を読み直す。
- フォルダ内のひな形は全部チェック済み。外せる。配る先は保存後の配る窓と同じアカウント選択部品。ひな形かアカウントが0なら進めない。
- ひな形ごとに既存 preflight と配布方法の確認を行い、全部を確認してから既存 distribute を順に呼ぶ。期限切れの未配布分は確認し直す。
- 進み具合・結果はひな形×アカウント単位で集約。同じ dEvJM の結果部品を使う。失敗した組だけ新しく確認し、成功した組には再POSTしない。
- POST前に所属先・利用者・種類で分けた sessionStorage にひな形ID・アカウントID・配布番号だけ記録。応答不明・running は GET result で確認し、結果が確定するまで次のひな形へ進まない。再読込後も同じ番号をGETで確認。未送信分は確認を取り直す。
- 新規API・Worker・DB変更なし。
