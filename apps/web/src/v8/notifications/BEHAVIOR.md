# 通知（V8）の動き

入口：`app/notifications/page.tsx`（V8 のときだけ `src/v8/notifications/list.tsx`、それ以外は今の画面）。
絵：`y8QQV`（通知 V8）。

## 受け付ける URL と指定（今の画面と同じ名前・同じ意味）
- `/notifications`：すべて。
- `?category=error`・`?category=update`：エラー・アップデートだけ。ほかの値はすべてとして読む。タブを押すと `router.replace` で書き換える（ほかの指定は残す）。

## 呼ぶ口（今の画面と同じ）
- 一覧：`api.notifications.center.list(accountId, { category, limit: 50, offset })`。返事は `isDashboardNotificationData` で形を確かめる。古い返事は番号で捨てる。
- 既読：`api.notifications.center.markRead(id, accountId)`。押した瞬間に画面へ反映し、失敗したら未読へ戻して「やり直す」の知らせ（`runOptimistic`）。
- まとめて既読：`api.notifications.center.markAllRead(accountId, category)`。同じく先に反映し、通ったら読み直す。未読が 0 のときは押せない。分類を選んでいるときは「この分類をすべて既読にする」。
- さらに読み込む：50件ずつ。残りの件数をボタンに出す。

## 並び
- 未読が先・新しい順（今の画面と同じ）。口（`GET /api/notifications/center`）が作成日の新しい順で返すので、画面は未読と既読に分けるだけで、それぞれの中は口の順のまま（今の画面は画面でも日時で並べ直していた。実際の順は同じ）。

## 行
- 印（エラーは赤い丸の三角、アップデートは青い丸の光）・題（未読は太字と青い点、読み上げは「（未読）」）・日時・右に「〇〇を開く →」。
- 行のどこを押しても既読にして行き先へ移る（1行＝1つのボタン。右の言葉は行き先の説明）。
- 本文（`body`）は絵に無いので行の `title`（指を乗せると出る）に置く。

## 行き先（今の画面からの変更）
- ダッシュボードの通知パネルと同じ判定（`dashboardNotificationDestination`）。
- **変更**：種類が `ec.` / `ec_` で始まる EC連携の通知は `/ec-commerce` へ（今まではお知らせ一覧 `/updates` へ行っていた）。
- 右の言葉：EC連携を開く・運用状態を開く・配信を開く・マニュアルの表を開く・更新履歴を見る（アップデート）・詳細を見る（メンテナンスの予告とそのほか）。

## 読み込みの状態
- 読込中：箱の下に「読み込み中…」。
- アカウント未選択：「LINEアカウントを選択してください」の帯。
- 一覧が取れない：箱の中に共通の失敗の1枚（403 は再試行なし、429・通信失敗は「もう一度」）。追加読み込みの失敗は上の帯（「もう一度読み込む」）。
- 0件：「通知はまだありません」。
- 未読が 0：下の注記が「未読のお知らせはありません。」に替わる。

## 絵に無いが残したもの
- 「通知設定」（`/line-notifications?tab=operator`）：今の画面の右上のボタン。絵に無いので下の注記の右に小さな道として置いた。
