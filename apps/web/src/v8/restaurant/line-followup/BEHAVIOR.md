# LINE来店フォロー（V8）の動き

入口：`app/restaurant-test/line-followup/page.tsx`（V8 だけで出す）。絵：`n9vvGx`（LINE来店フォロー 融合）。

## 受け付ける URL と指定
- `/restaurant-test/line-followup`：指定なし。

## 呼ぶ口（本番接続）
- 1店舗分：`GET /api/restaurant-test/followups/:storeId?account_id=...`（ひな形・結び・ジョブ）。まだ無い店舗は 404。
- 本文：`GET /api/scenarios/:id` の一歩の `messageBubbles`（共通の scenarios の口）。吹き出しが無く旧来のテキスト1通だけの一歩は、1通に読み替えて出す。
- 本文の保存：`PUT .../steps/:stepId/messages`（テンプレートの版＋吹き出し1〜5個）。
- オン/オフ・時期：`PATCH .../bindings/:stepId`（テンプレートの版＋きっかけ＋時期の分＋オン/オフの4項目）。
- 承認の申請：`POST /api/scenarios/:id/publish`（確認キーつき）で本体を公開し、増えた版を取り直してから `POST .../request-start`（取り直した版）。止める：`POST .../stop`。
- 口コミ依頼の送信履歴：`GET .../review-history`。
- 版はすべてテンプレートの版（`template.template_version`）。保存・申請の後は読み直して版を取り直す。
- 時期の規則は鯖と同じ（前は負・後は0以上・525600分以内）。記念日前は今の鯖ではどの値も通らない。
- 申請は本体の公開版を対象にする。申請の直前に公開して画面の本文との一致を保つ（公開に失敗したら申請を出さない）。公開で版が増えるため、申請には取り直した版を使う。取り直した中身が公開時と違えば（ほかの担当者の割り込み）、申請を止める。

## 表示
- 板の頭：題・「?」の説明・題の下に店名。右に店舗を選ぶ欄。検証環境の帯と数の帯は出さない（融合の絵どおり）。
- 送りの状態の行：本送信しています／承認を待っています／本送信は止めています（中身の版つき）。読めない数は 0 や作り話で埋めない。
- 7つの行（印・名前・説明・時期・状態の札）。押すとその行の下に操作が開く。選んだ行は緑の枠＋薄い緑の地。
- 行の定義は `config.ts`（業種ごとに差し替えられる形。今つながっているのは飲食だけ）。
- 開いた行：［送る／止める］・時期（数値＋単位→分。既存値は割り切れる一番大きい単位で正確に出す）・本文（共通の MessageComposer を1通だけの形 `bubblesOnly`）・［本文を保存する］・［くわしく設定する →］（本体のシナリオ画面）。
- 本文が2通以上あってもこの画面で直せる（本体では保存を断られるため）。テキスト以外の吹き出しは理由を出して触らない。
- 吹き出しが無く旧来の形もテキスト以外の一歩は、空欄に見せず編集を止める（本体では直せる）。
- 口コミ依頼の行には送信履歴の件数。読めなければ「読めませんでした」（0にしない）。
- 承認の申請中は送りの状態の行が［承認の確認へ →］の行き先になる（`/restaurant-test/approvals`。左メニューは変えない）。
- 行を切り替えても未保存の本文を保つ。読み直したら捨てる。店を切り替えると作り直す（別の店の下書きを持ち込まない）。
- 右の「LINEでの見え方」は選んだ行の送る中身そのまま（共通の吹き出し部品。送らない画像やボタンは付けない）。描けない通は消さず、その位置に未対応の説明を出す。直せない形の本文は正直な一文を出す。白い板1100px未満では共通の開閉ボタンから確認する。
- 閲覧のみは操作を隠さず灰色＋理由（lockedReason）。役割が読めない間は閲覧のみと断定せず理由なしで止める。
- まだ無い店舗は7行の見本を出し、保存系は置かない。
- 記念日前はオンと時期を止め（サーバーの口がまだない理由つき）、本文だけ直せる。
- 結びの無い行は理由を出して変えさせない（本体の一歩の自動作成の口がまだない）。
- 409（ほかの担当者の先読み）は読み直しても知らせを保つ。
