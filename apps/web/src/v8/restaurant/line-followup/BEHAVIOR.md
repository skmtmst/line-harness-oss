# LINE来店フォロー（V8）の動き

入口は `app/restaurant-test/line-followup/page.tsx`。予約の回答フォームと7つの送り方を8枚のカードで設定する。見た目はオーナー承認のカード案に従う。

## URLと店の境界

- `/restaurant-test/line-followup?store_id=...` で店を指定する。`repair_form=1` は壊れた予約フォームの修復窓を開く指定。
- アカウントや店を切り替えると画面を作り直す。前の店の遅い応答や未保存内容を次の店へ持ち込まない。未保存のまま離れる操作には共通の確認を出す。
- 管理APIはアカウントと店の所属をサーバー側で照合する。変更・テスト・開始・修復・今は使わないの保存はオーナーと管理者だけ。閲覧のみの人は変更できない。

## 読み取りと保存

- 店の既存設定は `GET /api/restaurant-test/followups/:storeId`、新しい実物と簡易編集用の内容は同じ配下の `GET /engines`、フォームは `GET /reservation-form`、口コミの案内履歴は `GET /review-history` で読む。
- 最初の保存は `POST /engines/initialize` で7行を同じbatchにまとめる。一部の行だけを新しい送り手へ切り替えない。以後は変更した行だけ `POST /engines/:trigger/draft` へ、読んだ行と実物の版を付けて保存する。
- 保存は止めた下書きまで。既存の実物のIDを保って更新する。保存の窓には作った場所・成功した行・失敗した行を分けて出し、一部失敗を全件成功にしない。失敗した入力は残す。
- 詳しい構成の実物は簡易編集に戻さず、本文や条件を消さずに詳細へ案内する。旧来のシナリオのAPIは互換のため残すが、この画面の新しい保存には使わない。

## テストと送り始め

- カードの操作から `POST /engines/:trigger/test-send` でテストする。宛先はサーバーが本人のLINEか登録済みテスト宛先に決め、画面から友だちIDを渡さない。
- テスト成功後の［この内容で送り始める］は `POST /engines/:trigger/start`。同じ版・同じ中身のテスト成功を照合し、公開と承認を同じbatchで行う。結果不明のテストは再送しない。
- 状態の札は実際の送信ゲートで判定した状態を使う。詳細画面から編集・再公開した後は止まる理由を出し、同じ版のテストと承認へ戻す。
- 旧ジョブの送信結果が不明な店は移行を拒否する。LINEへ出していないことが確定した失敗だけは移行できる。手動で成功を作る口や自動再送は置かない。

## 予約フォームと復旧

- フォームのカードにスイッチはない。名前・日時・人数は必須で固定。項目名・任意項目・完了文は `PUT /reservation-form` で保存し、実際のLIFF予約画面でも同じ設定を使う。
- 予約確定時は、読んだフォームの版と保存値を予約の確定・通知と同じbatchで照合する。途中で設定が変わった場合は確定も通知も残さない。
- 設定が壊れたとき、お客さま側は必須3項目の復旧フォームで受付を続ける。管理側は503と修復情報を返し、ダッシュボードと来店フォローに理由と修復への入口を出す。
- 修復は壊れた保存値の指紋とCASを使い、成功したときだけ監査に残す。通常の保存で壊れた設定を黙って上書きしない。

## 表示と権限

- 8枚のうち7枚にスイッチと［変える］の窓を出す。題を強く、時期を小さくし、文字操作は緑。常設の説明はこの画面の指定に従い、共通Noticeで1行と2つの設定画面へのリンクを出す。
- スマホ見本は共通部品を使い、カード内だけ高さを抑える。本文とテンプレートの中身をそのまま描き、描けない構成を空の成功表示にしない。
- 権限がない操作は灰色と理由。状態で押せない操作は、その近くに理由を出す。役割が未取得の間は変更を許可しない。
- ［今は使わない］は全てオフで未保存変更がないときだけ選べる。`PUT /setup` で店ごとの判断と版を保存する。スタッフと閲覧のみの人には［オーナーか管理者が決めます］と案内する。
- リマインダとオートメーションの一覧・詳細にも管理元と実際の停止理由を出す。読めない件数を0で埋めない。

## 送り方の編集中に画面を離れる時

- 送り方の編集窓が開いている間は、その窓がページ側と窓内の未保存変更をまとめて守る。リンクやブラウザの戻るで確認を1つだけ前面に出す。［編集を続ける］は両方の入力を保ち、［保存せずに移る］を明示した時だけ両方を破棄して元の行き先へ移る。
- 窓のキャンセル・×・Esc・背景は、窓内だけの入力破棄を確認する。窓を閉じてもページへ確定済みの未保存変更は残し、その後の画面移動はページ側が守る。［この内容でオンにする］はページへ入力を渡すだけで、保存・テスト送信・開始は行わない。
- 確認の行き先は窓を閉じ直した時、別の送り方・アカウント・店に替えた時に引き継がない。処理中や閉鎖済みの窓から、古い離脱確定を実行しない。
- 予約フォームの編集窓も、ページ側と窓内の未保存変更をまとめて守る。窓だけを閉じる時は窓内の変更だけを確認し、ページの未保存変更を保持する。
