## Uber Eats の現在の提供範囲（2026-10-20）

- 接続設定の完了と注文の連携は別。接続済みでも注文の取り込み・受ける・断る・取消・準備完了・営業状態の変更・メニュー同期はまだ利用できない。共通の準備中の窓で説明し、実操作は押せない。
- 設定画面のログイン・店舗選択は維持。接続の確認・解除の入口と結果不明時の再送停止も維持し、未接続のAPIを成功したように表示しない。
- 受注画面の接続の札は設定画面と同じ保存済みの接続APIを読む。この読み口はオーナー・管理者専用なので、閲覧のみ・権限の読込中は照会せず「接続未確認」とする。失敗・未取得は「接続未確認」、結果不明は異常として表示し、別の店の遅い応答を混ぜない。
- Uberの注文は一覧・詳細・履歴・CSVで確認できる。一括受付と停止の対象からUberを除く。他社の受注・停止・再開は維持する。
- 品切れのAPIは商品に紐付いた全サービスへ送るため、Uberを含む商品の選択・切替は止める。他社だけの商品は従来どおり。保存済みの商品・販売状態は消さない。
- 閲覧のみでは変更操作を隠す。Worker・DB・通信APIの実装、署名・権限・別店の境界・送信停止旗・上限は変更しない。

以下の既存の送信仕様は、Uber以外の操作と保持している実装の説明。Uberを利用可能とする記載には使わない。

## 入口・受け付ける URL
- `app/restaurant-test/delivery/page.tsx`：新しい画面なので V8 だけで出す。横の案内（`lib/menu.ts` の `restaurant-delivery`）から入る。
- `?view=`：`history`（注文履歴・売上 OzHLO）・`sold-out`（品切れ一括設定 h7OeT）。無いときは注文一覧（kDQHr）。
- `?tab=`：`new`（新着）・`cooking`（調理中）・`handed_over`（受け渡し済み）・`all`（すべて）。無いときは `new`（まず受けるべき注文を出す）。
- `?id=`：注文の詳細（hjdqV）を開く。閉じると `?id=` だけ外す。
- 注文履歴の日付とサービスの絞り込みは URL に出さない（画面の中の状態だけ）。
- 画面の移動は `useSamePageUrl` を通す。段やタブの切り替えは `replace`、注文の詳細を開くときは `push`（戻るで閉じられる）。読み直しが起きないようにするため、`useRouter` を直に呼ばない。
- 器は `../common-a/frame` の `RestaurantPage`（板の印・読み込み／失敗）。頭と筋道は `usePageTitle` / `usePageCrumbs` でこの画面が付ける。検証環境の帯は `BoundaryBanner`。

## 読み込み・送る形
- 注文一覧：`restaurantDeliveryApi.orders(accountId, { tab })`。店舗を選ぶ欄のために `restaurantTestApi.snapshot(accountId)` も同時に呼ぶ（`orders` の `store` は id と名前だけなので）。snapshot が取れなくても一覧は出す。
- 30秒ごとに、画面を光らせずに注文一覧を取り直す。帯には最後に取れた時刻を出す。取れていないときは「—」。
- 注文の詳細：`restaurantDeliveryApi.order(accountId, id)`。
- 状態を進める：`accept`（受け付ける）・`ready`（準備完了）・`reject`（拒否）。
- キャンセル：`cancel(accountId, id, reasonCode)`。取り消せないので `x-confirm-irreversible: delivery-order-cancel` を付ける（合わないとサーバが 428 で断る）。
- 受付の一括停止：`stopIntake(accountId, services, preset)`。同じく `x-confirm-irreversible: delivery-intake-stop`。再開は `resumeIntake(accountId, services)`。
- 注文履歴：`history(accountId, { from, to, service, status })`。CSV は `historyCsv` で、返った `totalCount` / `returnedCount` / `truncated` から「何件のうち何件を書き出したか」を帯に出す。
- 品切れ一括設定：`menuItems(accountId)` で品目を取り、`bulkSoldOut(accountId, itemIds, soldOut)` で送る。1件ずつの切り替えも同じ口。
- 「まとめて受け付ける」のまとめ送りの口はサーバに無いので、この画面が選ばれた新着を1件ずつ順に `accept` する。
- 取得と送信はこの画面だけが持つ。子（`orders` ・`history`・`bulk`・`order-detail`）は受け取った数と状態を出すだけ。

## 画面
- 注文一覧（kDQHr）：
  - 状態の段（新着・調理中・受け渡し済み・すべて）。新着が1件以上あるときだけ数を琥珀で出す。
  - サービスの札3枚：接続済み／未接続／接続の異常と、受付中／停止中。停止中は「〇〇 まで停止」も出す。1段目の右に止める・再開のボタン（札と数は2段目で、狭い幅でも重ならない）。
  - 数5：本日の注文・本日の売上・急ぎ対応・平均準備時間（それぞれ「…」から注文履歴・売上を開ける）。
  - 表（選ぶ・注文番号・サービス・注文内容・金額・経過・急ぎ度・状態・操作）。新着だけ選べる。選ぶと上に「選択中 〇件」と「まとめて受け付ける」が出る。
  - 操作：行の右端は主な操作を1つだけボタンにし、残りは「…」（新着＝受け付ける／…に 詳細を見る・断る、調理中＝準備完了にする／…に 詳細を見る、それ以外＝詳細）。注文番号を押しても詳細が開く。
  - 下に共通のページ送り（「〇件中 1〜〇件を表示」）と、道具の段の右端に表示件数（10・20・50件。既定20）。サーバの頁送りではなく、受け取った分をページに分けて出す。
- 注文の詳細（hjdqV・幅560・上120）：受信と受け取り希望の時刻、急ぎ度の案内、注文内容、受け取り情報、合計（税込）。下の操作は状態で変わる（新着＝注文をキャンセルする／断る／受け付ける、調理中＝注文をキャンセルする／閉じる／準備完了にする、それ以外＝閉じる）。
- キャンセルの確認（dgeTy・幅460・上330）：取り消せない操作の確認。**頭は絵のとおり白地で、題の左に丸い注意三角を置く**（共通の窓が持つ桃・赤の帯は `plainTitle` で外す）。理由は選択肢だけ（品切れ・混雑・調理機器の不具合・お客様からの申し出・その他）で自由文は送らない。「取り消せません」と書く。
- 注文履歴・売上（OzHLO）：日付とサービスを選び、売上の数と表を出す。CSV で書き出せる。きょうを見ているときは数の見出しに「本日 」が付く。
- 品切れ一括設定（h7OeT）：品目を名前で探せて、品切れだけに絞れる。選んでまとめて品切れ／取り消し、1件ずつの切り替えもできる。
- 受付の一括停止（XCVGd・窓）：止めるサービス（受付中のものだけ）と時間（30分・60分・90分・本日中）を選ぶ。窓に書いてあるとおり、選んだ時間が過ぎると受付中へ自動で戻る（下の「期限が過ぎた停止の自動再開」）。
- 時刻はすべて店舗の時間帯（日本時間）。取れない数は作らず「—」。
- 急ぎ度の判定はサーバ側だけで行い、画面には「急ぎ・注意・ふつう」と理由の文しか来ない。判定の仕組みの名前は画面に出さない。

## 期限が過ぎた停止の自動再開
- 受付の一括停止（XCVGd）は「過ぎると自動で再開します」と約束しているので、期限が来たら受付中へ戻す。画面側に新しい部品は足さない（承認 v02 の6枚のまま）。
- 戻す仕掛けは時刻起動（cron）ではなく**読み込みのとき**。注文一覧 `GET /api/restaurant-test/delivery/orders` はサービスの状態を読む前に、停止の期限が過ぎているものを探して各サービスへ再開を送る。検証環境は cron を使えないため、この形にした。
- 30秒ごとの取り直しも同じ口を通るので、画面を開いたままでも期限が過ぎれば札が「受付中」に戻る。
- 再開が**通ったサービスだけ**を受付中へ書き戻す。送れなかったサービスは停止のまま残し、次に読み直した時にもう一度試す（送れていないのに画面だけ受付中になることを防ぐ）。
- 画面で確かめるときは、停止したあと期限が過ぎてから `/restaurant-test/delivery` を開き直す（または開いたまま30秒待つ）。

## 閲覧のみ
- 役割が staff（`useStaffRole`）のときは、受け付ける・拒否・準備完了・キャンセル・停止・再開・品切れの切り替え・まとめて受け付けるを置かない（2026-10-06 オーナー決定にそろえる）。役割が分かるまでは出さず、役割が閲覧のみのときは閲覧のみの帯を出す（サーバの 403 が最後の守り）。
- 見るだけの注文履歴・売上と CSV は閲覧のみでも使える。
- サーバ側も同じ線で切る。書き込む口（受け付ける・準備完了・受け渡し済み・拒否・キャンセル・停止・再開・品切れのまとめ設定）は `requireRole('owner','admin')`、見るだけの口（一覧・詳細・履歴・CSV・品目一覧）は staff も通す。
