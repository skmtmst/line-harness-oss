# 飲食店向け（担当 a）の共通の器の動き

画面ではなく、ダッシュボード・承認・組織・LINE来店フォローが使う器と小さな部品。

## frame.tsx
- `RestaurantFrame`：題・説明・右上の「店舗を選ぶ」（幅210）→ 検証環境の帯 → 板ごとの中身。
- 呼ぶ口は今の画面（app/restaurant-test/v8/shell.tsx）と同じ `restaurantTestApi.snapshot(accountId, query)`。
- 取得失敗と未登録を混ぜない（D024）：失敗は共通の失敗の1枚（もう一度）、組織が無いときは「店舗が登録されていません」。
- 店舗の選択：先頭の店舗が既定。`allStores` の画面（承認）は「店舗：すべての店舗」が既定。
- 書き込み（`mutate`）は成功したら取り直して帯に結果、失敗したら API の文（無ければ「保存できませんでした。」）。
- 板ごとの任意：`pickerAs="select"`（店舗を選ぶ欄を共通の EntitySelect に）・`banner={false}`（検証環境の帯を出さない）・`subtitle`（題の下の1行）・`actions`（店舗の欄の右の操作）。渡さない画面は今までどおり（LINE来店フォロー n9vvGx が使う）。
- `RestaurantPage`：取得を持たない画面（Googleビジネス）用の板の頭と中身だけ。

## parts.tsx
- 数のカードは共通の `KpiCard` を絵の寸法（見出し11/600・数22/700・下11）で使う。日本語を含む数（「38件」）は日本語の書体で出す（絵の行の高さ32）。
- 状態の札は共通の `StatusBadge`。差戻しは灰（絵どおり）。
- 日時「2026/09/30 10:12」は `formatStamp`。
