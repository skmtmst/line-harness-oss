# Googleビジネス（V8）の動き

入口：`app/restaurant-test/google/page.tsx`（V8 で出す。今までどおり完全切り替え）。
絵：口コミ `j0Wcg`・返信を作る `x9HIR`・投稿 `Cfed0`・投稿を作る `T1j2Sw`・パフォーマンス `SrmVs`・プロフィール `JUTGz`・設定 `CuHXG`。

## 受け付ける URL と指定（今の画面と同じ名前・同じ意味）
- `?tab=reviews|posts|performance|profile|settings`：タブ。未接続のときは設定に固定。
- `?tab=reviews&view=draft&id=<口コミ>`：返信を作る。id が無いときは一覧。
- `?tab=posts&view=new&kind=standard|event|offer`：投稿を作る（kind 既定は standard）。`view=edit&id=`：直す。`view=confirm&id=`：公開前の確認。
- `?tab=profile&view=confirm&id=<変更案>`：現役の V8 外枠と共通部品で変更の確認を出す。複数の変更案はカンマ区切りで1件ずつ確認して送る。
- `?tab=profile&view=history&result=all|applied|pending|failed`：現役の V8 の変更履歴。種類・結果・期間・検索で絞り、CSVで出力し、変更案のある行から確認画面を開く。
- `?tab=profile&view=edit`：現役の V8 の共通部品で店舗名・住所・電話・サイト・紹介文・写真を編集する。変更した項目だけ変更案を作って確認画面へ移る。
- `?tab=profile&view=hours&mode=text|calendar|weekly&date=YYYY-MM-DD`：現役の V8 の共通部品で営業時間を変更する。文章/日付指定/毎週の3方式。日付指定は共通の暦と登録済み/変更する日の一覧で日を選び、複数日を保持する。
- `?google=connected|reconnected|select_location|error:*`：Google からの戻り。1回だけ帯に出して URL から消す。

## 呼ぶ口（今の画面と同じ `restaurantGoogleApi`）
- 接続：`connection`（＋店舗を選ぶ欄のために `restaurantTestApi.snapshot` の店舗）。店舗を選ぶと、その店舗の LINE アカウントへ切り替える。
- 口コミ：`listReviews`（評価・状態・並び・検索 300ms・20件ずつ）、`syncReviews`（最終同期が古いと開いたとき1回）、`review`・`generateDraft`（押すだけ。長さや調子の指定は無い）・`saveDraft`・`publishReply`（409 already_replied・502 の扱いも同じ）。
- 投稿：`posts`（状態・種類で絞る）・`syncPosts`・`cancelPost`・`removePost`（確認の小窓）・`post`・`createPost`・`savePost`・`publishPost`。画像は登録メディアから選ぶか、端末からアップロード（道具は入口が渡す。src/v8 から @/app を読まないため）。
- パフォーマンス：`performance(7|28|90)`（既定28日）。
- プロフィール：`profile`・`syncProfile`・`proposeHours`（今日を休みにする・今日は早く閉める → 変更の確認へ）。
- 変更確認：`change`・`sendChange`・`cancelChange`。確認チェック・送信の権限と環境を守る。競合は最新値を示して停止。送信結果不明は再取得して確認を外し、再送時の照合を案内する。同時の連打は1回に制限する。
- 変更履歴：`history`（表示20件・CSV100件ずつ最大25ページ）。検索は300ms待って取得し、古い応答を捨てる。絞り込みで先頭へ戻す。失敗は再試行でき、途中で失敗したCSVを保存しない。
- プロフィール編集：`profile`・`photos`・`api.media.list(image,60,newest)`・`proposeProfile`。項目/住所/写真ごとに変更案を順番に作り、全部成功したら確認へ移る。途中の失敗は作成済み件数を知らせて入力を保つ。休業/閲覧のみは変更を止める。書きかけで戻る/タブ/店舗の切替は共通の確認を通す。
- 営業時間：`profile`・`proposeHours(text|calendar|weekly)`。基準日は店舗の今日、過去からの初期指定は今日へ戻す。共通の日付欄で今日〜366日先を選ぶ。1日3枠/15分刻み/24:00表示・同時刻/重複/最後以外の翌日跨ぎの検証を保つ。特別営業時間の取消は通常の営業時間に戻す案を作るだけ。未保存の方式変更/戻るも確認を通し、成功後に変更案の確認画面へ進む。
- 設定：`connectStart`（Google の認可画面へ）・`selectLocation`・`disconnect`（確認の小窓）。

## 送れない設定・権限
- 口コミはサーバーで確認した担当者の権限を使う。閲覧のみ・権限未確認では帯を出し、下書き作成・編集・保存・AI生成・同期（自動も含む）・公開を起動しない。保存済みの下書きと公開済み返信は「返信を見る」から読める。下書きURLを直接開いても同じ条件を守り、編集担当者の下書き保存は保つ。
- `writeEnabled` が false（検証環境）や公開の権限が無いときは、返信の「返信内容を確認」を置かない（帯の約束「送れない設定のときは送信ボタンを出しません」）。下書きの保存はできる。
- 接続を管理できない人には、接続・つなぎ直す・解除のボタンを置かない。Google の接続・解除はこの［設定］タブ 1 か所（SNS 連携のカードからはここへ移る）。

## 絵に合わせて変えた所
- 口コミの状態の絞り込みは「すべて」が既定（閉じた欄では「状態：すべて」と出る。選択肢には頭を付けない）。表示件数は口コミ・投稿・変更履歴で 10・20・50 から選べる。同期は道具の段の右の印のボタン。
- 行のボタンは「下書きを作る」／「返信を見る」の2つ（今の画面は状態ごとに言い方が違った）。
- 投稿の一覧は1つの箱に行を並べ、操作は行の「…」（中身を見る／編集・Googleで表示・取り消す・Google から削除）。
- 投稿を作るは1列。種類は選ぶ欄、期間は「はじめ・おわり」の日時の欄（送る形は今と同じく日付と時刻に分ける）。特典のときボタンは付けられない（Google の決まり）ので押せない形。表示イメージの欄は絵に無いので置かない。
- パフォーマンスの推移の棒グラフは、数のマスの「…」→「表示数の推移を見る」で下に開く。「料理の写真の閲覧」は返す口が無いので「—（未取得）」にする。料理の注文（`foodOrders`）を写真の閲覧数として使わない。
- プロフィールの店舗情報は5行（店名・住所・電話・サイト・カテゴリ）。通常の営業時間・特別営業時間・写真は「ほかの項目」で開く。カテゴリは返す口が無いので「—（未取得）」とし、意味の違う営業時間を代わりに出さない。
- 設定の LINEアカウント・接続店舗・最終同期は、下の小さな行に出す。
- 日時は店舗の時刻（日本時間）で「9/30 21:40」の形。

## Instagram にも投稿する（★V8-B `U1X7T2`・`HEEN9`、2026-10-07 利用者承認）
- 出す条件：`api.instagram.connection` が `connected` のときだけ、投稿を作る画面に「Instagram にも投稿する」の区画を出す（「出す＝使える」。つないでいない口には欄も札も出さない）。
- 新しい投稿は「Instagram にも投稿する」が**はい**で始まる。直すときは保存済みの設定（`post.instagram.enabled`）に従う。
- いいえのときは、Instagram 用の文章の欄と注記をたたむ（空の欄を見せない）。
- Instagram 用の文章は空のままでよい。空なら Google の本文をそのまま使う。上限は 2,200 文字。
- はいのときは画像が1枚必要。画像が無いまま保存しようとしたら「Instagram にも投稿するときは、画像を1枚選んでください。」と出す。
- 読むだけの状態（公開済みなど）では、スイッチの代わりに「Instagram にも投稿する：はい／いいえ」の行を出す（共通のスイッチに押せない形が無いため）。
- 投稿の一覧の札は絵のことばの3つだけ：「Instagram 済み」「Instagram 失敗・再試行」「Instagram なし」。送る前（はいだがまだ結果が無い）は札を出さない。`post.instagram` が `null` のとき＝この口が同時投稿にまだ対応していないので、札も操作も出さない。
- 失敗したときだけ、行の「…」に「Instagram へ再送」を置く（`restaurantGoogleApi.retryInstagram`）。Google の公開はそのまま残る。
- 公開前の確認の画面には「Instagram」の行を出す（出しません／Google と同時に出します／出しました／出せませんでした（再送できます））。失敗しているときは帯で「Google への公開はそのまま残っています」と伝え、再送の場所を案内する。
- 画像の変換（PNG → JPEG）と公開用の URL の用意、Instagram への2段階の公開（コンテナを作る → 公開する）は Worker 側の仕事。画面は結果（`post.instagram.status`）を見せるだけ。

## 入力の誤り（2026-10-09）
- 投稿の本文・タイトル・期間は共通 Field の赤枠と欄の下の理由で知らせ、最初の誤りへ focus＋中央へスクロールする。同じ理由を上の帯に重ねない。保存失敗は入力を残して帯で知らせる。
- 日時欄は36pxの compact、本文は共通 TextArea の compact（96px）。画像送信中は下書き保存・公開確認を止める。
