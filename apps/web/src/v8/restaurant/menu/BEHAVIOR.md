# メニュー管理の動き（BEHAVIOR.md）

対象：`app/restaurant-test/v8/menu.tsx`（今の V8）から写して `menu.tsx` を一から書いた。板 MJoJR・停止 MV5Os・追加と変更 NkmwU。

## 入口・受け付ける URL
- `app/restaurant-test/menu/page.tsx`：V8 だけで出す（今と同じ完全切り替え）。指定（?）は受け付けない（今と同じ）。
- 器は `../booking-kit/shell.tsx`（板の頭・店舗を選ぶ欄・検証環境の帯・読み込み／失敗／店舗なし）。

## 読み込み・送る形（今と同じ口）
- `restaurantTestApi.snapshot`：品目（`menuItems`）・承認（`approvals` の `menu_change` が承認待ちの数＝要承認）。店舗を選ぶと品目をその店舗に絞る。
- 追加：`createMenu`（storeId・kind・name・price・effectiveAt・allergens・servicePeriods）。
- 変更：`updateMenu`（同じ形）。価格を変えたときは「保存して申請する」になり、知らせは「承認待ちとして申請しました」。
- 停止＝`updateMenu {status:'archived'}`、再開＝`{status:'active'}`。
- 削除（新しく）：一度も公開していない下書きだけ。`DELETE /api/restaurant-test/menus/:id`（口はあったが画面が無かった）。サーバが公開済み・申請中・予約で使用中を 409 で断る。

## 画面
- 数5：全メニュー・コース・単品・要承認（琥珀）・アレルギー登録。
- 一覧の枠：頭に「メニューを追加する」、その下に「…」の決まりの帯、表（メニュー・種類・価格・提供時間・所要時間・アレルギー・状態・操作）。
- 状態の札：有効／保管済／下書き／停止中。価格の改定中は「申請中」（承認済みで開始待ちは「開始待ち」）、新しい価格と開始日時は札の title に出す。
- 行の右端は「…」（読み上げ名「メニュー「〇〇」の操作」）：有効＝変更・停止、保管済み＝変更・再開（行にも再開ボタン）、下書き＝変更・削除。名前を押しても変更が開く。
- 窓：追加と変更は同じ窓（幅560・上180）。停止・削除は確認の窓（幅480・上300）。

## 閲覧のみ
- 役割が staff（`useStaffRole`）のときは、追加・「…」・再開を置かない（2026-10-06 オーナー決定）。役割が分かるまでは出す（サーバの 403 が最後の守り）。
