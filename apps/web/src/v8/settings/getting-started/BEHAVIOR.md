# はじめの設定の動き（BEHAVIOR.md）

対象：`app/getting-started/page.tsx`（今の画面）から写して `getting-started.tsx` を一から書いた。板 `xuJ7D`。

## 入口
- `app/getting-started/page.tsx` は常にこのV8画面を出す。
- 枠：設定の型（`SettingsPage`）＋白い板の中の「設定の中のメニュー」（`SettingsInnerNav inline`）。中身の幅は `../sa-frame.module.css`。

## 受け付ける URL と指定
- `/getting-started#first-message` は最初の1通の確認方法へ進む。

## 読み込み（API）
- `api.gettingStarted.get(accountId, 'v8')` の段を正本にする（状態・権限・行き先）。
- 更新途中の応答で段2が無いときだけ機能設定の実物の版で補う。取得失敗は共通の失敗表示へ渡し、未取得を未設定にしない。
- 機能設定の保存の合図（`FEATURE_SETTINGS_UPDATED_EVENT`）で読み直す。
- `use-first-run.ts` と `steps.ts` をダッシュボードと共用する。両方で同じAPIの状態を数える。

## 見せ方
- 進み具合の帯（`n / 6 済み`＋棒）。棒は共通 `ProgressBar`（割合と読み上げ名を渡す）。
- 6段：済みは共通のチェック札と「済み」の札、まだは番号の札と行き先のボタン、押せない段は理由の文字。
- 下の2枚：いま止まっている理由（止まっている段・権限で進めない段・確かめられない段。無ければ出さない）／気をつけること。

## 失敗
- 読み込みの失敗は `ListState` の error（再試行つき）。読み込み中は loading。

## 最初の1通
- QRから自分を友だち追加する方法と、シナリオを選んで既存のテスト送信を開く方法へ案内する。ここを開いただけでは送信しない。
- 友だち追加時の配信かシナリオの送信記録を完了条件とし、送らずに判定する試験と受信箱の手動返信を数えない。端末での受信確認も案内する。
- サーバが最終段を権限不足とした時は送信への案内を出さない。

## 今の画面から変わったところ
- 2段目の言葉の空き（「チャネル ID」「自分の LINE」）を絵に合わせた。判定は同じ。
