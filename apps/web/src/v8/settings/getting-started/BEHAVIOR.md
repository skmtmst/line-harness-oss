# はじめの設定の動き（BEHAVIOR.md）

対象：`app/getting-started/page.tsx`（今の画面）から写して `getting-started.tsx` を一から書いた。板 `xuJ7D`。

## 入口
- `app/getting-started/page.tsx` は常にこのV8画面を出す。
- 枠：設定の型（`SettingsPage`）＋白い板の中の「設定の中のメニュー」（`SettingsInnerNav inline`）。中身の幅は `../sa-frame.module.css`。

## 受け付ける URL と指定
- `/getting-started#first-message` は最初の1通の確認方法へ進む。

## 読み込み（API）
- 標準の6段は `api.gettingStarted.get(accountId, 'v8')` の状態・権限・行き先を使う。業種の3〜5段は `stepsForStyle` を通し、その業種の実設定を読む `loadStyleSetupProgress` の結果だけで済みを決める。元のタグ・配信の済みを業種の段へ持ち込まない。
- 段1は選択中のアカウントが登録済みなら完了。Webhookなどの接続状態は別の運用表示で確認する。
- 業種の実設定が未登録なら「まだ」、未取得・失敗・確認する口が無い場合は「未確認」。取得済みの他の段は保持する。店舗やスタイルが変わった直後は前の結果を使わず、遅い旧応答も捨てる。
- スタイルの読込中・失敗は元の標準の段で代用せず、読込・再試行を出す。同じ店の前回のスタイルを代用した時は共通の要確認の案内を出す。
- 更新途中の応答で段2が無いときだけ機能設定の実物の版で補う。取得失敗は共通の失敗表示へ渡し、未取得を未設定にしない。
- 機能設定の保存の合図（`FEATURE_SETTINGS_UPDATED_EVENT`）・スタイルの保存・タブが前に戻った時に読み直す（時間での読み直しはダッシュボードの待つ間だけ）。
- `use-first-run.ts`・`steps.ts`・業種の実設定の読込を、設定画面・ダッシュボード・最初の1通の窓で共用する。

## 見せ方
- 進み具合の帯（`n / 6 済み`＋棒）。棒は共通 `ProgressBar`（割合と読み上げ名を渡す）。
- 6段：済みは共通のチェック札と「済み」の札、まだは番号の札と行き先のボタン、権限で押せない段は共通の灰色ボタンと理由の吹き出し。未確認と権限不足を混同しない。
- 下の2枚：いま止まっている理由（止まっている段・権限で進めない段・確かめられない段。無ければ出さない）／気をつけること。

## 失敗
- 読み込みの失敗は `ListState` の error（再試行つき）。読み込み中は loading。

## 最初の1通
- 読み直しは見出し右の小さな副ボタン、QRとテスト送信の入口は本文の下に左寄せで並べる。本文は要点だけにし、送信記録による判定の詳細は見出し横のHelpTipに置く。
- QRから自分を友だち追加する方法と、シナリオを選んで既存のテスト送信を開く方法へ案内する。ここを開いただけでは送信しない。
- 友だち追加時の配信かシナリオの送信記録を完了条件とし、送らずに判定する試験と受信箱の手動返信を数えない。端末での受信確認も案内する。
- 閲覧のみ・サーバが最終段を権限不足とした時も、入口は同じ位置の灰色ボタンで残す。共通の理由を示し、移動・送信を起動しない。本人の権限が不明な間は送信への入口を出さない。

- 2段目の言葉の空き（「チャネル ID」「自分の LINE」）を絵に合わせた。段1の完了条件は2026-10-31の利用者指示で登録完了時点に変更した。
