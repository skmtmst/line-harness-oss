# LINEアカウント一覧の動き（BEHAVIOR.md）

対象：`app/accounts/page.tsx`（今の画面）から写して `accounts.tsx` を一から書いた。板 `V7vn3`。

## 入口
- `app/accounts/page.tsx`：一覧はV8に固定。`?tab=migration`（UID の移行）だけ移行の入口へ渡す。

## 受け付ける URL と指定
- `?tab=migration`：今の画面へ渡す（上）。ほかの指定は無い（今の画面と同じ）。

## 読み込み（API）
- `api.lineAccounts.list()`。「接続をもう一度確かめる」は `list(true)`（live）で一覧ごと取り直す。
- 判定・言葉は `view.ts`（[現役の入口・本体](../README.md) の写し＋数の4枚・並び）。直すときは両方。

## 見せ方
- 数の4枚：つないでいる（全部）・稼働中・接続に問題・友だちの合計（アーカイブは数えない）。未取得は「—」（0 と出さない）。
- 探す欄（名前・チャネル ID。打つたびに取り直さない）＋絞り込みの札（すべて・稼働中・停止中・接続に問題・アーカイブ。数つき）。
- 表：アカウント／接続状態／Webhook／友だち／既定（★）／親アカウント／「…」。並びは displayOrder（「並び順と親子を変える」で決めた順。サーバと同じ）。

## 操作
- 頭：「並び順と親子を変える」→ 窓で今ある並び替えの部品（`components/accounts/account-ordering`）。閉じたら読み直す。「LINEアカウントを登録」→ `/accounts/new`。
- 行の「…」：詳細（`/accounts/detail?id=`）・接続をもう一度確かめる・引き継ぎ（`/accounts/handover?id=`）・アーカイブ（理由・本人確認）／アーカイブから戻す。
- 見るだけの人にも頭の2つ・スタイルの変更・引き継ぎ・アーカイブ（戻す）を灰色＋理由で出す。詳細と確かめ直しは読み取りとして残す。本人未確定の間は理由と権限帯を出さず、普通のdisabledで止める。
- **「LINEアカウントを登録」はオーナーと管理者に出す**（2026-10-20 利用者依頼）。一覧が空でも同じ権限で登録への入口を表示する。スタッフ・閲覧のみには灰色の入口と頼む先を案内する。閲覧の代理ログインも書込入口を止め、APIを呼ばない。
- 「並び順と親子を変える」とスタイルの入口の既存権限は維持する。見張りは `registration-access.test.tsx`。
- 要件変更と保護された正本への同期事項は `../../account-new/BEHAVIOR.md` の「誰ができるか」に記録する。

## 失敗
- 一覧の失敗は `ListState` の error（再読み込み）。アーカイブできない理由（blockers）は運用者の言葉で窓の中に。428 は本人確認の窓を立ててやり直す。

## 今の画面から変わったところ
- 数は 稼働中・停止中・アーカイブ の3枚から、絵の4枚へ。頭に「並び順と親子を変える」（今まで画面から開けなかった部品）を足した。スマホ幅のカード表示は持たない（PC 幅の表だけ）。

## 接続と期限の表示
- 接続は一覧・単体・ヘルス・運用確認で同じ保存記録の集計を使う。bot と Webhook の両方が成功した場合だけ正常にする。記録なしは未確認、停止中・アーカイブは別の状態として扱う。
- Webhook の24時間以上の無受信は、受信不要の指定がない場合だけ要確認とする。通知・一覧で同じ日時の判定を使い、未確認を正常や故障へ読み替えない。
- トークンの期限と自動更新の失敗は接続と別に表示する。時差の無い保存日時はJSTとして読み、残りの日数と期限の状態は共有の関数から得る。
- ヘルスのログは履歴。現在の接続状態が不明なとき、過去のログで補わない。

期限が近いことの予告は14日前から表示する。運用確認の注意は、期限切れ・自動交換の失敗・残り7日未満でも交換されない場合に分け、正常な自動交換を予告だけで異常にしない。
