## 1. 社名のあとの半角の空き → 作りを直した

絵の本文は「Uber Eats での許可をいただきました。Uber Eats に登録されているお店が2件…」。
英数字で終わる名前のうしろだけ半角の空きを入れる決まりで、`docs/v8-design-rules.md` の
「単位は数字の後ろに半角の空き」と同じ考え方。この画面の `SERVICES` も前から
Uber Eats は「Uber Eats に入った注文を…」、出前館は「出前館に入った注文を…」と書き分けていた。

直したのは文字をはめ込んでいた9か所。`withParticle(name, particle)` を1つ置いて、
英数字で終わる名前のときだけ空きを足す。出前館・ロケットナウは今までどおり空きなし。
DL-3 の題と本文（Codex が調べていない窓）にも同じ間違いがあったので、あわせて直した。

## 2. 窓の左のボタン「やめる」 → 「キャンセル」のまま

`docs/v8-design-rules.md` B-146：
「入力をやめる＝「キャンセル」、窓を閉じるだけ＝「閉じる」。「やめる」は使わない
（予約のキャンセル窓の「やめる」も「閉じる」）」。

これはオーナーの決まり（順位2）で、Pencil の板（順位3）より上。
同じ §1 に「絵と食い違う時は決まりが勝つ。コードは決まりどおりにし、絵と写しを直してから
その板を測り直す（B-240）」とある。よって作りは「キャンセル」のままにし、**絵の側を直す**。

v03 の DL-3 `a3W4B`／DL-4 `K3aIxK` の両方が「やめる」なので、この板だけの写し間違いではない。

## 3. 右上の× → 消さない（絵の側を直す）

共通部品 `components/shared/dialog.tsx` は右上の×を必ず出す。止める入口（prop）は無い。
部品の中にも「閉じ方は必ず右上の×。フッターの「閉じる」ボタンは置かない（UI-25）」と書いてあり、
`components/shared/dialog-close-ui25.test.tsx` が見張っている
（標準・確認・危険操作の3つすべてに `aria-label="閉じる"` が出ること）。

`docs/v8-design-rules.md` 20〜21行目：
「見た目を変えるときは Pencil を先に直す。コードだけ直すと、次に絵を見た人が元に戻す。」
「…ただし **LINE の決まり・安全・見張りに反する絵は、今の作りに合わせて絵を直す**」。

×を消すと見張りが落ちるので、この但し書きのとおり**絵を直す**側になる。
v03 は DL-3 `k9HHE`／DL-4 `wU4HH` のどちらも窓の頭に題だけで×が無い。

> 注：UI-25 はコードと試験にしか書かれておらず、`docs/` の markdown には記録が無い
> （`grep -rn "UI-25" docs AGENTS.md` で0件）。だから絵を描くときに漏れた。
> 正本 `docs/v8-design-rules.md` への追記は**司令塔の枝の仕事**で、この枝からは触れない
> （`docs/v8-*` は司令塔の持ち物で、lane の PR から変えると `required-pr-gate` が落ちる）。

## 4. 窓の高さ 396 と 451 → 数字を合わせ込まない

幅は絵も作りも 480（共通の `small`、決まりの「窓の幅は 480／560／720／960」どおり）。
高さが違うのは、絵の余白と間隔が共通部品の値と違うから。

| ところ | 絵（v03） | 共通部品 |
| --- | --- | --- |
| 窓の頭 | 47（上下10） | 20 / 24 / 8＋×のボタン36 |
| 中身の余白 | 上12・左右24・下20 | 24 |
| 中身の間隔 | 12 | 16 |
| ボタンの段 | 60（上下12） | 14＋区切り線1px |

積み上げると 441 前後で、Codex の実測 451 とほぼ合う。作りの不具合ではない。

`docs/v8-design-rules.md` 161行目「作る画面の細かい違い（閉じるボタンの枠・欄の高さ 36・
右の欄の幅）は共通部品の値にそろえる」。
部品には板ごとに余白を変える入口（`designHeaderPadding` など）もあるが、
使っているのは窓を出す165ファイルのうち29ファイルだけで、既定値がこのアプリの標準。
この板に標準から外れる理由（オーナーの決まり）は無いので、**絵を標準の値へ直す**。
