# 運用状態の動き（BEHAVIOR.md）

対象：`screen.tsx`・`health.tsx`（★V8 健全性チェック `Y4LkX1`）・`history.tsx`（更新履歴 `I2V65v`）。緊急コントロール（`OHwbU`）は現役の [現役の入口・本体](../README.md) を入口から差し込む。

## 入口・URL
- `app/emergency/page.tsx`：この V8 画面に固定。`?tab=health|history|control|security`。安全監視のタブはオーナー・管理者に表示し、閲覧専用のオーナー・管理者も一覧を読める。

## 読み込み（API）
- `GET /api/operations/health`（手動は `POST …/runs`）・`GET /api/operations/alerts`・`GET /api/operations/history`（下の3枚）・`api.health.accounts()`。
- 初回だけ読み込み中、5分ごとに取り直す（隠れたタブでは取らない）。手動確認は連打を止め、世代とアカウントで古い応答を捨てる（N-458）。
- 古い確認（10分より古い）と未確認を言い分ける（A32-01）。異常が読めないときは「異常なしとは扱いません」。

## 操作
- いますぐ確かめる（頭の右）。開いている異常：受領する（1回目でメモ欄、2回目「受領を記録する」で記録）・通知をやり直す。
- 緊急停止／復旧：専用の許可が無い人にも同じ操作を灰色＋理由で残す。本人未確認・許可の読込中は通常disabled。previewの通信失敗は読直しの案内を残し、権限拒否へ置き換えない。全体停止はowner、個別はownerまたは専用鍵を持つadminで、最新previewの許可も必要。APIの権限は変更していない。
- 緊急停止の題の操作と本文は同じ許可から描き、理由の帯は題の下へ1回。本人／代理モード／対象が変わったら本人確認待ちの要求を捨て、writeに戻っても自動再開しない。対象を選ぶ読取と履歴・経路のGET、記録のコピーは残す。復旧差分の確認はPOSTの純読取で、現API契約では専用権限と範囲の許可が必要。閲覧のみ・read代理はPOST制限に従い、APIの例外は追加しない。
- 健全性の受領・やり直しの権限表示と安全監視の変更操作は別の未了scope。

- 緊急制御：競合で古い確認・窓・要求キーを破棄し、読み直し成功まで操作を止める。失敗後も再取得できる。停止/復旧/読み直しの連打は1要求だけ。本人確認の実行中は閉じず、成功・失敗後は理由が前面に出る。止める条件を変更したままの離脱は共通の番兵で確かめる。

- 更新履歴は1回の更新＝1枚（新しい順・10枚ずつページ送り）。区切りは検証への配備（成功）1回ごと。最初の配備より前・最後の配備より後の行と、配備の記録が無い所は日本時間の日ごと。失敗・戻した・本番の配備は区切りにせず、結果の1枚として残す。決め方は `history-updates.ts`。
- 1枚に日付（`<time datetime>` は日本時間）・版・配備の結果と仕方・種類の数・3行・［すべて見る（N 行）］。3行は版の人が書いたまとめ（組み立ての台本の `updates[].highlights`。あればその版のいちばん新しい1枚に）、無ければその回の行から修正→追加→変更の新しい順に3つ（足りなければ足りないまま）。
- 「最新」は今動いている版（`/admin/version`）と同じ版の、成功したいちばん新しい1枚だけ。版が分からなければ付けない。次回反映予定はいちばん上の別の1枚（行の数と種類の数だけ・「最新」なし）。保管用の版（`summary: false`）は「保管用の版（N 行）」の1枚で、行は画面に出さない。
- 配備の記録が読めない時も版の並びは出し、「読み込めませんでした」を出す。記録が無い回に結果の札は出さない（成功と言わない）。上の帯の題は「運用状態 › 更新履歴」、ブラウザのタブは「更新履歴」。
- 更新履歴の頭の操作メニュー：止めた・戻した記録を見る（期間と同じ集計・CSV）、更新内容を見る（新しい10件/続き/未反映件数）。取得失敗を記録なしとせず、窓の中で読み直せる。

## セキュリティの見張り（B-343・Bsc2d）

- 別の開発枝に残っていた画面を、運用状態の4番目のタブへ接続する。既存の [画面とAPIの契約](../../../../../../docs/security/SECURITY-MONITOR-CONTRACT.md) に従う。新しい監視処理・DB・設定・通知先は追加しない。
- 店を選択してから、共通API関数でその店の一覧を取得する。選択なしを運営全体への要求へ変換しない。5分ごとの可視時の再読込と監視時刻の更新を行い、重複取得と解除後・店変更後の応答を捨てる。
- 未対応一覧と、初回・最終検知・通知・受領状態を表示する。空は「見張りの記録では未対応なし」と表現し、全領域の安全とは表現しない。failed・stale・unknown・設定不正・取得失敗を異常なしへ変換しない。通信が止まっても最後の完了から15分で古い状態と分かる。
- 「確かめた」と「解決した」は共通の行メニューと確認窓を使い、現在の版と選択店を付けて更新し、成功後に再読込する。古い版は確認を閉じ、再読込後に改めて判断する。閲覧のみ・代理ログイン・セッション不明では更新操作を出さない。
- 状態の面・札・表・行操作・確認・省略文字は既存の共通部品で組む。未実装の操作記録・関係者・解決履歴を動くメニューとして足さない。実画面の合否と検証配備は別工程。

## 接続と期限の表示
- 接続は一覧・単体・ヘルス・運用確認で同じ保存記録の集計を使う。bot と Webhook の両方が成功した場合だけ正常にする。記録なしは未確認、停止中・アーカイブは別の状態として扱う。
- Webhook の24時間以上の無受信は、受信不要の指定がない場合だけ要確認とする。通知・一覧で同じ日時の判定を使い、未確認を正常や故障へ読み替えない。
- トークンの期限と自動更新の失敗は接続と別に表示する。時差の無い保存日時はJSTとして読み、残りの日数と期限の状態は共有の関数から得る。
- ヘルスのログは履歴。現在の接続状態が不明なとき、過去のログで補わない。

期限が近いことの予告は14日前から表示する。運用確認の注意は、期限切れ・自動交換の失敗・残り7日未満でも交換されない場合に分け、正常な自動交換を予告だけで異常にしない。
