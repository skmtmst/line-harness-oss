# 統括のスタイルの初期セット

入口は `/hq/templates/starter-sets`。司令塔の依頼により、段1の承認済みの画面案を実装する。見た目の正式な合否は司令塔の写真確認による。

- 6スタイルごとに10種類の欄を常に表示する。左の一覧は文字のナビで、狭い板では共通の選ぶ窓で切り替える。
- 統括の既存カタログがあるリッチメニュー・テンプレート・タグ・自動応答・クーポン素材・回答フォームは、同じ統括の版を固定して選ぶ。既に選んだ古い版も候補に残す。同じカタログを二度選んだときは、最後に選んだ版だけを使う。
- 来店スタンプ・お店の情報・案内ページ・LINE来店フォローは欄と選ぶ口だけ。候補が無いときは「まだありません」。本文を書く欄や新規作成の口は置かない。
- 選択を外しても配布済みの店の実体は消さない。選んだ版の中身を読む窓を持つ。メニューは実際の領域数と位置・行き先を表示し、割り当て直しはカタログで新しい版を作って選び直す案内と編集リンクを置く。
- 従来の組から切り替えるときは、含まれなくなる物を確認し、従来の内容を履歴へ残す。空の組は「何も自動で入れない」ことを確認して保存できる。既存店にある見本文面は維持する。
- 保存は下の帯だけ。自動投入の未保存時の既定はオン。未保存の切替・離脱を確認し、保存失敗では入力を残す。保存しただけでは既存店へ配らない。
- 既存店への配布は、配る先と店の編集の扱いを事前確認した token で実行する。編集済みは知らせるだけを既定とし、明示した別名コピーで新しい実体を作れる。元の実体は上書きしない。一部失敗時は配布窓を残し、実際の成功・保留・失敗に合わせて表示する。
- 店でスタイルを選ぶと、承認済みの同じ統括の組だけを内部処理で入れる。起点の担当者へ統括権限を渡さない。保存後の投入失敗は保存・登録の失敗と混ぜず、同じアカウントで不足分を再試行できる。
- テンプレート・クーポン・フォーム・メニューは未公開、自動応答は停止・下書き。初期投入で送信や公開を始めない。手動の通常の統括カタログ配布の意味は変更しない。
- 比較用の内容は実体と同じDB処理で保存する。回答数・更新時刻など運用で変わる値は比較に含めず、店が内容を直した場合は依存物も自動で上書きしない。
- 更新は、統括の管理者かつ店限定・閲覧のみでない人に限る。使えない操作は灰色で理由を表示し、権限の読込中も許可しない。サーバーも同じ条件と別統括・別店舗の境界を確認する。

主な動きの試験は `empty-set.test.tsx`、`use-distribute.test.tsx`、Workerの `style-starter-catalog.test.ts`。権限・版固定・未公開・再試行・店の編集保護は、実際のSQLiteへ当てて確認する。
