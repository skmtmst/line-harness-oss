# ダッシュボードの動き（BEHAVIOR.md）

- 最初の手順と、質問で後回しにした使い方の設定は1枚のカードにまとめ、基本の手順が取得できたときだけ、その進捗を1つ出す。後回しの設定への行と操作は同じカードに残す。取得失敗の再試行はそれぞれに残し、片方の失敗で取得済みの設定入口を消さない。

対象：★V8 共通ダッシュボード（Pencil `WQmep`、1440）。動きの説明。業種の要件は `docs/v8-requirements/styles.md` が正本。最終確認：2026-10-26。

## 入口
- `app/page.tsx` → `style-dashboard/home.tsx`。所属を確かめたサーバーの業種を読み、標準・ECは本体、飲食・サロン・面談・教室は業種の盤へ。未取得・失敗の間に標準や前の店の盤を出さない。QRの入口は共通画面を維持する。
- 標準はECのカードを出さない。標準・ECの初期表示から予約カードを外し、保存済みの並びと業務データは保持する。NEN専用カードは提供契約の読取情報が整うまで出さない。
- ECは日本時間の今日の注文・今日と明日の出荷予定・定期便の次回発送日・つき合わせ待ちと、期間内注文・再購入割合を組み合わせる。ECの保存済み配置にも今日の予約・予約状況は出さず、来店スタンプの未設定案内も出さない。配置の保存値自体は変更しない。
- ECの各読取を別々に判定し、一部失敗でも読めた値を保持する。注文の履歴取得成功と接続先の同期時刻を確かめ、同期済み0件と未同期を分ける。出荷走査が上限に達した時・定期便の欠測や不正な発送日は未確認とし、0や仮の日付で補わない。集計期間・式・最終取り込みを表示する。
- 共通カードのアカウント境界・配置保存・確認・権限の回帰試験は本体を直接描く。`style-dashboard/home.test.tsx` が6業種の入口・失敗・切替・QRを検査し、撮影は実際の入口から行う。

## 受け付ける URL と指定（公開名と意味を保つ）
- `?period=last7|last30`：集計の期間（無ければ今日、旧last28のURLはlast30として開く）。切り替えると URL に書く（今日は消す）。
- `?edit=1`：ダッシュボード編集を開く。閉じると消す。アカウントを替えると閉じる（DASH-04）。
- `?qr=base|<経路ID>`：友だち追加リンクの QR を開いたまま再読込できる。

## 保存先・API（既存の公開契約を保つ）
- 配置：`GET/PUT/DELETE /api/dashboard/preferences`、手元の写しは `localStorage` の `lh_dashboard_v4:<アカウントID>`。保存は版つき、409 は「ほかの人が配置を変えました…」（引き出しの下の帯・「最新の配置を読み込む」）。
- 概要：`GET /api/dashboard/overview?period&account_id`。応答は「どのアカウントのどの期間か」と組で持ち、違う対象の数を出さない（DASH-02）。
- 受信一覧：`/api/support/inbox?status=open`（30秒ごと・画面に戻ったとき）。表示件数は担当者ごと `lh_pending_inbox_page_size:<担当者ID>` を読むだけ。
- 補足：写真審査 `photoReviewMetrics`（403 は「権限なし」）、予約 `listRequests`＋`requestsSummary`、稼働 `health`、二段階認証 `staff.list`、対応マーク `supportMarks.list`、今後の予定 `dashboard.upcoming`、配信の失敗 `dashboard.deliveryFailureOrigins`、出荷 `ShipmentPanel`、経路 `entryRoutes.list`、はじめにやること（`gettingStarted.get` の段1・`friendAddRules.list`・`richMenuGroups.listPage`・`broadcasts.list`・`scenarios.listPage`・`staff.list`）、本人 `staff.me`（あいさつの名前・役割）。
- 比べる値：`dashboard.comparisons`（`GET /api/dashboard/comparisons?account_id`）。最初の表示を遅くしないよう、概要が読めてから読む。読めない・古い Worker で返らない時は札を出さない。応答はアカウントと組で持ち、替えたら前のアカウントの値を出さない。
- 最近の動き：専用の API が無いので、通知センター `notifications.center.list` の新しい順の先頭3件を出す。押すと通知と同じ行き先、「すべての動きを見る」は `/notifications`。

## 板の並び（WQmep）
- 板の頭：あいさつ（日本時間で おはようございます／こんにちは／こんばんは＋名前の最初の語）、「更新 ◯ ・ 動きの状態」、期間の切り替え、ダッシュボード編集、配信を作る（`/broadcasts/new`）。
- 帯：閲覧のみの帯 → はじめにやること（修正案 D-3・2026-10-07 採用。オーナー・管理者だけ。`n / 6 済み`・進みの線・［畳む ⌃］／［開く ⌄］・手順6つを3列×2行。済みは ✓、まだは行き先のリンク。全部済むと出ない。畳むと頭の1行だけ（2026-10-08 オーナー：閉じるではなく畳める）。畳んだことはアカウントごとにこの端末の localStorage に覚え、前の「閉じる」の印は畳んだ形として読む。1つでも判定できなければ出さない）→ 失敗の帯。
- はじめにやることの読み直し：QR の窓（`?qr=`）を開いている間と、帯が開いていて「友だち追加の時の配信は済み・最初の1通はまだ」の間は 10 秒ごとに読み直す（裏のタブでは止める・15 分で止めて帯に［もう一度確かめる］）。
- 最初の1通が届いた時の窓（SPEC-11 ③・`first-run-done.tsx`）：この画面で見ている間に最初の1通が「まだ」から「済み」に変わった時だけ、オーナー・管理者に開く。開いた時にもう済みの人・別のアカウントへ移った直後には出さない。題「最初の 1 通が届きました」、説明に「開始から N 分」（Worker の分。60 分を超えたら時間と分。古い Worker で分が無ければ出さない）。入った物を種類ごとに 1 行（動いています・止めています・入っています・入れなかった（あとで））、まだの段を「次にやること」に出す。［閉じる］は `getting-started/dismiss` を呼ばず、開いたことも覚えない。「読まれました」とは書かない。
- 初期セットが入っていない時の帯（SPEC-11 1-3・`starter-retry.tsx`）：はじめにやることの Worker の返事 `starter` が「入っていない（`applied=false`）」で入れる物が 1 件以上ある時だけ、オーナー・管理者に「初期セットが入っていません」＋［入れ直す］を出す。閲覧のみの人には出さない。［入れ直す］は今のスタイルの版で `POST /api/dashboard/style/starter-items/ensure` を呼び、足りない物だけを止めた状態で入れる（何度押しても二重に入らない）。入れた後は「初期セットを N 件入れました」と出し、はじめにやることと使い方の設定を読み直す。ほかの人が先にスタイルを変えていた（409）時は入ったとは言わずに読み直す。入れる数を数えられない時（`missing=null`）は押せる形にせず理由を言う。
- 数の帯（今日やること）：編集の `today` の順。各マスの「…」＝内訳を見る（帯の下に1行で開く）・行き先・ダッシュボード編集。
- 帯の上に「いつ時点か」の1行（「10/25 17:51 時点・先週の同じ曜日と比べています」）。時刻は概要の集計時刻（日本時間）。数のもとが遅れている（stale・delayed）時は取れた中で一番古い時刻と「（更新が遅れています）」。比べた札が帯に無い時は基準の言葉を付けない。見出しの「？」の説明はそのまま残す。
- 前週比（SPEC-6）：今日の予約だけ先週の同じ曜日と比べ、差の札（増えると良い＝緑・減ると赤・差 0 は灰色の →）を数の右に出す。対応が必要な受信・写真審査・出荷予定は前の値を記録していないので比べず、札も「—」も置かない（「？」に理由）。先週の記録が無い数も札を出さない（0 として比べない）。帯の数（来店済みを除く今日の予約）と比べる値の今の数（来店済みを含む）が食い違う時も、矛盾して見えるので札と基準の言葉を出さない。札は矢印と言葉と読み上げの文（「先週の同じ曜日より 2 件多い」）で、色だけに頼らない。
- 接続状態の欄：有効友だちの右に先週比（増えると良い）。アカウントに友だちの上限（店が入れた目安）があるときだけ「友だちの上限 146 / 150 人」と棒。警告の人数以上（上限に届いたときも）は注意の色。上限が無いアカウントには出さない（LINE には友だちの数の上限が無いため作り物の上限を出さない）。
- 今日の配信の失敗：先週の同じ曜日の同じ時刻までと比べる（減ると良い）。欄の数と比べる値の今の数が違う時（読んだ時刻のずれ）は札を出さない。
- 本文の段：編集の `main` の順。推移の段の右に「今月の送信枠・運用アラート」、受信の段の右に「現在の対応状況・接続状態」、追加リンクの段の右に「友だちの状態」。
- 残りの右の列のカード（今後の予定・今日の配信の失敗・今月の配信・最近の成果、編集で出した追加のカード）は `right` の順に4つずつ横に並べる。
- 板が狭く型が右の列を隠す幅（1099px 以下）では、右の列のカードを横並びの段で出し直す（数字を落とさない）。
- 出荷予定の一覧（ShipmentPanel）は、今日・明日の出荷があるときだけ段として出す。0件や隠したときも件数は取り続ける（数の帯の出どころ）。受信の段を隠しても受信の件数は取り続ける（DASH-21）。

## 閲覧のみ（役割が owner・admin 以外）
- 閲覧のみの帯を出す。「配信を作る」「経路を分けて発行」は隠す。コピー・QR は出す。
- ダッシュボード編集（自分の並び：板の頭のボタン・数のマスの「…」の項目・`?edit=1`）は、閲覧のみ（読み取り専用。`/api/staff/me` の role が `viewer`＝サーバーが保存を断る人）にだけ出さない。書き込みできるスタッフは今までどおり編集・保存できる（2026-10-08 司令塔・確認表 B-42）。判定は `canEditDashboardLayout`。
- 役割が読めるまで・取得失敗・閲覧のみでは隠す。最後の守りはサーバの 403。

## 失敗・読み込み中
- 概要が取れない：板の上に文と「もう一度試す」。概要を使う段（推移・送信枠・友だちの状態・今月の配信・最近の成果）も骨組みのまま待たせず「データを読み込めませんでした」＋「もう一度試す」。一部だけ取れない：1行で知らせ、0件としては出さない。
- 段ごとに「データを読み込めませんでした」＋「もう一度試す」。最初の読み込み中は骨組み（受信の一覧も骨組み）。
- 狭い幅：1280 では右の列の左右の余白を 20→16 に詰めて題を切らない。1152 では題と行き先が1行に入らない段だけ行き先を次の行へ回す（題は「…」にしない）。
- 送信枠：上限なし・未接続・取得失敗を分ける。残り 10% 以下は赤。

## ダッシュボード編集（mcOqK・2026-10-08）
- 引き出し `dashboard-editor.tsx`（共通のDrawer）。並べ替え・表示のON/OFF・4枠の計算は関連する共通処理を使う。
- 頭：「カードと配置／プレビュー」の切り替え（共通の SegmentedControl）と説明1行。行：持ち手・名前と置き場所・上下（24 の枠つき）・スイッチ。OFF の行は薄い地。
- 4枠の注意は 5つ目を ON にした瞬間だけ「今日やること」の上に出し、OFF にしたカードの名前を書く。開き直すと消える（今の候補は4つなので実際には出ない）。
- 下：左に「初期状態に戻す」（確認の窓 400：キャンセル／削除して初期状態へ戻す）、右に「閉じる」「ダッシュボードに反映」（保存中は「保存中…」）。
- 失敗は下の帯：保存できない（もう一度保存する。初期化の失敗は「もう一度試す」で初期化をやり直す）、409（最新の配置を読み込む）。キーボードで持ち上げている間だけ操作の案内の帯を出し、その間の Esc は移動をやめるだけ（引き出しは閉じない）。
- 開くのは 200ms、閉じるのは 150ms（提案 F）。動きを減らす設定では動かさない。

- ECの部分失敗は読めた数を残し、帯の上の1行の注意と読み直しを出す。全取得失敗だけ大きな失敗表示。定義は題の?にまとめ、状態の帯は1本にする。

## 受信一覧の内容
- LINEのスタンプ・画像・動画などは、受信箱と同じ共有の種別名を表示する。内部JSONを一覧へ出さず、テキスト本文とメール本文は保つ。
- 表示の言い換えで、保存したメッセージ・未対応の数・閲覧できるアカウント・返信や既読の状態は変えない。
