# ダッシュボードの動き（BEHAVIOR.md）

対象：★V8 ダッシュボード（Pencil `WQmep`、1440）。v7 の `app/page.tsx`（DashboardPageInner）から動きを写し、見た目だけ一から書いた。

## 入口
- `app/page.tsx`：`theme === 'v8'` のときだけ `@/v8/dashboard/dashboard` を出す。v7 の画面・試験は触らない。

## 受け付ける URL と指定（v7 と同じ名前・同じ意味）
- `?period=last7|last28`：集計の期間（無ければ今日）。切り替えると URL に書く（今日は消す）。
- `?edit=1`：ダッシュボード編集を開く。閉じると消す。アカウントを替えると閉じる（DASH-04）。
- `?qr=base|<経路ID>`：友だち追加リンクの QR を開いたまま再読込できる。

## 保存先・API（v7 と同じ）
- 配置：`GET/PUT/DELETE /api/dashboard/preferences`、手元の写しは `localStorage` の `lh_dashboard_v4:<アカウントID>`。保存は版つき、409 は「別の画面で配置が更新されました」。
- 概要：`GET /api/dashboard/overview?period&account_id`。応答は「どのアカウントのどの期間か」と組で持ち、違う対象の数を出さない（DASH-02）。
- 受信一覧：`/api/support/inbox?status=open`（30秒ごと・画面に戻ったとき）。表示件数は担当者ごと `lh_pending_inbox_page_size:<担当者ID>` を読むだけ。
- 補足：写真審査 `photoReviewMetrics`（403 は「権限なし」）、予約 `listRequests`＋`requestsSummary`、稼働 `health`、二段階認証 `staff.list`、対応マーク `supportMarks.list`、今後の予定 `dashboard.upcoming`、配信の失敗 `dashboard.deliveryFailureOrigins`、出荷 `ShipmentPanel`、経路 `entryRoutes.list`、はじめにやること（`gettingStarted.get` の段1・`friendAddRules.list`・`richMenuGroups.listPage`・`broadcasts.list`・`scenarios.listPage`・`staff.list`）、本人 `staff.me`（あいさつの名前・役割）。
- 最近の動き：専用の API が無いので、通知センター `notifications.center.list` の新しい順の先頭3件を出す。押すと通知と同じ行き先、「すべての動きを見る」は `/notifications`。

## 板の並び（WQmep）
- 板の頭：あいさつ（日本時間で おはようございます／こんにちは／こんばんは＋名前の最初の語）、「更新 ◯ ・ 動きの状態」、期間の切り替え、ダッシュボード編集、配信を作る（`/broadcasts/new`）。
- 帯：閲覧のみの帯 → はじめにやること（修正案 D-3・2026-10-07 採用。オーナー・管理者だけ。`n / 6 済み`・進みの線・閉じる・手順6つを3列×2行。済みは ✓、まだは行き先のリンク。全部済むか閉じると出ない。閉じたことはアカウントごとにこの端末の localStorage に覚える。1つでも判定できなければ出さない）→ 失敗の帯。
- 数の帯（今日やること）：編集の `today` の順。各マスの「…」＝内訳を見る（帯の下に1行で開く）・行き先・ダッシュボード編集。
- 本文の段：編集の `main` の順。推移の段の右に「今月の送信枠・運用アラート」、受信の段の右に「現在の対応状況・接続状態」、追加リンクの段の右に「友だちの状態」。
- 残りの右の列のカード（今後の予定・今日の配信の失敗・今月の配信・最近の成果、編集で出した追加のカード）は `right` の順に4つずつ横に並べる。
- 板が狭く型が右の列を隠す幅（1099px 以下）では、右の列のカードを横並びの段で出し直す（数字を落とさない）。
- 出荷予定の一覧（ShipmentPanel）は、今日・明日の出荷があるときだけ段として出す。0件や隠したときも件数は取り続ける（数の帯の出どころ）。受信の段を隠しても受信の件数は取り続ける（DASH-21）。

## v7 から変えたところ
- 通知のベルとパネルは共通のトップバーにあるので、板の中には置かない。
- 補足の口は最初から叩く（右の列が最初の画面に入るため、見えるまで待たない）。稼働は板の頭の「動きの状態」に使うので常に読む。
- 友だち数の推移は「グラフ／表」の切り替え。表は v7 と同じ表（FriendTrendTable）。
- 数の帯の「…」から内訳を開く（v7 V8 の「数を押して広げる」の代わり）。

## 閲覧のみ（役割が owner・admin 以外）
- 閲覧のみの帯を出す。「配信を作る」「経路を分けて発行」は隠す。ダッシュボード編集（自分の並び）・コピー・QR は出す。
- 役割が読めるまでは出し、閲覧のみと分かったら隠す。最後の守りはサーバの 403。

## 失敗・読み込み中
- 概要が取れない：板の上に文と「もう一度試す」。概要を使う段（推移・送信枠・友だちの状態・今月の配信・最近の成果）も骨組みのまま待たせず「データを読み込めませんでした」＋「もう一度試す」。一部だけ取れない：1行で知らせ、0件としては出さない。
- 段ごとに「データを読み込めませんでした」＋「もう一度試す」（V8 の失敗の言葉 RqO7O。v7 は「もう一度読み込む」のまま）。最初の読み込み中は骨組み（受信の一覧も骨組み）。
- 狭い幅：1280 では右の列の左右の余白を 20→16 に詰めて題を切らない。1152 では題と行き先が1行に入らない段だけ行き先を次の行へ回す（題は「…」にしない）。
- 送信枠：上限なし・未接続・取得失敗を分ける。残り 10% 以下は赤。
