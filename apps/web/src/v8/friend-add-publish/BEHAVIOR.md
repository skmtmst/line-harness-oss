# 友だち追加時の配信 作る⑤ 確認・完了（V8）の動き

入口：`app/friend-add-settings/publish/page.tsx`（V8専用で `src/v8/friend-add-publish/publish.tsx`）。
絵：確認 `U8Xm3X`・有効にした完了 `e0FD1J`。

## 受け付ける URL と指定（今と同じ）
- `/friend-add-settings/publish?id=<設定>`：確認の面
- `?done=1`：作る⑤（編集画面）の「有効にする」から来たとき。読み込んだ設定で完了の面を出す
- `id` が無い → 「指定されていません」、404 → 「確認する下書きがありません」、403 → 権限なし、ほか → 読み込めませんでした＋もう一度

## 呼ぶ口（今と同じ）
- 読む：`api.friendAddRules.get` → `validate`（画面を開くだけではテストを走らせない）・`conflicts`
- 有効にする：`publish(accountId, ruleId, 鍵)`（鍵は既存の公開名を保つ `friend-add-publish-<アカウント>-<版>`）。押した時点のアカウント・読み込み回数と違えば返事を映さない
- 有効にできるのは、サーバの確認が通り・最後のテストが成功しているときだけ（現在の `canPublish` で判定）

## 現在の表示
- 「テストする（送らずに判定）」を置いた（`test(accountId, ruleId, { friendId: null })`）。押したときだけ走り、終わったら設定と確認を読み直して「有効にする」の可否に映す
- 「有効にする前の確認」は4行（重なり・二重送信・テスト・Slack）。「変える」「見直す」は編集画面の該当の手順へ。4行に入らないサーバの確認の失敗は帯で出す
- 「下書きのまま保存」：この画面では何も書き換えないので、下書きはすでに保存済み。知らせを出して一覧へ戻る
- 完了の面（e0FD1J）は読み直さず、有効にしたときの設定名・流入リンク・順番・Slack の接続で出す。行き先は一覧・流入リンク・実行結果
- 閲覧のみ（staff）には「下書きのまま保存」「有効にする」「テストする」「変える」「見直す」を置かない。閲覧のみの帯を出し、下の帯は「一覧へ戻る」だけ
- 確認・完了ともページ内の戻るリンクを置かず、型の題・説明とパンくずを使う

## 閲覧のみの読み込み（2026-10-12 F3）
- 閲覧のみ・役割未確認ではGETの設定と保存された最終テスト結果だけを表示し、編集権限が必要なvalidate／conflictsを呼ばない。確認結果を読めていない間は合格の札を作らず、有効にする前の確認は編集できる人が行う旨を表示する。
- 編集権限が確定・変更した時は設定を読み直し、今までどおりvalidate／conflictsを両方確認する。編集できる人の確認失敗を無視して公開へ進めない。閲覧のみでも一覧へ戻る道を残す。
