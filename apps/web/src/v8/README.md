# V8画面の置き場と入口

管理画面はV8に固定しています。Nextの `app/<route>/page.tsx` はURL・読込・権限と画面をつなぐ入口、本体は `src/v8/<機能>/` に置きます。機能ごとのREADMEから入口・本体・API・試験へ進めます。動きの説明はBEHAVIORに残し、仕様をREADMEへ複製しません。

## 置き場と外に見せる名前

画面、対応するCSS Modules、hook、純粋な関数、型、動作試験を機能の近くに置きます。別の機能へ見せる名前だけを `index.ts` に明示します。内部は宣言元を直接読み、自分のindexへ戻りません。Nextのpage・layoutは本体へ直接接続し、barrelを通す必要はありません。

画面本体は `src/v8/<機能>/` に置き、現在のpageのimportと機能READMEで接続を確かめます。過去の見た目の一致率による置き場の選び方は使わず、移動済みの本体を旧パスへ戻しません。

## importの境界

- 型は `@/components/templates`、共通の表示・操作は `@/components/shared/*`・`@/components/layout/*`、既存のUIは `@/components/ui/*` を使います。
- 通信・認証・権限・日時は `@/lib/*`、共通hookと状態は `@/hooks/*`・`@/contexts/*` を利用します。通信は既存APIクライアントへ集約します。
- app内の画面・Reactの部品をV8へ取り込むimportは禁止です。現役V8のCSS Modulesと、React・Nextの描画を持たない型・純粋な関数は旧画面の持込みとは区別します。共通化・公開入口の条件は構成の決まりにも従います。
- Webのimportに `.js` 拡張子を付けません。Worker・packagesの既存の決まりは維持します。
- `useAdminTheme` などによる見た目の切り替えを画面へ持ち込みません。
- CSSの値は共通変数から読みます。`v8-boundary.test.ts` はappの画面依存・テーマ分岐・CSSの直書きを検査します。描画と操作の試験の代わりではありません。

## 入口を変えても動きを保つ

1. 現在のpageから本体・API・試験を追い、URLの `?id=`・`?tab=`・`?step=`・`?folder=` などの公開名と意味を確認します。
2. BEHAVIORのURL・保存先・API・権限・失敗を現在の実装と照合します。保存値やlocalStorageのキーを整理だけで変えません。
3. 型と共通部品で作り、保存・送信・入力保持・競合・再読込・別店舗を守ります。閲覧のみでは変更操作を隠し、権限が未取得・失敗の間も許可しません。
4. 関係する試験・型・ビルドと1152・1440の操作・崩れを確認します。合格の判断はV8の決まりに従い、司令塔が画像を見て記録します。文字一致やビルド成功だけを見た目の合格にしません。

新しい画面は `pnpm new:screen <機能名> --title <題名> --board <板ID> --dry-run` で雛形を確認します。雛形だけで接続・動作・見た目が完成したとは扱いません。[本番切替の条件](../../../../docs/v8-requirements/v8-switch.md)と司令塔の合格記録を確認して次の工程へ渡します。
