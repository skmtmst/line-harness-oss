# 統括の一括配信（V8）の動き

入口：`app/hq/broadcasts/page.tsx`（一覧）・`new/page.tsx`（作る・絵 `p17Qku`）・`detail/page.tsx`（詳細・絵 `xOXuY` ⑤ 送った結果）。新しい画面なので V8 だけ。
オーナー決定：選んだフォルダ（アカウントのタグ）・店舗のアカウントに一回で同じ内容を送り、いちいち店舗のアカウントへ入らずに送れるようにする。
統括の左メニュー（`lib/menu.ts` の HQ_MENU_SECTIONS）の末尾に「一括配信」（今の並びを動かさない）。

## 受け付ける URL と指定
- `/hq/broadcasts/new?tag=<アカウントのタグの id>`：そのタグの付いたアカウントを選んだ状態から始める（昔の入口）。`?folder=<フォルダの id>`：その札で絞った状態から始める。`?step=`：段（店の一斉配信と同じ値）。
- `/hq/broadcasts/new?id=<下書きの id>`：下書きを読み（`GET /:id` の `input`）、宛先・中身・時刻を戻して直す。送った（予約した）配信は「直せません」の案内と［詳細を見る］。
- `/hq/broadcasts/new?copy=<一括配信の id>`：その一括配信の配信名・中身・送るアカウント・対象を写して新しく作る（詳細の［複製して作る］）。
- `/hq/broadcasts/detail?id=<一括配信の id>&tab=overview|recipients|activity`。

## 口（API-7 の hq-broadcasts。`lib/hq-broadcasts-api.ts`）
- 作る `POST /api/hq/broadcasts`（requestId・title・messageType・messageContent・messageBubblesJson（素材のとき）・accountIds または accountTagIds・excludedAccountIds・audience=all・scheduledAt）。
- 直す `PATCH /api/hq/broadcasts/:id`（作る入力全体＋ expectedVersion。requestId は作ったときのまま）。送った後・古い版は 409。
- 確かめ `POST /:id/preflight`、外す `PUT /:id/exclusions`、送る `POST /:id/send`（`X-Confirm-Irreversible: broadcast-send`）、止める `/stop`、取り消す `/cancel`、やり直す `/targets/:accountId/retry`（店の配信の版）。
- 店とタグ：`GET /api/line-accounts`（タグ・友だちの数）、`GET /api/line-account-tags`。

## 作る（B-37・BBRDb：店の一斉配信と同じ5段＋送るアカウント。10-08 に p17Qku の1枚の形から置き換えた）
- 店の一斉配信を作る画面と同じ5段（`?step=basic|audience|message|schedule|confirm`・履歴を積まない）、同じ部品（段の帯 BroadcastStepRail・選ぶカード・LINE の見え方・下の帯）、同じ CSS（`components/broadcasts/broadcast-form-v8.module.css`）。
- ① 基本設定（lmWCZ・RqYwI）：配信方法（新しく作る／テンプレートを選択／過去の配信を複製）・配信名（必須・60字）・最近の配信2件（［複製する］）。
  - 「テンプレートを選択」：下に「テンプレートを選ぶ」一覧（名前で探す・丸の選び・種類・中身の要約・更新日）。選ぶと吹き出しがそのひな形になり、右の見え方も変わる。
  - 「過去の配信を複製」：下に「写す配信を選ぶ」一覧（送った日・人数・種類）。選ぶ・［複製する］・詳細の［複製して作る］（?copy=）はどれも、配信名に「（コピー）」を付け、中身（吹き出し）・フォルダ・社内メモだけを写す。宛先（送るアカウント・対象）と日時は写さない（オーナー 10-08）。
- 右の列「LINE での見え方」（スマホ・PC 切り替え・設定内容・テストを送る・配信イメージを見る・「LINEプレビュー確認済み」のチェック）は店の一斉配信と同じで、全部の段でいつも出す。白い板が 1100px 未満のときだけ畳み、頭の［LINEの見え方］で開く。
- ② 配信対象（AL5vR）：上に統括だけの「送るアカウント」（J5DH6o）。フォルダの札（すべて・各フォルダ・未分類。数つき）で絞り、アカウントのカード（名前の前にフォルダの色の丸・友だちの数）にチェック。口へは `accountIds`（選んだアカウント）で送り、`accountTagIds` は空。
  配信対象は「友だち全員」か「タグで絞る」（選んだアカウントのタグを名前でまとめた候補。口は同じ名前のタグを各アカウントで探す。無いアカウントは最終確認で外す）。人数は全員なら友だちの合計、タグは最終確認で数える。
- ③ メッセージ（lLyFR）：種類のタブは絵の並び（テキスト・画像・動画・音声・スタンプ・カルーセル・リッチメッセージ・位置情報・質問・紹介・その他）。見出しの右に［テンプレートから選ぶ］（統括のメッセージのひな形で開いている吹き出しを置き換える）と［保存してテンプレート化する］（開いている吹き出しを統括のひな形に保存。テキスト・画像・カルーセル・クーポン・その場で作ったリッチメッセージ。ほかは保存せず理由を出す）。
  - テキストは本文（5,000字）と差し込み（{店名}・{店の電話番号}・{予約ページ}・{友だちの名前}）。
  - 画像・動画は店の一斉配信と同じアップロード欄（置き場はどの店にも属さない＝lineAccountId null）。音声・スタンプ・位置情報は店と同じ入力欄（MessageKindFields）。
  - カルーセルは統括のカルーセルのひな形（listByKind('carousel')）から選び、カードの中身を吹き出しに控える（carousel、素材のカードタイプは card_message）。ボタンで「動きを実行する」（postback）カルーセルは、店にそのテンプレートが無く押しても動かないので保存しない（口の付け替え待ち）。
  - カルーセル・リッチメッセージは［その場で作る］で店の作る部品（templates/carousel・template-edit/rich の host 口）を画面いっぱいに開き、［メッセージに入れる］で吹き出しに入れる（テンプレートには残らない）。リッチメッセージの画像は統括の置き場（uploadRichMessageImage）。
  - リッチメッセージ・その他（クーポン）は統括で使える共有の素材から選ぶこともできる。
  - 質問・紹介は「まだ統括からは送れません」の1行だけ。保存・確かめで止め、口を呼ばない。
  - 口へは店側と同じ吹き出し（messageBubblesJson）で送る。テキスト以外の1つだけのときは messageType・messageContent も店と同じ変換（bubbleLegacyMessage）。
- ④ 送信設定（ZU4Ae）：今すぐ／日時を指定して予約（日本時間）。送信枠はアカウントごとに最終確認で確かめる。
- ⑤ 最終確認（H9eG3n）：配信前チェックの4行（各段へ戻る）＋「N件の確認が残っています」＋統括だけの「アカウントごとの確かめ」（送る人数・今月の送信枠の残り・確かめ・送るか・「…」で外す／戻す。外すアカウントは必ず1行、送るのは4行まで・残りは「ほか N アカウント」）。段の帯や「配信前チェックへ」で入ると自動で確かめる。
- 確かめ＝下書きを作る（作った時点でアカウントが固定）→ preflight → 問題のあるアカウントを自動で外す。中身を変えたら同じ下書きを `PATCH`（版つき・依頼番号はそのまま。取り消して作り直さない）。
- 下の帯：（⑤だけ）戻って修正・下書きを保存する・次の段へ／⑤は［この内容で予約する］か［今すぐ送る］（確かめの窓「送った LINE は取り消せません」→ 送る → 詳細へ）。
- 入れていない所があると口を呼ばず、帯に理由と［〇〇へ移動］を出す。保存した下書きは URL に `?id=` を残す。
- 閲覧のみ・担当店舗だけの人（owner・admin 以外）には作る画面を出さない（口が 403）。

## 詳細（M2tJM・10-08 に店の一斉配信の詳細と同じ形へ。xOXuY の動きはそのまま）
- 頭（名前・状態の札・中身・対象・日時・アカウントの数）と操作（取り消す・止める・下書きを直す・N店に送る）、数の帯（届いた・失敗・開いた・外した）、「アカウント別の内訳」に下の表、右の列は「配信した設定」と店と同じスマホの見本（`broadcast-detail/phone.tsx`）。店の詳細の CSS を読む。
- 開いた・押した・反応・CSV・複製して作る・宛先・記録のタブは統括の口に無い（API 待ち）。開いたは「—」。

### 動き（xOXuY から）
- 下書き：店ごとの確かめの表と［下書きを直す］［N店に送る］［取り消す］。送る直前にもう一度確かめる。一覧の「…」にも「下書きを直す」。
- 送った後：⑤ 送った結果。頭に「日時・N店に送信・成功 N人・失敗 N人」と［失敗した店にやり直す］。表は店・送った・成功・失敗（1人以上なら太字）・状態（送れた・失敗・外した（理由）・予約中・送っています・止めた・取り消した）・「…」（この店にやり直す）。
- 表の下に「失敗・送れなかった理由」：店ごとの `failureReasons` の label（LINE が混雑しています・LINE の応答なし・友だちが0人です など）と人数・やり直せるか。外した店は出さない。
- 予約中・送っている店があるあいだ：［止める］（まだ送っていない分を止める）・［取り消す］。15 秒ごとに読み直す。
- やり直すのは一時的な失敗と止める前の未送信だけ（届いた人に二重に送らない）。取り消した配信はやり直せない。

## 店側の一斉配信の一覧（l3RQH）
- 統括から来た配信（口の `fromHeadquarters`）は名前の横に「統括から」の札と鍵。「…」は見る・複製するだけ（編集・フォルダ移動・削除を出さない。口も 403）。右の詳細の窓も編集を続ける・削除を出さない。

## API-18 でつないだもの（2026-10-08）
- 一覧：左の列のフォルダ（`folders`・追加・名前を変える・消す。中身は未分類へ）。行の名前の前にフォルダの丸。
- ①：フォルダ（`folderId`）・社内メモ（`internalMemo`）。
- ②：配信対象は店と同じ4つ。シナリオ購読中（`targetType: segment` と `scenario_subscribed`＝シナリオの名前・空ならどれか）、タグ（`audience.tagName`）、詳細条件（店と同じ ConditionBuilder に名前の候補を渡す。友だち情報・対応マーク・回答フォーム等は選ばせない）、保存した条件（`savedSearchId`＝名前）、除くタグ（`excludedTagIds`＝名前）。候補は選んだアカウントごとに読み、同じ名前でまとめる。
- ③：吹き出しは5つまで（テキスト・クーポン・リッチメッセージ）。2つ以上は `messageBubblesJson`、テキスト1つは今までどおり本文だけ。
- ⑤：承認（`approval`・`approvalCandidates`・`requestApproval`・`approve`（本人確認 broadcast.approval）・`reject`・`cancelApproval`）。2人以上の運用は主ボタンが［承認を依頼する］→承認されるまで送れない、1人運用は送るときに人数を入れる（`confirmedRecipientCount`）。テストを送る（`testSend`・アカウントを選ぶ）は右の列。
- 詳細：開いた・押した・反応（アカウントの合計。1つでも取れていなければ「—」）、アカウント別の表に同じ列、CSV（`export.csv`）、［複製して作る］（`/hq/broadcasts/new?copy=<id>`）、タブ 概要・宛先（アカウントを選んで50人ずつ）・記録（?tab=、履歴を積まない）。下書きはテスト送信・承認も。
