# 来店スタンプ（V8）の動き

入口：`app/visit-stamps/page.tsx`（V8 だけで出す）。絵：G-8 の `fpPlW`（設定）・`byCFU`（移行）・`NVN1Y`（記録）。`G8KDe` は追加前の設定、`w4SBbv` は参考。左メニューは「予約」の組（予約管理・予約設定・イベント予約の次）。飲食店もサロンも使うので `/restaurant-test` の外に置く。マイル（オンライン・特定の動き）とは別のカード・台帳。

## 受け付ける URL と指定
- `/visit-stamps`：カードの設定を開く。
- `/visit-stamps?tab=settings|paper|history`：カードの設定／紙のカードの移行／押した・使った記録を直接開く。知らない値はカードの設定へ戻す。共通の Tabs を使い、切り替えは `replace`（履歴を増やさない）で、ほかのクエリとハッシュを残す。
- `/visit-stamps?friend=<友だちID>`：タブ指定がないときは記録タブを開き、「店で手入力」でその友だちを選ぶ。記録は店全体のまま。`tab` もある場合は指定のタブを優先する。
- タブと開いたパネルを読み上げ用のIDで結び付ける。タブを切り替えても①②の下書きを保持する。下の保存の帯は設定タブだけに置く。別の画面への移動・再読込では今までどおり未保存を確かめる。

## 呼ぶ口（`lib/visit-stamps-api.ts`・Codex の API-7）
- 読む：`GET /api/visit-stamps/cards`（選んでいる店が押せるカード→無ければ先頭）、`GET /api/visit-stamps/paper-requests?accountId`、`GET /api/visit-stamps/entries?accountId&page&pageSize`（④ 店全体の記録）、`GET /api/visit-stamps/paper-photos/:id?accountId`（紙の写真。非公開なので権限つきで Blob として読む）。名前は `api.friends.list`（店の友だち 200 人）と `api.friends.get`（一覧に無い人だけ）、担当者は `api.staff.list`。
- 書く：
  - ①② の下書き → 下の帯［保存する］で `POST /cards`（まだ無いとき）／`PUT /cards/:id`（`expectedVersion` 付き）。ほかの人が先に保存していたら（409）知らせて読み直す。［キャンセル］は保存した値に戻す。
  - ③［承認］→ `POST /paper-requests/:id/review`（approve・理由は「紙のカードの写真を確認しました」）。［却下］は理由を書く窓から reject。
  - 店で手入力［押印を足す］→ `POST /cards/:id/grants`（理由＝選んだ理由＋メモ。「紙のカードから移す」は `source: paper`、ほかは `manual`）。`requestId` は押すたびではなく成功するまで同じ（二重押しで2回足さない）。
  - ④「…」→［この記録を取り消す］→ 理由を書く窓 → `POST /entries/:id/reverse`。取り消しも台帳に残り、元の行に「→ 取り消し」と出す。
  - 設定タブの①「…」→［店員の暗証番号］→ 店員と4桁 → `PUT /pins/:staffId`。保存後は番号を出さない（口も返さない）。
  - 設定タブの①「…」→［押せる店を選ぶ］→ 店を選ぶ窓（下書き。保存は［保存する］）。

## 表示の決まり（`display.ts`・試験は `display.test.ts`）
- マスの数は特典の個数と別（`slotCount`）。無い古いカードはいちばん大きい特典の個数。マスより大きい特典はマスの数に詰める（保存の前に「特典の個数をマスの数以下に」）。
- 特典の下の1行：サーバは使うと特典の個数だけ減らす。いちばん大きい特典は「使ったら新しいカードへ」、途中の特典は「使うとスタンプが N個へる」（絵の「使ったらマスはそのまま」はサーバの動きと違うので書かない）。
- 倍率の名前と中身：付けた名前（`name`・窓の「名前（任意）」）があればそれ、無ければ曜日か時間がある倍率は「N倍デー」。中身は「毎週 火曜 17:00〜19:00 ・ 1/1〜3/31」（期間の終わりはその日を含めて見せる）。スイッチを切る＝止める（`active:false`・中身の前に「止めています」）。消すのは「…」から。
- 初回来店ボーナスのスイッチ：入れると +1個（「…」で個数を変える）、切ると 0。会員ランクの倍率のスイッチ：入れるとランクの窓、切ると消す。
- 「重ねたときの順番」（`stackingOrder`）：初回ボーナスを足してから倍率／倍率のあとで初回ボーナス。倍率どうしはかけ合わせ、ランクはいちばん高い倍率だけ（止めたものは使わない）。
- 「1回の上限」（`maxPerVisit`・会計の金額のとき）は倍率の前、「重ねたときの上限」（`maxStackedStamps`）は倍率とボーナスを重ねた後。無い古いカードは 1回の上限をそのまま出す。
- 記録タブは左に店全体の記録（`entries`。共通のカードでも、この店で押した・使ったものだけ）、右に店で手入力。友だちを選ばなくても記録を出す。最初は20件、10・20・50件に切り替えられる。共通 Pagination でページを送り、件数を変えたら先頭へ戻る。手入力は共通 DetailColumns の補助欄。白い板が1100px未満では畳み、［店で手入力］から開く（タブを切り替えても開閉を保持）。取り消しは元の行にまとめる。古い読込の返事で最新の記録を上書きしない。誰に＝その記録の友だち。
- 紙のカードの移行タブは申請表だけを出す。タブの数は `pending` の件数（承認済み・却下は含めない）。未取得は数を出さない。承認・却下のあとに読み直す。店舗を切り替えた後の古い返事で、別の店舗の申請と数を上書きしない。
- 日時は日本時間「1/13 18:40」。誰が：自動押印は「自動」、特典は「店員：名前（暗証番号）」、紙の承認は「名前（承認）」。

## 入れ切り
- 左メニューと機能設定のキーは来店スタンプ専用の `visit_stamps`（予約の `booking` を切った飲食店でも使える）。

## 権限
- 閲覧のみ（viewer）：閲覧のみの案内帯を出し、変える操作を置かない（頭の2つ・下の帯・特典と倍率の「…」・特典を足す・倍率を足す・承認／却下・店で手入力の欄）。入力は読み取りだけ。
- 担当者（staff）：③ の承認・却下と店で手入力はできる（サーバも owner/admin/staff）。カードの設定・暗証番号・取り消しは出さない（サーバは owner/admin）。
- 役割が読めるまでは操作を出す（最後の守りはサーバの 403）。


## ショップカードに合わせた設定（G-1・2026-10-08）
- 保存先は今のカード設定。背景は既存の `POST /api/images` で預けたJPG・PNG（3MBまで）。画像があるときは画像を使い、選んだ色は文字の下地にする。見本とLINEのカードに名前・たまった数・マス・説明・期限を出す。
- 有効期限は「最後の来店から／最初の来店から／設定しない」と1〜120か月。古いカードの `expiryMonths` は最後の来店からとして読む。最初の来店からの期限は、その財布の最初の押印（受け取りボーナスを除く）から数え、来店で伸ばさない。
- 期限のお知らせは前日・3日前・1週間前・2週間前・1か月前・知らせない。同じ財布・同じ期限には一度だけ自動でLINE送信。1か月前は暦の月で数える。送信失敗は同じ再試行キーで再送し、二重送信を避けるため23時間を越えた未確認通知は止める。専用機能停止・緊急停止・ブロック・期限切れでは送らない。
- ゴール後は「同じカードをもう一度／同じ店舗で使える別のカードへ」。いちばん大きい特典を店員の暗証番号で使った時だけ、次の財布を作る。次のカードはそれまで受け取れない。途中の特典では移らない。循環する設定は保存しない。
- 使い方の説明は500字まで、改行を保ってLINEにも出す。
- 押印の間隔は「同じ日は1回（日本時間の0時で戻る）／1〜23時間／制限しない」。手入力と来店押印は共通の制限を使い、紙の移行・取消・受け取りボーナスは除く。取り消した押印は制限に数えない。制限の理由は操作の失敗表示に出す。設定がない古いカードは制限なし。
- 受け取りボーナスは0〜50個、財布の初回作成時だけ。台帳の理由は「受け取りボーナス」。既存の財布へ設定変更で追加しない。今の初回来店ボーナスは別に残す。
- QRの発行・読み取りの受け口は既存実装になく、今回の発行方式の確認待ち。間隔制限の共通処理は手入力・来店押印で実装済みだが、QRを経由した試験はまだ行えていない。

## G-8 の決定と未実装部分（オーナー 2026-10-09）

上の G-1 の間隔制限は現在のサーバの動き。次の G-8 の決定へはまだ変更していない。
- 店頭の固定QR（A）だけに間隔の制限を効かせる。「制限しない」でも最低同じ日は1回、日本時間の0時で戻す。店員のQR（B）と店で手入力には効かせない。
- 店員のQRは有効30秒。読まれなければ自動で次へ替え、古いQRは無効。閉じるまで続ける。読まれたときは結果を出し、［続けて出す］から再開する。
- 固定QRの取得・作り直し、店員QRの発行・使用結果の取得、LIFFでの読み取りのAPIが未実装。Bの使い捨てと使用結果を保存する表は前回の追加承認待ち。承認・番号の指定なしに表を作らない。
- そのため頭の［QRを出す］、設定内の店頭QR、G-8b・b′・c・d・e・fとLIFFのg〜jは未実装。受け口のない操作や見本のQRで代用しない。
- G-8 の座標表と撮影対応表が未作成のため、今回のタブ変更も90%合格は未判定。司令塔の表ができたら `measure.sh stamp fpPlW,byCFU,NVN1Y` で照合する。
