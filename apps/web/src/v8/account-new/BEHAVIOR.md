## 5段の並びと、中の小さな段
- ①は5つの質問を1問ずつ出し、選択すると次の質問へ自動で進む。下書きで選択済みの回答も再クリックで進む。後続の質問一覧は表示しない。友だちを引き継ぐ場合だけ人数、ほかの配信ツールを使う場合だけ今後の使い方を尋ねる。公式アカウント未作成・50万人超は案内で止まり、引き継ぐ場合は認証済みの確認にチェックしてから自動で進む。最後の回答後はチェック結果を表示し、その「次へ」で②へ進む。回答の変更・戻る・下書き復元でも同じ判定を使う。
- ①事前確認 → ②アカウント接続 → ③接続確認 → ④使い方を選ぶ → ⑤完了。
- ②は中で4つに分かれる（`Step 1 / 4`〜`Step 4 / 4`）。Step1＝「Messaging API の情報を入れる」、Step2＝「プロバイダーIDを確認する」、Step3＝「Webhook（受信のつなぎ）を設定する」、Step4＝「LINEログインの情報を入れる」。
- Step1ではLINE公式アカウントマネージャー（`https://manager.line.biz/`）を開き、「設定」→「Messaging API」にあるChannel ID・Channel secretをコピーする。Step2ではLINE Developersを開き、Step1で使ったチャネルと同じプロバイダーの「プロバイダー設定」→「基本情報」にあるプロバイダーIDをコピーする。Step4の「LINE Developers のプロバイダーを開く」は、そのIDから `/console/provider/<プロバイダーID>` を開く。チャネルIDをプロバイダーIDとして使わない。古い下書きにIDがないときはリンクを表示せず、Step2へ戻って入力するよう案内する。プロバイダーIDは秘密値ではなく端末の下書きに保存し、接続APIには送らない。従来の3段の下書きは、WebhookをStep3、LINEログインをStep4に読み替える。
- ②の中だけ、進むボタンは「次のステップへ」、戻るボタンは行き先の名前（`事前確認へ戻る`／`Messaging API へ戻る`／`プロバイダーIDへ戻る`／`Webhook の設定へ戻る`）。③Step1 の戻るは「LINEログインへ戻る」。ほかの段は「次へ」「戻る」。
- ③は中で2つに分かれる。**Step1 で接続を確かめ、そのまま「登録する」で登録する**（登録は④や⑤ではなく③Step1）。Step2 は「友だち追加できるか確かめます」。
- 済んだ段へは戻れるが、登録後（`createdId` あり）は戻れない。段の表示は登録済みでも先に飛ばさない（`currentKey={String(currentStep)}`）。

## 入れてもらうもの（v06で減らした）
- ②Step1：チャネルID・チャネルシークレット（Messaging API）。②Step2：プロバイダーID。②Step4：チャネルID・チャネルシークレット（LINE Login）。入力欄は計5つで、接続APIへ送る秘密値などは従来どおり4項目だけ。②Step3 に入力欄は無い。
- **登録の前にタグ・親アカウント・担当範囲・既存のLIFF ID・表示名は聞かない**（承認済みの v06 で外した）。保存の口（`connect`）の形は変えていないので、`tagIds` などは空のまま送る。
- ②Step3（Webhook の4つ）・②Step4（LINEログインの2つ）には「LINE側でやったこと」の印（チェック）がある。全部入れるまで進めない。アクセストークンと LIFF ID は musubo 側で作るので入力欄を置かない。
- ②Step3 の題は「Webhook（受信のつなぎ）を設定する」。段の名前（戻るボタンの行き先）は「Webhook の設定」。
- **②Step3 に Webhook URL の控え（写す欄）と［コピー］を置く**（承認済み `LINE新規追加_v07.pen`・2026-10-18承認の `Ds3E2`）。LINE の「Messaging API設定」に URL を貼って「更新」を押すまで、LINE 側に Webhook の3つのスイッチが出てこないため、利用者が自分で貼る必要がある。字は `musuboWebhookUrl(channelId)`（`<NEXT_PUBLIC_API_URL>/webhook/<Messaging APIチャネルID>`・`apps/worker` の `expectedWebhookUrl` と同じ形）。チャネルIDが数字で確定するまではURLを出さず、コピーもできない。
- そのため印は4つで、先頭が「Webhook URL を貼り付けて「更新」を押した」（`dqe2M`）。左の細い列の「musubo が自動で行うこと」からは **「Webhook URL の登録」を外した**（自動登録しないので・`iaTqO`）。③の接続チェックの行「Webhook URL の登録」は、貼られた URL が musubo のものと合っているかの確認として残す。
- ②Step1 の青い囲みから **「LINE公式アカウントマネージャーを開く」**（別タブ）。②Step2 はLINE Developersのコンソールを開く。②Step3 はStep1で入力した数字のチャネルIDで `/console/channel/<チャネルID>/messaging-api` を直接開く（`developerChannelUrl`）。IDがない・数字でない古い下書きではリンクを出さずStep1へ戻す。②Step4 はStep2で入力されたプロバイダー画面を開く（`developerProviderUrl`）。マニュアル全文は②の右の列の「マニュアルを開く」（`/manuals/line-connect/index.html`・別タブ）から。

## 読み書き（API）
- ③Step1「接続を確かめる」＝ `api.lineAccounts.connectCheck`。合否は1回の返事がすべて持ち、画面は5行を上から順に見せる（1行ずつ・各420ms）。行の状態は `data-phase`（`waiting`／`checking`／`ok`／`error`）。
- 5行すべて `ok` になってはじめて「登録する」が出る。止まったときは案内（`checkErrorText`）と「もう一度確かめる」を出し、`connect` は呼ばない。「Webhookの利用」がOFFのときだけ赤ではなく案内の色にする。
- 確認そのものが落ちたとき（通信・権限・混み合い）は、理由を「時間をおいて」の一文に畳まず、共通の `describeActionFailure` で 403・404・429・入力の直し を言い分ける。権限不足の人が待ち続けたり、混み合いの人が連打したりしないため。
- 4項目のどれかを変えると接続確認はやり直し（結果を消す）。
- 「登録する」＝ `api.lineAccounts.connect`。本人確認を求められたら `StepUpPrompt` で立て直してやり直す。
- 重複・応答なし（R523）：同じチャネルIDで作られた行を `api.lineAccounts.list` で1件だけ特定できれば、その詳細へ案内する（未保存と断定しない）。
- ③Step2：登録後にそのLINEアカウントへ届いた、署名確認済みの友だち追加またはユーザーのメッセージを `api.lineAccounts.registrationReceipt` で確認する。既存の友だち数やLINEの設定画面からの空のテスト送信では合格にしない。すでに友だちなら同じトークへ「接続テスト」と送る。受信待ち・受信処理エラー・確認成功を表示し、成功するまでは「次へ」を無効にする。押した時点でもサーバに再照会してから④へ進む。友だち追加URL・QRは `lib/qr-image.ts`（`qrcode` は必要になってから読み込む・PERF-09）。
- ④：使い方の型は画面の中だけで選ぶ（保存の口は無い）。いまは「飲食店向け」だけ選べる。
- ⑤：取り込みは `api.lineAccounts.stepFollowerImport` で**続きを進めながら**進みを受け取る（1回ぶんが終わったらすぐ次を呼ぶ。他の経路が同じアカウントを握っている `busy` のときだけ3秒待つ。失敗は5秒後）。読むだけ（`followerImportState`）だと次の自動処理（5分ごと）まで進まないので、画面を開いている間はこちらで進める。画面を閉じたあとは自動処理とアカウント一覧の「入る」が続きを拾う。総数は前日の友だち数 `api.lineAccounts.followerInsight`。
- ⑤：取り込みの間は進み具合だけを出し、終わってから「登録したアカウントを見る」を出す。取り込みが終わったら契約者専用LINEの案内（`NoticeLineRegisterDialog`）を一度だけ出す（運営側で未設定なら出ない）。

## 6業種の保存と後半の再開

④は標準・EC・飲食店・サロン・面談/相談・教室/レッスンを正式キーで選ぶ。作成済みのアカウントに既存styleApi.get/saveでexpectedVersion付き保存を行い、保存成功まで⑤へ進まない。失敗時は選択を保ち、再読込後に同じIDでやり直す。端末内の `musubo-registration-style` は再開対象IDだけをsessionStorageへ置き、秘密値・権限・業種の正本にしない。再開時は再度サーバーのオーナー・管理者権限を確かめ、connectを再実行しない。飲食店を保存した場合だけ既存の店舗追加への導線を出す。

閲覧のみの帯はPageContentの内側に置き、見出し下の共通12pxと左右24pxを使う。オーナー以外は作成や後半の保存のAPIを呼ばない。
