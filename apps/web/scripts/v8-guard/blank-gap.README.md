# 大きな空白の見張り（B-187）

`node apps/web/scripts/v8-guard/blank-gap.mjs <baseUrl> [out.json]`

既存のV8画面の見張りと同じモックAPI・書き出した管理画面を使い、報告の52画面と既存の主要画面を1152・1440で1画面ずつ測ります。開けない画面も失敗として扱います。CIは既存のはみ出し検査と同じ必須チェックです。

- 空白から余白24を引き、96以上は失敗、48〜95は参考として出します。
- 数の帯は、すべてのマスで「高さ−中身の下端−16」が24以上の場合だけ失敗にします。
- 横の空白は72以上が160以上続く場所を測り、同じ閾値で判定します。
- ページ下の余り、見本の中、ページの頭、入力欄、同じ役目のカードの高さ合わせは除外します。入力側と見本側の高さ合わせは除外しません。
- `data-blank-ok="理由"` の箱は除外し、理由を結果に残します。空の理由は失敗です。

未解決のものだけ `blank-gap-allow.json` に画面・幅・持ち主・空白の上限・具体的な理由を登録します。CSS Modulesのハッシュは識別子に含めません。上限を超えた悪化は登録済みでも止めます。

```
node --test apps/web/scripts/v8-guard/blank-gap.test.mjs
node apps/web/scripts/v8-guard/blank-gap.mjs --self-test
```

対照試験は縦240pxの空白、横に偏った大きな空白、高すぎる数の帯の3つです。理由つきの除外も確認します。数の帯は1マスだけ文が長い場合の高さ合わせも確認します。

探す処理の元は司令塔の `design/v8/review/blank-gap-1010/gap-browser.js`。通常の見張りは実寸を読むだけです。`scanBlankGap({diagnose:true})` の診断時だけCSSを一時変更して原因を調べ、元に戻します。除外と判定は本番ビルドでも読める属性・クラス・実寸で決め、Reactの部品名は参考情報に留めます。
