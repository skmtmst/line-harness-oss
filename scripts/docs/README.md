# 文書の入口とリンクの検査

`pnpm exec tsx scripts/docs/check.ts` をリポジトリのルートで実行する。Git管理下と無視されていない新規ファイルを対象にするので、文書の追加直後にも使える。

文書を追加・移動したら `docs/README.md` に一度だけ直接リンクする。docs配下のデータや図、リポジトリ全体のmd・mdx・txt・rst・adoc、拡張子のないREADME・BEHAVIOR・NOTES・TODO、公開手引きの画像も含む。実行設定や製品画像は文書として登録しない。

検査は未掲載・重複、入口の欠落、ローカルリンクの欠落を失敗にする。Markdownの画像・参照形式とHTMLのhref/srcも読む。`/docs/...` で始まる参照もリポジトリの文書として確認する。コード例、外部URL、アプリの画面URL、同じ文書内の見出しはファイルリンクと分ける。見出しIDの一致・外部サイトの稼働・文言や実装の正しさを保証する検査ではない。

`pnpm exec vitest run scripts/docs/catalog.test.ts` で故障対照と実リポジトリの検査を実行できる。ルートの `test:scripts` から通常のCIにも接続される。わざと未掲載の文書・消したリンク先・外した文書への参照を置くと落ち、復元後に通ることを確かめる。

文章の頭には用途・正本か説明か・最後に確認した日を記す。画像・データ・実行時に読む基準表へ文章を挿入せず、入口と棚卸し一覧に役割と確認日を記す。要件・保護文書・反映履歴の扱いは `AGENTS.md` と担当依頼に従う。過去の記録を新しい要件として復活させない。
