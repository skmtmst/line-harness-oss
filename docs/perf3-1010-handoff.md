## 確認した原因と修正

| 原因 | 証拠 | 修正 |
| --- | --- | --- |
| 読み込み済みでも骨組みを約400ms表示 | 本番CSSは300msが`.3s`へ圧縮され、parseFloatで0.3msと誤読。固定応答は300ms以内に到着 | 共通の秒・ミリ秒変換を利用。300msの表示開始・400msの最低表示契約を維持 |
| タグの各行から遷移先を自動先読み | 行のリンクで追加のJS取得。修正前の撮影では2要求、後は0 | 名前・件数のLinkでprefetch=false。クリック先は同じ |
| 仮想表の高さ・描画範囲更新で存続行を再作成 | 描画回数の試験で確認 | 行をmemo化。データ・renderRowが変われば更新するため、選択状態とコールバックを保持 |
| タグの隠れた測定用コピーも寸法監視・吹き出し処理 | ResizeObserverの対象を試験で確認 | inertな測定用コピーだけ吹き出しの監視を省略。表示中の文字は従来どおり |
| タグごとに寸法読み取りと状態更新が交互に走る | リサイズ通知と幅読み取りの試験、CDP Layout回数 | 同じmicrotaskの幅読み取りを先にまとめ、状態更新はその後に実行 |

測定道具のlocal-stubが`/admin/version`と`/admin/manifest`を実際の検証環境へ送っていたため、CIと同じ固定応答にそろえた。既存のAPI固定応答、計測開始・終了、スクロール、回数、上限は変えていない。最初の外部通信が混じった測定は比較から外し、上の前後を両方測り直した。

タグ行の名前・件数リンクは、初回クリック時に遷移先を取得する。移動先・リンクとしての意味・別操作の分離は維持し、行の操作試験でも確認した。
