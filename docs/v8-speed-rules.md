# V8の速さの測り方（2026-10-11）

CI・検証・手元の正式な入口は次の1つ。開発サーバー・公開環境・診断トレースの数値をこの合否へ混ぜない。

```sh
NEXT_PUBLIC_API_URL=https://nen-line-stg.skmtmst.workers.dev NEXT_PUBLIC_RESTAURANT_TEST_ENABLED=true pnpm --filter web build
node apps/web/scripts/v8-guard/serve-out.mjs apps/web/out 4310
# 別の端末。画面は本番用の書き出し、APIは同じリポジトリの固定応答に差し替える。
pnpm qa:speed http://127.0.0.1:4310 /tmp/v8-speed.json
```

共通入口はV8・1440×900・Playwright Chromium・CPU制限なし・11場面を各5回の中央値で測る。APIとadmin/version・admin/manifestは同じmock-apiの応答器へ差し替える。公開環境の通信速度や、別版の待ち受けAPIを混ぜない。結果には全55サンプル、APIの指紋、端末・CPU・Node・Chromium・負荷・開始終了時刻を残す。worktreeShaは実行場所のHEADであり、配信中の版や書き出しのSHAを証明する値ではない。比較時はビルドしたSHAと未コミット差分も別途記録する。

| 判定 | 同じ上限・条件 | 使う数字 |
|---|---|---|
| 既存の悪化予算 | 時間は既存基準×1.2×1.3、長い処理の基準0は50msを下限。JSは既存基準＋1KB | 5回中央値。JSに時間倍率を掛けない |
| 元の全画面目標 | 表示/LCP 1000ms、反応100ms、長い処理50ms | 未達を表示する。既存運用どおり参考 |
| 友だち2000件 | 表示1300ms、長い処理65ms（元の1000/50×1.3） | 5回中央値、実際の応答2000件と描画行を確認 |
| PERF-01 | タグ表示1000ms、友だち2000件の長い処理65ms | 固定目標。倍率を追加しない |
| 列車17の固定目標 | ダッシュボード表示1000ms、配信一覧/作成/友だち2000件の長い処理50ms | 固定目標。倍率を追加しない |

悪化予算と固定目標は目的の違う既存の判定である。共通入口がすべて実行し、どれか1つの成功を「速度全体の合格」としない。途中結果・欠測・5回未満・2000件未描画は失敗。CIでも手元でも時間倍率は同じ1.3を使い、固定目標はそのまま。上限・基準表・CIで速度が参考チェックという扱いは変更しない。2000件の単独CLIも結果に保存した測定条件を読むため、後から読む端末のCI環境変数で50/65msが切り替わらない。CLIは超過または測定不能で終了1、CIは生の失敗を概要へ残す。

表示showMsは文書取得開始からAPIと画面の準備完了まで。通常10画面は従来どおりnetworkidleの500msの静止待ちも含み、友だち2000件はcommitから実データの描画まで。LCPとshowMsを入れ替えず、両者を別に報告する。長い処理は読込・最初の操作（2000件では20回スクロール）を含むメインスレッドの最大longtask。0msは50ms以上の通知を観測しなかったという意味で、処理が無かったという意味ではない。

MacとGitHubのUbuntuの数字は同じ機械での前後差ではない。機械差を解消するためCPU倍率を推測で足したり、上限を緩めたりしない。同じ機械・ビルド・API・命令・回数の前後を並べ、CIの解消はCIの結果で確かめる。CDPトレースやCPU制限を使った診断は別ファイルへ保存し、正式の中央値に足さない。

CIで正式の測定が完了して超過した場合は、同じブラウザと固定APIで4場面を別に3回診断する。結果は `<結果JSON>.diagnosis/` のCPUサンプル・トレースへ保存し、正式の55サンプルと混ぜない。API例外や画面未取得の場合は遅さの診断へ進まず、未完了のまま残す。診断失敗も速度の失敗を合格へ変えない。

手元から同じ診断だけを回す場合：

```sh
PERF3_DIAGNOSE=only PERF3_SCREENS=broadcast-new,templates,tags,friends-2000 node apps/web/scripts/v8-guard/perf3-profile.mjs http://127.0.0.1:4310 /tmp/v8-speed-diagnosis 1
```
