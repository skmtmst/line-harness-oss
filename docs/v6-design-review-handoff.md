### 決めた型は5つだけ

| 型 | 見分け方 | 帯の並び |
|---|---|---|

### そろえたこと（7つ）

1. **ページヘッダーの中身を1つに。** 子の名前は `見出し` と `ヘッダー操作` に統一（`左`／`右操作` が混ざっていた）。

2. **情報帯は1画面に1本だけ。** `案内`（青）と `案内（要確認）`（赤・黄、ボタン付き）の2トーン。

   **一覧型・ボード型には必ず1本。作成型・詳細型には置かない**（右カラムが説明を担うため）。
3. **右390カラムの末尾は「つながる先 → 気をつけること」の順**に固定。
4. **つながる先カードを1つの形に。** 「相手の機能名（`$status-info` 太字＋`arrow-right`）／ひとこと（`$ink-faint`）」の行だけ。

5. **「動きの要約カード」をつながる先に畳んだ。**

6. **一覧の中身フレーム名を `一覧` に統一**（`一覧列` `一覧本体` `週の台帳` が混ざっていた）。

### 生値・はみ出しの判定ルール（2026-08-24 に確定）

**1. 透明は生値ではない。**

```js
var a = (v.length===9) ? v.slice(7).toUpperCase() : "FF";
if (a === "00") return;   // 透明。数えない
```

`#00000000` は「塗りなし」を書いただけ。トークンに置き換える意味がなく、
`fill: null` での削除もできない（スキーマが色以外を受け付けない）。**数え方を直すのが正解。**

**2. 部品プレビューの「切れ」は実体ではない。**

部品の定義そのものを `Get` すると、`height:"fill_container"` の部品は親がいないので潰れ、
中身が `fully clipped` と報告される。`fill_container(240)` の**フォールバックも効かない**。
インスタンス側では正しく伸びている（`Pw4WX` は親が高いので6フォルダ全部出る）。

> **はみ出しは必ず ★画面側で数える。** 部品定義に対して `ctx.problems` を回さない。

**3. `enabled:false` の要素は「切れている」と誤報告される。**

**これがいちばん効いた。** 3-x の「はみ出し4枚」は全部これで、実体は無かった。
隠してある要素は描画されないのに `ctx.problems` は評価する。

```js
Get(id, function(x, c){
  if (!(c && c.problems)) return;
  if (x.enabled === false) return;                 // 自分が隠れている
  var q = c; while (q) { if (q.node && q.node.enabled === false) return; q = q.parentCtx; }
  //                                                  ↑ 親が隠れている
  problems.push(x.name + " :: " + c.problems);
});
```

> **部品を作るときは、既定で全部を有効にしておく。** 使わない部分はインスタンス側で
> `enabled:false` にする。部品の定義に `enabled:false` を残すと、その部品を使う全画面で
> 誤検知が出続ける。

## 2. 作業のルール

1. **新規に作るもの・変更するものは、まず `★ V6 …` として作る。** 承認後に `★ V5 …` へリネームして入れ替える。
   **V6 は対応する V5 の真下に置く**（左右に並べず縦に重ねる）。入れ替えの判断がしやすい。
   友だち 3-x なら V5 が `y=-2541`、V6 は `y=-1200`。x は V5 と同じ。
2. **見た目が1pxでも変わる修正は、必ず `★ V6 …` として出す。V5 を直接編集しない。**
   理由: 修正前と修正後を並べて比べられなくなる。トークン適用・部品差し替え・数値の修正も含めて例外なし。
   V5 を直接編集してよいのは、**名前の変更と位置の移動だけ**。
   （2026-08-23 にこのルールを破り、ダッシュボード5枚・受信箱17枚を直接編集してしまった。
   　修正前の状態は復元できない。§6 の「直接編集してしまったもの」に記録。）
3. 1機能ずつ完了させてから次へ進む。レポート → 修正 → 確認 → 次。
4. **Pencil の execute は60秒でタイムアウトする。** 全ノード走査は不可。5〜9画面ずつ分割する。
5. `TakeScreenshot` は描画が間に合わないことがある。**空白に見えたらもう一度撮る。**

### テキストの折り返しは `textGrowth` を付けないと効かない（2026-08-24）

`Update(id,{width:"fill_container"})` を**テキストに当てても無視される**。読み返しても
`width` は `undefined` のまま返り、`ctx.problems` は `partially clipped` を出し続ける。

```js
Update(id,{textGrowth:"fixed-width", width:"fill_container"});
```

`textGrowth` の意味（スキーマの原文）:

| 値 | 動き |
|---|---|
| `auto`（既定） | 内容に合わせて伸びる。**折り返さない** |
| `fixed-width` | 幅を固定して**折り返す**。高さが伸びる |
| `fixed-width-height` | 幅も高さも固定。**あふれる** |

長い説明文をカードに入れるときは、**作るときから `textGrowth:"fixed-width"` を付ける**。
あとから直すと、当たっていないことに気づかないまま `partially clipped` を数え続けることになる。

### 入れ子にした部品は、外側から個別に書き換えられない（2026-08-24）

**部品Aの中に部品Bを置くと、画面から B の中身を差し替えられない。**
`descendants` は**平らな id 引き**なので、A のインスタンスから `B の内側の id` を指定しても
**A の中の B 全部に同じ値が当たる**（B を2つ置いていたら両方変わる）。

```
共通 アクション設定 tCSBG
  ├ ref uzNEC（キャンセル）  → AMDS4 で書き換えられる（uzNEC は1つだけ）
  ├ ref nBRKk（決定）        → YbOqB で書き換えられる（nBRKk は1つだけ）
  └ 動作カード ×2            → 直接持たせた（ref にすると2枚とも同じ文言になる）
```

**規則。** 部品の中で**中身が1枚ごとに変わるもの**は、ref にせず直接持たせる。
1つしか置かないもの（ボタン・プルダウン・入力欄）は ref のままでよい。

同じ理由で `共通 標準一覧表 RwC76` の**見出しセルは `tPTMp` の ref をやめて直接持たせた**。
そうしないと6列の見出し文字が全部同じになる。

### フォルダレールの5・6行目が幅120px固定だった（2026-08-24）

`Pw4WX` の `vYHdL`（フォルダ5）と `r9b18`（フォルダ6）だけ `width:120`。
名前と件数と「…」が重なる。**普段は5行目以降を `enabled:false` にして使っていたので誰も踏んでいなかった。**
`fill_container` に直した。他11インスタンスは5行目以降が非表示なので見た目は変わらない。

> **部品は「普段使わない部分」ほど壊れている。** 全部を有効にして1度は見る。

### フレームの既定の並びは横（2026-08-24）

`Frame` の既定は `layout=horizontal, width=fit_content, height=fit_content`。
縦に積むつもりで `layout` を書き忘れると、黙って横に並ぶ。**毎回 `layout` を明示する。**

### 作った直後の `bounds` は古い（2026-08-25）

**同じ `execute` の中で `Insert` したあとに `ctx.problems` を数えると、まだ再計算が終わっていない。**
「全部 fully clipped」という嘘の報告が出る。実際には正常。

> **はみ出しは、作った呼び出しとは**別の**`execute` で数える。**
> `CHK(id)` を次の呼び出しの先頭に置く。

### 表の操作列は2ボタンなら 220 以上（2026-08-25）

`RwC76` の6列目に小ボタン（h30・`$size-caption`・padding[0,10]）を2つ並べると、
**「中身を見る」81 ＋ gap6 ＋ 2つ目 92〜117 ＋ セル余白24 = 203〜228px** かかる。
既定の 140 では必ず切れる。**しかも `Get` に `resolveInstances:true` を付けないと見つからない**
（画面の判定はサイドバーが誤検知するので付けられない）。

> **表は画面と別に、`resolveInstances:true` を付けて1つずつ数える。**
> 目安: ボタン1つ 150 ／ 2つ **230** ／ 3つ **300**。

### 6列の幅を足すと、1列目（fill）が潰れる（2026-08-25）

`TABLE` の1列目は `fill_container`。2〜6列目の合計が「使える幅 − 名前に要る幅」を超えると、
名前と副題が切れる。**列幅を直すときは、必ずどの列を直しているかを確かめる**
（`cols[2]` は `d9xfoV/u6xRWA/…`、`cols[4]` は `i23a6T/e8B53/…`。1つずれると別の列が広がる）。

### `eval` が使える。共通関数は .pen の中に置いておく（2026-08-25）

`execute` のサンドボックスでは **`eval` と `new Function` が動く**。テンプレート文字列も使える。
グローバルが持ち越されない問題は、**共通関数をテキストノードに置いて毎回 `eval` する**ことで解決した。

```

`M2kMQ` は `◆ ビルド用スクリプト（画面ではない）` `m4g8E`（x=-99000 / y=43795）の中。
**画面ではないので枚数には数えない。**

## 7. 確定した判断（覆さない）

| 判断 | 理由 |
|---|---|
| 通知パネルは**システム専用**（エラー・アップデート） | 業務系はダッシュボードの「今日やること」「運用アラート」が担う。二重に出さない |
| 通知の遷移先は既存の `/emergency`（運用状態）と `/updates`（更新履歴） | 新規ページを作らずに済む |
| **一括既読ボタンは作らない** | V5 は開けば既読になる設計。Lステップは手動確認なので必要だっただけ |
| Lステップ側の送信上限は**表示しない** | 自社は送信数課金をしないため。LINE公式の枠のみ表示 |
| ページ見出しに**副題を付けない** | 見出しだけで役割が分かる。全画面で統一 |
| 「更新時点・最新データへ更新」は**表示しない** | — |
| 「推定」注記は**表示しない** | 表に該当行が無い |
| メールは **`MAIL`** 表記＋封筒アイコン＋青系（`$mail-blue`） | LINE（英字・吹き出し・緑）と対称にする。説明文中の「メール」は日本語のまま |
| 変数の定義値は**実使用の多数派に合わせた** | `$ink-secondary` #333333→#4A5565、`$ink-faint` #7a7a7a→#6E7781、`$hairline` #e0e0e0→#DADDE2。見た目を変えずに統一するため |
