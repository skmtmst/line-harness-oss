# Lステップの実際の挙動 — Webリサーチによる検証

「画面がある」だけでなく「どう動くか」をWebで調べた結果。V2の設計に影響したものを中心にまとめる。

- 調査日: 2026-08-15
- 方法: 公式マニュアル（`manual.linestep.net`）と、Lステップ公式ブログ・代理店の解説記事を照合
- 反映: 判明した仕様のうち5件をV2の画面に反映済み

---

## 1. シナリオ配信 — 設計の前提が変わる仕様が3つ

### 1-1.【重大】同時に購読できるシナリオは1人1つだけ

> 一人の友だちが購読できるシナリオは一度に一つだけという仕様なので、メルマガのように複数のシナリオを同時に購読させることはできません。

**挙動の詳細**

| 状況 | 何が起きるか |
|---|---|
| シナリオAを購読中に、シナリオBを開始 | **Aはその時点で購読停止**。Bが始まる |
| そのあとAを再度開始 | **止まったところの続きから**流れる（読了位置を保持） |
| 複数の流れを同時に届けたい | **1つのシナリオ内で条件分岐を組む**必要がある |

**V2への影響**

Lステップ自身が「複数同時配信の代替は、1シナリオ内の分岐」と言っている。つまり **V2がシナリオ内に分岐を持つ設計は、この制約を解消する上位互換**にあたる。前回「V2はLステップと分かれている」と書いたが、正確には**Lステップが制約回避のために勧めている形をV2は標準にしている**。

**反映済み**：`V2 4-1-1 シナリオ編集` の上部に情報バーを追加。

> 同時に購読できるシナリオは 1つ。別のシナリオを開始すると、いま流れているシナリオは停止します。あとで戻すと、止まった続きから再開します。複数の流れを同時に届けたい場合は、1つのシナリオ内で分岐させてください。

あわせて **「重複を許可しない／許可する」の切替**を置いた。V2では複数同時購読を選べるようにするが、既定はLステップ同様「許可しない」。許可すると配信が重なって友だちに大量に届くため。

### 1-2. 配信方式は「時刻で指定」と「経過時間で指定」の2種類

| 方式 | 挙動 |
|---|---|
| **時刻で指定** | 誰がいつ登録しても決まった時刻に配信。**購読開始が配信時刻を過ぎていた場合、翌日の配信時刻から開始** |
| **経過時間で指定** | 「登録から5時間後」のように、購読開始からの経過時間で配信。分単位で設定できる |

V2は「1日後 20:00」という形で両方が混ざった表記になっていた。**反映済み**：`V2 4-1-1` のメタ情報に「配信方式：時刻で指定 ／ 経過時間で指定 に切り替え可」を追加。

### 1-3. 状態が「停止」のシナリオは、購読開始しても配信されない

シナリオ自体の状態が停止だと、アクションで購読を開始させても何も流れない。V2の一覧に「配信可／停止中」の列はあるが、**停止中のシナリオをアクションから呼んでいる場合の警告**は未実装。実装時に入れる。

### 1-4. 読了のリセットは個別作業

購読停止・予約キャンセルは一括操作できるが、**読了状態のリセットは1人ずつ**。V2で一括リセットを用意すれば差別化になる。

## 2. リッチメニュー — タブ機能が抜けていた

### 2-1.【重大】タブでメニューを切り替えられる

> 6マスのリッチメニューを別のタブで表示できます。タブは2〜3つまでが理想で、多すぎると離脱率が上昇します。

1枚のリッチメニューの中でタブを分け、タブのボタンを押すと別の面に切り替わる。LINEの Rich menu switch アクションで実装される。

**タップできる領域は全体で最大20個**（LINE公式仕様）。タブを増やすとこの枠を食う。

**V2への影響**

V2の `4-7-1 リッチメニュー編集` は**単一メニューのエリア分割しか持っていなかった**。タブは実運用でほぼ必須（ふだん使い／はじめての方へ、など）。

**反映済み**：`V2 4-7-1` に「タブ（メニューの切り替え）」セクションを追加。タブ1「ふだん使い」6分割 ／ タブ2「はじめての方へ」4分割 の構成と、「タブは2〜3つまで推奨」「全タブ合わせて最大20個」の注記を入れた。

### 2-2. 出し分けはタグ・属性・行動履歴で行う

友だち追加直後／購入済み／VIP会員 で別のメニューを出す、という使い方。V2の「表示する友だち＝タグ条件」で同等。**差分なし**。

## 3. 自動応答 — 未確認のまま残った点

キーワードのマッチ方法（完全一致／部分一致）、最低字数、文字種の区別は実物で確認済み。

**未確認**：複数のルールに同時にマッチした場合の優先順位。検索でも公式記載が見つからなかった。

**V2での扱い**：一覧の並び順＝評価順とし、「上から順に評価し、最初に一致した1件だけを実行する」を既定にする。実装時にLステップの挙動と突き合わせること。

## 4. 分岐の実現方法（再確認）

Lステップでシナリオを分岐させる経路は4つ。

| 起点 | 流れ |
|---|---|
| 回答フォーム | 回答内容 → タグ付与 → 別シナリオ開始 |
| 自動応答 | キーワード → タグ付与 → 別シナリオ開始 |
| **カルーセル** | ボタンのタップ → アクション実行 |
| 流入経路 | 登録したリンク → タグ付与 → 別シナリオ開始 |

カルーセルのボタンがアクションの起点になる点は、**`V2 4-3-3 カルーセルの編集` として独立画面を作成し反映済み**（下記4-1）。

### 4-1. カルーセルの仕様（調査済み・V2に反映）

| 項目 | 仕様 | 出典 |
|---|---|---|
| パネル枚数 | **最大10枚**。横スワイプで表示 | Lステップ / LINE |
| パネルの中身 | パネルタイトル ／ パネル本文 ／ 画像 | Lステップ |
| パネル本文の長さ | **最大60文字**。超えると途中で切れる | LINE |
| ボタン | **1パネルにつき最大3つ**（LINEの仕様） | LINE |
| ボタンの動き | URLを開く／回答フォームを開く／タグを追加 など、**アクション10種から選ぶ** | Lステップ |
| 画像 | 横1024px以上を推奨。比率は **1.51:1 または 1:1** | LINE |
| 注意 | パネルごとに画像比率が違うと表示が崩れる | LINE |

**V2への反映**：テキストテンプレートとは編集内容がまったく違うため、`4-3-1 テンプレート編集`（テキスト用）とは分けて `4-3-3 カルーセルの編集` を新設した。

**＋ V2の上乗せ**：ボタン別のタップ数を右カラムに表示し、「3枚目はほとんど押されていません。並び順を変えるか、枚数を減らすことを検討してください」と示す。Lステップはカルーセル単位のクリック数までで、ボタン別の内訳は確認できなかった。

## 6. 友だちリストの一括操作と、配信の絞り込み条件

### 6-1. 一括操作でできること（6種類）

友だちリストで複数選択したときに実行できる操作。

| 操作 | 内容 |
|---|---|
| 対応マーク | まとめて状態を変える |
| テンプレート送信 | 選んだ人に同じテンプレートを送る |
| シナリオ | シナリオの購読を開始・停止する |
| タグ | まとめて付ける・外す |
| 友だち情報 | 情報欄の値をまとめて書き換える |
| リマインダ | リマインダの購読を開始する |

**V2への反映**：`V2 2-2 友だち` に一括操作バーを追加。選択中の人数と、上記6つのボタンを並べた。これまで「一括アクション」ボタンだけで中身が未定義だった。

### 6-2. 配信の絞り込みに使える条件

| 条件 | 備考 |
|---|---|
| タグ | |
| 友だち情報欄 | |
| 流入経路 | |
| アンケート（フォーム）の回答 | |
| リンクのクリック履歴 | URLクリック測定と連動 |
| 購入の有無 | EC連携と連動 |
| **表示状態** | 「非表示の友だち」を配信対象から除外できる。比較的新しいアップデート |

**V2への反映**：`V2 4-2-1 一斉配信の作成` の条件ビルダーに「**表示状態 が 表示中（非表示を除く）**」を追加。

これまで「ブロック中 12人を自動で除外」しか持っていなかったが、**ブロックとは別に「こちらから非表示にした友だち」という状態がある**ことが分かった。V2の友だち詳細には V1 から引き継いだ「表示操作（非表示／ブロック）」があるので、それと整合する。

## 7. 残る未確認

**自動応答の優先順位のみ。** 複数のルールに同時マッチしたときにどれが実行されるか（1件だけか、全部か、順序はどう決まるか）は、公式マニュアル・解説記事のいずれにも記載がなかった。

V2は「一覧の並び順＝評価順。上から順に評価し、最初に一致した1件だけを実行する」で仮置きしている。実装前にLステップのサポートへ問い合わせるか、検証用アカウントで2つのルールを同じキーワードに設定して確かめるのが確実。
