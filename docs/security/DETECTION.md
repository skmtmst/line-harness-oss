# 漏れたかもしれない、と気づくために

## 誰が、いつ見るか

ケンタが一次確認、マサトが停止・復旧の判断、司令塔が調査と修正を担当する。休みの交代担当と電話は非公開の連絡帳へ置く。以下の時間は社内の対応目標で、法律の期限ではない。

- 自動集計は既存の5分ごとの定期確認から実行し、直近15分を数える。基準以上で運用状態の「要対応」用APIとSlackの `#line-harness-エラー報告` へ知らせる。画面への接続はClaude担当。
- 通知を見た人は15分以内にケンタ・マサトへ連絡し、担当者が受領する。漏れの疑い・知らない管理者・知らない鍵の更新は夜間でも即時連絡。15分返事がなければ非公開の電話連絡へ切り替える。
- 毎営業日の始めに、運用状態とSlackを両方確認する。監視の最終完了が15分以上古い／未取得／失敗なら「異常なし」と読まず、監視の故障としてマサトへ連絡する。
- 不審な操作は1時間以内に一次判断し、停止が必要なら[事故対応](INCIDENT-RUNBOOK.md)へ。調査中は1時間ごとに状況と次の連絡時刻を共有する。

**現状はコードを準備した段階。691の適用・配備・通知先の確認・画面接続はまだ行っていない。通知が実運用で動いているとは扱わない。**

## 設定と故障の見つけ方

`SECURITY_MONITOR_THRESHOLDS` は固定の項目名に対する正の整数のJSON。項目と初期値、APIは[画面との契約](SECURITY-MONITOR-CONTRACT.md)。通常変数でよく、秘密は入れない。未指定は初期値、不正・0・未知の項目は初期値へ戻し設定不正をAPIへ出す。オーナーが変更し、変更理由と時刻を非公開の運用記録へ残す。本作業では環境設定を変更しない。

Slack失敗は成功にせず5分後以降に再送。同じ未解決の異常はまとめ、件数が落ち着いても人が確認して解消するまで残す。再送では重複防止IDを使うが、通信切断後の成否不明時に完全な一度限りを保証するものではない。Slack未設定はAPIで「未設定」、集計の失敗・未取得・15分以上の停止も別に示す。監視そのものが止まるとSlackも止まり得るため、Cloudflare側の実行失敗・最終実行時刻も別に見張る。

既存Cronの配備設定は変更しない。[Cloudflare公式の定期実行](https://developers.cloudflare.com/workers/configuration/cron-triggers/)と対象Workerの設定をオーナーが照合し、架空データだけの検証で、しきい値超え→要対応→Slack→受領→解消→再発を練習する。

## 「わな」の値の案（検証だけ）

今回は実運用へわなや有効な鍵を追加しない。採用前に、オーナーが配置場所と観測経路を決め、架空の接触1回で通知が出ること、ログやSlackへ見本の値も出ないこと、productionでは登録・有効化できないことを検証する。通常の失敗通知に紛れる案、実際にログインできる鍵を作る案は採用しない。現実の見本値が使われたことを検知できた、とはまだ報告しない。

### CPUの目安と月の見積もり

計算は30日、5分ごと＝**8,640回／月**。集計3本の手元での所要時間は約13〜21msだった。Node側のCPU計測とローカルD1のSQL時間は測定結果へ別々に記録した。これらはCloudflare WorkerのCPU時間ではない。配備前の予算として、監視のJavaScriptに**1回50ms**を仮置きする。実際のCPUは反映後にCloudflareの実行記録で確認する。Slack待ち時間をCPU時間と足し合わせない。

| 対象 | 30日分の計算 | 共有の無料枠を使い切った後の追加料金の目安（米ドル） |
| --- | --- | ---: |
| 定時の呼出し | 8,640回 | 約$0.0026 |
| Worker CPU | 仮定50ms × 8,640＝432,000ms | 約$0.0086 |
| 監査集計のD1読み取り | 実測4,501行 × 8,640＝38,888,640行 | 約$0.0389 |

**上の3項目だけなら約$0.05／月。総額の上限ではない。** 既存の定期処理へ追加しているため、監視だけで定時の呼出しが8,640回増えるわけではない。監視状態の保存、警告一覧の読込み、異常時の記録・再送、画面からの取得、保存容量と既存の配信処理は別。全店数・警告数によっても変わる。

691は検索用の列を保つため、監査1件ごとの書込みも増やす。索引と自動処理の増分は、ローカルD1で両方とも監査1件あたり3行だった（測定結果の`writeOverhead`）。合計で月100万件の監査を記録するなら300万行、無料枠超過時は約$3／月。平常時の費用では、この書込み増分も確認する。監視の状態を1回2行保存すると月17,280行、超過時約$0.0173。索引・更新回数を含む配備先の実測で再計算する。

691の初回適用では既存行の検索用時刻を補完し、索引を作る。これは**毎回の監視とは別の一度限りの負荷・読書き・容量**。100万行×2表なら少なくとも200万行を補完する。オーナーは控え・dry-runで所要時間とD1の制限を確認し、一度に終わらない場合は適用せず分割手順を司令塔へ依頼する。本作業では適用しない。

2026-10-16に確認した公式単価：Workers有料は月$5から、要求1,000万回・CPU3,000万msを含み、超過分は100万回$0.30・100万CPU ms $0.02。[Workersの料金](https://developers.cloudflare.com/workers/platform/pricing/)。D1有料は月250億行の読取り・5,000万行の書込みを含み、超過分は100万行あたり読取り$0.001・書込み$1。索引も書込みと保存容量を使う。[D1の料金](https://developers.cloudflare.com/d1/platform/pricing/)。枠はほかの処理と共用。無料プランは日ごとの上限で止まるため、この月額計算だけで判断しない。
