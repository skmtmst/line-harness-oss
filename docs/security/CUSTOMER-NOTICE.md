# 情報漏えいの疑いを伝える文の型

2026-10-16 / B-343。店への業務連絡と、その先の友だち本人への連絡を分ける。ケンタ・マサトが事実と対象を確認し、案内の責任者を一本化してから送る。原因が未確定なら「調査中」と書き、未確認の安全や復旧時刻を約束しない。この文書を作っただけで送信してよいわけではない。

## 送る前の確認欄

| 項目 | 入れること |
| --- | --- |
| 何が起きたか | 確認済みの事実と調査中のことを分ける |
| いつ | 発生した可能性のある期間・気づいた日時。日本時間と明記。不明なら不明 |
| どの範囲 | 対象のサービス・情報の種類・対象人数または確認中。別人の情報を例として転載しない |
| 何をしたか | 公開・配信の停止、鍵の失効等、実施を確かめた対処。攻撃を再現できる詳細は載せない |
| お願い | 対象者に必要な具体的行動。変更が不要なら、不要と確認できた範囲を書く |
| 問い合わせ | 安全が確認された窓口、受付時間、事故ID、次の案内時刻 |
| ⚖ 専門家への確認 | 個人情報保護委員会への報告・本人への通知の要否、期限、対象、文面を専門家に確かめる |

⚖ 24時間・72時間は内部の作業目標で、法的期限の代わりではない。専門家への相談を調査終了や72時間後まで待たない。[個人情報保護委員会の公式案内](https://www.ppc.go.jp/personalinfo/legal/leakAction/)を専門家と確認する。委託先と店のどちらが誰へ報告するかも確認する。

## 店への初回連絡（メール）

```text
件名：【要確認】サービスの情報漏えいの疑いについて（事故ID：［管理番号］）

［確認日時・日本時間］に、［機能］で［確認できた事実］を確認しました。
情報が外部へ渡ったかは［確認できた状況／調査中］です。
対象の可能性がある期間は［期間／確認中］、情報の種類は［種類］です。
影響する範囲・人数は［確認できた範囲／確認中］です。

現在、［実施を確認した停止・対処］を行っています。
店舗さまには［具体的なお願い］をお願いします。
友だちへの案内は、対象と文面を確認して別途ご連絡します。
他の店舗や友だちの情報を、このメールへの返信に添付しないでください。

次のご案内：［日時・日本時間］。状況が変わらない場合もご連絡します。
お問い合わせ：［安全を確認した窓口・受付時間］／事故ID：［管理番号］
ご心配とご不便をおかけして申し訳ありません。
［案内の責任者・組織名］
```

## 友だち本人への初回連絡（LINE）

```text
［店舗名］から、情報漏えいの疑いについてのお知らせです。
［確認日時・日本時間］、［確認できた出来事］を確認しました。
対象の可能性がある情報：［種類］
対象期間：［期間／確認中］。現在［実施済みの対処］を行っています。
お願い：［本人が取る具体的な行動］
次のお知らせ：［日時・日本時間］
問い合わせ：［安全な窓口］／事故ID：［管理番号］
ご心配をおかけし申し訳ありません。
この連絡への返信で、パスワードや確認コードを送らないでください。
```

送るLINEチャネルの鍵・端末が安全か先に確認する。疑いのある経路が使えない場合は、確認済みの別経路へ切り替える。1対1の担当者返信をProxyで行うときは `X-Line-Harness-Source: manual` を付け、自動の一括案内へは付けない。

## 管理画面のお知らせ

```text
［確認日時・日本時間］：［対象機能］の情報漏えいの疑いを調査しています。
確認済み：［事実］／調査中：［未確認の範囲］
対処済み：［確認した対処］
ご協力のお願い：［行動］
次回更新：［日時・日本時間］
お問い合わせ：［安全な窓口］／事故ID：［管理番号］
```

管理画面に入れない人にも届く経路を用意する。公開のお知らせに個別の店・友だちの情報を載せない。

## 続報・完了のとき

初報から変わった事実、調査した範囲、対処をもう一度試した結果、まだ分からないこと、再発防止、問い合わせ先を書く。初報の日時と事故IDを維持する。漏れた情報を回収できたと確認できない場合、コードの復旧だけで「すべて解決」と書かない。店・本人への送信済み／未送信／届いたか不明を非公開で記録し、未達の別経路も責任者が判断する。
