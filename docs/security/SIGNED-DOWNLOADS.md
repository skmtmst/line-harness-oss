# 添付と支払明細の短い取得期限（B-351/4）

2026-10-16 / kenta・Codex。DBの表・列は増やさない。新しいマイグレーション・既存データの書換え・secret登録・配備は行っていない。

## 何を変えるか

保存しておく期間と、1回の取得URLを使える期間を分ける。チャットのファイルは従来の保存期限を保つが、取得URLは画像・動画も含めて最長15分。支払明細も最長15分で、明細自体の期限が先ならその時刻で終わる。

既存のWorker binding `API_KEY` でHMAC-SHA-256署名を作る。配備先でsecretとして登録済みかは今回未照会で、オーナーが名前・型・存在だけを確認する。用途・資源ID・持ち主・期限をまとめて署名し、添付の署名を明細へ流用できない。署名の書換え、別のID・持ち主、期限ちょうど以降、15分より先の期限、鍵不足を拒否する。鍵の登録・変更は今回行わない。鍵を変えると発行済みURLは失効する。個別URLの即時失効は、現状では元ファイルの削除・所有情報の変更・明細の停止/期限切れを使う。URLを1つだけ失効させる台帳を別に作るなら、表・番号の承認が必要。

URLには `expires` と `signature` だけを載せ、LINEの認証情報、名前、友だちID、店IDを載せない。署名付きURL自体も取得権限なので、Slack・監査ログへ転載しない。取得応答は `private, no-store` と `no-referrer`。

## チャット添付

- アップロード・動画の確定は従来どおり店/統括・会話・権限を確認し、その会話に属する添付だけへ署名する。鍵がなければ保存前に503。
- LINEへ送る直前にも、R2の持ち主とファイルの保存期限を確認して新しい署名を作る。予約時に作った短命URLを翌日の送信に使い回さない。画像も、チャット添付の名前空間なら他の会話の物を拒否する。
- `GET /images/chat-attachments/:attachmentId` は署名を必須とする。画像・動画も期限なしでは渡さない。動画のRange取得を保つ。公開の固定見本PNGには個人情報がなく、署名を求めない。
- 管理画面が会話の既存APIを読み直すと、JSON内の添付URLを更新する。`privateImageResponseMiddleware` が対象の会話、R2の持ち主、店の範囲、受信箱の閲覧権限を確認する。別の会話へ貼り込んだURL、未登録の他origin、期限を過ぎたファイルには署名しない。古いWorker名は既存の `WORKER_ALIAS_URLS` で明示したHTTPSの名前だけを認める。
- 予約の再試行では署名と短い取得期限が変わっても同じ送信として扱う。添付以外のメッセージは従来の本文比較を保つ。手動返信だけにmanualを付ける既存の送信方式を保つ。

**制約：LINEが画像・動画を取得するとき、管理画面や本人の認証ヘッダーを付けられない。そのため署名URLを受け取った第三者も、15分以内なら読める。** 別人によるURLの作成/更新と、取得URLの無期限利用を防ぐ方式であり、転送されたURLの利用者本人を判定する方式ではない。ここを本人限定にするには、LINEへの直接画像配信をやめ、本人認証を行うLIFFの取得画面へ移す別の契約が必要。画面の作成は今回行わない。

既存の署名なしリンクも拒否する。過去のLINE本文のURLは自動で書き換えられない。過去の画像・動画をLINEが再取得する場合や、15分後のファイル再取得には、運用担当による再案内が必要。後から開けることを約束する画面へ接続するときは、本人確認とURL更新の導線を画面担当が用意する。DB変更は不要だが、この運用上の変更を確認してから司令塔が反映する。

## 本人向けの支払明細

新しい経路は増やさず、既存の2経路を変える。

| 操作 | メソッド・パス・受け取り | 返す物・権限 |
| --- | --- | --- |
| 一覧 | `GET /api/liff/affiliate/statements`、`Authorization: Bearer <LINE本人の認証情報>` | 従来の `{success,data}`。LINE本人・店・統括・紹介者の所属照合を保つ。queryだけの認証は不可 |
| URLの発行 | `GET /api/liff/affiliate/statements/:id/download?issue=1`、同じ認証ヘッダー | `{success:true,data:{url,expiresAt}}`。本人の有効な明細だけへ署名する。R2本文は読まない。鍵不足503 |
| PDFの取得 | 同じdownloadパスへ署名付きqueryと同じ認証ヘッダー | 本人・所属・明細状態/期限を再確認し、署名を照合してPDFを返す。認証なし400、別人/改ざん/期限切れ署名403。資源なし404 |

明細の署名URLだけを転送しても、LINE本人の認証がなければ取得できない。他の本人のヘッダーを添えても署名が一致せず拒否する。認証情報のqueryによる代用は認めない。

画面の見た目は変えず、`apps/liff/src/lib/affiliate-self-api.ts` の `affiliateSelfApi.statements()` と `affiliateSelfApi.download(id)` が新契約を使う。downloadはまず発行し、同じorigin・同じpathであることを確認してからヘッダー付きでPDFを取得する。他originへ認証情報を送らない。既存のボタンクリックの呼び方を保つ。古い呼び出し元は認証ヘッダーへの更新が必要。

## 確かめ方

`routes/chat-attachments.test.ts`、`routes/affiliate-self.test.ts`、`services/download-capability.test.ts`、`services/image-access.test.ts`、LIFFの `lib/affiliate-self-api.test.ts`。架空のデータだけを使い、欠落/改ざん/他ID/他人/期限ちょうど/鍵変更、会話の読み直し、Range、予約・再試行を確認する。故障を入れた検査と全体検査の結果は [今回の記録](SECURITY-B351-CONTINUATION.md)。
