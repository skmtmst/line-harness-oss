## オーナーが自分でやること

- [ ] GitHub・Cloudflare・Google・LINE Developers・Stripe・Slack・ドメイン管理の二段階認証を付ける。マサトさんにも自分のアカウントで進めてもらう。
- [ ] 回復コードと予備の認証方法を保管し、スマートフォンがなくても取り出せるか確かめる。値やQRコードをこの文書・Git・Slackへ書かない。
- [ ] [権限の表](TWO-FACTOR-SETUP.md#誰に何の権限があるか)を管理画面と照合する。名前と役割だけを記録する。
- [ ] 点検表の「未」12件と「分からない」10件を開発担当と確認する。特にGoogle認証情報の保存、Slackへの情報流出防止、依存関係、本番用設定を先に扱う。
- [ ] 本番のバックアップの保持期間・復旧担当・復元練習の結果をマサトさんと確かめる。
- [ ] 事故の手順を手元にも安全に保管し、管理画面やGitHubへ入れない場合にも読めるようにする。連絡先の実値は非公開の連絡帳に置く。
- [ ] B-332の「落ち着いたらリポジトリを非公開に」を司令塔と実施する。切り替えまでは文書・画像・履歴も誰でも読める前提にする。非公開化しても過去のコピーは回収できない。

## 担当者との確認の進め方

点検表は40項目（済18・未12・分からない10）。「済」はその行に書いた範囲だけの確認です。たとえば署名を検証するコードがあっても、本番に鍵が正しく設定されている証明にはなりません。

危なさ「高」の未解決項目は、対処結果か、公開判断に必要な残るリスク・担当・期限をオーナーとマサトさんが確認してから公開を判断します。「分からない」を「問題なし」に読み替えません。

記録するのは、点検ID・担当の名前・確認日・結果・秘密を除いた証拠の場所だけです。顧客情報、アカウントのメールアドレス、秘密の値、復元点の実値、認証画面の写しは載せません。
