# V1 → V2 棚卸しと移行要件

V1のデザインをV2へ作り替えるにあたり、何を引き継ぎ、何をそのまま残し、何を新しく作る必要があるかをまとめたもの。

- 作成日: 2026-08-15
- 対象ファイル: `pencil-new.pen`
- 現状: **V2（PC）67ページ / V2（スマホ）9ページ / V1 82ページ / 飲食店案 3ページ**

---

## 1. V1から引き継いだもの

### 1-1. 文言をそのまま移したもの（書き直していない）

V1のコピーは平易で正確だったため、**言い換えずにそのまま移した**。特に以下は意図的に温存している。

| 種類 | 例 | 移した先 |
|---|---|---|
| 削除の危険を先に伝える文言 | 「5か所で使われています。削除すると、その箇所の本文が空になります。」 | V2 4-3-2 テンプレートの詳細 |
| 「気をつけること」の注意書き | 「アクセストークンは保存後に全体を再表示できません」「1つのLINEアカウントを複数のツールにつなぐと、Webhookが競合します」 | V2 10-1-1 ほか全フォーム |
| 実装状況を正直に書いた注記 | 「確定待ちにした分を確定させる操作は、まだ用意されていません。運用の仕方をあわせて決める必要があります。」 | V2 6-4-1 付与ルールを作る |
| 送られない条件の明示 | 「・友だちがブロックしている ・予約がキャンセル済みになっている ・設定した時刻を過ぎてから予約が入った」 | V2 4-4-1 リマインダを作る |
| 概念の説明 | 「アフィリエイター＝紹介してくれる人。案件＝何を成果として、いくら払うか。」 | V2 6-1-2 案件 |
| セクションの名づけ方 | 「どの案件か」「いくら払うか」「自動で行うこと」 | 全フォーム画面 |

## 2. V1のまま残すもの（V2で変えない）

| 項目 | 理由 |
|---|---|
| **デザイン言語** | LINEグリーン `#06c755`、Inter、8pxグリッド、角丸18、`$canvas-parchment` 背景。V1の変数定義をそのまま使用 |
| **サイドバーのコンポーネント** | `UGV7c`（Sidebar）を全V2ページで参照。差し替えれば全ページに反映される |
| **平易な日本語の書き方** | 「〜できます」「〜してください」の常体まじり。専門用語を避ける方針 |
| **「テンプレート」「シナリオ」「タグ」などの機能名** | 定着している名前は変えない |
| **フォームの3〜4セクション構成** | 手順が見える構成はV1のまま |
| **ログイン方式（LINEログインのみ）** | ID/パスワードを持たない方針を維持 |
| **実装済み機能の挙動** | 出荷予定・QR発行・友だち追加リンクの計測は、表示位置だけ変えて挙動は据え置き |

## 4. V2化に必要な要件

デザインをそのまま実装するために、現状の実装に足りないもの。

### 4-1. データベース（新規テーブル）

| テーブル | 用途 | 対応画面 |
|---|---|---|
| `folders(id, kind, name, parent_id, display_order)` | 汎用フォルダ。kind でタグ／シナリオ／テンプレート等を分ける | 全一覧画面 |
| `friend_fields(id, folder_id, name, type, default_value, options_json, is_starred, display_order)` | 友だち情報欄の定義 | 3-2, 3-2-1 |
| `friend_field_values(friend_id, field_id, value)` | 友だちごとの値 | 2-2-1 |
| `saved_searches(id, name, conditions_json, scope)` | 保存した検索条件 | 2-2, 4-2-1 |
| `media(id, folder_id, kind, filename, size, width, height, r2_key)` | メディアライブラリ | 5-1 |
| `media_usages(media_id, ref_kind, ref_id)` | メディアの使用箇所 | 5-1 |
| `common_vars(id, folder_id, name, key, type, value)` / `common_var_schedules(var_id, effective_from, value)` | 共通情報と日付切り替え | 5-2, 5-2-1 |
| `notification_targets(id, name, channel, endpoint, events_json, frequency)` | Slack／メール通知先 | 7-2 |
| `login_audit(id, staff_id, action, screen, ip, user_agent, result, created_at)` | ログイン履歴 | 10-2 |
| `feature_flags(scope, feature_key, enabled)` | 機能のオン/オフ | 10-3 |

### 4-3. API・処理

| 機能 | 必要なもの |
|---|---|
| ステップ別到達人数 | `friend_scenarios` の現在ステップを集計するエンドポイント |
| 送信残枠 | Messaging API のクォータ取得を定期実行し保存 |
| 過剰配信の警告 | `messages_log` から直近24時間の受信者を引く |
| 変数の差し込み | `{ニックネーム}` `{ペット名}` などの置換エンジン（友だち情報欄・共通情報・フォーム回答・配信日を解決） |
| フォーム回答→情報欄 | フォーム項目の `登録先` に従って `friend_field_values` へ書き込む |
| ケアフラグ検知 | `nen_health_logs` の連続日数判定（実装済み）をダッシュボードに出す |
| Googleカレンダー同期 | 受付時間の自動ブロック（5分間隔） |
| メディアの使用箇所 | テンプレート・リッチメニュー本文をスキャンして `media_usages` を更新 |

## 5. レスポンシブ方針

**PC 1910px を基準に、スマホ 390px へ次の規則で組み替える。** MV2 の9画面が実例。

| PC | スマホ | 実例 |
|---|---|---|
| 左サイドバー（常時表示） | **下タブ5つ＋ハンバーガーのドロワー** 下タブはホーム／受信箱／友だち／配信／その他。残りはドロワー | MV2 メニュー（ドロワー） |
| テーブル（7〜9列） | **カードリスト** 1行を2〜3段に畳む。1段目＝名前と状態、2段目＝要約、3段目＝メタ情報と `>` | MV2 3-1 タグ管理 |
| KPI帯（4〜5枚） | **横スクロールのカード**（2枚ずつ見える幅） | MV2 1-1 ダッシュボード |
| 3ペイン（一覧／本体／サイド） | **1画面ずつ＋戻る** 一覧 → 本体。サイドは「>」で別画面へ | MV2 2-1 受信箱 一覧 → トーク |
| 右カラム（プレビュー／注意書き） | **本文の下に積む**。プレビューは固定フッターの「届き方を見る」でシート表示 | MV2 4-4-1 リマインダを作る |
| フォームの番号付きセクション | **アコーディオン＋上部に進捗バー（2/4）** 開いているのは1つだけ | MV2 4-4-1 |
| ヘッダーの主アクション | **固定フッターの2ボタン**（副＋主） | MV2 2-2-1 友だち詳細 |
| 「＋ 作成」ボタン | **右下のFAB** | MV2 3-1 タグ管理 |
| 友だち詳細の情報欄タブ | **横スクロールのチップ** | MV2 2-2-1 |
| フィルタ・フォルダ | **上部の横スクロールチップ**（件数バッジ付き） | MV2 2-2 友だち一覧 |

### スマホで落とすもの

| 落とすもの | 理由 |
|---|---|
| ドラッグでの並び替え | 「上へ／下へ」ボタンに置換 |
| リッチメニューのエリア編集 | 精密なドラッグ操作が必要。PCのみ。スマホでは閲覧と公開切替まで |
| 予約台帳の席別タイムライン | 横幅が必要。スマホでは日別のリスト表示に置換 |
| 一括操作バー | 複数選択はPCのみ |

### タブレット（768〜1279px）

サイドバーをアイコンのみ（64px）に畳み、テーブルは列を減らして維持する。3ペインは2ペイン（一覧＋本体）にし、サイドはシートで開く。
