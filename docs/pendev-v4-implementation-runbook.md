# Pen.dev V4を実装するときの必須手順

## 目的

Pen.devで承認した画面を、機能名だけ似せた別デザインにしないための手順です。

「必要な文字やボタンがある」「テストが通る」だけでは、デザイン一致とは判定しません。
**実ノード、同じ画面状態、同じ横幅の画像比較**が終わるまで、V4完了とは扱いません。

## 今回の失敗

友だち属性では、次の3つを混同しました。

1. タグ・マイル・ページ切替などの**機能が存在すること**
2. 見出しやボタン名などの**文字が存在すること**
3. Pen.devと**見た目・配置・画面遷移が一致すること**

既存のV2系部品を組み替え、1と2だけを確認して3も完了したと判断したため、
一覧、タグ作成、右側パネル、ダイアログがPen.devとは別物になりました。

## 開始前ゲート

次の表を埋めるまで実装を始めません。

| 確認項目 | 必須内容 |
|---|---|
| 対象ルート | 一覧・作成・編集・詳細とクエリを列挙する |
| 画面状態 | 通常・空・読込中・エラー・モーダル・ドロワー・確認画面を列挙する |
| 操作 | すべてのボタン、タブ、検索、並び替え、ページ切替と遷移先を列挙する |
| Pen.dev実ノード | 画面名ではなく、Pencil MCPで取得した英数字のノードIDを記録する |
| 機能の正本 | 現行アプリ、Lステップ、Linyのどれを残す・追加するかを記録する |
| 影響 | 保存・送信・削除・既存ユーザーへの遡及など、運用へ影響する操作を分ける |

実ノードIDが不明な状態で、`V4 4-1-A` のような画面名をID欄へ代入してはいけません。
不明な場合は「未取得」として作業を止めます。

## 実装手順

1. Pen.devの対象ノードを1920pxで書き出し、対象状態をすべて保存する。
2. 現行アプリの同じ画面・同じ状態を保存し、残す機能を一覧にする。
3. V2の共通部品は無条件に再利用しない。Pen.devと寸法・配置が一致する場合だけ使う。
4. データ取得、保存、送信などの機能を保ったまま、表示層をPen.devの構造へ置き換える。
5. ボタン、タブ、モーダル、ドロワー、作成・編集・削除確認まで動かす。
6. 1440pxと1920pxで、ページ全体と表の横スクロールが無いことを確認する。
7. Pen.dev画像と実装画像を、**同じ状態・同じ横幅で横に並べて**比較する。
8. 差があれば修正し、比較画像を撮り直す。古い画像を合格証拠に使わない。

## 画像比較で必ず見る項目

- サイドバーの幅、並び、選択状態
- 画面全体の座標、最大幅、左右余白
- 文字サイズ、太さ、行間、色
- カード・表・入力欄の幅、高さ、余白
- 枠線、角丸、背景色、影（現在の基準は下1px・右1px）
- 列幅、折り返し、省略、行の高さ
- ボタン、リンク、アイコン、バッジの位置と状態
- モーダル、ドロワー、確認画面、空・読込中・エラー状態

## 完了判定

次をすべて満たした場合だけ「V4にそろえた」「実装完了」と報告します。

- Pen.devの実ノードIDが記録されている
- 対象状態と遷移先に漏れがない
- 1920pxのPen.dev画像と1920pxの実装画像を比較済み
- 1440pxの表示崩れと横スクロールを確認済み
- 見た目の差を直した後の画像を確認済み
- 機能テスト、型検査、ビルドが成功している
- PRのVisual Parity欄に比較証拠と未確認事項が記録されている

文字列テスト、`data-design`、ビルド成功だけでは完了にしません。

## PRと検証環境のゲート

- 比較証拠が無いPRは、機能実装としては統合できても「V4完了」にはしない。
- 実ノードが未取得、または比較できない状態が1つでもあれば、`blocked` と記録する。
- 検証環境へ上げるのは、PRでVisual Parityの合否を明示した後にする。
- 検証環境で差が見つかった場合は、設計契約の状態を未検証へ戻す。

## 友だち属性の現在地

- `/tags` と `/tags/new` は、機能追加はあるがV4の視覚一致は未完了。
- 一覧とタグ作成の実ノードIDが未記録。
- 連動アクション、編集、遡及確認、削除確認、フォルダ作成のノードは確認できているが、
  一覧・作成を含む一連の比較が終わるまでV4完了とはしない。
