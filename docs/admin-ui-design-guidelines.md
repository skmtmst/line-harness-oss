# 管理画面 UI デザイン設計ルール

## 目的

PCの管理画面で、利用者が横へ移動せずに主要情報と操作を見渡せるようにする。
文字が単語の途中で分断される表示を防ぎ、一覧を素早く比較できる状態を標準とする。
見た目の判断基準は「使う人にとって分かりやすく使いやすいか」と Pencil の ★V7 です。★V6 は最初の土台であり、見た目を合わせる対象ではありません（オーナー決定 2026-09-25）。

## PC一覧の基本ルール

1. 幅1440pxと1920pxの両方で確認し、ページ全体と主要な表に横スクロールを発生させない。**加えて実効1152px（1440pxを125%に拡大した環境）でも確認する。** 1280〜1400pxはサイドバー（256px）が現れた直後で本文が最も狭い帯（谷間）であり、ここで表のはみ出しが起きやすい。
2. 名前、識別コード、見出し、状態、ボタンは原則1行で表示し、単語の途中で改行しない。
3. 列幅に収まらない値は `nowrap` と省略記号を使い、マウスを重ねたときの `title` などで全文を確認できるようにする。
4. 一覧で選択済みの分類名など、画面内ですでに分かる情報は重複表示しない。
5. 見出しは意味を失わない範囲で短くし、セルの左右余白と文字サイズを一覧の情報量に合わせて調整する。
6. 列が多い場合は、関連情報の統合、重要度の低い列のレスポンシブ非表示、詳細画面への移動の順で整理する。
7. `min-width` で大きな表を固定し、常に横スクロールさせる設計は原則使用しない。

## 狭い帯で使う表のパターン

横スクロールがやむを得ない表（比較に全列が必要な場合など）は、操作だけは常に見えるようにする。

- **操作列の右端sticky**: `th`/`td` に `sticky right-0`＋背景色を付け、表が横に流れても「編集・削除・詳細」が右端に留まる。行ホバー時は `group-hover` でstickyセルの地色も連動させる（白抜けしない）。
- **コンテナクエリで切替**: 画面幅ではなくカードの実幅でレイアウトを切り替えたいときは `@container` / `@lg:` 系を使う（友だち詳細の履歴表が先例）。グリッドの内容列には `minmax(下限, 1fr)` で潰れ防止の下限を付ける。
- **タブ帯の横スクロール**: タブを折り返さず `overflow-x-auto` で流す場合、はみ出し中だけ右端にフェードを出して「続きがある」を示す。macOSではスクロールバーが出ないため、フェードなしでは気づかれない。

## 例外

- スマートフォンでは、操作性と情報欠落を比較し、カード表示または横スクロールを選択できる。
- URL、ハッシュ、秘密値などを詳細画面で全文表示する場合は、安全な位置での折り返しを許可する。
- 比較作業のため全列を同時に維持する必要がある表は、理由をコードまたは設計資料に記録したうえで横スクロールを許可する。

## 実装確認

- 短い語句に `break-all` を使用していない。
- 省略された値を別手段で全文確認できる。
- ボタンの文言とクリック領域が省略後も理解できる。
- 主要な行が不必要に2行以上になっていない。
- 1152px・1440px・1920pxで横スクロールと意図しない改行がない。1280〜1400pxの谷間帯も含めて、表の操作列が画面内に留まることを確認する。
