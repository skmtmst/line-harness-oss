# ダッシュボードV5 Pen.dev移行要件

作成日: 2026-08-24

対象: LINE Harness 管理画面の標準ダッシュボード

状態: **基本設計の全面入替後に再確認する下書き。画面実装は未着手**

先に `docs/v5-v6-base-design-replacement-plan-2026-08-24.md` の基本設計を入れ替える。本書の共通部品、直書き、影響範囲は、その完了後のコードを基準に再棚卸しする。

## 1. 結論

標準ダッシュボード `/` は、Pen.devの**V5**を正本として移行する。標準ダッシュボードのV6は見つかっていない。別機能である店舗ダッシュボードのV6は今回の対象に含めない。

移行で残すのは、現在動いている**機能とデータの意味**である。現在の画面構造、直書きCSS、V4固有の寸法や見た目を残すという意味ではない。

次を実装方針として固定する。

1. 現在の運用機能は、明示的に「外す」と決めない限り残す。
2. Pen.dev V5と違う構造、位置、寸法、色、文字、余白、枠、角丸、影はV5へ置き換える。
3. 色、文字、角丸、影は既存の設計トークンを使い、画面内へ新しい値を直書きしない。
4. 複数箇所に繰り返すカード、見出し、表、ボタン、プルダウン、モーダル、ドロワー、通知、データ状態は、先に共通部品として契約化する。
5. 共通部品を変えた結果、他画面にも届く変更は影響先を列挙し、代表画面を同じPRで確認する。
6. Pen.devにない読込中、空、失敗、キーボード操作は、共通状態として追加する。見た目の新ルールが必要な場合は、先にPen.devへ戻して正本を更新する。

したがって、現在の `DashboardCard`、`TodayTaskCard`、直書きの `<th>` やボタンを、そのまま見た目だけ微調整して残す方針ではない。機能を共通部品へ載せ替え、V5へ作り直す。

## 5. 機能差分と判断

判断の意味:

- **残してV5化**: 機能は残し、表示はV5の部品へ載せ替える
- **追加**: Pen.devにあり、現在ないため実装する
- **整理**: 既存機能の意味を保ち、重複や分かりにくさをV5構造へ合わせる
- **対象外**: 今回は変えない

| 項目 | Pen.dev V5 | 現在 | 判断 | 受け入れ条件 |
|---|---|---|---|---|
| 共通メニュー | `J33xq` | V4の `AppShell` / `Sidebar` | 残してV5化 | 正式V5部品へ置換し、権限・アカウント切替・件数バッジを失わない |
| 画面全体 | V5の位置・余白・色・角丸・影 | V4指定と画面内直書きが混在 | 残してV5化 | 1920pxでV5と一致し、1440pxで横スクロールなし |

## 6. 通知パネルで不足している機能

Pen.devの通知パネルは、現在のAPIをそのまま表示するだけでは完成しない。

現在の `notifications.status` は `pending / sent / failed` であり、**既読・未読ではない**。また、現在のAPIには次がない。

- 未読日時または既読日時
- 1件を既読にするAPI
- すべて既読にするAPI
- 「エラー」「アップデート」の表示分類
- 未読件数だけを軽く取得するAPI
- 各通知から開く安全な画面遷移の標準

通知パネルを見た目だけ置くと、ベルの件数と「すべて既読」が偽物になる。次を別のデータ・API要件として、画面実装より先に確定する。

| 要件 | 推奨仕様 |
|---|---|
| 既読 | 配送状態とは別に `readAt` を持つ |
| 分類 | `error / update / info` を持つ。既存 `eventType` からの推測だけにしない |
| 一覧 | アカウント、分類、未読、limit、cursorを指定できる |
| 既読更新 | 1件既読、表示中を既読、すべて既読を分ける |
| 件数 | アカウント別・分類別の未読件数を返す |
| 遷移 | 任意URLを保存せず、許可済みroute keyとIDから組み立てる |
| 更新 | パネルを開いた時、30秒間隔、画面復帰時に更新する |
| 失敗 | 件数取得失敗を0件に見せず、再試行を出す |

DB更新が必要になった場合は、コード配備と分け、既存通知の初期既読状態、バックアップ、dry-run、検証環境反映を別工程にする。

## 7. 部品対応と直書き解消

Pencilの5状態を調べると、再利用参照として置かれているのは正式共通メニュー `J33xq` と通知パネル `z6TmF` だけだった。ほかのダッシュボード要素は画面内に直接配置されているものが多い。Pencilでローカル配置だからといって、コードでも直書きしてよいとは判断しない。

### 7-1. 先に共通化する部品

| 役割 | Pen.dev | コードの方針 | 影響範囲 |
|---|---|---|---|
| 画面枠・メニュー | `J33xq` | `AppShell` / `Sidebar` をV5契約へ更新 | 原則すべての管理画面 |
| サマリーカード | V5上部カード | 契約済み `SummaryCard` を使用。意味が違う場合だけ名前付きvariant | ダッシュボードと既存利用画面 |
| 標準ボタン | V5各操作 | 契約済み `Button` を意味が一致する操作へ使用 | ボタン利用画面 |
| 表見出し | 受信、推移、出荷 | 契約済み `TableHeadRow` / `Th` を使用 | ダッシュボード内3表 |
| ページ切替 | 受信一覧 | 契約済み `Pagination` を使用 | ダッシュボード、一覧画面 |
| カード枠・見出し | `t0jk8p`候補 | `Card` / `CardHeader` を新規契約 | 複数画面のカード |
| プルダウン | 件数、経路、QRサイズ | `rpot9` / `Gfsb4`から用途別に契約 | フォーム・一覧 |
| 通知パネル | `z6TmF` | `NotificationCenter` として共通化 | 共通ヘッダーを持つ画面 |
| モーダル | QR | `Dialog`土台＋画面専用 `FriendQrDialog` | モーダル利用画面 |
| 右ドロワー | 編集 | `Drawer`土台＋画面専用 `DashboardEditor` | 右パネル利用画面 |
| データ状態 | 空・読込中・失敗 | `BDOJu` / `sZE9Q` / `OLMp0`を契約 | データ表示画面 |
| 状態バッジ | 未確認、正常、要確認 | 共通 `StatusBadge` | 一覧・運用画面 |
| 通知・警告 | 部分失敗、コピー成功 | 共通 `Notice` / `Alert` | 全画面 |

### 7-2. ダッシュボード専用に残す部品

- 今日やることのデータ対応
- 友だち推移表の列と推定値説明
- 出荷予定の業務列と期間分類
- ダッシュボードのカードID・表示可能グループ・最大件数
- 右サイドカードごとの集計内容

専用部品でも、色・影・角丸・フォーカス・ボタン・見出し・空状態は共通部品を組み合わせる。

### 7-4. 現在の直書きで置き換える対象

少なくとも次は、現在の実装をそのまま残さない。

- `DashboardCard` の `rounded-[18px]` と `shadow-[...]`
- `TodayTaskCard` の高さ、余白、文字サイズ
- 画面内に直接書かれた主要・副次ボタン
- 受信、友だち推移、出荷予定の直書き `<th>`
- QRモーダルの枠、ボタン、閉じる操作、状態表示
- 編集ドロワーの枠、タブ、スイッチ、行、下部操作
- 出荷予定内の `gray / amber / blue / red` の直接色
- ローディング、空、失敗の画面ごとに異なる表示
- `data-design-shell="v4-1920"` とV4を正本とするコメント・テスト名

既存部品のCSSを変えて他画面へ波及させる場合は、`design:impact` の結果と代表画面の比較をPRへ添付する。

## 9. アクセシビリティと表示規則

- すべてのボタン、リンク、タブ、行、プルダウン、スイッチに `focus-visible` を出す。
- フォーカスの見た目はPen.devの共通状態へ追加してから契約する。推奨はアクセント色2pxと背景から離すoffsetである。
- モーダルとドロワーは、開いた時に見出しまたは最初の操作へ移動し、中だけをTab移動し、Escapeで閉じ、起点へ戻す。
- ドラッグはポインターだけにせず、キーボード並べ替えを残す。
- 表見出しは `scope="col"` を既定にする。
- 状態は緑・赤だけで伝えず、「正常」「要確認」「未確認」等の文字を併記する。
- 友だち推移はグラフへ変更せず、数値を表で読める状態を残す。
- 1440px・1920pxでページ全体と主要表に横スクロールを出さない。
- 名前、見出し、ボタンは単語途中で改行しない。省略時は `title` 等で全文を確認できるようにする。

表見出しは、現在の設計値 `$ink-faint` on `$surface-pearl` が4.36で、12px文字のAA 4.5へ届かない。推奨はPen.devの表見出し文字を `$ink-secondary` へ変更し、その後コード契約を更新することである。承認されるまで「視覚一致かつAA適合」とは扱わない。
