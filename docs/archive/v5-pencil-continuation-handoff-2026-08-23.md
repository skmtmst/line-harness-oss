## 1. 現在の作り方

メニューバーの機能を上から1つずつ、同じ規格でV5として作る。

1. 既存の8/22画面とLステップ・Liny分析資料から、その機能の目的と必要な遷移を確認する
2. 左端に「提案V5」を置く
3. 右隣に基本画面を置く
4. ボタンを押した後の作成・編集・確認・完了・分析・削除などを右へ並べる
5. 既存の正式共通メニューと既存部品だけを使う
6. 画面ごとの固有内容は画面内に置くが、新しい共通部品にはしない
7. 全画面をスクリーンショットで確認してから、次のメニューへ進む

重要:

- **新しい共通部品を作らない。** ユーザーから明示的に再許可されるまで禁止
- 基本画面の名前だけを変えた汎用コピーにしない。各機能に必要な操作・状態・文言へ変える
- V4と8/22画面は変更・移動・削除しない
- 現在の継続作業では直接 `V5` として作る。`V6` はユーザーが改めて指示した場合だけ使う
- Pencilデザインであり、コード実装や機能接続が完了した意味ではない

## 5. 正式共通メニューの切り替え方

各画面のメニューは `J33xq` の参照を使う。

1. 既定で選択されている項目と、直前の機能の選択状態を通常色へ戻す
2. `J33xq` を読み、対象機能名のテキストNodeを探す
3. 対象行を `$accent-soft`、アイコンと文字を `$accent` にする
4. 文字の太さは `700`

機能名のNode IDを推測しない。毎回最新の `J33xq` を読み、文字列から対象行を取得する。

概念コード:

```js
const base = Get("J33xq", {resolveInstances:false});
walk(base, (node, parent) => {
  if (node.type === "text" && node.content.includes("対象機能名")) {
    overrides[node.id] = {fill:"$accent", fontWeight:"700"};
    overrides[parent.id] = {fill:"$accent-soft"};
    parent.children.forEach(child => {
      if (child.type === "icon") overrides[child.id] = {fill:"$accent"};
    });
  }
});
```

## 6. Pencil操作の必須ルール

- `.pen` は暗号化されているため、シェル・Python・`rg`で直接読まない
- `mcp__pencil__get_app_state` と `mcp__pencil__execute` だけを使う
- 最新スキーマを持っていない場合は最初に `get_app_state` を実行する
- 新規またはコピーするトップフレームは作業中 `placeholder:true`
- その画面の作業が終わったら、すぐ `placeholder:false`
- 1回の `execute` は小さく分ける
- 失敗した `execute` は、返された `editId` を使って修正する。新規実行として同じコードを送り直さない
- Pencilは共同編集なので、Node ID・位置・部品の状態を毎回読み直す

## 8. 完成確認

各機能で以下をすべて確認する。

- [ ] 提案、基本画面、必要な遷移先が同じ行にある
- [ ] 全画面が1920×1080
- [ ] xが2080px刻み、画面間の空きが160px
- [ ] 行内のyが同じ
- [ ] 次の行まで3552px
- [ ] 正式共通メニュー `J33xq` を使用している
- [ ] 対象メニューだけが緑色で選択されている
- [ ] 新しい共通部品を作っていない
- [ ] 旧機能名やコピー元の文言が残っていない
- [ ] 画面固有の操作と遷移が表現されている
- [ ] 文字、カード、表、モーダルが潰れていない
- [ ] 横方向の切れ・重なり・はみ出しがない
- [ ] 全画面を `TakeScreenshot` で確認した
- [ ] `placeholder:true` が残っていない
- [ ] V4・8/22・コードを変更していない

`execute` が `fill_container` 警告を返した場合は放置しない。親をflex layoutにするか、その画面内だけ明示幅へ直し、再度スクリーンショットを確認する。
