# Pen.dev V5/V6 共通部品棚卸し

作成日: 2026-08-24

正本データ: `apps/web/design/pencil-component-inventory.json`

## 結論

Pen.devの再利用部品85件を、V5を基本、対象にV6がある場合だけV6差分を使う前提で分類した。画面を移す前に、どの部品を共通化し、どこへ影響させ、既存部品へ統合するかをCIで確認できる。

B2ではダッシュボードを実証先として、カード、カード見出し、状態バッジ、アイコン操作の共通部品を追加した。B3では入力欄、複数行入力、検索、選択（閉・開・表示件数）を共通部品へまとめた。B4では確認ダイアログ、右詳細パネル、成功・入力確認・失敗通知、操作メニュー、通知パネルを追加し、友だち属性のフォルダ操作・削除確認・連動アクション・保存結果へ接続した。意味が一致する既存の直書きは削除せず、同じ保存・検索・選択・削除・並び替え処理を保ったまま共通部品へ載せ替えている。

## 棚卸し結果

| 分類 | 件数 | 意味 |
|---|---:|---|
| 全画面共通 | 46 | メニュー、ボタン、入力、表、ダイアログ等。変更が全管理画面へ届く候補 |
| 機能群共通 | 31 | 配信、友だち、テンプレート等の同じ機能群で共有する候補 |
| 画面専用 | 8 | その画面だけに残すか、後で昇格を判断する候補 |
| 合計 | 85 | Pencil上の再利用部品定義を全件確認 |

| 移行方針 | 件数 | 意味 |
|---|---:|---|
| そのまま再利用 | 27 | 既に契約済みの共通部品を使う |
| 新規実装 | 27 | 共通部品または機能群部品として実装する |
| variantへ統合 | 26 | 開閉、成功・失敗、選択等を別部品にせず状態として統合する |
| 置換 | 2 | 重複・廃止候補を正式部品へ置き換える |
| 調査してから決定 | 3 | 設計上の不整合やコピー利用を解決してから使う |

現在コードで利用中として契約済みなのは27件である。B4で `J6x4Q` / `H2S1T4`（確認）、`VJKAT`（右詳細）、`ApbSZ` / `zPRvi` / `I5rKbM`（通知）、`hGpFq`（操作メニュー）が利用中になった。`H0V8EK`（アイコン操作）と `z6TmF`（通知パネル）はコード実装済み・画面適用待ちで、残り56件は未実装として扱う。通知パネルは既存に通知センターAPIとベル入口がないため、見た目だけを既存画面へ足していない。Pencilに存在するだけで移行済みとは判定しない。

## 統合ルール

- 開いたSelectは別部品にせず、閉じたSelectの `open` 状態へ統合する。
- 成功、失敗、空、読込中は別々の土台を作らず、NoticeまたはDataStateのvariantへ統合する。
- KPIの色や説明の違いはSummaryCardの名前付きvariantへ統合する。
- 重要・削除確認はDialogのvariantへ統合する。
- Pencil上のボタン見本は、既存Buttonのvariantへ統合する。
- 見た目が似ていても意味や操作が違うものは無理に統合しない。

各ファミリーは `props` と必須状態を持つ。例えばButtonは通常・hover・focus・押下・無効・処理中、Dialogは閉・開・処理中・成功・失敗、Selectは閉・開・選択・未選択・無効・検索・エラー・focusを必須にしている。

## 調査中

| Node ID | 理由 | 次の判断 |
|---|---|---|
| `AWHUI` | ref参照だけではコピー利用を数えられず、標準一覧表の正本と断定できない | コピーを含む利用実態を確認してDataTableの正本を決める |
| `LMiL2` | 生の色、角丸、文字サイズが共通ルールとずれている | Pen.devを直すかStepperの例外variantにする |
| `gk4ne` | 生の色、角丸、文字サイズが共通ルールとずれている | `LMiL2`と同じStepperへ統合できるか判断する |
| チェックボックス / スイッチ | 再利用部品85件に全画面共通の正本Nodeが無い | V5または対象画面のV6で通常・選択・無効・エラー・focusを定義する |

Pencil全体のref参照数は、全体走査が規模上限で中断したため合格証拠にしていない。既存契約で実測済みの部品だけ参照数を利用し、85件の存在・直接定義・分類・状態・影響先を今回の合格条件にした。

## CIで落とす条件

- 85件を下回る
- 全画面共通・機能群共通・画面専用のいずれかが無くなる
- Node ID、名称、部品ファミリー、設計状態、役割、実装状態が欠ける
- V5基準またはV6差分の記録が欠ける
- propsまたは必須状態が欠ける
- 影響候補ルートが欠ける
- 全画面共通なのに全画面を表す `*` が無い
- 実装中部品が既存のactive契約に接続されていない
- 調査中部品が調査一覧に記録されていない

`design:impact --part <Node ID>` は、未実装部品でも分類、状態、V5/V6差、移行先、契約上の影響候補を表示する。実装後はコードから実際に到達するルートと照合する。
