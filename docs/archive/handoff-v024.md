## 送る文面

まさとさん

0.21.0 から 0.24.0 までの修正が終わりました。
データベースの変更を含むので、**手順書に沿って**アップデートをお願いします。

**手順書**: `docs/migration-runbook.md`

### 版ごとの中身

| 版 | 中身 | データベース |
|---|---|---|
| 0.21.0 | 既存データが未表示だった5件 | 変更なし |
| 0.22.0 | デザイン刷新＋既存APIで対応できる16画面 | 変更なし |
| 0.23.0 | 列追加を伴う9件 | **088〜098（11件）** |
| 0.24.0 | 新規5件＋V2の全画面 | **099〜104（6件）** |

**データベースの変更は合わせて 17 件です。**

当初の見込みから2件ずつ増えています。理由は次のとおりです。

- 0.23.0 は 088〜096 の予定でしたが、友だち検索が遅かったので索引（097）を、
  イベントのキャンセル待ちに `event_bookings.status` の CHECK 制約を
  変えられなかったので別テーブル（098）を足しました。
- 0.24.0 は 099〜103 の予定でしたが、103 で足した
  `scenarios.allow_concurrent` の既定が 0 で、そのままだと
  **いま複数のシナリオに入っている人への配信が止まる**ため、
  既存行を1に寄せる 104 を足しました。

### アップデートの流れ

1. **PRをマージする** — 順番は `docs/merge-order.md` にまとめました
2. **検証環境で先に当てる** — Actions の **Migrate D1** から。
   まず `dry-run`（何も変わりません）、次に `apply`
3. **検証環境で10項目を確認** — 手順書の表のとおり
4. **`main` にマージ** — この時点で**本番に自動で当たります**
5. **本番で同じ10項目＋4項目を確認**
6. **30分ほど様子を見る** — 配信・リマインダは次のcronまで結果が出ません

### 特に見てほしいところ

**シナリオ詳細の「他のシナリオが動いている人は登録しない」**。
ここに**チェックが付いていたら 104 が当たっていません**。
その状態で本番に上げると、いま複数のシナリオに入っている人への
配信が止まります。手順書に単体で当てる方法を書いてあります。

### 戻すとき

追加のみのポリシーで down マイグレーションが書けないので、
戻す手段は D1 の Time Travel だけです。

復元点は当てるたびに自動で取り、実行結果のサマリーに
`restore` のコマンドごと出ます。**その行を控えておいてください。**
30日間有効です。

巻き戻すので、**当てたあとに入った友だち・メッセージ・予約も
一緒に消えます**。戻す前にその間に何が入ったかを確認してください。
