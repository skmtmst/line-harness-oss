# PR #3 V5/V6 サマリーカード移行仕様

## 目的

既存画面に分散している3種類の数値カードを、Pencilを正本にした共通 `SummaryCard` へ集約する。以後は共通部品を1回直すと対象画面へ反映される状態にする。

## 設計の優先順位

- 基本はPencil V5の共通サマリーカード `XywGr`。
- 対象画面にV6がある場合は、その画面のV6を優先する。
- シナリオはV5の配信KPI `mNUQ3` を `broadcast` variantとして使う。
- 運用状態画面の文字列値カードは、数値専用部品へ無理に統合しない。

## 実装範囲

- `SummaryCard` に `v5`、`v6`、`broadcast` の名前付きvariantを追加する。
- 既存 `KpiCard` は呼び出し側を壊さない互換層にし、内部描画を `SummaryCard` だけにする。
- `FriendKpis` と `ListKpis` はデータ取得・計算・エラー処理を変えず、描画だけを差し替える。
- 9ルートの到達関係を `design-parts.json` に記録し、`summary-card` を `active` にする。

## 影響範囲

見た目が変わるのは上表の数値カードだけ。API、保存、送信、削除、タブ切替、カード内リンクの遷移先は変えない。レスポンシブの2列・4列グリッドも維持する。

## 受け入れ条件

1. 3種類の旧実装がすべて共通 `SummaryCard` を描画する。
2. V5/V6/broadcastの寸法と文字指定がPencilの実測値に一致する。
3. 通常・読込中・取得失敗でカードの高さが跳ねない。
4. 数値、単位、説明、カード内リンク、aria属性を維持する。
5. `design:impact --part summary-card` が9ルートを追跡する。
6. `verify:design` がビルド後CSSの配信まで合格する。
7. 型検査、テスト、ビルド、設計負債検査が通る。
8. 1440pxと1920pxでページ全体の横スクロールが増えていないことを確認する。

## 視覚検証の扱い

Pencilの実ノード値は取得済み。ログイン済みの実装画面を同じ状態・同じ幅で撮影できない場合、画像による画面全体の一致は `unverified` とし、完了済みとは書かない。CSS値・DOM・ビルドの合格と画像一致を混同しない。
