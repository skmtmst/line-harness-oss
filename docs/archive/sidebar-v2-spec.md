## 2-1. 設計の絵との差分（意図的に外している。戻さないこと）

設計の絵（`Sidebar V2` / id `khQh9`）と実装は**4か所ちがう**。
**2026-08-18 に「メニューバーは今のままでよい」と決めた。** 実装が正。

絵を見て「仕様と違う」と思ったときは、まずここを読むこと。

### 1. 「対応」「友だち属性」の見出しを付けない

| | |
|---|---|
| 絵 | `対応`（受信箱・友だち）と `友だち属性`（友だち属性）に見出しを立てる |
| 実装 | ダッシュボードと同じ、**見出しなしのかたまり**に4項目まとめる |

**理由。** 項目が1〜2個の区分に見出しを付けると、行数のわりに縦が伸びる。
ここは毎日開くものなので、上に詰めて出したい。

### 2〜3. テンプレート・リッチメニュー・回答フォームを「コンテンツ」へ集める

| 項目 | 絵 | 実装 |
|---|---|---|
| テンプレート | 配信 | **コンテンツ** |
| リッチメニュー | 配信 | **コンテンツ** |
| 回答フォーム | 成果と分析 | **コンテンツ** |

**理由。** この3つは配信そのものではなく、**配信や画面から呼ばれる材料**。
絵のままだと同じ性格のものが3か所に散る。「作って置いておくもの」を
コンテンツ区分に集めた。

### 4. タブレット幅のアイコンレールを廃止

| | |
|---|---|
| 絵・旧仕様 | 768〜1279px で 64px のアイコンレールに畳む |
| 実装 | **1280px未満はすべてハンバーガー＋ドロワー** |

**理由。** アイコンだけの帯は、どの項目か分からず押せない。狭い幅の
振る舞いをハンバーガー1つにそろえた。

### （差分ではないが紛らわしいもの）写真審査のルート

**`/health` ではなく `/nen-members`。** `/health` は「BAN検知ダッシュボード」で
写真審査ではない。BAN検知は §3-1 のとおり「運用状態」へ統合済み。

## 3. 現行実装からの差分

現行は **6区分46項目**。46 → 30 に減るのは、機能が消えるからではなく**タブに統合されるため**。

### 3-1. 名前を変えるもの

| 現行 | V2 | 変える理由 |
|---|---|---|
| 未対応 | **受信箱** | LINE・メール・返信待ちを1か所に集約した実態に合わせる |
| 友だち管理 | **友だち** | 「管理」は全項目に付くので情報量ゼロ |
| タグ管理 | **友だち属性** | タグ／情報欄／対応マーク／保存した検索の4タブの総称 |
| アフィリエイト ＋ CV計測 | **成果とアフィリエイト** | 成果地点を決める→誰が生んだかを見る、が一続き |
| フォーム回答 | **回答フォーム** | フォームを作る画面なので、回答は結果 |
| リファラルリンク ＋ サイトスクリプト ＋ 広告連携 | **流入と計測** | どこから来たかを測る設定の総称 |
| Webhook | **外部連携** | 通知先設定も含むため |
| ユーザー一覧 ＋ スタッフ管理 | **ログインユーザー** | 予約の「スタッフ」と紛らわしいので分離 |
| BAN検知 ＋ 緊急コントロール ＋ アップデート履歴 | **運用状態** | 気づく→履歴を見る→止める、が一続き |
| 自動返信ルール | **自動応答** | Lステップと用語を統一 |
| 表示設定 ＋ メニュー設定 | **機能設定** | どちらも管理画面の見え方 |
| メニュー（予約） ＋ スタッフ（予約） ＋ 受付時間 | **予約設定** | どれも予約枠を決める設定 |
| LINEアカウント ＋ プール管理 ＋ データ移行 | **アカウント** | 追加→振り分け→引き継ぎが一続き |
