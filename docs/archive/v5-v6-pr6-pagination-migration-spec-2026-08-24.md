# PR #6 V5/V6 ページネーション移行仕様

## 目的

画面ごとに高さ・色・角丸・省略方法が分かれているページ切替を、Pencilの `Blot6` を正本にした共通 `Pagination` へ段階移行する。共通部品を1回直すと、前後ボタン・ページ番号・現在地・省略記号が利用画面へ一括反映される状態にする。

## 設計の優先順位

- 基準はV5。
- 対象画面にV6がある場合は、そのV6画面を優先する。
- `Blot6` はPencil全体で139回参照されている。
- V6代表10画面では受信箱を除く9画面が同じ `Blot6` を使うため、V6専用variantは作らない。

## Pencilから固定する値

- 前後ボタン: 64×38px
- ページ番号・省略記号: 38×38px
- 間隔: 8px
- 枠: `$hairline` 1px、角丸 `$radius-sm`
- 通常: `$canvas` / `$ink` / 12px / 600
- 現在地: `$accent` / `$on-accent` / 700
- 表示枠: ページ項目5枠。先頭・現在地・末尾を残し、間を `…` で省略する。

## 第1段階の対象

| 利用先 | 採用版 | 移行理由 |
| --- | --- | --- |
| `/friends` | V5基盤 | 既にページ番号と省略移動を持つ |
| `/tags` | V5 | ページ番号へ直接移動できる状態へそろえる |
| `/reminders` | V6 | 全ページ番号の直書きを共通化する |
| `/contents` | V5基盤 | 全ページ番号の直書きを共通化する |
| `/contents/vars` | V5基盤 | 全ページ番号の直書きを共通化する |
| 旧タグ一覧部品 | V5基盤 | Pencil見本と同じ5枠を既に持つ |

## 対象外

- 「前へ・次へ」と現在/総数だけを持つ画面
- ページ切替機能が未実装で、無効ボタンだけを表示している画面
- フォームやウィザードの「前へ・次へ」

これらはページ番号へ直接移動する処理を持たない。見た目だけを差し替えて動作を変えないよう、次段階でAPIを確認して移す。

## 影響と負債

- 共通 `Pagination` の利用先は0から6ファイルになる。
- 主要ボタン直書きは158件から154件へ減る。
- 副次ボタン直書きは315件から301件へ減る。
- 任意値記法は1495件から1482件へ減る。

## 実装ルール

- 呼び出し側は `page`、`pageCount`、`onPageChange` だけを渡す。
- ページ数は最低1、現在ページは1〜総ページ数へ正規化する。
- 5ページ以下は全番号を表示する。
- 6ページ以上は5枠に収め、先頭・現在地・末尾を常に移動可能にする。
- `aria-label`、`aria-current="page"`、前後の無効状態を部品側で付ける。
- API、取得、絞り込み、ページサイズ、選択状態は変えない。

## 受け入れ条件

1. 共通 `Pagination` とCSSモジュールが存在する。
2. 6利用先が共通部品を直接importする。
3. 先頭・中央・末尾・5ページ以下の省略規則をテストする。
4. 前後ボタン、番号、現在地、無効状態のHTML契約をテストする。
5. ビルド後CSSで `Blot6` の17宣言が一致し、配信漏れがない。
6. 直書きボタンの負債基準を移行後の実測値へ締める。
7. 型検査、全テスト、ビルド、設計負債検査が通る。
8. 1440px・1920pxの画像比較ができない場合は `unverified` のままにする。

## 視覚検証

Pencil実ノードとビルド後CSSは照合する。固定データの `/visual-qa/friend-attributes-v2` は1440px・1920pxで描画し、ページ全体と表の横スクロールが無いことを目視確認する。実ルートがAuthGuardからLINEログインへ遷移して同じデータ状態を用意できない場合、Pencil全画面との画像一致は `unverified` とし、視覚一致済みとは書かない。
