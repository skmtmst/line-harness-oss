## 5-2. 部品の書き方（2026-08-24 決定）

**共通部品の中身はCSSモジュール。ページ側のレイアウトはTailwindのまま。**

理由:

- 3系統に割れた原因はTailwindの任意値記法だった。`rounded-[14px]` `border-[#DADDE2]`
  `shadow-[1px_1px_2px_rgba(29,29,31,0.13)]` は普通のクラスと同じ見た目で、
  規格から外れたことが目で見て分からない。
- Pencilのノード属性はCSS属性そのもの。`padding: [14,16]` → `padding: 14px 16px` に
  翻訳が要らない。V5の 13px・22px・11px・角丸10px はTailwindの標準目盛りに無く、
  部品を足すたびに `@theme` への翻訳表が増える。

ただし技術の選択だけではズレは止まらない。友だち属性V3のCSSモジュールは
ローカル変数 `--v3-accent: #08c654` を持ち、3つ目の色系統になっていた
（Pencilと `globals.css` はどちらも `#06c755`）。

**止めるのは規律のほう。** 部品には次の2つを必ず付ける。

1. 値は `globals.css` のPencil由来トークンを `var()` で参照する。ローカル変数を作らない
2. 契約テストで、CSSの宣言とPencilの指定を1対1で突き合わせる
   （例: `friends-v4-contract.test.ts` の「共通カードはPencil V5の XywGr と同じ値で描く」）
