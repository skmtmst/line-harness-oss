# Lステップの一斉配信 — 実機で確認した内容と、こちらとの差

meauty渋谷店（本番の実データ）に**読み取りのみ**でログインして確認した。
登録・削除・送信は行っていない。確認日 2026-08-19。

シナリオ配信の調査は `lstep-scenario-research.md`。

---

## 1. 作成画面（`/line/magazine/new`）

5段構成。

```
１. 管理用タイトル
     タイトル ／ フォルダ

２. 配信先設定
     ○ 友だち全員に配信する
     ○ 友だちを絞り込んで配信する → [絞り込み]
     未選択のときは「※ 配信対象を選択してください」

３. 配信日時設定
     ○ 登録後すぐに配信する
     ○ 配信日時を指定する → [日付] [時刻] に配信

４. 開封数の取得設定
     「取得する」を選択するとメッセージを閲覧した友だち数を測定できます。
     ○ 取得する  ○ 取得しない

５. 配信メッセージ設定
     タブ: テキスト / スタンプ / 画像 / 質問 / カルーセル / 位置情報 / 紹介 / 音声 / 動画
     本文 [必須]  [短縮URL対応]
       undo / redo / 名前 / 友だち情報 / 共通情報 / 回答フォーム / 配信日 / その他 / 絵文字
       0/22500（約4,500文字を超えた場合は複数のメッセージに分割されます）
     URL設定
       [URL読み込み]  □ このメッセージではURLを短縮しない
       表: サイト名 / 訪問時
     公式アイコンで送信（変更不可）

□ テンプレートとして保存
[配信登録] [下書き保存] [テスト送信] / 戻る
```

上部に「下書きを開く」。

### いちばん大事な発見

**配信先の絞り込みが、シナリオとまったく同じ条件ビルダーだった。**

```
配信対象  ☑ 表示中の友だち  ☑ 非表示にした友だち     [カスタム検索からコピー]

「すべて満たす」必要がある条件 (and条件)
  名前 / タグ / 友だち情報 …（行ごとに消せる）
  絞り込む項目を更に追加できます
    名前・個別メモ・ステータスメッセージ・友だち登録日・対応マーク・タグ・
    友だち情報・シナリオ・イベント予約・カレンダー予約・リマインダ・
    回答フォーム・最終反応日・その他
＋「いずれか1つ以上を満たす」必要がある条件(or条件)を追加
[決定する]
```

シナリオの配信対象・1通ごとの配信対象・アクションの実行条件と同じ部品。
**Lステップは1つの条件ビルダーを全部で使い回している。**

### もうひとつ

**Lステップの一斉配信は1通しか送らない。** 「メッセージを追加」が無い。
こちらは3通まで書ける（ただし2通目以降はまだ配信できない）。

## 2. 一覧（`/line/magazine`）

```
[新しいフォルダ] [新規配信] [テンプレート配信]
□ 配信予約中のみ  □ 非表示のみ   配信日 [開始]-[終了] [検索]
フォルダ（左） 未分類

列: タイトル / 配信日時 / 配信条件 / 内容 / 開封数(開封率) / 配信数
```

「テンプレート配信」が新規配信とは別の導線として並んでいる。

## 3. カルーセルの中身

こちらの実装よりかなり厚い。

```
パネル #1〜10（arrow_back / arrow_forward / content_copy / delete）
  タイトル 0/40（差し込み可）
  本文 [必須] 0/60（差し込み可）
  画像（横1024px 縦678px 推奨）
  選択肢 1〜4
    選択肢名 [必須] 0/20（10文字を超えると途中で切れる）
    ユーザーメッセージ / 詳細設定
    アクション実行 → [アクション設定]
      未設定なら「アクションが未設定です。押されたときに何も起きません。」

オプション
  選択肢のタップ回数制限（カルーセル全体で1回のみ）
  制限を超えた時の設定（全選択肢で同じ / 選択肢ごと）
  制限を超えた時のテキスト返信（既定の返信をする「すでに押されています！」/ しない）
  制限を超えた時のアクション
PC版・通知欄での代替テキスト 0/400（差し込み可）
```

こちらのカルーセルはテンプレートから選ぶだけで、**選択肢ごとのアクションも
タップ回数制限も無い**。

## 4. こちらとの差（2026-08-20 時点）

### 埋めたもの

| | |
|---|---|
| 配信先 | シナリオと同じ条件ビルダー（15項目・and/or）に差し替え（#179） |
| 友だち全員 | 追加。それまで画面から全員宛にする道が無かった（#179） |
| 差し込み | 名前・友だち情報・共通情報・配信日・カウントダウン（#179 #180） |
| URLを短縮しない | `track_links` は前から通っていたが画面に無かった（#179） |
| メッセージ種別 | スタンプ・カルーセル・位置情報・音声・動画（#182） |
| 一覧の内容列 | JSON の種別は読める1行にする（#183） |
| 配信日での絞り込み | （#183） |
| フォルダ | ボタンだけあって押せなかった（#185） |
| 開封数の取得設定 | 集計ユニットは月1,000までなので選べる意味がある（#185） |

### 直したもの（壊れていた）

| | |
|---|---|
| 一斉配信が1つも作れない | 二重送信よけのヘッダがCORSで許されていなかった（#180） |
| 作れても送れない | 1通でも「複数吹き出し」扱いで断られていた（#181） |
| 詳細条件が誰にも当たらない | 値を書き込む経路の無い場所を見ていた（#179） |
| 配信前チェックの人数 | 詳細条件を無視して全員を数えていた（#179） |
| 一覧の宛先表示 | 詳細条件も「タグ指定」と出ていた（#183） |
| 一覧の種別表示 | text/image 以外がすべて「Flex」（#183） |
| テスト送信の差し込み | 確かめたい本文だけ通らなかった（#180） |

### まだ無いもの

| | 理由 |
|---|---|
| 2通目以降の配信 | Lステップは1通のみなので、機能差ではない |
| カルーセルの選択肢ごとのアクション | 押されたときのタグ付与など。厚い |
| カルーセルのタップ回数制限 | 上と同じ仕組みが要る |
| 「紹介」の種別 | LINEに該当する種別が無い。代替を画面に出してある |
| 回答フォームの差し込み | フォームへのリンクを本文に入れる |
| 表示中／非表示の選択 | 条件ビルダーの `is_hidden` で書けるが、既定の扱いを決めていない |
| カスタム検索からコピー | 条件の保存自体が未実装 |
| テンプレートとして保存 | |
| 「非表示のみ」の一覧絞り込み | 配信の非表示という概念がこちらに無い |
| 短縮URLのクリック計測表 | 計測はしているが、作成画面に一覧が出ない |
