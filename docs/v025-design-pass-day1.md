### 途中で見つけて直したもの

- **メールを開くと、以後どのトークも開けなくなっていた。** LINEを選ぶ処理でメールの選択を外していなかった。右側はメールを先に見るので、一度開くとずっとメールが出続ける。メール側は逆にLINEを外していたので、片側だけ抜けていた
- **タグの名前と色を変える受け口が無かった。** 作るときにしか決められず、打ち間違えたタグは消して作り直すしかない。作り直すと付いていた友だちが全部外れる
- **本文の上余白のずれ。** 固定ヘッダーは 768px で消えるのに、余白を外すのは 1024px からだった
- **サイドバーのヘッダーに TEST が残っていた**（ログイン画面からは外したのに漏れていた）
- **開けなくなっていた作成フォーム 215行。** 「＋ タグを追加」をリンクに変えたとき、開く手段だけが無くなっていた

## 決めてほしいこと

### 1. 対応マークの「自動で切り替える」パネル

設計（3-3）は下段に「受信したとき → 未対応にする」のようなルールを並べ、
プルダウンで変えられる。いまは表の中のチェックボックスで同じことをしている。
**見た目を絵に寄せるか、いまの形でよいか。**

### 2. 「自動付与のもと」「自動付与ルール」

タグ一覧の列と KPI の4枚目。**きっかけが回答フォームとオートメーションの側に
あって、タグから引く口が無い。** 数えるには、どの設定がどのタグを付けるかを
横断で集める受け口が要る。列は置いてあるが中身は「—」。

### 3. 友だち詳細の4タブ（健康記録・リマインダ・アクション・注文）

タブは出したが、引く口が無いので中身は「何が足りないか」を書いてある。

- **健康記録** — 記録そのものの仕組みが無い。「ケアが必要な子」の帯（1-1）も同じ理由で保留中
- **リマインダ** — reminders はあるが「この友だちのぶん」を引く口が無い
- **アクション** — 操作の履歴を残す仕組みが無い
- **注文・定期便** — EC連携はあるが「この友だちのぶん」を引く口が無い

### 4. 「項目を追加する」の EC 連携

設計（3-2-1）は「EC連携から自動で入れる」を選ぶと、EC側の項目と突合キーを
選ばせる。列（`ec_field_path` / `ec_is_master`）はあるが、**作るときに指定する
受け口が無い。** いまは準備中として出している。

### 5. メールの相手と友だちの結びつけ

受信箱でメールを開くと、相手が友だちと結びつかない。**メールは差出人の
アドレスしか分からず、LINEの友だちはアドレスを持っていない。**
いまは「何ができるか」を案内するに留めている。

結びつけるなら、友だち情報欄にメールアドレスの項目を作って値を貯め、
そこから引く形になる。**どの項目を突合に使うかを決める必要がある。**

### 6. 保存した検索の KPI

設計（3-4）は「配信で使用中 6」「該当者が0人 2」「今月の呼び出し 48」を出す。
**使われ方を記録していないので出せない。** いまは「空き」「タグ数」で埋めている。

## 触るときの注意

- `data-design="..."` の印と `parts` に登録した語を消すとテストが落ちる。言い回しを変えるときは `design-structure.json` も一緒に直す
- **押せない状態にしてあるボタンを、押せるようにしない。** 受け口が無いからそうしてある。理由はすぐ横のコメントに書いてある
- マイグレーションを足したら `pnpm --filter @line-crm/db generate:bootstrap` を回す。`bootstrap.sql` が `schema.sql` + migrations と揃っていることをテストが見ている
- `packages/shared` の型を変えたら `pnpm --filter @line-crm/shared build`。web の型チェックはビルド済みを見る
