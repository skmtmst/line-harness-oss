# U1 送信の取り消しと「送る前の確かめ」（板 lKmZK ほか 6 か所）

- 書いた日：2026-10-16 03:20（日本時間・B-340）。担当：配信・受信箱・CRM・分析・連携・統括の系。
- 正本の決定：B-310（送った物の取り消し）・**Q-17（決定 B-337：送った後は取り消さない。できるのは送る前の取り消しと［訂正を送る］だけ。「元に戻す」はやめる）**・Q-38（送信予約は 1 分前まで取り消せる）・Q-52（全員への配信は止められないことを 1 行で書く）・B-160 ①（知らせの「元に戻す」はやめる）。

- 共通の契約：[索引 §5](../../v6-requirements/v6-requirements-master-index.md)・[共通基盤](../../v6-requirements/v6-shared-platform-requirements.md) §3 権限・§6-2 再試行・§8 代理ログイン・§11 応答コード・§15 進み。要件：[02 受信箱](../../v6-requirements/v6-02-inbox-requirements-draft.md) §9・§14、[06 一斉配信](../../v6-requirements/v6-06-broadcast-requirements-draft.md) §3-8。挙動の既存：[behavior/02](../behavior/02-inbox.md)・[behavior/06](../behavior/06-broadcast.md)。

## 1. 目的・効く目標・ライバルとの差

- 目的：「消えたつもりで届いている」を作らない。送ったら戻せないことを、送る前の 1 か所で必ず分かるようにし、間違えたときは［訂正を送る］で正しく直せるようにする。
- 効く目標（B-336）：② 直感的（どの画面でも同じ窓・同じ言葉で迷わない）・① 引き継ぎ（「送ったら戻せない」が仕様として 1 か所に書いてある）・④ 仕上げ（取り消せる振りをしない誠実な作り）。
- ライバルとの差：公式 LINE の管理画面は 1 対 1 で手で送った物を取り消せる（24 時間・日本は 2026-10 下旬から 1 時間）が、**Messaging API には送った物を取り消す口が無い**（受け取るのは相手の取り消し＝unsend イベントだけ）。Lステップ・エルメも API 経由のため取り消せない。musubo は「取り消せる振りをしない」＋「送る前の確かめが全部の送信でそろっている」＋「訂正の見本がある」で差を出す。LINE が口を出したらすぐ足す（§6 の決定 4）。

### 2-2. 共通の「送る前の確かめ」窓（部品 1 つ。名前の案：`SendConfirmDialog`）

- 置き場：`apps/web/src/components/shared/`（共通部品）。中は共通の `ダイアログ/中`（Pencil q3DPdz）に入れる。6 か所は中身の差し替えだけで、窓の形・ボタンの位置・言葉は同じ。
- 中身（上から）：
  1. 題：「送る前の確かめ」（予約は「予約する前の確かめ」）。
  2. 送る相手：人数（太字）・除外の内訳（ブロック・止めている人・重複）。統括は「12 アカウント・合計 ○人」と店ごとの内訳（畳める）。
  3. 送る目的：取引（予約・注文の連絡）／お知らせ／宣伝 のどれか。宣伝なら「宣伝を止めている ○人には送りません」。
  4. 日時：「今すぐ」または「10/18（土）10:00」。夜の静かな時間（Q-11：既定 21〜8 時）にかかる宣伝は「8:00 に送ります」と出す。
  5. 本文の頭（1〜2 行）と吹き出しの数。送り手（G8）を使うときは名前とアイコン。
  6. 注意の帯（琥珀・隠せない）：「**送ったあとは取り消せません。** 間違いに気づいたら、送ったあとに［訂正を送る］で正しい内容を送れます。」全員への配信では「全員への配信は、送り始めると途中で止められません」（Q-52）を足す。
  7. 1,000 人以上（承認のある店）は主ボタンが［承認を依頼する］（B-14）。それ未満は［1,272 人に送る］／［10/18 10:00 に予約する］。数をボタンに入れる。
- ボタン：右下に主ボタン、左に［戻る］（副）。主ボタンは押したら即押せなくなる（二重押し防止）。窓の外を押しても閉じない（Esc は閉じる＝送らない）。
- 自動で答える版（y4nixm）：2 は「対象：これから届く質問すべて（この店）」、5 は「公開中の Q&A 18 件」、6 は「自動で送った答えは取り消せません。お金・予約の変更・苦情・個人情報の質問は人へ回します」。

### 2-3. 受信箱 1 対 1 の送信（lKmZK の直し）

- ［送る］を押したらすぐ LINE へ送る（待たせない。5 秒待つ・元に戻すはやめる＝Q-17）。
- 知らせ（トースト）：「送りました」だけ。押せる物を付けない。
- 送った吹き出しの「…」：［訂正を送る］［文をコピー］。［取り消す］は置かない。
- ［訂正を送る］：入力欄に見本の文が入り、元の文を引用で添える（送るのは人。自動で送らない）。見本：「先ほどのメッセージに誤りがありました。正しくは次のとおりです。〈ここに正しい内容〉」。見本は店ごとに直せる（設定 › 受信箱）。
- 送信予約（chats の schedule）：行に［予約を取り消す］。予約時刻の 1 分前を過ぎたら押せず「まもなく送ります。取り消せません」（Q-38）。
- 失敗した送信：吹き出しを失敗の形に戻し、理由と［もう一度送る］だけ（Q-17）。
- お客さまが取り消した（unsend）：今の作りどおり「お客さまが取り消しました」と残す（中身は見せない）。

### 2-4. 一斉配信・統括の一括配信・自動の送信

- 送る前：予約中・承認待ちは［予約を取り消す］［依頼を取り下げる］で止められる（今の作り）。
- 送った後：詳細の「…」に［訂正を送る］：同じ宛先（送れた人だけ）に送る新しい下書きを作り、本文に見本を入れる。全員への配信の訂正は「全員」へ。A/B は勝った案を送った人＋試しの人を宛先にする（案ごとに分けた訂正もできる）。
- 送信中：絞り込み・タグの配信は［未送信分を止める］（今の API）。全員への配信は止めるボタンを出さず 1 行（Q-52）。

### 2-5. 決めること・既定値

| 項目 | 既定値 | 決定 |
|---|---|---|
| 1 対 1 の送信に窓を出すか | 出さない（すぐ送る）。代わりに［訂正を送る］ | 決定：おすすめ（Q-17） |
| 一斉・一括・A/B の残り・ランクの知らせ・自動応答オン | 必ず共通の窓を通す | 決定：おすすめ（findings-D 横断） |
| 送信予約を取り消せる期限 | 予約時刻の 1 分前まで | Q-38 |
| 訂正の見本の文 | 上の文（店ごとに直せる） | 決定：おすすめ |
| 訂正の配信の宛先 | 元の配信で「送れた」人だけ | 決定：おすすめ |
| 訂正を送った記録 | 元の送信に「訂正を送った（日時・人）」の印 | 決定：おすすめ |

### 2-6. 権限

| 役割 | 1 対 1 送信・訂正 | 一斉の送る前の窓 | 予約の取り消し |
|---|---|---|---|
| オーナー・管理者 | できる | 開ける・送れる | できる |
| スタッフ（運用担当） | 見える会話だけ | 送る権限（`broadcast.send`）が無ければ窓の主ボタンを出さず「送るには権限が要ります（頼む先：管理者）」 | 自分が作った予約・見える会話の予約 |
| 閲覧のみ | 入力欄・「…」の［訂正を送る］を隠す。帯「閲覧のみで見ています」 | 窓を開くボタン自体を隠す | 隠す |
| 統括 | 統括の一括配信だけ（店の配信は店で） | 統括の窓 | 統括の予約だけ |
| 代理ログイン | 見るだけ。理由つき書き込みモードでもお客さまへの実送信は止める（Q-01）。［訂正を送る］も出さない | 窓の主ボタンを出さず「代理ログイン中は送れません」 | 取り消しは**できる**（送らない方向の操作なので許す・記録に理由） |

### 2-7. 状態と言葉

- 状態：送信前（窓を開いた）／送信中／送りました／送れませんでした／予約中／予約取消／承認待ち。
- 読み込み中：窓の人数は骨組みで出し、数が出るまで主ボタンは押せない。
- 失敗：人数が読めないとき「人数を数えられませんでした」［もう一度数える］。主ボタンは押せない。
- 期限切れ：予約時刻を過ぎた承認待ち・予約は「期限切れ」で自動では送らない（Q-16）。［日時を決め直す］。
- 使わない言葉：「元に戻す」「取り消せます」「送信を取り消し」（送った後の物に）。使う言葉：「送ったあとは取り消せません」「訂正を送る」「予約を取り消す」。

## 3. データと API の形（案・Codex）

- 表の追加は小さい：
  - 送った記録（今の `messages_log` 系）に欄「訂正の元 ID」（`correction_of_message_id`・任意）。訂正で送った物から元へ、元から「訂正あり」を引ける。
  - 一斉配信に欄「訂正の元の配信 ID」（`correction_of_broadcast_id`・任意）。
  - 店ごとの設定に「訂正の見本の文」（`inbox_correction_template`・任意・空なら既定）。
- 口：
  - `GET /api/broadcasts/:id/send-preview` → `{ recipients, excluded: {blocked, optedOut, duplicate}, purpose, scheduledAt, quietHoursShiftTo, needsApproval, firstText, sender }`。共通の窓の中身。統括は `GET /api/hq/broadcasts/:id/send-preview`（店ごと内訳つき）。
  - `POST /api/broadcasts/:id/correction` → 新しい下書き（宛先＝送れた人）`{ broadcastId }`。Idempotency-Key 必須。
  - `POST /api/chats/:id/messages` に `correctionOfMessageId`（任意）。`X-Line-Harness-Source: manual` を付ける（担当の 1 対 1 送信のため）。
  - `DELETE /api/chats/:id/scheduled/:scheduleId`（今ある）は「予約時刻 − 60 秒」を過ぎたら 409 `SCHEDULE_TOO_LATE`。
- 応答コード（共通 §11）：409 `SCHEDULE_TOO_LATE`・`BROADCAST_NOT_STOPPABLE`（今ある）・403 `IMPERSONATION_SEND_BLOCKED`。

## 5. 連携とエラーが出そうな所
