## 1. 目的・効く目標・ライバルとの差

- 目的：一斉配信の本文を 2 つ作り、一部の人に試して、**クリック・予約・購入**が多かった方を残りの人へ自動で送る。店が「どっちが効くか」を勘でなく数で決められる。
- 効く目標：③ 作り込める（改善の回し方を持てる）・② 直感的（作る手順の中で完結）・④ 仕上げ（結果が正直）。
- ライバルとの差：LINE 公式の A/B は 2024-10 に終了、Lステップ・エルメに無い。Klaviyo・Braze・KARTE にはあるが LINE ではない。musubo は ①開封（LINE では推定値でぶれる）でなくクリック・予約・購入で決める ②差が小さいときは「決められない」と正直に出し勝手に送らない ③承認は 1 回で試しと残りを両方通す。

### 2-4. 状態と言葉

- 配信の状態に「試し中」を足す：下書き → 承認待ち → 予約中 → **試し中（残り 2 時間 10 分）** → **勝ちが決まった（残りへ送信中）** → 送信済み／**決められない（選んでください）** → 送信済み・送らずに終えた・期限切れ。
- 詳細の札（n4kwM の「状態を分ける」）：「試し中」「選んでください」「残りへ送信中」「送信済み」を別の札にする（1 つの「送信中」にまとめない）。
- 空：結果の区画は試しを送るまで「まだ結果がありません（14:00 に決まります）」。
- 読み込み中：数は骨組み。
- 失敗：試しの送信が一部失敗しても結果は送れた人で数える。試しがほぼ失敗（送れた人が 1 案 50 人未満）なら「試しが送れなかったため決められません」。
- 未取得（共通 §9）：購入の数が EC から届かないときは「—（取得待ち）」。0 と出さない。
- 言葉：「A 案」「B 案」「試す」「残りの人」「勝ち」「決められない」。使わない：「バリアント」「有意差」「CVR」（「？」の中では「確からしさ」と説明）。

## 3. データと API の形（案・Codex）

- 表（マイグレーション・番号はオーナー承認）：
  - `broadcast_variants`：`id`・`broadcast_id`・`variant_key`（A/B）・`messages_json`・`version`・`created_at`。A は今の本文を写す（今の一斉配信は A だけの配信として読める）。
  - `broadcast_ab_tests`：`broadcast_id`（主キー）・`test_ratio_pct`・`metric`（click/booking/purchase）・`decide_after_minutes`・`undecided_policy`（stop/send_a）・`status`（testing/decided/undecided/finished/expired）・`winner`（A/B/null）・`decided_at`・`decided_by`（auto または スタッフ ID）・`remainder_scheduled_at`・`remainder_sent_at`・`stats_json`（判定した時の数の控え）。
  - 宛先の台帳（今の broadcast の宛先）に欄 `variant_key`（A/B/R＝残り）。
- 口：
  - `PUT /api/broadcasts/:id/ab-test`（設定・`expectedVersion`）・`DELETE /api/broadcasts/:id/ab-test`（下書きのときだけ）。
  - `PUT /api/broadcasts/:id/variants/:key`（本文）。
  - `GET /api/broadcasts/:id/ab-result` → `{ status, variants: [{key, sent, failed, clicks, clickRate, bookings, purchases, purchaseAmount}], winner, confidence, decideAt, remainder: {count, scheduledAt, sentAt} }`。
  - `POST /api/broadcasts/:id/ab-test/choose` `{ variant: 'A'|'B'|'none', confirmedRecipientCount }`（Idempotency-Key 必須・決められないときだけ）。
  - 定時の仕事（Worker の cron・毎分）：`decide_after` を過ぎた試しを判定 → 残りを予約 → 送る。判定は 1 回だけ（状態の条件付き更新で原子に）。
- 数え方：クリック＝musubo の計測リンク（今の URL の計測）で、試しを送ってから判定までに押した人数／送れた人数。予約＝配信→予約の集計（STYLE-PLAN A7）。購入＝EC のできごと（直接の購入・7 日）。

## 7. 実装の順番と分担

1. 最小：絞り込み・タグの配信で A/B（クリックで決める・決められないときは止めて知らせる・選ぶ）。API＝Codex（表 2 つ＋宛先の欄・口 4 本・cron の判定）。画面＝Claude（`v8/broadcasts` の ③④・`v8/broadcast-detail` の結果区画・U1 の窓を使う）。
