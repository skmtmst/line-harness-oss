## 1. 目的・効く目標・ライバルとの差

- 目的：Google マップ・検索の店の情報に「予約」ボタンを出し、そこからの予約を musubo の台帳に直接入れる（集客の入口）。
- 効く目標：③作り込み（載せるメニューを選べる）、①引き継ぎ（Google からの予約も同じ台帳・同じ札）。
- ライバル：TableCheck・Square・Boulevard・Fresha。LINE ツールには無い。媒体の在庫と二重になる → F-24 と同じ数え方で残りを合わせる。

## 3. データと API の形の案（審査の後に Codex が作る・マイグレーション）

- `google_reservation_settings`：`line_account_id`・`status`・`listed_menu_ids_json`・`last_feed_at`・`last_error_code`・`version`。
- `bookings` の経路に `google` を足し、`external_source_ref`（Google の予約 ID・一意）。
- 口：Google の決まりの在庫の送り出し（空きの batch を使う）と予約の受け口（作る・取消・変更・空きの確かめ）。受け口は Google の署名を確かめる。同じ Google の予約 ID は 1 件だけ（二重を防ぐ）。
- 管理の口：GET/PUT `/api/booking/admin/google-reservation`（載せるメニュー・止める、expectedVersion）・GET 成果（今月の件数）。

## 5. 連携とエラー

- Google（予約の受け口・送り出し、審査後）：署名の失敗は 401・反映しない。確認済みの一時失敗は共通 §6-2、結果不明は [段2 §4](../cleanup-stage2-contract.md#unknown-result) に従い照合する。
- Google カレンダー（B7）：空きと書き込みは B7 の決まりのまま。Google で予約の分も担当のカレンダーに書く。
- LINE：Google の予約者が友だちでなければ LINE は送らない（Google の確定メールに任せる）。

## 6. 決めていない所（B-337：おすすめで決定）

1. 先払い・カード登録・回数券専用・繰り返し・同伴のメニューは最初の版では載せない。**決定：おすすめ**

3. Google 経由の承認制・即時確定の扱い、Google に渡す個人情報の扱い。⚖ **仮・専門家に確かめる**（Google の決まりと個人情報の取り扱い。審査の時に決める）。
