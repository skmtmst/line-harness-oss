## 1. 目的・効く目標・ライバルとの差

- 目的：EC で カートに入れたのに買わなかった／商品を見たのに買わなかった／売り切れの商品が戻った 人に、決めた時間のあと LINE で 1 通だけ知らせる。
- 効く目標：③ 作り込める（EC スタイルの売上の柱）・② 直感的（3 行のオン・オフ）・④ 仕上げ（送りすぎない・買った人に送らない）。
- ライバルとの差：ソーシャルPLUS・CRM PLUS・ECAI ほか 7 社にある。musubo は ①送る直前に購入を確かめる（買った後の「お忘れですか」を出さない）②1 人 1 日 1 通・同じ商品は 30 日に 1 回 ③成果は musubo の配信→購入で数える（提供元の数字だけにしない）④予約・受信箱と同じ画面の中で完結。

### 2-4. 状態と言葉

- 行の状態：準備中（タグ未設置）／止めている／動いている／止まった（EC の受信が 6 時間無い・送信枠）。
- 空：送った 0 件「まだ送っていません」。値は「—」でなく 0（送れる状態で 0 件の時）。準備中の行の数は「—」。
- 失敗：EC から届かない「お店のサイトから 6 時間できごとが届いていません」（Q-35）と［つながりを確かめる］。
- 言葉：「カゴ落ち」（「？」で「カートに入れて買わなかった人」）・「閲覧落ち」・「再入荷」・「サイトに入れる読み込み」。**「計測のコード」「タグ」（HTML の意味）は使わない**（TSRlY の指摘。musubo の「タグ」と取り違えるため）。

## 3. データと API の形（案・Codex）

- 表（マイグレーション）：
  - `ec_behavior_events`：`id`・`account_id`・`ec_integration_id`・`ec_customer_id`・`friend_id`（結べた時）・`type`（cart_add/cart_remove/product_view/purchase/restock/restock_subscribe）・`product_id`・`product_snapshot_json`（名前・画像・値段・URL）・`occurred_at`・`received_at`・`dedupe_key`。保存は 90 日（⚖ 仮・専門家に確かめる。Q-05 と同じ扱い）。
  - `ec_auto_line_rules`：`account_id`・`kind`（cart/browse/restock）・`enabled`・`wait_minutes`・`messages_json`・`caps_json`・`version`・`updated_by`。
  - `ec_auto_line_sends`：`id`・`rule_kind`・`friend_id`・`product_id`・`trigger_event_id`・`scheduled_at`・`status`（scheduled/sent/skipped_purchased/skipped_opted_out/skipped_cap/skipped_late/failed）・`sent_at`・`line_message_id`・`converted_order_id`・`converted_amount`。
- 口：
  - 取り込み：`POST /api/ec/events`（EC-CUBE プラグイン・サイトのタグ。署名つき・1 分 600 回）・Shopify は今の Webhook の受け口に `checkouts/create`・`products/update`（在庫）を足す。
  - `GET /api/ec/auto-line/rules`・`PUT /api/ec/auto-line/rules/:kind`（`expectedVersion`）・`POST /api/ec/auto-line/rules/:kind/enable`（窓のあと・Idempotency-Key）。
  - `POST /api/ec/auto-line/rules/:kind/test`（自分のテストの友だちへ・見本の商品）。
  - `GET /api/ec/auto-line/stats?from&to`・`GET /api/ec/auto-line/sends?kind&status&cursor`。
  - 見回り（毎分）：予定の送信 → 直前に購入・同意・上限・夜・遅れを確かめる → 送る。送る物には manual を付けない。
