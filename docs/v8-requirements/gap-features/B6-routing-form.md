# B6 回答で予約先を振り分けるフォーム

- 作った日時：2026-10-16 03:58（日本時間）。担当：司令塔の作業役（予約・LIFF・運用者スマホの系）。
- 正本の順：B-306（「誰にするか」は割り当て）・B-308・B-337 → 要件 13 回答フォーム・`docs/v8-requirements/restaurant-fusion4-contract.md`（フォームの予約ブロック）→ この文書。
- 絵：B6-1（フォーム編集の振り分けの表）・B6-2（LIFF 答えから日時へ）。

## 1. 目的・効く目標・ライバルとの差

- 目的：面談・相談で「相談の内容・地域・予算」の答えに合わせて、合う担当とメニューへ自動で案内する。店が LINE で聞き直して手で予約を取る手間をなくす。
- 効く目標：②直感的（お客さまは選ばずに日時から始まる）、③作り込み（1 行 1 決まりの表）。
- ライバル：Calendly（上位プランのみ・条件式が難しい）・TimeRex・jicoo。LINE ツールには無い。musubo は**表の 1 行 1 決まり・上から順に当てる・最後の行（どれにも当たらない）は必須**。jicoo と同じく「行き先（メニュー・担当の組）」と「誰にするか（B-306）」を分ける。

### 2-3. 権限

フォームの編集権限（要件 13）に従う：オーナー・管理者・フォームの編集権限のあるスタッフ。閲覧のみ＝表は見える・編集と「試しに答える」は出す（試しは保存しない）→**決定：おすすめ**＝試しは閲覧のみにも出す（何も変えないため）。統括＝ひな形のフォームに振り分けを入れて配れる（行き先のメニューは配り先の店で選び直す＝配る前の確認に「行き先を選び直す行 N」）。代理ログイン＝見るだけ。

### 2-4. 状態と言葉

- 編集：行 0（「どれにも当たらない」の行だけ）／行き先が使えない行（金の札）／予約ブロックが無いフォーム（区画を出さない）。
- 試しに答える：どの行にも当たらない（最後の行が光る）。
- LIFF：行き先が決まった（上の案内文）／行き先に空きが 0（「ご案内できる日時がありません」と［お問い合わせ］）。
- 言葉：「答えで行き先を分ける」「もし〜なら」「どれにも当たらないとき」「試しに答えてみる」「行き先」。「ルーティング」「分岐」は使わない。

## 3. データと API の形の案（Codex が作る）

- **表の変更なし**で作る（決定：おすすめ）：フォームの版の JSON（予約ブロックの設定）に `routing:{enabled, rules:[{conditions:[{questionId, op:'is'|'in'|'between', value}], target:{menuId, staffGroupId?, staffId?, meetingMode?}}], fallback:{...}}` を持つ。予約に `routing_rule_index` を残す欄だけ足す（小さいマイグレーション）。

| 道 | 入力 | 出力 | 権限 |
|---|---|---|---|
| 既存のフォームの版の保存（拡張） | `routing` | 保存の時に行き先の存在・fallback の必須・自由記述の不可を確かめる（400 `routing_invalid` と行番号） | フォームの編集 |
| POST `/api/forms/:id/routing/preview` | `answers` | `{matchedIndex, target, usable}`（保存しない） | フォームを見る |
| POST `/api/liff/forms/:id/routing/resolve` | `answers`（回答の送信と同じ本人確認） | `{target, matchedIndex}`。使えない行き先は fallback | 本人 |
| 既存の予約の作成（拡張） | `routingToken`（resolve の結果を署名した物） | 予約に行き先と行番号。お客さまが行き先を書き換えられない | 本人 |

## 5. 連携とエラー

- フォームの回答と予約は別の書き込み（回答が保存されてから resolve）。予約まで進まなかった人は「予約まで進まなかった回答」として受信箱・フォームの結果に残る（今の仕組み）。
- B7（会い方）：行き先にオンライン／対面を持てる。会議の URL は B7 の決まりで作る。
