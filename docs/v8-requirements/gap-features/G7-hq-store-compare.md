## 1. 目的・効く目標・ライバルとの差

- 目的：本部が全店の主な数を 1 枚の表で比べ、遅れている店を見つけてその店の画面へすぐ行ける。
- 効く目標：① 引き継ぎ（買った人が全店の様子を一目で）・② 直感的（平均との差が色で分かる）・④ 仕上げ。
- ライバルとの差：多店舗向けの各社にあるが、「51 店のアカウントが並ぶだけ」の不満がある。musubo は ①主な数 7 つだけ ②平均との差の札・下位から並べられる ③業種で使わない数は「—」④押すとその店に切り替えて開く。統括には今、分析が 1 枚も無い。

### 2-5. 状態と言葉

- 空：店が 1 つだけ「比べるには 2 つ以上の店が要ります」と、その店の数だけ。
- 読み込み中：骨組みの行。
- 失敗：「読み込めませんでした」［もう一度試す］。
- 作り直し中：今朝の控えの失敗は「10/15 4:30 時点（今朝の集計は失敗しました）」。
- 未取得：店の LINE の数（ブロックなど）が取れなかった日は「—（取得待ち）」。0 と出さない（共通 §9）。
- 言葉：「店の比較」「平均との差」「前の期間」「店の組」。使わない：「KPI」「ベンチマーク」。

## 3. データと API の形（案・Codex）

- 表（マイグレーション。重いので日ごとの控えを作る）：
  - `hq_store_daily_metrics`：`account_id`・`date`（日本時間の日）・`friends_added`・`friends_blocked`・`friends_at_start`・`broadcast_recipients`・`broadcast_clicks`・`bookings`・`visits`・`no_shows`・`first_response_median_minutes`・`first_response_count`・`computed_at`。90 日分を置く（それより前は月ごと）。
- 口：
  - `GET /api/hq/store-comparison?from&to&compare=previous|average&poolId&sort&order&page&pageSize` → `{ rows: [{accountId, name, style, metrics: {key: {value, diff, unit, available}}}], average, total, computedAt }`。
  - `GET /api/hq/store-comparison/:accountId?from&to` → 推移・最近の配信 3 件・対応が要る物（B-312 の口を使う）。
  - `POST /api/hq/store-comparison/export`（CSV・裏の仕事・できたら知らせ）。
  - 毎日 4:30 の仕事：前日の控えを店ごとに作る（店ごとに分けて進め、1 店の失敗で全体を止めない）。
  - 権限：統括の権限の口（今ある `hq` の authority）で見える店に絞る。
