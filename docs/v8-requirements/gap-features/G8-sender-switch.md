## 1. 目的・効く目標・ライバルとの差

- 目的：LINE のメッセージの上に出る名前とアイコンを「担当の顔」や「○○店 予約係」に切り替え、お客さまが誰と話しているか分かるようにする（LINE Messaging API の `sender`）。
- 効く目標：③ 作り込める・② 直感的（入力欄の左で選ぶだけ）・④ 仕上げ（見本に名前とアイコンが出る）。
- ライバルとの差：Lステップ・Liny・エルメにある（Lステップは上位プランだけ）。musubo は全部の店で使え、ログインユーザーごとに「自分の送り手」を 1 つ持てる。

## 2. 要件

### 2-1. 画面（板 ID）

| 板 | 場所 | 足す物 |

### 2-2. 決めること・既定値

| 項目 | 既定値 | 決定 |
|---|---|---|
| 名前の文字数 | 20 字まで（LINE の上限） | LINE の仕様 |
| 名前に使えない物 | 「LINE」「ライン」を含む・空白だけ・絵文字だけ（LINE が断る物を先に止める） | 決定：おすすめ |
| アイコン | 登録メディアの画像（PNG・JPEG、1MB まで、正方形に切る、https の URL）。無しも可（アカウントのアイコンのまま） | 決定：おすすめ |
| 送り手の数 | 店ごとに 20 まで | 決定：おすすめ |
| 自分の送り手 | ログインユーザーごとに 1 つ（初期は作らない。自分のメニューから作る）。受信箱の既定はこれ。無ければ送り手なし | 決定：おすすめ |
| 使える人 | 全員／本人だけ（自分の送り手は本人だけで固定） | 決定：おすすめ |
| どこで使えるか | 受信箱の 1 対 1・一斉配信・テンプレート（テンプレートの送り手は送る時に上書きできる）。シナリオ・自動応答は次の段 | 決定：おすすめ |
| 送り手を消した時 | 消さずに「使わない」にする（新しく選べない）。予約中の配信・送信予約は控えた名前・アイコンで送る | 決定：おすすめ |
| 担当が退職 | その人の自分の送り手は使わないにする。予約は送り主＝アカウント名に戻して送る（Q-38） | Q-38 |
| 自動の送信 | 予約の知らせ・リマインド・自動応答は送り手なし（アカウントの名前） | 決定：おすすめ |

### 2-4. 状態と言葉

- 空：「まだ送り手がありません。担当の名前と顔で送ると、お客さまが誰と話しているか分かります」［送り手を追加］。
- 失敗：アイコンの画像が LINE に断られた時「この画像は使えません（1MB まで・PNG か JPEG）」。
- 言葉：「送り手」「自分の送り手」「使える人」「使わない」。使わない：「sender」「なりすまし」（「？」の中では「他の人・他社に見える名前」）。

## 3. データと API の形（案・Codex）

- 表（マイグレーション・小）：
  - `line_senders`：`id`・`account_id`・`name`・`icon_media_id`・`icon_url`（配る用の https）・`visibility`（all/owner_only）・`owner_staff_id`（自分の送り手）・`status`（active/inactive）・`version`・`created_by`・`updated_at`。
  - 送った記録（`messages_log` 系）・一斉配信・チャットの送信予約・テンプレートに `sender_id` と `sender_snapshot_json`（送った時の名前・アイコン URL）。
- 口：
  - `GET/POST /api/line-accounts/:id/senders`・`PUT/DELETE /api/line-accounts/:id/senders/:senderId`（DELETE は inactive にする）。`expectedVersion`。
  - `GET /api/me/sender`・`PUT /api/me/sender`。
  - 送信の口（`POST /api/chats/:id/messages`・一斉配信・テンプレート）に `senderId`（任意）。Worker は LINE の各メッセージに `sender: {name, iconUrl}` を付ける（配信の仕組みは変えない）。
  - 検査：名前 20 字・禁止の語・アイコン 1MB・https。
