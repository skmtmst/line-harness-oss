# B2 回数券・月謝（サブスク）と予約の連動

- 作った日時：2026-10-16 03:30（日本時間）。担当：司令塔の作業役（予約・LIFF・運用者スマホの系）。
- 正本の順：B-308 追記（**回数券・月謝は店が手で入れられる。オンライン購入はそのあと。LIFF でお客さまが残りを見られる**）・追記 2 ③・B-315・B-337（Q-22）→ API の契約 `~/lh-work/design/v8/review/API-CONTRACT-3.md` §2（手で入れる回数券・月謝。作り済み）→ [behavior/style-and-money.md](../behavior/style-and-money.md) SM-80〜SM-89 → この文書。
- ここで足すのは、**①券の「種類（プラン）」を店が登録して一覧で持つ ②予約の確認で券を選ぶ LIFF の画面 ③期限・残り・引き落としの失敗の見張り ④（次の段）Stripe でのオンライン購入と月謝の定期課金**。手で 1 人に付与する口（SM-80〜89）はもうあるので作り直さない。
- 絵：B2-1・B2-2・B2-3、点検 C の pjLdP・w1ks4・nrtRJ・uGfHo・vWHHO・fVvmX。

## 1. 目的・効く目標・ライバルとの差

- 目的：教室・整体・ジム・サロンが「回数券・月謝を紙と表計算で管理し、予約は別のツール」をやめられるようにする。残りが分からない電話を減らす。
- 効く目標：②直感的（お客さまは LIFF で残りを見て、予約の確認で選ぶだけ）、③作り込み（店ごとの券の種類・使えるメニュー・期限）、①引き継ぎ（付与・調整・取消の理由と担当が全部履歴に残る）。
- ライバル：STORES 予約・RESERVA・hacomono・Mindbody ほか 8 社。LINE ツールには無い。SelectType の「回数券が無いと予約できない」は初めての人を逃す → musubo の既定は**券でも普通の支払いでも予約できる**。hacomono は月謝の引き落とし失敗が店に見えにくい → 数の帯に「引き落としの失敗」と［支払いのリンクを送る］。

## 3. データと API の形の案（Codex が作る）

今ある：表 `booking_entitlements`（手で付与・残り・月謝の月の枠・履歴・トリガーで減算）と口（API-CONTRACT-3 §2）。足す（マイグレーション・番号は承認で）：

- `booking_pass_plans`：`id`・`line_account_id`・`kind`（ticket／monthly）・`name`・`price`・`count`（回数券）・`monthly_limit`（null＝上限なし）・`valid_days`・`target_scope_json`（menu／course／event の ID の一覧、空＝全部）・`allow_without_pass`・`makeup_rule_json`（B3）・`status`（draft／on_sale／stopped）・`sort_order`・`version`・`created_by`・`updated_at`。
- `booking_entitlements` に `plan_id`（null 可＝種類なしの付与）・`source`（manual／online）・`stripe_subscription_id`・`billing_status`（ok／grace／stopped）・`grace_until` を足す。
- `booking_entitlement_notices`：残り 1・期限 14 日前・引き落としの失敗の知らせの記録（同じ物を二重に送らない一意キー）。

| 道 | 入力 | 出力 | 権限 |
|---|---|---|---|
| GET `/api/booking/admin/pass-plans` | account_id・status・q・limit・offset | `{items, total, summary:{onSale, holders, expiringIn30d, billingFailed}}` | owner/admin/staff |
| POST/PUT `/api/booking/admin/pass-plans(/:id)` | 本文＋`expectedVersion`、POST は Idempotency-Key | 種類 | owner/admin |
| POST `/api/booking/admin/pass-plans/:id/stop` | `{}` | 状態 stopped（持っている人には影響しない） | owner/admin |
| GET `/api/booking/admin/pass-plans/:id/holders` | limit・offset | 持っている人の一覧（友だち・残り・期限） | owner/admin/staff |
| 既存 POST `/api/booking/admin/entitlements`（拡張） | `planId` を足せる（無ければ今のまま） | 券 | 今のまま |
| 既存 GET `/api/liff/booking/entitlements` | 今のまま | `usable` が false の時に `unusableReason`（menu_out_of_scope／expired／month_used_up／billing_stopped）を足す | 本人 |
| 既存の取消（拡張） | — | 期限内の取消で 1 回戻す（同じ batch・履歴に「取消で戻した」） | — |
| （次の段）POST `/api/liff/booking/pass-plans/:id/checkout` | Idempotency-Key | Stripe Checkout の URL | 本人 |
| （次の段）Stripe Webhook（拡張） | `checkout.session.completed`・`invoice.payment_failed`・`invoice.paid`・`customer.subscription.deleted` | 券の作成・猶予・止める・再開 | 署名を確かめる |

## 6. 決めていない所（B-337：おすすめで決定）

1. 同じメニューに使える券が複数のときは期限が近い方。**決定：おすすめ**
2. 残り 1・期限 14 日前の知らせは取引の知らせとして送る（初期オフ）。**決定：おすすめ**
3. 月謝の引き落とし失敗は 7 日の猶予。**決定：おすすめ**
4. 券の有効期限・返金（未使用の回数の払い戻し）の扱い。⚖ **仮・専門家に確かめる**（前払式支払手段に当たるかで届け出・払い戻しの決まりが変わる。最初の版は「払い戻しは店が手で全額返金できる」だけ・6 か月を超える期限の券を売るときは注意の文）。
5. 月謝の解約の受付（LIFF で解約できるか）。**決定：おすすめ**＝次の段で LIFF の［解約する］（次の更新日で止まる）。最初の版は店が手で止める。

## 7. 実装の順番と分担

1. **最小**（今の口の上）：回数券・月謝タブ（種類の一覧・作る・販売をやめる）、付与で種類を選ぶ、LIFF ⑤ で券を選ぶ・使えない理由、取消で 1 回戻す（Q-22）。
2. 次：残り・期限の知らせ、数の帯、持っている人の一覧。
3. 次：オンライン購入（Checkout）→ 月謝の定期課金と引き落とし失敗。
- 画面（Claude）：タブ・作る画面・友だち詳細の段・LIFF ①⑤ の印と段・マイページ。
- API（Codex）：種類の表と口、`entitlements` の拡張、取消で戻す、知らせの定時、（次の段）Stripe。
