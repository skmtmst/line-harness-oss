## 1. 目的・効く目標・ライバルとの差

- 目的：無断・直前の取消で空いた枠の損を店が取り戻せるようにする。デポジット（一部前払い）で、全額前払いほど重くなく無断を減らす。
- 効く目標（B-336）：②直感的（お金の決まりを予約の確認・前日・取消の前の 3 か所で同じ文で見せる）、③作り込み（店ごとに段・条件を決められる）、①引き継ぎ（請求の記録と理由が残り、誰が見ても経緯が分かる）。
- ライバルとの差：Square・TableCheck・OpenTable・Fresha・Airリザーブにある。LINE ツール（Lステップ・エルメ・Liny）には無い。Square・Fresha は「知らないうちに請求された」の揉めごとが多い → musubo は**店が［請求する］を押すのが既定**、自動の請求は設定でオンにしたときだけ、請求の前に LINE で知らせる。TableCheck の与信（仮押さえ）は数日で切れる → musubo は与信を使わず**カード登録（Stripe の SetupIntent）＋後で請求**。

### 2-5. 言葉（そろえる）

- 「キャンセル料」「デポジット（一部前払い）」「カードを登録」「請求する」「請求しない」「返金する」。「与信」「オーソリ」「SetupIntent」は画面に出さない。
- LIFF の同意：「キャンセル料の決まりを確認しました」。**初めはチェックなし**。押すまで主ボタンは押せない（点検 C 上位 3：kwC8E は初めからチェック済み→直す）。
- 主ボタン：カード登録＝「カードを登録して予約する」、デポジット＝「¥2,520 を払って予約する」、両方なし＝「予約する」。
- 料金の行：「料金 ¥8,400／今お支払い（デポジット）¥2,520／お店で ¥5,880」。点検 C の fVvmX（料金 ¥8,400 なのに「お店で払う ¥2,000」）のような合わない数字は出さない＝画面は API の計算結果だけを出す。

## 3. データと API の形の案（Codex が作る）

マイグレーションは要る（番号は書かない。番号ごとにオーナーの承認）。B-305 追記の「お客さまが選ぶ」と同じ束にするのがよい。

**表（案）**

- `booking_cancellation_policies`：`line_account_id`・`scope`（account／menu／course／event）・`scope_id`・`enabled`・`tiers_json`（`[{beforeHours:24,percent:0},{beforeHours:0,percent:50}]`）・`no_show_percent`・`card_required_for`（all／no_show_flagged／conditions）・`conditions_json`・`charge_mode`（manual／auto）・`version`・`updated_by`・`updated_at`。
- `booking_deposit_rules`：`scope`・`scope_id`・`kind`（none／amount／percent）・`value`・`conditions_json`・`version`。
- `booking_payment_methods`：`friend_id`・`line_account_id`・`stripe_customer_id`・`stripe_payment_method_id`・`card_brand`・`card_last4`・`exp_month`・`exp_year`・`created_at`・`detached_at`。カード番号は持たない。
- `booking_charges`：`id`・`booking_id`・`kind`（deposit／cancellation_fee／no_show_fee）・`amount`・`policy_snapshot_json`（予約の時点の段を写す）・`status`（pending／scheduled／succeeded／failed／waived／refunded）・`scheduled_at`・`reason`・`actor_staff_id`・`stripe_payment_intent_id`・`idempotency_key`（一意）・`version`・`created_at`・`updated_at`。
- 予約の作成時に `policy_snapshot_json` を予約に写す（後で設定を変えても、その予約は予約時の決まりで計算する）。

**口（案）**

| 道 | 入力 | 出力 | 権限 |
|---|---|---|---|
| GET/PUT `/api/booking/admin/cancellation-policy` | account_id、PUT は本文＋`expectedVersion` | 店の既定 | GET owner/admin/staff、PUT owner/admin |
| GET/PUT/DELETE `/api/booking/admin/menus/:id/cancellation-policy`（コース・クラスも同形） | 上と同じ | 上書き（DELETE で既定へ） | 同上 |
| GET/PUT `/api/booking/admin/deposit-rules`・`/menus/:id/deposit` | 同上 | | 同上 |

| POST `/api/booking/admin/charges/:id/refund` | `{reason}`、Idempotency-Key | 返金済み（全額だけ・Q-20） | owner/admin |

| Worker の定時（5 分おき） | — | `charge_mode=auto` の請求待ちを請求。1 時間前の LINE の知らせを先に送る | — |

## 5. 連携とエラーが出そうな所

| 相手 | 起きうること | 画面 | 復旧 |
|---|---|---|---|
| Stripe（Setup・Checkout） | お客さまが戻らない・期限切れ | 予約は未確定、LIFF で［もう一度］ | 同じ申込は同じ URL |
| Stripe（請求） | カード拒否・3D セキュアが要る（オフセッションで通らない） | 「カードの失敗」の札 | ［支払いのリンクを送る］（Q-25：店が押す・manual の印） |
| Stripe（Webhook） | 遅れ・重複・順番の入れ替え | 通知の記録（SM-67〜71） | 再読込。請求の行は Webhook と API の結果の新しい方 |
| LINE | 請求前の知らせが届かない（ブロック） | 請求の行に「知らせ：届かない」 | 自動の請求は止め「店が押す」に落とす（知らせずに請求しない）。**決定：おすすめ** |
| 法律 | 料金の割合 | — | ⚖ 仮・専門家に確かめる（初期値・上限の注意文） |

## 6. 決めていない所（B-337：おすすめで決定）

1. 段の物差しは「開始の N 時間前」1 つ（時刻の物差しは使わない）。**決定：おすすめ**
2. スタッフは請求できる・返金はできない。**決定：おすすめ**
3. 自動の請求は確定から 24 時間後・1 時間前に知らせる。知らせが届かない人は自動で請求しない。**決定：おすすめ**
4. デポジットはキャンセル料の上限として扱い、一部返金は次の段階（Q-20）。**決定：おすすめ**
5. キャンセル料の初期値と上限。⚖ **仮・専門家に確かめる**（見本 24 時間前まで無料・以降 50%・無断 100%。100% を超える値は保存しない）。
6. 領収書・インボイスの記載（キャンセル料は不課税の扱いになりうる）。⚖ **仮・専門家に確かめる**（最初の版は「キャンセル料」と金額だけの控え）。

## 7. 実装の順番と分担

1. **最小**：店の既定のキャンセル料（段・店が押す）＋カード登録（全員）＋詳細パネルの［請求する］［請求しない］＋LIFF ⑤ の決まりの行と同意＋履歴の取消の前の金額。返金は既存の口。
2. 次：メニュー・コース・クラスの上書き、デポジット（金額／％・条件）。
3. 次：自動の請求（定時・前の知らせ）、無断の印の人だけカード登録、ダッシュボード・分析の「キャンセル料」の数（B-305 追記 2 の別の数）。
- 画面（Claude）：お支払いタブの区画・メニューの段・詳細パネルの段と確かめの窓・LIFF ⑤／履歴。予約設定のタブ列を 8 つにそろえる。
- API（Codex）：表・口・定時・Stripe の Setup と請求・Webhook の正規化・計算の関数（LIFF・リマインド・取消で同じ関数）。
