## 1. 目的・効く目標・ライバルとの差

- 目的：①担当が自分のカレンダーに入れた私用・社外の予定で、予約が二重にならない ②予約が決まったら担当のカレンダーに予定が入り、変更・取消も勝手に直る ③オンラインの面談・レッスンの URL を毎回手で作って送る手間をなくす。
- 効く目標：②直感的（担当は自分のカレンダーを使うだけで空きが合う）、③作り込み（URL を手で入れる店・自動で作る店の両方）、①引き継ぎ（つなぎの状態と最後に合わせた時刻が 1 画面で分かる）。
- ライバル：Calendly・TimeRex・jicoo（面談の中心）、Lステップ・エルメは Google カレンダーと Meet まで。Outlook・Zoom・Teams まで揃うのは日程調整ツールだけ。よくある事故＝日時を変えたのに古い URL がリマインドで届く → 変更で作り直し、リマインドは**送る時点の URL** を差し込む。外のカレンダーが読めない時に二重予約 → 読めない間はその担当の枠を閉じる。

## 2. 要件 A：外部カレンダーの同期（B-341 (1)・補足 (1)・追記 2）

### A-0. 同期するかしないかの選び方（B-341 追記 2）

- スイッチは **2 段 × 2 方向**。どれも**初期値はオフ**。
  - 段：**店全体**（予約設定 › 担当スタッフの上の区画「カレンダーとの同期」）と**担当者ごと**（担当の編集の「つなぐ先」の行）。
  - 方向：**読み込み**（カレンダーの予定 → 空き枠から外す）と**書き込み**（予約 → カレンダーに予定を書く）。別々にオン・オフできる。
- 効き方：担当の実際の状態 ＝ 店全体のその方向 **かつ** 担当のその方向。店全体がオフなら担当のスイッチは灰色の文で「店全体がオフのため止まっています」と出す（押せない形のトグルは置かず、文で状態だけ出す）。
- 担当のスイッチをオンにできるのは、その担当のカレンダーが「つながっている」ときだけ。つないでいない担当はスイッチの代わりに［つなぐ］。
- 読み込みがオフの担当は**勤務の枠だけ**で空きを作る（A-1 の「つないでいない担当」と同じ）。読み込みオフのときは fail-closed（読めないと閉じる）も効かない。
- 書き込みがオフの担当は、予約が確定してもカレンダーに書かない。A-3 の「書かない」はこのスイッチのこと。
- **オフにしても予約はそのまま残す**（取消・日時の変更・担当の変更は起きない）。
- **それまでに書いた予定を消すか**は、書き込みをオフにするときの確かめの窓で選ぶ：
  - 「カレンダーの予定は残す」（**初めに選ばれている**）／「これから先の予約の予定を消す」（今日より後の予定だけ。過去の予定は消さない）。
  - 窓に件数を出す：「〇〇さんのカレンダーに書いた、これから先の予定 12 件」。店全体をオフにするときは担当ごとの件数の合計。
  - 消す作業は順番待ちで行い、消せなかった予定は件数と［もう一度消す］を出す。消している間にオンに戻したら、残りの消去は止める。
- 読み込みをオフにするときの窓：「オフにすると、〇〇さんの空きはカレンダーを見ずに勤務の枠だけになります。カレンダーの予定と予約が重なることがあります」と［オフにする］［やめる］。
- オンに戻したとき：読み込みは次の定時（5 分以内）から空きに効く（それまでは控えが無いので、確定の直前の確かめだけで守る）。書き込みは**オンにした後に確定・変更した予約から**書く。オフの間に確定した予約をまとめて書くかは窓で選ぶ（「これから先の予約 N 件も書く」・初めは選ばれていない）。
- つなぎ直し（権限切れのあと）：スイッチの値は変えない。つながった時点で、オンの方向がそのまま動き出す。書き込みがオンなら、切れている間に書けなかった予約（順番待ちの失敗）を書き直す。
- 権限：店全体のスイッチはオーナー・管理者。担当のスイッチは本人とオーナー・管理者。スタッフはほかの担当のスイッチを見るだけ。閲覧のみ・代理ログインは見るだけ（ボタン・トグルは隠す）。**決定：おすすめ**（代理ログインは変えない）。
- 記録：スイッチを変えた人・時刻・前後の値・消すを選んだかを履歴に残す。

### A-1. 担当ごとの空き枠の作り方

```
予約で選べる時間 ＝ 担当の勤務の枠（予約設定 › 担当スタッフ・日ごとの休み・短縮）
                 − 担当のカレンダーの予定（つないだカレンダーの「予定あり」の時間）
                 − musubo の予約（申込中・確定）
                 − 資源・定員の不足（要件 28 §7）
                 ＋ 予約のルール（何分前まで・何日先まで・前後の空き時間）
```

- **つないでいない担当は勤務の枠だけ**で空きを作る（今のまま）。
- カレンダーからは**「予定あり（busy）」の時間だけ**を読む。予定の題名・参加者・本文は読まない・残さない（要件 28 §6-2）。終日の予定・「予定なし（free）」にした予定は塞がない。
- musubo が書いた予約の予定は、読み戻した時に二重に数えない（予約そのものとして既に塞いでいる）。
- 担当 1 人に読むカレンダーを 1 つ以上（例：仕事・私用）。書くカレンダーは 1 つ（A-3）。

### A-2. 反映の速さ（**決定：おすすめ**）

| 時 | すること |
|---|---|
| 5 分おき（Worker の定時） | つないだ担当の、今日から「何日先まで受け付けるか」までの「予定あり」を読み直して控える（担当ごとに最後に読めた時刻を残す） |
| LIFF・管理画面で空きを出す時 | 控えを使う。控えが 15 分より古い担当は、その場で読み直す。読めなければその担当の枠は閉じる |
| **予約を確定する直前** | その担当のその時間だけ、もう一度カレンダーを読む。予定が入っていたら確定しない（「その間に埋まりました」と近い空き 3 つ・Q-56） |
| 次の段 | Google の変更の通知（push の watch）・Microsoft の変更の通知で、予定が増えた・消えたをすぐ反映（定時の読み直しは残す） |

- 目安：予定を入れて**最大 5 分**で空きから消える。消した予定も**最大 5 分**で空きに戻る。確定の直前の確かめがあるので、5 分の間でも二重予約は作らない。

### A-3. どのカレンダーに書くか（選び方）

| 選び方 | 既定 | 備考 |
|---|---|---|
| 担当のカレンダー（読むカレンダーの中から 1 つ） | **これが既定**（つないだ最初のカレンダー） | 担当の編集の引き出しで変えられる |
| 店の共有カレンダー（全員の予約を 1 つに） | 任意。店の設定で「全部の予約をこのカレンダーにも書く」 | 担当のカレンダーと両方に書ける |
| 書かない | 書き込みのスイッチがオフ（**初期値**・A-0） | 読み込みだけオンにすれば二重予約は防げるが、担当の予定には出ない |

- 書く時：**予約が確定した時**（申込中・承認待ちは書かない。musubo の中で枠は塞いでいる）。日時・担当の変更で書き直す。取消・店が断った時は予定を消す。来店・無断の印は書き換えない。
- 担当が変わった時：前の担当のカレンダーから消し、新しい担当のカレンダーに書く。

### A-4. 予定に書く中身（お客さまの個人情報）

| 欄 | 書く物（既定） | 書かない物 |
|---|---|---|
| 題名 | 「カット 60 分｜山田さま」（**名前とメニューだけ**） | 電話・メール・LINE の名前の写真・住所・フォームの答え・メモ・タグ・支払い |
| 本文 | 「musubo の予約：<管理画面の予約のリンク>（ログインが要る）」とオンラインなら会議の URL | 同上 |
| 場所 | 対面なら店の場所・部屋、オンラインなら会議の URL | |
| 参加者 | 入れない（お客さまに Google の招待が飛ばないように） | |

- 店の設定で「名前も書かない（題名は『カット 60 分｜予約』）」を選べる。
- **決定：おすすめ**（名前とメニューだけ）。⚖ **仮・専門家に確かめる**（外のカレンダーへ名前を写すことの個人情報の扱い・プライバシーポリシーへの書き方）。

### A-5. つなぎ方

- Google：今の「共有するメールアドレス」方式（担当が自分のカレンダーを musubo の共有先に「予定の変更」権限で共有し、カレンダー ID を入れる）を残す。Meet を自動で作る（B-2）には担当の Google アカウントでのつなぎ（OAuth）が要る見込み → Meet の自動発行をオンにする時だけ OAuth でつなぐ。⚖ ではなく技術の仮：Codex が試験のアカウントで確かめる。
- Outlook（Microsoft 365）：Microsoft のつなぎ（OAuth・予定の読み書きの権限だけ）。
- 画面の言葉：「つなぐ」「つながっている」「切れています」「最後に合わせた時刻」「共有するメールアドレス」「カレンダー ID」「確認結果」（要件 28 の言い換え）。「結んだ」は使わず「設定済み」（X81Ro7）。「サービスアカウント」「OAuth」「トークン」は出さない。

### A-6. 同期の失敗と復旧

| 失敗 | 見分け | すること | 画面・知らせ | 復旧 |
|---|---|---|---|---|
| 権限切れ（共有を外された・つなぎを取り消された・パスワード変更で切れた） | 401／403・`invalid_grant` | **その担当の新しい枠を閉じる**（fail-closed）。既にある予約はそのまま | 担当の行に赤の札「切れています」と帯「〇〇さんの Google カレンダーが切れています。この人の空きは閉じています」。運用者の知らせ（`booking_sync_notices` の calendar_disconnected・G4 のプッシュ）。統括の「対応が要るもの」（B-312）に件数 | 担当が［つなぎ直す］。つながったら次の定時で枠が開く |
| 時間切れ・Google／Microsoft の不調（5xx・429・通信断） | 時間切れ・5xx・429 | 読み：3 回まで再試行（共通 §6-2）。だめならその担当の枠を閉じる（控えが 15 分以内なら控えで出してよいが、確定の直前の確かめが読めなければ確定しない） | 担当の行に金の札「読めていません（最後に読めた 10:05）」。30 分続いたら運用者へ知らせ | 自動で直る。直らなければ［もう一度読む］ |
| 書けない（予定の作成・書き直し・削除の失敗） | 上と同じ | **予約は成立させる**。書く作業を順番待ちに入れ、3 回まで再試行 | 予約の詳細パネルに「カレンダーに書けていません」と［もう一度書く］。要対応「カレンダーに書けていない予約 N」 | ［もう一度書く］。権限切れなら先につなぎ直す |
| 二重（同じ予約の予定が 2 つできる） | — | 予定の ID を予約の ID から決めて作る（同じ予約は同じ ID）。「もうある」と返ったら書き直しとして扱う | 出さない | 起きない作り。古い控えから 2 つ見つかったら、予約の ID を持つ方を残し、もう一方を消す（定時の見回り） |
| musubo 以外の人が予定を消した・動かした | 予約の予定が見つからない／日時が違う | **予約は変えない**（カレンダーから予約を動かさない） | 予約の詳細パネルに金の札「カレンダーの予定が消されています／日時が違います」と［書き直す］ | ［書き直す］で予約の内容に戻す |
| 担当がカレンダーを別の物に替えた | — | 新しいカレンダーへ書く。前の予定は消す（読めれば） | — | — |

## 3. 要件 B：Web 会議の URL（B-341 (2)・補足 (2)）

### B-1. 会い方（メニューごと）

- メニューを作る（`QqER7`）に段「会い方」：**対面／オンライン／お客さまが選ぶ**（初期＝対面）。
  - 対面：場所（店の住所＝店の設定から、または「別の場所」：住所・部屋の名前・地図の URL）。ELruS の場所の欄。
  - オンライン：会議の URL の出し方を **① 手で入れる** か **② 自動で発行** から選ぶ（B-2）。
  - お客さまが選ぶ：LIFF ⑤ で「対面／オンライン」を選ぶ。選んだ方で空き（オンラインは部屋の資源を使わない等）を出す。両方とも空きが無い日は灰色（Z76uuv）。

### B-2. URL の 2 通り

| | ① 手で入れる（事前に自分で入れる・固定の URL） | ② 自動で発行（Meet・Zoom・Teams とつなぐ） |
|---|---|---|
| 入れる所 | メニューごと（メニューを作るの会い方の段）と担当ごと（担当スタッフの編集・自分の勤務） | 担当スタッフの編集・自分の勤務の「つなぐ先」で会議のサービスをつなぐ（担当ごと） |
| どの URL を使うか | **担当の固定 URL があればそれ、無ければメニューの固定 URL**（担当ごとの部屋を優先）。**決定：おすすめ** | 予約の担当のつなぎで作る |
| いつ決まるか | 予約が確定した時に写す（後で固定 URL を変えても、確定済みの予約は前の URL のまま。［新しい URL に入れ替える］を詳細パネルに） | **予約が確定した時に発行** |
| 日時の変更 | そのまま | **作り直す**（前の会議を消して新しく作る。Zoom・Teams は同じ会議の日時を直せるなら直す） |
| 担当の変更 | 新しい担当の固定 URL に替える | 前の担当の会議を消し、新しい担当で作る |
| 取消・店が断った | — | **消す** |
| 入力の確かめ | `https://` で始まる URL だけ。Meet・Zoom・Teams 以外の URL も可（Webex など）。保存の時に形だけ確かめる | — |

- 発行に**失敗**した時（つなぎが切れた・会議のサービスの不調・上限）：
  1. 予約は成立させる（会議の URL の失敗で予約を落とさない）。
  2. **担当かメニューの固定 URL があればそれを使う**。無ければ URL は「未発行」で、詳細パネルに**手で入れる欄**と［もう一度発行する］。
  3. 運用者に知らせる（予約の詳細パネルの赤の札「会議の URL を作れませんでした」・要対応・G4 のプッシュ「〇〇さまの会議の URL が未発行です」）。
  4. お客さまへの案内は「会議の URL は前日までにお送りします」に替える（URL を出せる時まで出さない）。
  5. 前日の定時までに URL が入らなければ、前日のリマインドの 2 時間前に運用者へもう一度知らせる。
- 既定：つないでいない担当で「自動で発行」のメニューを受けたら、①の固定 URL → 未発行の順。

### B-3. お客さまへ URL をいつ出すか（**決定：おすすめ**）

| 時 | LINE | LIFF |
|---|---|---|
| 申込中・承認待ち | 出さない | 出さない（「確定したら会議の URL をお送りします」）。sjkwK の確認待ちで［会議に参加する］が押せる形は直す |
| 確定した時 | 確定の知らせに URL（自動の送信。manual の印は付けない） | 受け付けました（`VU6Xi`）・予約の履歴に「オンライン（Zoom）」と URL のコピー、開始 10 分前から緑の［会議に参加する］。それより前はボタンを出さず「11/20（金）13:50 から参加できます」の文 |
| 前日のリマインド | URL（**送る時点の URL** を差し込む＝変更で作り直した URL） | 同上 |
| 当日（1 時間前）のリマインド | URL（同上） | 同上 |
| 終わった後 | 出さない | ボタンを消し「終わりました」 |
| 取り消した | 出さない | 「取り消しました」。古い URL は残さない |

- 予約の履歴に 2 つ以上の予約がある時は、予約ごとの箱に分けて URL を出す（sjkwK の混ざりを直す）。

### B-4. 既存の Meet の相談（`POST /api/meet-consultations`）との関係

- **今の決まりは残す**：予約の外で担当（または LINE Harness Proxy から操作する人）が Google カレンダーで直接作った Meet の個別相談は、AGENTS.md のとおり `POST /api/meet-consultations` に Google Calendar の予定 ID・友だち ID・日時・Meet の URL を登録し、前日・1 時間前の LINE リマインドを付ける。キャンセルは `DELETE /api/meet-consultations/:externalEventId`。
- **予約から作った会議は予約の仕組みが正**：musubo の予約で確定し、B-2 で URL を作った物は `meet_consultations` には登録しない。リマインドは予約のリマインド（前日・当日）が送る。
- **二重のリマインドを防ぐ**：`meet_consultations` に `booking_id` が入っている行（553 で予約と結んだ物）がある予約は、予約のリマインドのうち同じ時（前日・1 時間前）の物を送らない（相談の側が送る）。**決定：おすすめ**。
- 次の段：`meet_consultations` だけで持っている相談を、予約（会い方＝オンライン・手で入れた URL）に写す移し替えの口を作り、相談の仕組みを予約へ寄せる（移し替えは別の承認）。

## 4. 画面の要件（置き場・権限・状態・言葉）

### 4-1. 置き場と板

## 5. データと API の形の案（Codex が作る・マイグレーション）

- `calendar_connections`（今の `google_calendar_connections` を広げるか、並べて作る）：`id`・`line_account_id`・`staff_id`・`provider`（google_shared／google_oauth／microsoft）・`read_calendar_ids_json`・`write_calendar_id`・`status`（connected／degraded／disconnected）・`last_synced_at`・`last_error_code`・`secret_ref`（鍵は秘密の保管先に・D1 に生で置かない）・`version`。
- 同期のスイッチ（B-341 追記 2）：店の設定に `calendar_read_enabled`・`calendar_write_enabled`（初期 0）、`calendar_connections` に `read_enabled`・`write_enabled`（初期 0）と `version`。切り替えの履歴 `calendar_sync_switch_log`（`scope`＝account／staff・`direction`・`before`・`after`・`delete_future_events`・`include_backlog`・`actor_staff_id`・`created_at`）。口：PUT `/api/booking/admin/calendar-sync`（店全体・owner/admin）と PUT `/api/booking/admin/staff/:id/connections/:connId/sync`（担当・本人と owner/admin）。本文 `{read?, write?, deleteFutureEvents?, includeBacklog?, expectedVersion}`、返り値に影響の件数。確かめの窓の件数は GET `.../sync/preview` で出す。
- `calendar_busy_cache`：`connection_id`・`range_start`・`range_end`・`busy_json`（時間だけ）・`fetched_at`。
- `booking_calendar_events`：`booking_id`・`connection_id`・`calendar_id`・`external_event_id`（予約 ID から決める）・`status`（pending／written／failed／deleted）・`attempts`・`last_error_code`・`updated_at`。書く作業の順番待ち（outbox）を兼ねる。
- `meeting_connections`：`staff_id`・`provider`（google_meet／zoom／teams）・`status`・`secret_ref`・`version`。
- `bookings` に `meeting_mode`（in_person／online）・`meeting_url`・`meeting_url_source`（fixed_staff／fixed_menu／auto／manual）・`meeting_provider`・`meeting_external_id`・`meeting_status`（none／issued／pending／failed／deleted）・`location_json`。
- メニューに `meeting_mode_option`（in_person／online／customer_choice）・`meeting_url_mode`（fixed／auto）・`fixed_meeting_url`・`location_json`。担当に `fixed_meeting_url`。
- 店の設定に `calendar_write_shared_id`・`calendar_title_includes_name`。

## 7. 連携とエラーが出そうな所（まとめ）

| 相手 | 起きうること | 復旧 |
|---|---|---|
| Google カレンダー | 共有を外す・権限不足・5xx・429・予定の手での削除 | A-6 の表 |
| Microsoft（Outlook・Teams） | 認可の期限切れ（更新の鍵の失効）・組織の管理者の承認が要る | 「切れています」とつなぎ直し。組織の承認が要る時は「御社の Microsoft の管理者の許可が要ります」 |

| LINE | 確定・リマインドが届かない | 送信の記録に残す（今の仕組み） |
| 鍵の保管 | 更新の鍵の漏れ | 秘密の保管先に置き、D1 には参照だけ。外した時に鍵を消す |

## 8. 決めていない所（B-337：おすすめで決定）

1. 反映は 5 分おきの読み直し＋確定の直前の確かめ。控えは 15 分で古いとみなす。変更の通知は次の段。**決定：おすすめ**
2. 書くのは確定の時だけ（申込中は書かない）。既定の書く先は担当のカレンダー。**決定：おすすめ**
3. 予定に書くのは名前とメニューだけ・参加者は入れない。**決定：おすすめ**／⚖ **仮・専門家に確かめる**（外のカレンダーへの名前の写し）。
4. 固定 URL は担当が優先、無ければメニュー。**決定：おすすめ**
5. URL を出すのは確定の時・前日・当日（1 時間前）。LIFF のボタンは 10 分前から。**決定：おすすめ**
6. 予約に Meet の相談が結ばれている時は相談のリマインドを正とする。**決定：おすすめ**
7. 外の人がカレンダーで予定を消しても予約は変えない。**決定：おすすめ**

## 9. 実装の順番と分担

1. **最小**：同期のスイッチ（店全体・担当者ごと × 読み込み・書き込み、初期オフ、オフの窓で予定を消すか選ぶ＝A-0）、Google の空き（今の共有方式）を担当の勤務の枠と重ねる・5 分の読み直し・確定の直前の確かめ・確定で書く／変更・取消で直す・失敗の札と知らせ。会い方（対面・オンライン）と**手で入れる固定 URL**（担当・メニュー）・LIFF の出し方。
