## 1. 目的・効く目標・ライバルとの差

- 目的：①来店・購入の「最後の日 × 回数（× 金額）」でお客さまを言葉の名前で分け、押せばその人たちに送れる（RFM）。②回数・金額・マイルで段（ランク）を決め、段ごとの特典と知らせで通い続けてもらう。
- 効く目標：③ 作り込める・② 直感的（専門の言葉を使わず「常連」「離れかけ」）・① 引き継ぎ（ランクの上げ下げの履歴）。
- ライバルとの差：カスタマーリングス・Klaviyo・CRM PLUS・ソーシャルPLUS にはあるが、表が専門的。LINE ツール（Lステップ等）は「タグで手作り」。musubo は ①マスに言葉の名前・押すと人と LINE ②予約の店でも来店の印で同じ表 ③下がる 14 日前に知らせ・猶予 ④ランクの特典は予約メニューの出し分け（B9 のタグ）とつながる。

### 2-4. 宣伝の受け取り（mAbif・横断「送る目的」）

- 友だちの「配信の受け取り」は目的ごと（予約の連絡・お知らせ・キャンペーン・宣伝・アンケート）に 受け取る／止めている／不明。
- **本人が LIFF で止めた宣伝を店が「受け取る」に戻すとき**：窓「山田 花子さんは 10/02 にご自分で宣伝を止めています。店が戻すのは、本人から『また受け取りたい』と言われた時だけにしてください」と理由の入力（必須）。記録に残す。本人に「受け取りを戻しました」の知らせは送らない。⚖ 同意の扱いは仮・専門家に確かめる。
- 「不明」（古い友だち）は宣伝を送ってよい扱い（今までどおり）。表示は「不明（初期は受け取る扱い）」と「？」。→ 決定：おすすめ。
- 送る側の画面（RFM の［この 42 人に LINE を送る］・一斉配信・ランクの知らせ）に共通の部品「送る目的」を置き、宣伝なら止めている人数を出して外す（a5r5Wg と同じ）。

### 2-6. 状態と言葉

- RFM：空（来店・購入 0 件）「来店や購入がまだありません。予約の来店の印か EC の注文が入ると、ここに出ます」／読み込み中（骨組み）／失敗［もう一度試す］／作り直し中「今朝の集計を作っています（4:30 ごろ）」／未取得（EC が止まっている）「購入の数は 10/15 までです」。
- ランク：止めている／動いている／判定中。下がる予定の人は「下がる予定（11/30）」。
- 言葉：「マイル」（mile と書かない＝mAbif の指摘）・「会員ランク」・「段」・「上がる」「下がる」。使わない：「RFM」（タブ名は「お客さまの分け方」。「？」の中で RFM と説明）・「セグメント」・「ティア」。

## 3. データと API の形（案・Codex）

- 表（マイグレーション。NEN の 410・550 とは別の汎用の表）：
  - `customer_activity_daily`（集計の控え）：`account_id`・`friend_id`・`visit_count_365`・`purchase_count_365`・`purchase_amount_365`・`last_visit_at`・`last_purchase_at`・`r_bucket`・`f_bucket`・`m_bucket`・`computed_at`。毎日 4:00 に作り直す（Q-62：大きい表は裏で）。
  - `rfm_segment_names`：`account_id`・`r_bucket`・`f_bucket`・`name`。
  - `member_rank_programs`（店ごと）：`account_id`・`metric`（visits/amount/miles）・`window_months`・`downgrade_grace_days`・`notify_upgrade`・`notify_downgrade`・`status`（stopped/active）・`activated_at`・`version`。
  - `member_rank_tiers`：`id`・`program_id`・`sort`・`name`・`threshold`・`mile_multiplier`・`coupon_reward_id`・`tag_id`（自動のタグ）・`upgrade_message_json`・`downgrade_message_json`。
  - `member_ranks`：`account_id`・`friend_id`・`tier_id`・`since`・`downgrade_due_at`。
  - `member_rank_history`：`friend_id`・`from_tier_id`・`to_tier_id`・`reason`（initial/upgrade/downgrade/program_change）・`notified`・`at`。
  - 受け取りの変更の記録（目的ごとの同意の表＝お知らせ止めの機能で作る物）に `changed_by_role`（customer/staff）・`reason`。
- 口：
  - `GET /api/analytics/customer-segments?basis=visit|purchase|both&measure=count|amount` → `{ cells: [{r, f, name, count, optedOutCount}], outside: {count}, computedAt }`。
  - `GET /api/analytics/customer-segments/cells/:r/:f/friends?cursor`・`POST .../saved-search`（保存した検索にする）。
  - `GET/PUT /api/member-ranks/program`・`PUT /api/member-ranks/tiers`（並べ替え含む・`expectedVersion`）。
  - `POST /api/member-ranks/preview` → `{ byTier, wouldUpgrade, wouldDowngrade }`（窓の数）。
  - `POST /api/member-ranks/activate`（Idempotency-Key）・`POST /api/member-ranks/stop`。
  - `GET /api/friends/:id/member-rank`（今・次まで・履歴）。LIFF：`GET /api/liff/member-card`。
  - 友だちの絞り込みの条件に `visit_count`・`purchase_amount`・`last_activity_at`・`member_tier`。
