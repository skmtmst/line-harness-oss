> **正はこの文書**（2026-10-07 オーナー「おすすめで全部」、2026-10-09 オーナー B-105・B-124 で書き換え）。司令塔の手元の `ROLLOUT.md`（10-01）・`COMPLETION-PLAN.md`（10-04/05）・`SWITCH-READINESS.md` の条件の書き方、記録の「主要 68 画面」と食い違うときは、この文書が勝つ。

> **2026-10-09 の書き換え（B-124）**：前は「環境変数 `NEXT_PUBLIC_ADMIN_THEME=v8` で一度に切り替え、1週間は変数を戻せば v7 に戻る。v7 は1週間後の別の PR で消す」だった。これをやめ、**管理画面を V8 に固定する**。次の本番リリースは V8（B-105）。v7 には変数で戻さない。

## 0. V8 に固定する 3 段（B-124）
1. **固定**：全画面を V8 に固定し、見た目の切り替えの仕組み（`NEXT_PUBLIC_ADMIN_THEME`・`THEME_BOOT`・localStorage `lh-admin-theme`・設定の「画面の見た目（試作）」の切り替え）を外す。古い v7 のコードは使われないまま残す（Codex の v8lock）。
2. **機能ごとの書き換え**：その機能を触る担当が、ついでに v7 の分岐（`useAdminTheme`／`isV8` の分かれ道、`v7-only`・`v8-only`、入口の page.tsx の v7 側）と v7 を守る試験を V8 へ書き換える。保存・送信・権限・失敗時・読み直しを守る**動きの試験は消さず V8 へ書き換える**。
3. **最後の掃除**：残った v7 の画面ファイル・v7 だけを読む試験と見た目の契約・`[data-theme='v8']` の囲み（値は `:root` へ）・Tailwind の `v7:` 接頭・`layer-order: V8 移行後に消す` の1行・CI の v7 の写真の比べ（`v7-pixel-diff.mjs`）を一括で消す。代わりに「合格した V8 を変えない」見張りを用意する。

一括削除の枝（rmv7・lh-train-8）は参考に残す。

## 1. 本番へ出してよい条件
- **管理画面の 434 枚（測る対象）がすべて合格**していること。合格＝絵の文字の位置が ±4px で 90% 以上合う（`measure.sh`、幅 1440・1152）＋重ねた絵を目で確かめて `PASSED.tsv` に記録したもの（`docs/v8-design-rules.md` §3）。
- **機能追加待ちの板**（板の名前に「機能追加 F-n・API待ち」）は別に数える。機能が入るまで条件の分母に入れない。
- **LIFF（お客さまの画面）の 28 枚は別の関門**。LIFF も 28 枚すべて合格してから出す。分母はあわせて 462 枚（管理画面 434＋LIFF 28）。
- 進み具合は `SWITCH-READINESS.md`（`tools/hq/switch-readiness.py` が作る）で、この条件の数え方で言う。
- 本番へ出すのは、オーナーが「出して」と言った後だけ。

## 2. 本番へ出す日にすること
V8 は 0 節の①で固定済みなので、環境変数を変える作業は無い。
1. 本番の配備（`deploy-cloudflare-admin.yml`、`main` への push で配備）に入れる値（規約などの URL・404・OG 画像）を、司令塔の確認表 `V8-INTRO-CHECKLIST.md` の C 節のとおり用意する。
2. 本番の DB（D1）の未適用を件数で数え、1本ずつ当てる（dry-run → 適用）。
3. **LIFF は管理画面と同じ日にそろえて出す。**LIFF には切り替えの仕組みが無く、★V8 の値は無条件で効くので、**それまで V8 の LIFF を本番（`main`）へ配備しない**。
4. **絵も V8 も無い 41 ページ**（`/login`・`/register`・`/password/*` など）は、今の作りのまま **V8 の色と書体だけ当てて出す**。絵は後で描く。
5. 反映履歴に1行（`docs/release-log/unreleased/<PR番号>-<担当>-<内容>.md`）と、運用者へのお知らせ。

## 3. 本番へ出す前後の確かめ（検証環境で先に）
検証環境の既定はすでに V8（`deploy-cloudflare-staging.yml`）。配備は手動（`tools/hq/deploy-staging.sh`、run が success かを見る）。
- **全画面を開いて落ちないこと**：管理画面の全ルートを開き、白い画面・エラーの画面・はみ出しが 0（幅 1152・1440・1920）。
- **主な流れ**：ログイン → ダッシュボード → 友だち一覧と詳細 → 一斉配信を作る → シナリオ・自動応答・リマインダを作る → 受信箱で返信 → 予約（管理画面と LIFF で予約・変更・取り消し）→ 回答フォーム → 設定とスタッフ。閲覧のみの人で、押せないボタンが隠れていること。
- 本番の配備のあと、同じ「全画面を開く」と主な流れを本番で見る。本物の LINE で送受信を確かめる（オーナーかマサト）。

## 4. 巻き戻しの手順
v7 には戻さない（変数での巻き戻しは無い）。
1. 本番で問題が出たら、原因の PR を revert して `main` へ入れ、再配備する（前の配備の版へ戻す）。
2. LIFF も同じく、LIFF の変更を revert して再配備する。
3. 戻した理由と、どの画面で何が起きたかを記録し、直してから出し直す。
