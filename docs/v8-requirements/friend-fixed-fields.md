# 友だちの決まった欄と表示項目

正本：V8-INTRO-CHECKLIST B-234・B-235・B-238①③④⑤⑦（2026-10-11採用）。見た目は proposal-1010 の採用済み画像と proposal-b234 のHTML。B-238が以前の上限を置き換える。

## 決まった欄

基本は名前・ふりがな・生年月日・年齢・メール・電話・住所・アレルギーの8つ。記念日・席の好みは別の「飲食の情報」。生年月日がある年齢は日本の暦で計算し、無ければ回答年齢。値の出どころ（回答フォーム名・日付／手で入れた）を示す。情報欄タブは基本と店が作った項目を分類ごとに表示。「本名」は「名前」、「誕生日」は「生年月日（◯歳）」にする。

アレルギーは複数の文字の配列。選択肢は店ごと、初期値は卵・乳・小麦・そば・落花生・えび・かに・くるみ＋そのほか（自由に書く）。空、重複、過長、不正な種類を検査する。既存のfriend_field_values.valueにJSON配列を保存し、旧文字値は1要素として読む。既存の固定欄のDB定義やmigrationは書き換えない。共有型と読み取り時の型を複数選択にする。店ごとの選択肢は既存account_settingsへ保存する。

回答フォームでは「書いてもらう」の3行目。保存先はアレルギー（決まった欄）に固定し［変える］を出さない。LIFFは複数を選択し、自由記入も配列に含めて送る。受信箱・概要のcustomer-info-panelは基本の行に札を表示し、［編集］で追加・解除、保存失敗時は入力を残す。飲食予約の注意は予約時の写しを維持し、配列も人が読める形にする。後の編集で過去予約の写しを変えない。

## 一覧の表示項目

今の6列（対応・担当、シナリオ、最新のメッセージ、タグ、流入元、最終接触）、基本8つ、店が作った情報欄（分類つき、作った数だけ）から選択・並べ替え。友だちの名前は常に表示。追加列の上限は1440幅で7、1152幅で4。上限に達したら追加不可、「ほかの列を外してから足してください」。横はみ出しは0。

共通の窓を顧客情報の表示項目にも使う。検索・縦送り・件数・［情報欄を管理］。0件は「まだありません」と作成リンク。開くたび最新の項目を読む。friends.visibleColumnsの設定キーを引き継ぎ、固定はfixed:鍵、店の項目はfield:IDで保存。消された項目は列から外す。

一覧APIは指定された欄だけを返す。担当外の店、非公開の個人情報、保管済み項目を返さない。項目ごと・友だちごとの往復を増やさずまとめて取得。2,000件で問い合わせ回数・返す値の数・速度を検証する。閲覧のみは編集操作を隠し、APIでも更新を拒否する。

## 統括と受け入れ条件

統括のフォームもアレルギーと本人確認書類を使う。選択肢は配った先の店から読む。記念日・席の好みを含むフォームを飲食未使用の店へ配る時は事前確認で知らせる。本文の差し込みは店名・店の電話番号・予約ページ・名前＋基本8つ。店が作った情報欄と共通情報は統括で選ばせない。

店AとBで設定・回答が混ざらない。旧文字値が表示・編集・配布・予約で読める。必須・自由入力・権限・再読込・保存失敗・出どころ・削除された列を動作試験で守る。故意に処理を壊して試験が落ちることを確認する。1440・1152はmeasure.shと画像重ね合わせ、1152・1440・1920は崩れの見張りを行い、未達の数値を報告する。
