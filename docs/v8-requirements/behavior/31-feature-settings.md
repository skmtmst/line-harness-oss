# 31 機能設定 操作と挙動（受け入れ）

要件の正本：[31 機能設定](../../v6-requirements/v6-31-feature-settings-requirements-draft.md)・[共通基盤 §3・§6-3・§11](../../v6-requirements/v6-shared-platform-requirements.md)・[30 ログインユーザー §7〜§8](../../v6-requirements/v6-30-login-users-requirements-draft.md)。この文書は「操作したらどう動くか」を試験が書ける形にしたもの（2026-10-16 B-333）。食い違ったときは要件が勝つ。

「使えるか」は次の積で決まる：契約で使える × 会社の機能設定がオン × その人の権限が見る/変える × 担当の LINE アカウント × 運用状態で止めていない。機能設定は「会社として使うか」だけを決め、緊急停止の代わりにはしない。

## 連携とエラーが出そうな所

| 相手 | 何が起きうるか | 画面の出し方 | 復旧 |
|---|---|---|---|
| D1 | 同時保存・版の不一致 | 409 の帯と比べる窓 | 最新を読み込んで差分を当て直す |
| D1 | 一括保存の途中失敗 | 失敗の通知（消えない）と「もう一度」 | 全部巻き戻っているのでもう一度保存 |
| cron・待ちの仕事 | オフにした機能の予約送信・自動処理が残る | 運用状態に「機能オフで飛ばした件数」 | オンに戻すか、その機能で止める |
| LIFF・公開ページ | オフでお客さまの画面が急に見えなくなる | 保存前の影響確認窓で公開中の件数 | 先に各機能で公開を止めてからオフ |
| 外部連携（Webhook・EC） | オフ時に配送待ちが残る | 影響確認で「配送待ち」 | 配送の完了・取消を待ってからオフ |
| 管理画面の他のタブ | 古いメニューが残る | 保存後の通知で他タブも読み直す | 読み直し |

## 日々の操作の手順

ふだんは触らない画面。触るのは次の時だけ。
1. 新しい店・アカウントを始めた日：使わない機能をオフにし、並びを使う順に変える（変更理由に「導入時の整理」）。
2. 月に 1 回：利用状況を見て、90 日使っていない機能を検討する（自動でオフにはしない。稼働中・公開中が 0 かを影響確認で見る）。
3. 機能をオフにする前：影響確認の件数を見て、公開中・予約受付中があれば各機能で止めてから保存。

異常の気づき方：スタッフから「メニューが消えた」→入った記録で機能設定の変更者と理由を見る。運用状態に機能オフでの飛ばしが急に増えた→直前の機能設定の変更を疑う。

## 要件と今の作りの食い違い

1. 公開中・稼働中・予約受付中があるときのオフ：要件 §6-2 は「オフを拒否し、停止先を出す」。今の作りは確認窓で確認すればオフを保存できる（確認の札で通す）。根拠：apps/worker/src/routes/feature-settings.ts:1288-1313（IMPACT_CONFIRMATION_REQUIRED の後、impactToken があれば保存）。
2. 変更の権限：要件 §11 は owner/admin のうち `settings.feature.edit` の個別権限。今は owner/admin なら誰でも変えられ、個別権限の判定は無い。根拠：apps/worker/src/routes/feature-settings.ts:981・1130（requireRole('owner','admin') のみ）、apps/worker/src に settings.feature.edit が無い。
3. 契約外の表示：要件 §12「鍵表示・管理者でもオン不可」。サーバーは FEATURE_NOT_ENTITLED を分けて返すが、機能設定の画面に契約外を出す処理が見つからない。根拠：apps/web/src/v8/settings/features/（entitle・contract の扱い無し）、apps/worker/src/middleware/feature-enforcement.ts:935-943。
4. 契約外の機能でも読み（GET）は通る。要件 §6-1「閲覧 URL は原則拒否」は会社オフの話で、契約外の読みをどうするかは書いていない（下の「仕様が無い」）。 → 決定 B-337 Q-37。根拠：apps/worker/src/middleware/feature-enforcement.ts:930-934。
5. 分類の無い API は 403 ではなく 500（ROUTE_FEATURE_UNCLASSIFIED）。要件 §10-3 は CI 失敗＋拒否。CI の網（feature-route-manifest）はあるが、すり抜けた時の応答が 500。根拠：apps/worker/src/middleware/feature-enforcement.ts:801-807。

### 仕様が無い

> 2026-10-16 オーナー「おすすめで」（B-337）で下の項目は全部決まった。各行の → が決定。問いは design/v8/review/SPEC-QUESTIONS-1016.md。

1. 代理ログイン中に機能設定を変えてよいか（FS-19）。 → 決定 B-337 Q-01：代理中は見るだけで、機能設定の変更は理由を入れた 30 分の書き込み中だけできる。
2. 契約外の機能の既存データを読む（GET）ことを許すか。 → 決定 B-337 Q-37：許す。契約外の機能のデータは見るだけ・書き出し可。
3. 「1 分以内に全員へ反映」の測り方（同じ画面を開いている他の人のメニューをいつ読み直すか）。 → 決定 B-337 Q-64：他の人のメニューは画面に戻ったときと 60 秒ごとに読み直す。
4. 並びの単位：要件は「選択中 LINE アカウント単位」だが、統括（複数アカウント）からまとめて並べ替える口を作るか。 → 決定 B-337 Q-64：統括からまとめて並べ替える口は作らない（並びは店ごと）。
