# 23 EC連携 操作と挙動（受け入れ）

2026-10-16 B-333。画面は「EC連携」（タブ：取り込みの記録／会員のつき合わせ／定期便／つなぎ先）と、行の「…」から開く「注文の状況」の引き出し。ネットショップ（EC-CUBE）からの受け口は運用者の画面ではなく、ネットショップが自動で呼ぶ。

- 本当の送信はしない前提。検証環境では、試しの LINE アカウント（試し受信者だけが友だち）と、検証用の受け口の鍵で署名した見本の出来事を送って確かめる。本番のネットショップ・本番の鍵は使わない。
- 「自動：単体」は Worker・DB の試験（vitest）、「自動：画面」は画面の試験（React の試験・Playwright）、「手」は検証環境で人が操作して見ること。

## 連携とエラーが出そうな所

## 日々の操作の手順

毎日（朝、営業の始まり）：
1. EC連携 → 取り込みの記録を開く。表の下の「最後に届いた日時」が今日か、「今日取り込んだ数」が普段どおりかを見る（注文がある日に 0 なら、つながっていない疑い）。
2. 数の帯の「失敗」を見る。1件以上あれば「失敗」の札で絞り、行の「…」→「注文の状況を見る」で理由を読む。一時的な理由なら「もう一度やる」。トークン切れなどは設定を直してから「もう一度やる」。
3. 「処理中」が1時間以上減らないときは、定期の回収が止まっている疑い。運用状態で確かめる。
4. 会員のつき合わせを開き、「結びついていない」と「結びついていない注文の金額」を見る。増えていれば候補を見て決める（名前だけで結ばない）。
5. LINE通知の「送れなかったもの」で、EC の注文のお知らせが「送信対象外」になっていないか見る。

毎週：
1. 定期便を開き、「決済の確認が必要です」の人を見る。必要なら受信箱から連絡する（自動の割引・自動送信はしない）。
2. つなぎ先で「この30日」と「失敗」を見て、失敗の割合が増えていないか確かめる。
3. 鍵を差し替えたときは、差し替えの後に届いた出来事が「処理完了」になっていることを確かめる。

異常の気づき方：「最後に届いた日時」が止まる／「失敗」が増え続ける／「処理中」が減らない／「結びついていない注文の金額」が急に増える。

## 要件と今の作りの食い違い

コードを読んで確かめたものだけ。直していない。

1. つなぎ先の「どこの出来事を取り込むか」「照合のルール」は保存されるが、受け口でも処理でも使われていない。外しても出来事は取り込まれる（要件 §4 の event subscription）。根拠：`apps/worker/src/routes/ec-commerce.ts:901-910`（保存だけ）、受け口がつなぎ先から読むのは鍵だけ `apps/worker/src/routes/ec-integrations.ts:456-458`。`event_types_json`・`identity_rules_json` をほかで読む所は無い。
