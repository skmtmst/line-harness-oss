# 21 NEN配信 操作と挙動（受け入れ）

要件の正本：[V6 21 NEN配信 要件定義](../../v6-requirements/v6-21-nen-delivery-requirements-draft.md)。共通の動き・権限は [共通基盤](../../v6-requirements/v6-shared-platform-requirements.md)（§3 権限・§6-2 再試行・§6-3 実行直前の判定・§9 未取得・§11 応答コード・§15 進みと知らせ）、権限モデルは [30 ログインユーザー](../../v6-requirements/v6-30-login-users-requirements-draft.md) §7〜§8。見た目は ★V8 と [V8 デザインの決まり](../../v8-design-rules.md)。

2026-10-16 B-333。画面の言葉は今の管理画面（NEN配信：自動配信・コラム・停止中・送った履歴、配信を直す、コラムを書く、誕生日クーポンの決めごと）に合わせた。検証環境では本当のお客さまへ送らず、試しの LINE アカウントと「テスト送信先」に登録した担当者だけで確かめる。EC 側は検証用の EC（またはその代わりの受け口）を使い、本当のクーポンを発行しない。

## 日々の操作の手順

毎日（朝）
1. NEN配信を開き、数の帯の「今月送った」が前日から増えているかを見る。増えていなければ、送る回（cron）か店の送信トークンを疑う。
2. 「送った履歴」で札「届きませんでした」を開く。理由が「上限まで失敗」のものは中身を確かめ、直せる原因（店の設定・友だちの状態）を直してから「再送待ちへ戻す」（理由を書く）。
3. 運用の知らせに「誕生日クーポンの発行に失敗しました」があれば、EC の接続（管理画面の EC 連携）を確かめる。翌日の回で自動でやり直す。
4. 夜 21 時〜朝 8 時に予約された分が朝に送られたか（「これから」が減ったか）を見る。

毎週
1. 自動配信の「止めている N」を見て、止めたままでよいかを決める。
2. コラムの予約（「予約中」）の日時と配信対象（タグ）を確かめる。届く人数が急に減っていないか。
3. 誕生日クーポンの決めごと（割引額・使える日数・2月29日の扱い）が今の方針と合っているか。

異常の気づき方
- 「これから」が何時間も減らない → 送る回の停止・機能オフ・緊急停止のどれか。
- 「送りませんでした」が急に増える → フォームの非公開・配信を止めた・注文の取り消しの波。理由の列で分ける。
- 同じ人に同じ配信が2通 → 重複防止が効いていない不具合。すぐ報告。
