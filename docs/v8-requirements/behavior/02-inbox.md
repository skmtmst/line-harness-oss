# 02 受信箱 操作と挙動（受け入れ）

要件の正本：[02 受信箱](../../v6-requirements/v6-02-inbox-requirements-draft.md)・[02 担当者ごとの未読数 引き継ぎ](../../v6-requirements/v6-02-inbox-assignee-unread-handoff.md)・[共通基盤 §3・§6-2・§9・§11・§15](../../v6-requirements/v6-shared-platform-requirements.md)・[30 ログインユーザー §7〜§8](../../v6-requirements/v6-30-login-users-requirements-draft.md)。この文書は「操作したらどう動くか」を試験が書ける形にしたもの（2026-10-16 B-333）。食い違ったときは要件が勝つ。

関係するオーナーの決定：B-5（右の欄・状態のタブの件数）、B-6（クリップから画像・動画・ファイル）、B-26（右の欄でその場で直す）、B-160 ①（知らせの「元に戻す」はやめる）⑥（受信箱のメモは自動保存）、B-251（受信の 200 のあとの失敗は直せる工程だけやり直し、返信の鍵が要る物は「要確認」）、B-308 追記 2 ①（AI は要約と返信案だけ・人が確かめて送る）、B-310（送ったメッセージの取り消し。案のみで未決定）、B-312（統括の「対応が要る物」）。

| 相手 | 何が起きうるか | 画面の出し方 | 復旧 |

## 日々の操作の手順

毎日（朝・昼・夕方）

1. 受信箱を開き、状態のタブ「未対応」の件数と、上の数字の「要返信」「最長待ち時間」「期限超過」を見る。最長待ちが長い（目安：営業中に 1 時間以上）なら先に返す。
2. 担当者の絞り込みで「自分」を選び、未読の印が付いた会話から開く。開いたら自分の未読は消える。
3. 会話を読んで右の欄（顧客情報・予約・購入・タグ）を確かめ、返信する。定型はテンプレートから選び、差し込みが解決されているか見本で確かめてから送る。
4. 返し終えたら対応状況を「対応済み」に。返事待ちなどで止めておく物は「保留」。他の人に回す物は担当を変え、内部メモに引き継ぎを書く。
5. 「未割り当て」の会話を見て、担当を決める。
6. 送信が失敗・結果不明の印が付いた会話を見る。結果不明は LINE 側の履歴を見てから、送り直すか決める（自動で送り直さない）。

毎週

1. 保存した検索（例「保留が 3 日以上」「自分担当の未読」）を開いて、溜まっている物を片づける。
2. 運用状態で、受信の「最後に届いた時刻」と「要確認」の件数を見る。受信が止まっている、要確認が増えている、は異常。
3. 送信予約の一覧で、もう要らない予約を取り消す。

異常の気づき方

- 受信箱に新着が半日来ない → 運用状態の「最後に届いた時刻」を見る（Webhook の接続切れ）。
- 送信がずっと「送信中」のまま → 結果不明の可能性。LINE 側の履歴を見る。
- 担当者の未読数が「—」 → 集計の失敗。読み直す。続くならエラー報告へ。
- 同じ問い合わせに 2 人が返している → 返信中の止め（409）が効いていないので不具合として報告。
