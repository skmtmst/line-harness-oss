# 26 外部連携 操作と挙動（受け入れ）

要件の正本：[26 外部連携](../../v6-requirements/v6-26-external-integrations-requirements-draft.md)・[25 共通アクション接続契約 §6・§7](../../v6-requirements/v6-25-automation-action-contract.md)・[共通基盤 §3・§6-2（送信 Webhook は最大 8 回・24 時間）・§9・§11・§15](../../v6-requirements/v6-shared-platform-requirements.md)・[30 §7〜§8 権限・§22 大事な操作の再確認](../../v6-requirements/v6-30-login-users-requirements-draft.md)。この文書は「操作したらどう動くか」を試験が書ける形にしたもの（2026-10-16 B-333）。食い違ったときは要件が勝つ。

検証環境では、送り先は自分で用意した検証用の HTTPS の受け口（応答コードを切り替えられる物）だけを使う。受け取り口へは、検証用の合言葉で署名した見本の本文を手で送る。本番の相手（EC・決済・Slack 等）の鍵は入れない。

## 連携とエラーが出そうな所

| 相手 | 何が起きうるか | 画面の出し方 | 復旧 |
|---|---|---|---|
| 送り先（相手のサーバー） | 5xx・時間切れ・つながらない・429・長時間の停止 | 記録に「再試行待ち」と次の時刻→尽きたら失敗 | 最大 8 回・24 時間の自動再送。5 回続けて失敗で自動停止と知らせ。直したら動かして、失敗分を選んで送り直す |
| 送り先 | 4xx（相手の仕様変更・認証の変更） | 「相手が受け取りを断りました」 | 送り直さない。相手の設定を確かめて直してから選んで送り直す |
| 送り先 | 届いたか分からない（送った後の記録の失敗） | 「届いたか分かりません」 | 確かめの窓を挟んで送り直す。相手は出来事 ID で重複を捨てる前提 |
| 送り先 | 安全でない URL・転送（社内の住所・ループバック） | 「送り先が安全ではありません」 | 送らない。URL を直す |
| 受け取り口の送り手（EC・決済・GAS 等） | 署名の失敗・時刻ずれ・合言葉の入れ替え忘れ・重複送信 | 401／重複は 200 | 入れ替え後の猶予の間に相手を切り替える。重複は 1 回だけ処理 |
| 受け取り口 | 大きすぎる本文・送りすぎ | 413／429 | 相手の送り方を直す |
| 受け取り口 | 照合できない（0 人・2 人以上） | 未照合の箱・保留 | 人が結び付ける |
| Google Sheets | 許可切れ・シートが消えた・Google の上限 | 同期の記録に失敗と理由 | つなぎ直す・シートを選び直す |
| cron（5 分） | 再送の回収の遅れ | 次の時刻が過ぎても再試行待ち | 次の回で拾う。取りかかったまま止まった行は 5 分で見放して拾い直す |
| 暗号の鍵 | 鍵が無く合言葉を復号できない | 送らない・受け取りは 503 | 鍵を設定（運営） |
| D1 | 同時保存 | 409 | 読み直してやり直す |

## 日々の操作の手順

毎日（オーナー・管理者）
1. 外部連携の数の帯（直近30日 送った・失敗）を見る。失敗が増えていたら「やり取りの記録」を失敗で絞る。
2. 自動で止まった送り先（5 回続けて失敗）が無いか見る。あれば相手の状態を確かめ、直してから動かす。
3. 未照合の箱・保留（複数一致）を開き、友だちを選んで結び付ける。

毎週
1. 失敗のうち再送の尽きた物を、原因を直してから選んで送り直す（届いたか分からない物は相手側で確かめる）。
2. API 接続の鍵の「最後に使った日」を見て、使っていない鍵を止める。
3. 合言葉を入れ替えたときは、猶予の間に相手側の設定が新しい合言葉に切り替わったか（記録の「前の合言葉」の印が消えたか）を確かめる。

異常の気づき方：失敗の急増（相手の停止・仕様変更）・送った回数が急に 0（送り先の自動停止・出来事の選び忘れ）・受け取りの 401 が続く（合言葉の入れ替え忘れ）・未照合の箱が増える（相手が送る ID の変更）。

## 要件と今の作りの食い違い

1. 受け取りの署名：要件 §7-1・§7-2・§19 は時刻・出来事 ID を署名に入れて再送の悪用を拒む。今は本文だけに署名し、時刻の見出しは任意（無ければ検査しない）で署名の対象でもない。根拠：apps/worker/src/routes/webhooks.ts:1730-1755・1779-1795。
2. 受け取りの処理：要件 §7-2 は記録したらすぐ 202 を返し、照合と処理はキューで行う。今は受け取りの要求の中で照合・処理・出来事の発火まで済ませてから返す。根拠：apps/worker/src/routes/webhooks.ts:1857-1960（executeIncomingWebhookActions・fireEvent を await）。
3. 送信の初回：要件 §6-4 は業務の処理では送り出し待ちに積むだけで、送るのは別の受け手。今は出来事を起こした処理の中で初回を同期に送り、落ちた物だけを 5 分 cron が拾う。根拠：apps/worker/src/index.ts:2148-2153（コメント）・apps/worker/src/services/event-bus.ts:154。
4. 手動の送り直しが Worker の中で待つ：要件 §6-4 は「retry は Worker 内 sleep で待たない」。記録からの送り直しは送り先の max_retries（最大 5 回）まで 0.5〜8 秒ずつ待って続けて送る。根拠：apps/worker/src/services/webhook-interactions.ts:190-193、apps/worker/src/services/outgoing-webhook-delivery.ts:123-128・700。
5. オートメーションからの送信 Webhook は配送台帳を通らず直接送り、再試行も 26 の 8 回・24 時間ではなく 1・5・30 分の最大 4 回。根拠：apps/worker/src/features/automations/automation-action-executors.ts:599-605、apps/worker/src/features/automations/automation-engine.ts:14-15。
6. 旧オートメーションの任意 URL への送信が残る（要件 §11・§17-8 は直接 fetch を廃止して登録済みの接続 ID だけ）。署名も付かない。根拠：apps/worker/src/services/event-bus.ts:689-711。
7. 合言葉はブラウザで 24 バイト（192 ビット）作り、送り手の値をそのまま保存する。要件 §6-3 は最低 256 ビット、§10 はサーバー側で作るのが既定。根拠：apps/web/src/v8/webhooks/secret.ts:12-15、apps/worker/src/routes/webhooks.ts:345-349・1101-1104（body.secret を検査して保存）。
8. 送った・届いた本文を保存している：要件 §8-1 は本文を既定で保存しない（debug を期限付きで有効にした時だけ）。今はやり取りの記録に送った本文を残し、送り直しにも使う。根拠：apps/worker/src/services/webhook-interactions.ts:153-159（requestBodyJson）、apps/worker/src/routes/webhooks.ts:1530（payload の口）。
9. 受け取りの合言葉の入れ替え猶予を 24 時間に決めて実装している。要件 §23 は期間の長さを未決定（オーナー確認）としている。根拠：packages/db/src/webhooks.ts:726、apps/worker/src/routes/webhooks.ts:391-404。
10. 受け取りの「届いたらすること」：直接の処理（タグ・テンプレート等）の失敗時の既定が「次へ進む」（接続契約 §2 の既定は「止める」）。共通アクションは版を指定しないと今の公開版を使う（要件 §7-5 は版固定）。根拠：apps/worker/src/services/incoming-webhook-actions.ts:173-174・190-197（COALESCE(?, current_published_version_id)）。
11. 画面の URL：要件 §13 は `/integrations/outgoing` などで、`/webhooks` は互換の転送。今は `/webhooks?tab=` のままで `/integrations/*` が無い。根拠：apps/web/src/v8/webhooks/BEHAVIOR.md「受け付ける URL」、apps/web/src/app/webhooks/page.tsx。
12. 送信の設定のうち、条件・送る項目と伏せ字・時間切れ・送信量の上限・下書き→テスト→公開（要件 §6-1）を保存する口が無い。「それでも送れないとき」も置いていない。根拠：apps/worker/src/routes/webhooks.ts:1070（入力は name・url・eventTypes・secret・isActive・lineAccountId だけ）、apps/web/src/v8/webhooks/BEHAVIOR.md「作る」。
13. 送り先の同時編集：作る口・直す口に版の競合（409）が無い。根拠：apps/web/src/v8/webhooks/BEHAVIOR.md「作る（競合 NGh7b）」、apps/worker/src/routes/webhooks.ts:1157。
14. やり取りの記録の CSV 書き出しの口が無い。根拠：apps/web/src/v8/webhooks/BEHAVIOR.md「やり取りの記録」。
