## 連携とエラーが出そうな所

| 相手 | 何が起きうるか | 画面の出し方 | 復旧 |
|---|---|---|---|
| LINE ログイン | 時間切れ・state の不一致・本人が許可を取り消し | ログイン画面に「もう一度ログインしてください」 | もう一度。記録に失敗 |
| LINE ログイン | 同じ LINE が別の人に既に連携 | 招待の受け取りで「この LINE は別の人に連携済み」 | 管理者の本人確認と移管手順（自動で付け替えない） |
| メール（招待・いつもと違うログイン） | 届かない・迷惑メール・送信上限 | 招待中の行は残る。送信失敗は帯で理由 | 管理者が「もう一度送る」。ログインは止めない |
| 端末の時計 | 6 桁がずれて通らない | 「コードが違います」 | 端末の時刻合わせの案内（仕様の文言は無い） |
| D1 | 同時に権限を変える・管理者を外す | 409 と最新を読み直す案内 | 読み直して差分を見てやり直す |
| D1（監査の書き込み） | 監査が書けない | 高危険操作は保存しない（fail-closed）。理由と追跡 ID | もう一度。運用状態へ |
| cron | 招待の期限切れ・期限付きユーザーの自動停止 | 一覧の「期限切れ」 | 管理者が確認して再送 |

## 日々の操作の手順

毎日（管理者）
1. 画面上部に「いつもと違う端末・場所」の帯が出ていないか見る。出ていたら入った記録の要確認の行を開き、本人に確かめる。
2. ログインユーザーの頭の「2 段階が未設定の人数」を見る。0 でなければ本人に設定を頼む。

毎週（管理者）
1. 招待中タブで期限切れを見て、要る人だけ権限を確かめてから送り直す。
2. 入った記録でログイン失敗が続いている人（同じ人に失敗が並ぶ）を探す。
3. 辞めた人・委託が終わった人を「止める」（消さない）。

異常の気づき方：ログイン失敗の急増、知らない国・地域の行、二段階の解除・復旧コードの使用（高危険）、管理者の人数が 1 人。

## 要件と今の作りの食い違い

1. 項目の伏せ字（§7-3）はメールだけ。電話・住所・売上の伏せ字の設定と API での切り分けが無い。根拠：apps/worker/src/routes/access.ts:67（maskEmail のみ）、apps/worker/src 全体で phone/address の mask の実装が見つからない。
2. 90 日使っていない人（§11-3）を数える処理が無い。画面は 0 固定の初期値。根拠：apps/web/src/v8/settings/staff/staff.tsx:77（unused90Days: 0）、apps/worker/src/routes/access.ts に該当の集計なし。
3. 社外委託の利用期限と期限での自動停止（§9-1・§11-3）が無い。根拠：apps/worker/src に staff の利用期限の列・処理が見つからない。
4. いつもと違うログインの知らせ先：要件 §14 は「管理者へ通知」、§22 は「本人にも知らせるかは未決定」。今の作りは本人へメールし、管理者への知らせは監査の要確認の行だけ。根拠：apps/worker/src/services/admin-session.ts:86-130。
5. 再確認が要るときの応答コードが 2 種類ある。共通の部品は 401、利用停止だけ 428。画面は code で判定しているので動くが、揃っていない。根拠：apps/worker/src/lib/step-up.ts:101（401）、apps/worker/src/routes/staff.ts:1176（428）。
6. 未分類の管理 API の拒否（§8）：staff 役は表に無い API を 403 にするが、owner/admin は表を通らない。機能の分類が無い API は機能設定の門で 500（ROUTE_FEATURE_UNCLASSIFIED）になり、要件の 403 ではない。根拠：apps/worker/src/middleware/auth.ts:779-797、apps/worker/src/middleware/feature-enforcement.ts:801-807。
7. 代理ログイン中に止められるのは削除・解約・状態変更だけで、権限の変更・二段階の必須の切り替えは止めていない。要件に代理ログインの決まりが無いため、良し悪しは決められない（下の「仕様が無い」）。 → 決定 B-337 Q-01。根拠：apps/worker/src/middleware/impersonation.ts:205-211。

8. 大事な操作の再確認（§22）は「TOTP で行う。2 段階認証を使っていない人はパスワードで代える旧案は採らない」。今の作りは TOTP が無い人にパスワードでの再確認を認めている。根拠：apps/worker/src/routes/admin-auth.ts:684-695（useTotp でなければ password で通す）、apps/web/src/v8/accounts-detail/dialogs.tsx:286-291（パスワードの欄・方法が無い人は「そのままアーカイブします」）。

### 仕様が無い

> 2026-10-16 オーナー「おすすめで」（B-337）で下の項目は全部決まった。各行の → が決定。問いは design/v8/review/SPEC-QUESTIONS-1016.md。
