# 03 友だち 操作と挙動（受け入れ）

要件：[V6 3 友だち 要件定義](../../v6-requirements/v6-03-friends-requirements-draft.md)・[友だちの決まった欄と表示項目](../friend-fixed-fields.md)・共通の動き [共通基盤](../../v6-requirements/v6-shared-platform-requirements.md)（§3 権限・§6-2 再試行・§9 未取得・§11 応答コード・§15 進み・トースト）・権限モデル [30 ログインユーザー](../../v6-requirements/v6-30-login-users-requirements-draft.md) §7〜§8。見た目は [V8 の決まり](../../v8-design-rules.md)。

作成：2026-10-16（B-333）。本当の送信はしない前提で、検証環境の「点検専用のアカウント」と「壊してよい見本のデータ」（B-292③）で確かめる。

対象の画面：友だち一覧（`/friends`）・詳細条件の窓・保存した検索・一括操作の窓（V8 の一括バー）・友だち詳細（`/friends/detail?id=`）・重複検出／比べて決める・統合ユーザー・CSV で書き出す／取り込む・UID 移行。

| FR-08 | 詳細条件で 0 人になる条件 | 適用する | 「検索結果 0 件」の案内と条件を外す道。保存はできる（要件 §6-2） | 空の店と同じ案内 | 画面の試験 |

| FR-11 | 保存した検索 50 件ある人 | 51 件目を保存 | 「保存できる検索は 50 件までです」。入力は残る | 黙って失敗・入力が消える | API 試験 |

| FR-23 | 一斉配信の承認の人数以上に一括でメッセージ | 実行 | 台帳は「待っています」。承認されるまで 1 通も送らない | 承認前に送る。再試行で承認を飛ばす | API 試験（承認待ち）／検証で試しアカウント宛てだけで手で |
| FR-24 | 10,001 人を選ぶ | 一括操作の下見 | 「一度に実行できるのは10,000人までです」。実行されない | 一部だけ実行 | API 試験（413） |
| FR-25 | 一括の窓を開いたまま | 上でアカウントを切り替える／窓を閉じる | 古い下見・結果を捨てる。閉じる前に変更があれば一覧を読み直す | 店Aの対象で店Bに実行 | 画面の試験（古い返事を捨てる） |
| FR-26 | 担当者（オーナー・管理者でない）・2 人以上選択 | 一括バーを見る | ［操作を選ぶ］は出ず「一括操作ができるのはオーナーと管理者だけです」。API も 403 | ボタンが押せる形で出る | 画面の試験／API 試験（role 403） |

| FR-29 | 管理者 | 行の「…」→対応状況・担当・タグ・テンプレート・シナリオ・友だち情報・リマインダ | その人への窓が開き、保存すると行が更新される | 別の行の人に保存 | 画面の試験 |
| FR-30 | 管理者 | 頭の［表示中をCSVで書き出す］ | 表示中のページ分を UTF-8（BOM 付き）で保存。先頭が = + - @ のセルは ' を付けて数式にならない | ページ外も出たように見える文言。数式が動く | 単体（セル守り）／検証で Excel で開いて手で |

## 連携とエラーが出そうな所

| 相手 | 何が起きうるか | 画面の出し方 | 復旧 |
|---|---|---|---|
| LINE Messaging API（一括のメッセージ送信） | 時間切れ・429（上限）・5xx。宛先のブロック | 結果の「あとでやり直す人」「直さないと進めない人」に分けて出す | 一時的な失敗は §6-2 の既定（1・5・30 分、429 は Retry-After 優先）。手のやり直しは失敗分だけ。同じ合言葉で二重送信しない |
| LINE Webhook（友だち追加・ブロック） | 同じ通知が 2 回届く・順番が前後する・署名の失敗 | 一覧の数とブロックの数が変わるだけ（画面に通知は出さない） | 受けた通知は記録して 2 回目は何もしない。署名が違う物は捨てる |
| LINE のプロフィール画像 URL | 画像の URL が変わる・同じ画像の別人 | 重複候補の「参考」まで | 同一人物の確定に使わない（要件 §9-1。食い違い 3） |
| LINE プロバイダーの違い（UID 移行） | 別のプロバイダーは同じ人でも別の ID。変換する API が無い | UID 移行の画面に常に書く | 対応表（LINE ログインの検証・署名付き外部 ID・本人確認済み・確認済み CSV）だけで移行 |
| cron（一括の予約実行・止まった台帳の拾い直し） | 実行中に Worker が止まる・予約時刻を過ぎる・契約先が停止 | 台帳の状態（順番待ち・実行中・待っています・一部失敗・完了・停止） | 5 分の借り期限で拾い直し。契約先が停止中に時刻を過ぎた物は「実行しませんでした」で止める |
| 一斉配信の承認 | 承認の人数を超える一括送信 | 「待っています」 | 承認されたら cron が続きを送る |
| D1 | 同時に保存（版のずれ）・大きな選択（1MB 超）・1 万人超 | 409 は「読み直す」、413 は人数の上限の文 | 読み直してから再操作。対象を分けて実行 |
| ブラウザの保存（sessionStorage・localStorage） | 保存できない・壊れた値 | 何も出さず既定の条件・列で開く | 一覧は動き続ける |
| CSV（Excel で開く） | 数式として動く・文字化け | 書き出しは UTF-8（BOM 付き）だけ。Shift_JIS は「まだ接続されていません」 | セルの先頭に ' を付ける |
| 代理ログイン | 閲覧モードで書き込み・個人情報の見せ方 | 閲覧のみの帯 | API が 403 で止める |

## 日々の操作の手順

毎日：
1. 友だち一覧を開き、数の帯の「未対応（要確認）」と「今月の追加」を見る。未対応が前日より増えていたら［未対応］の札で絞り、担当を決める。
2. ［注目のみ］で注目の人を見て、行の「…」から対応状況を進める。
3. 一括操作をした日は、結果の「あとでやり直す人」が 0 か確かめ、残っていれば［やり直す］。「直さないと進めない人」は理由を見て個別に直す。
4. 「ブロック・非表示」が急に増えていないか見る（一斉配信の直後に増えたら配信の中身を見直す）。

毎週：
1. 重複検出タブで未確認の候補を開き、結び付ける／別人／保留を決める（理由を必ず書く）。
2. 保存した検索を見直し、使わない物を消す（上限 50 件）。条件の項目が消されていないか見る。
3. 必要なら CSV で書き出して控えを取る（7 日で期限切れ）。

異常の気づき方：
- 数の帯が「—」のまま → 集計の読み込み失敗。［もう一度］。続くなら管理画面のエラー報告へ。
- 一括の台帳が長く「実行中」「順番待ち」のまま → cron が止まっている疑い。運用状態を確かめる。
- 一括の「待っています」が続く → 承認待ち。承認する人に知らせる。
