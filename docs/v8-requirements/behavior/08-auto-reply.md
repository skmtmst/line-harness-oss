# 08 自動応答 操作と挙動（受け入れ）

要件の正本：[08 自動応答](../../v6-requirements/v6-08-auto-reply-requirements-draft.md)・[共通基盤 §3・§6-2・§6-3・§11・§15](../../v6-requirements/v6-shared-platform-requirements.md)・[30 ログインユーザー §7〜§8](../../v6-requirements/v6-30-login-users-requirements-draft.md)。この文書は「操作したらどう動くか」を試験が書ける形にしたもの（2026-10-16 B-333）。食い違ったときは要件が勝つ。

前提の言葉：
- 「ルール」＝反応する言葉・種別・時間・友だち条件と、返す文面・後続の動作（タグ・友だち情報・シナリオ・リマインダ・知らせ）の組。
- 「返信」＝LINE の返信（無料・届いたメッセージ 1 通につき 1 回だけ・約 1 分で使えなくなる）。「push」＝後から送る送信（送信数に数える）。
- 時間帯・曜日・祝日は**日本時間**で見る。日をまたぐ時間帯（22:00〜翌 6:00）は、始まった日の曜日で数える。
- 1 つのメッセージで動くルールは**1 つだけ**。並び順は「このアカウントのルール → 全アカウント共通のルール」、その中で優先順位の数字が小さい順、同じ数字なら「キーワードのあるルール → すべてに応答」、作った順。
- B-308（2026-10-15）：登録 Q&A を使った AI の自動応答は店ごとにオン（初期オフ）。この文書の対象は、キーワードで決めるルールの自動応答。

## 連携とエラーが出そうな所

| 相手 | 何が起きうるか | 画面の出し方 | 復旧 |
|---|---|---|---|
| LINE Webhook | 同じイベントの再送・署名の失敗・届く順が前後 | 署名の失敗は受け付けない（記録だけ）。再送は何もしない | イベント ID で 1 行だけ確保。先に確保した処理が途中で落ちると、そのイベントは返信されないまま「進行中」で残る（受信箱で手で返す） |
| LINE 返信（reply） | 返信の期限（約 1 分）切れ・時間切れ・5xx・トークン切れ | 実行結果「返信失敗」と理由 | 返信は送り直さない。運用者が受信箱で手で返す。自動の push の代わり送信は既定オフ |
| LINE push（遅延返信） | 時間切れ・429・送信上限 | 実行結果に失敗・要確認 | 5 分ごとの見回り（2 本の cron）で拾う。結果不明は自動で送らない |
| 後続の動作（タグ・シナリオ・リマインダ・知らせ） | 一部だけ失敗 | 「一部失敗」と失敗した動作 | 失敗した動作だけ［もう一度実行］。成功済みは繰り返さない |
| 祝日の表 | 2000〜2099 年の外は祝日なし扱い | なし | 表の更新 |
| メール等の知らせ（当たらない時） | 送れない | 知らせの履歴 | 知らせの設定を直す |
| D1 | 評価の記録が書けない | 返信しない（記録できないまま返すと再送で二重になるため） | Webhook の再送で拾う |

## 日々の操作の手順

毎日：
1. 一覧の上の数を見る：「今日当たった回数」「返信成功」「要対応の失敗」。当たった回数と返信成功の差が大きければ実行結果を開く。
2. 実行結果を「返信失敗」「一部失敗」で絞る：
   - 返信失敗 → 受信箱でその人に手で返す（返信は送り直されない）。トークン切れなら LINE 連携を直す。
   - 一部失敗 → 失敗した動作の理由を読み、直してから［もう一度実行］。
3. 受信箱の未読（当たらなかったメッセージ）を返す。同じ質問が多ければルールを足す候補にする。
4. 営業時間外の返事が正しく出ているか、実行結果の時刻と勝ったルールで見る。

毎週：
1. 競合と優先順位を開き、新しく重なったルールが無いか見る。
2. 一致回数が 0 のルール・失敗が多いルールを見直す。
3. 祝日・臨時休業の週は、曜日と時間帯の設定を前もって確かめる（テストで日時を入れて確かめる）。

異常の気づき方：
- 「返信が 2 通来た」問い合わせ → 実行結果でそのメッセージの行が 1 つか、LINE 要求 ID が 2 つあるかを見る。
- 当たった回数が急に 0 → 緊急停止・課金停止・ルールの停止・LINE 連携切れを疑う。

### 仕様が無い
> 2026-10-16 オーナー「おすすめで」（B-337）で下の項目は全部決まった。各行の → が決定。問いは design/v8/review/SPEC-QUESTIONS-1016.md。

- クールダウンの範囲。今は「その人へのどの自動応答でも」最後の返信から数える（ルールごとではない）（apps/worker/src/features/auto-replies/auto-reply-conditions.ts:177-193）。ルールごとか全体か決まっていない。 → 決定 B-337 Q-45：その人へのどの自動応答でも数える（今のまま）。
- 遅延返信（○秒後に返す）は要件に無い。push で送るので送信数に数え、見回りの間隔で数分遅れる（apps/worker/src/features/auto-replies/auto-reply-delivery.ts、apps/worker/src/routes/auto-replies.ts:427-437、上限 86,400 秒）。使う場面・上限・遅れの許容が決まっていない。 → 決定 B-337 Q-69：上限は 1 時間。送信数に数えると画面に書く。
- 画像・スタンプ等に「すべてに応答」ルールが種別の指定なしで当たるか（今は種別の指定が無いと全部の種別に当たる。apps/worker/src/features/auto-replies/auto-reply.ts:175-191）。 → 決定 B-337 Q-45：種類を指定しないルールは文字だけに当てる。
- Webhook の処理が途中で落ちて「進行中」のまま残った評価を、誰がいつ片づけるか（自動で返し直すか・受信箱へ出すか）。 → 決定 B-337 Q-45：「進行中」のまま 10 分残った物は返し直さず、受信箱へ「自動応答できなかった」と出す。
- 受信本文の短期保存の日数（§13「短期保存」の具体の日数）。 → 決定 B-337 Q-04：受信本文の短期保存は 30 日。 （仮の値・専門家に確かめる（B-337））
- 臨時休業（店の休みの日）を自動応答の時間外として扱う設定。 → 決定 B-337 Q-45：臨時休業の日は時間外として扱う。
