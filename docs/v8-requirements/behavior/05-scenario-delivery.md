## 連携とエラーが出そうな所

| 相手 | 何が起きうるか | 画面の出し方 | 復旧 |
|---|---|---|---|
| cron（5分ごと） | 1回40件までしか送れない。予定が集中すると後ろが遅れる（1時間で約480件） | 一覧の「次回予定」は予定の時刻のまま。遅れは出ない | 待てば順に送る。大量の同時刻開始は分散を案内 |
| cron | 処理の途中で Worker が止まる | 購読は「送信中」に見える | 5分後に戻して同じ再試行キーで送り直す |
| LINE Messaging API | 一時失敗（408・409・429・5xx・時間切れ） | 送信中のまま見える | 5分ごとに送り直す。24時間わからなければ「送達不明」で一時停止 |
| LINE Messaging API | 恒久失敗（400 宛先・本文不正、401/403 チャネル権限切れ） | 一時停止・理由「配信失敗」・「失敗を再送」 | 原因（宛先・本文・アクセストークン）を直して再送 |
| LINE Messaging API | 月の送信上限（429） | 一時失敗と同じに見える | 上限の回復か追加購入のあと、送り直しが続く（食い違い参照） |
| LINE | 友だちがブロック | 状態は完了に見える（食い違い参照） | ブロック解除時は 09 の「前回配信した次から」で続き |
| LINE（postback） | 質問の押下が二重に届く | 1回分の結果 | 2回目は捨てる |
| D1 | 同時に同じ購読を書き換える | 一時停止が 409 | 少し待って押し直す |
| D1 | 公開の同時実行 | 409「同時公開が競合しました」 | もう一度公開 |
| アカウント設定・課金・緊急停止 | 送れない状態 | 一時停止（アカウント停止）または保留 | アカウント停止は人が再開。課金・緊急停止は解除後に自動で続く |

## 日々の操作の手順

1. 毎朝、シナリオ配信の一覧で数の帯（購読中・読み終えた・今週送った）を前日と比べる。急に減った・0 は異常の印。
2. 主なシナリオの「配信結果」を開き、一時停止の理由（配信失敗・送達不明・アカウント停止）が増えていないか見る。
3. 「配信失敗」は原因を見て、直してから「失敗した通を再実行」。同じ原因が多いときは本文・宛先・アクセストークンを疑う。
4. 「送達不明」は届いたかを友だちのトークで確かめ、届いていなければ再実行、届いていれば再開。
5. 新しく直したいときは下書きを直し、公開前シミュレーションで2〜3人を試してから公開する（公開済みの版は書き換えない）。
6. 毎週、完了後の移動先が止まっていないか、停止中のシナリオに購読が溜まっていないかを見る。
7. 大きな一斉開始（数千人を同時に入れる）をする前は、5分で40件という送る速さを見込んで時刻をずらす。
