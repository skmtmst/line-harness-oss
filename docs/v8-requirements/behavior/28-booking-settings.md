## 連携とエラーが出そうな所

| 相手 | 何が起きうるか | 画面の出し方 | 復旧 |
|---|---|---|---|
| Google カレンダー | 共有切れ・カレンダー ID 違い・サービスアカウントの鍵切れ | 担当の行に「確認が要る」、空きは閉じる | 共有し直して［確認する］ |
| D1 | 版の競合 | 409 と最新の読み直し | 読み直してやり直す |
| LIFF | 設定の変更が公開側に出ない（読み込み済みの古い画面） | お客さまが確定するとき空きを再検査して 409 | お客さまに空きを選び直してもらう |

## 日々の操作の手順

- 毎週：来週の勤務表と休み（臨時休業・担当の休み）を入れる。入れたらお客さま表示で空きを確かめる。
- 月初：メニューの予約数・取消・売上を一覧で見て、止める・出す・並べ替え。
- 異常の気づき方：予約設定の帯に「担当 0」「営業時間なし」「公開枠 0」「Google の確認が要る」が出る。LIFF の空きが急に減ったら Google の共有と休みの入れ間違いを疑う。

## 要件と今の作りの食い違い

1. **下書き条件での空き確認が見当たらない**：28 §11・§14 の `POST /api/booking/admin/availability/preview`（下書きと公開版の比べ）は `apps/worker/src/routes/booking.ts` に無い。あるのは公開中の条件で 1 枠を確かめる `availability-check`（`booking.ts:5350`）。
2. **公開・停止の口が分かれていない**：28 §14 の `menus/:id/publish`・`menus/:id/stop`・公開前検査は見当たらない。版の戻し（`menus/:id/versions/:version/revert`）と予約時の写しはある。
3. **割り当て方の設定が無い**：B-306 の「均等・優先順・ランダム」「担当の優先度・1 日の上限」は API 組3（641）の枝にあり、この木には無い（[27 の食い違い 1](27-booking-management.md)）。

仕様が無い：休業日を入れたとき、その日の既存予約のお客さまへ知らせるか（飲食は「連絡」と決まっている。人の予約は書いていない）。 → 決定 B-337 Q-29：飲食と同じ。取り消さず一覧を出し、店が確かめてから知らせを送る。
