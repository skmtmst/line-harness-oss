## 日々の操作の手順

1. 毎朝（受信箱の前）：よく使うテンプレートの「未公開の変更あり」の札が無いか一覧で見る。あれば直しかけを公開するか、下書きを捨てる。
2. 配信を作る前：使うテンプレートの詳細で「使っている所」と「今月送った数」を見る。公開の確かめの窓で、反映される所の数が思っていた数と同じかを見る。
3. 毎週：「使っていない」の札で絞り、要らない物をまとめて削除（使用中は消えない）。フォルダの未分類を整理する。
4. 月初め：今月の操作・回答（カルーセル・質問の押された数）を見て、反応の少ない物を直す。
5. 統括：見本を直したら、配った先のアカウントへ配り直す。結果の失敗が 0 か見る。
- 異常の気づき方：今月送った数が急に 0（配信側の停止か参照の外れ）／削除できない理由に知らない配信が出る（予約済みの配信が残っている）／公開の確かめの数がいつもより多い。

## 要件と今の作りの食い違い

1. テンプレートを消すと版の履歴も一緒に消える。削除は行ごと消し、版の表は「親が消えたら一緒に消す」作り。要件 §6「削除後も送信履歴の版内容は保持」・共通基盤 §4「delete cascade で history を消さない」と違う。確かめ方：`packages/db/src/templates.ts:322`（`deleteTemplate`）、`packages/db/migrations/466_template_versions.sql:8`（`ON DELETE CASCADE`）。
2. 使っている所の正本（参照表）が一斉配信・シナリオ・自動応答の 3 種類だけ。要件 §4-8・§12 はリマインダ・友だち追加・予約・フォーム・オートメーション・個別トークまで、参照表と全利用機能が一致すること。確かめ方：`packages/db/migrations/467_template_references.sql:13`（`consumer_kind IN ('broadcast','scenario','auto_reply')`）。
3. 公開・削除・この版に戻すが、作る・編集と同じ鍵（テンプレートの編集）。口では編集の権限を持つスタッフが公開・削除できる（画面はオーナー・管理者だけに出す）。要件 §8「作成・公開・削除は owner/admin」「編集・公開・送信は別権限」と違う。確かめ方：`apps/worker/src/routes/templates.ts:553`・`:635`・`:797`・`:932`・`:995`（すべて `requireDeliveryAccess('templates')`）、`packages/shared/src/staff-permissions.ts:74`。
