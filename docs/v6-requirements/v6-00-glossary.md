# 用語表（画面に出る言葉の決めごと）

横断レビュー §7 の **48番**「表記ゆれ・内部語を共通ルールの用語表に載せて全文検索で潰す」への答え。

**この表は画面に出る言葉だけを縛る。** 変数名・型・APIの値（`resolved` など）は対象外。
注釈も対象外だが、直した語を説明している注釈は一緒に直す。

## 1. 送り仮名・かな漢字

| 使う | 使わない | なぜ |
|---|---|---|
| すべて | 全て | 要件書が93対5で「すべて」。ひらがなのほうが札の中で読みやすい |
| 対応済み | 対応済 | 要件書は15か所すべて「対応済み」。未対応・対応中・保留と語尾をそろえる |
| 友だち | 友達 | 要件書467か所すべて「友だち」。LINE公式の表記に合わせる |
| 絞り込み | 絞込 | 要件書55か所。名詞の圧縮をしない |
| 未割り当て | 未割当 | 同上 |
| 読み込み | 読込 | 同上 |

## 2. 省略語を開く

| 使う | 使わない |
|---|---|
| アカウント | アカ |
| 選んだアカウント | 選択アカ |

## 3. 対応状況の4つと、その並び

**未対応 → 対応中 → 保留 → 対応済み**（要件書 `v6-02-inbox-requirements-draft.md:188`）

絞り込みの札もこの順に置く。「すべて」は先頭。

## 3-2. 「対応状況」と「対応マーク」は別物

要件書 `v6-02-inbox-requirements-draft.md:77`

> V6画面の「対応マーク」は、実装時に「対応状況」へ変更する。
> 友だち属性の対応マークは右パネル内の別項目として表示する。

| 呼び方 | 中身 | 見分け方（API の形） |
|---|---|---|
| **対応状況** | 未対応・対応中・保留・対応済みの固定4状態 | `chatStatus` / `status` |
| **対応マーク** | 友だち属性で自由に作る分類。名前と色を持つ | `support_mark` / `markId` |

実装は3通りの呼び方（対応マーク・対応状況・対応状態）が混ざっていた。
上の表の区別（固定4状態は「対応状況」、自由な分類は「対応マーク」）に、画面の言葉と実装をそろえる。
画面のどこにどう出すかは ★V8 の板（`docs/v8-design-rules.md`）に従う。
（2026-10-08 整理：「V6 の設計はそのままにして実装だけ直す」という当時の指示は、見た目を V8 にした決定（2026-10-05）で失効した。）

## 3-3. 同じ面・同じ窓を、1つの言い方で呼ぶ

| 使う | 使わない | なぜ |
|---|---|---|
| LINEプレビュー | LINEカードプレビュー／LINE配信プレビュー／配信プレビュー | 設計30枚すべて「LINEプレビュー」。実装は5通りに割れていた |
| 過去30日 | この30日／直近30日 | 2026-10-09 オーナー決定（B-158 の 5・B-160 の ⑦）。期間の部品は「過去7日／過去30日／過去90日／期間を指定」の1つ。7日・90日も同じく「過去◯日」 |

**28日の窓は 30日にする**（2026-10-09 B-160 の ⑦）。`/conversions`・ダッシュボード・配信などで本当に28日で
数えていた窓は、数え方ごと 30日に直す（語だけ「過去30日」にして中身が28日のままにしない）。
**28日のまま残すのは Search Console の数だけ**（Google が 28日で返すため。札は「過去28日」）。
（前の決定「この30日に寄せる」と、Webhook・マイルの「直近30日」（WEB-025・WEB-073）は、この決定で置き換え。）

## 4. 数と時間の言い方

| 場面 | 書き方 | なぜ |
|---|---|---|
| 待ち時間 | 1時間未満は分、1日未満は時間、それ以上は日 | 「9,110分前」は何日前か暗算することになる（§7 48番） |
| 送信枠 | 残り N / 上限 M通 | 「N / M通」だけだと使用数か残りか読めない（§7 26番） |
| 並び順 | 「〜が多い順」「〜が新しい順」「〜が高い順」 | 「優先度順」だと高い順か低い順か決まらない |

## 5. 状態の言い方（既存の `shared/not-connected.tsx` と同じ。2026-10-09 B-157・B-158・B-159 で更新）

| 状態 | 出す言葉 |
|---|---|
| 未接続 | `—` ＋「まだ繋がっていません。○○が接続されると表示されます。」 |
| 読み込み中 | 読み込んでいます（一覧・カードは骨組み。`docs/v8-design-rules.md` §6.5 の 8） |
| 取得失敗 | 読み込めませんでした ＋ 押し口「もう一度読み込む」（「再読み込み」「もう一度試す」は使わない） |
| 見る権限が無い | 見る権限がありません |
| 操作する権限が無い（403） | 操作する権限がありません。店の画面は「オーナーか管理者に頼んでください」、統括の画面は「統括の管理者に頼んでください」を続ける（文は `describeApiFailure` だけが作る） |
| 閲覧のみで開いている | 帯「閲覧のみで見ています。変える操作はオーナーか管理者に頼んでください。」（統括は「統括の管理者に頼んでください」） |
| 数を数えて本当に0 | 数字で `0 件`（件数・人数・回数の欄） |
| 中身の欄が空（付いているタグ・選んだ相手などが1つも無い） | なし |
| まだ設定していない | 未設定 |
| 取れない・不明 | `—` |

**これらを混ぜない。** 混ぜると、繋いでいないのか壊れているのか本当に0なのかが分からなくなる。
空の値の言葉は「—」「未設定」「なし」の3つだけ（「指定なし」「未登録」「未入力」は使わない。B-158 の 13）。
取れない数を `0` にしない。数の欄の「0 件」と、中身の欄の「なし」を取り違えない。

## 5-2. 物の状態の言葉（2026-10-09 B-158 の 1・B-160 の ⑧）

| 種類 | 使う | 使わない |
|---|---|---|
| 送るもの（一斉配信・統括の一括配信など） | 下書き／予約中／送信済み | 予約済み・送信完了・配信待ち |
| 公開するもの（回答フォーム・リッチメニュー・共通の情報・LIFF の公開物など） | 公開中／停止中 | 一時停止 |
| 自動で動くもの（シナリオ・自動応答・リマインダ・オートメーション） | 有効／停止中 | 稼働中・動いている・公開中・一時停止・無効・オフ |
| ウェビナー | 予定／開催中／終了 | 公開予定・公開中・一時停止 |
| 使わなくなったもの（共通） | アーカイブ | 保管・アーカイブ済み |

下書きは全部の種類で「下書き」。札は `StatusBadge` が表から言葉を出す（`docs/v8-design-rules.md` §6.12 の 1）。
「使用中」（ほかから使われているか）は状態の言葉ではないので残す。
操作の名前の「アーカイブから戻す」「止める」はこの表の対象外（ボタンの言葉は `docs/v8-design-rules.md` §6.6・B-160 の ④）。

## 6. この表の守り方

`apps/web/src/app/glossary-contract.test.ts` が、画面に出るコードから
「使わない」側の語を全文検索して落とす。表に足すときは試験にも足す。
期間（§3-3 の「過去30日」）は、2026-10-09 時点で「この30日」「直近30日」が残っているファイルを試験の中の
「直す途中」の一覧に入れてある。直したファイルは一覧から外す（一覧に無いファイルが古い言い方を足すと落ちる）。
§5・§5-2 の言葉はまだ試験で見張っていない（`StatusBadge` の言葉の表ができたら足す）。
