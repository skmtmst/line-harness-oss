# 用語表（画面に出る言葉の決めごと）

横断レビュー §7 の **48番**「表記ゆれ・内部語を共通ルールの用語表に載せて全文検索で潰す」への答え。

**この表は画面に出る言葉だけを縛る。** 変数名・型・APIの値（`resolved` など）は対象外。
注釈も対象外だが、直した語を説明している注釈は一緒に直す。

## 1. 送り仮名・かな漢字

| 使う | 使わない | なぜ |
|---|---|---|
| すべて | 全て | 要件書が93対5で「すべて」。ひらがなのほうが札の中で読みやすい |
| 対応済み | 対応済 | 要件書は15か所すべて「対応済み」。未対応・対応中・保留と語尾をそろえる |
| 友だち | 友達 | 要件書467か所すべて「友だち」。LINE公式の表記に合わせる |
| 絞り込み | 絞込 | 要件書55か所。名詞の圧縮をしない |
| 未割り当て | 未割当 | 同上 |
| 読み込み | 読込 | 同上 |

## 2. 省略語を開く

| 使う | 使わない |
|---|---|
| アカウント | アカ |
| 選んだアカウント | 選択アカ |

## 3. 対応状況の4つと、その並び

**未対応 → 対応中 → 保留 → 対応済み**（要件書 `v6-02-inbox-requirements-draft.md:188`）

絞り込みの札もこの順に置く。「すべて」は先頭。

## 3-2. 「対応状況」と「対応マーク」は別物

要件書 `v6-02-inbox-requirements-draft.md:77`

> V6画面の「対応マーク」は、実装時に「対応状況」へ変更する。
> 友だち属性の対応マークは右パネル内の別項目として表示する。

| 呼び方 | 中身 | 見分け方（API の形） |
|---|---|---|
| **対応状況** | 未対応・対応中・保留・対応済みの固定4状態 | `chatStatus` / `status` |
| **対応マーク** | 友だち属性で自由に作る分類。名前と色を持つ | `support_mark` / `markId` |

実装は3通りの呼び方（対応マーク・対応状況・対応状態）が混ざっていた。
**設計は「対応マーク」のままでよい**（要件書が「V6自体は変更しない」と書いている）。
直すのは実装側だけ。

## 4. 数と時間の言い方

| 場面 | 書き方 | なぜ |
|---|---|---|
| 待ち時間 | 1時間未満は分、1日未満は時間、それ以上は日 | 「9,110分前」は何日前か暗算することになる（§7 48番） |
| 送信枠 | 残り N / 上限 M通 | 「N / M通」だけだと使用数か残りか読めない（§7 26番） |
| 並び順 | 「〜が多い順」「〜が新しい順」「〜が高い順」 | 「優先度順」だと高い順か低い順か決まらない |

## 5. 状態の言い方（既存の `shared/not-connected.tsx` と同じ）

| 状態 | 出す言葉 |
|---|---|
| 未接続 | `—` ＋「まだ繋がっていません。○○が接続されると表示されます。」 |
| 読み込み中 | 読み込んでいます |
| 取得失敗 | 読み込めませんでした ＋ 再読み込み |
| 見る権限が無い | 見る権限がありません |
| 操作する権限が無い | 操作する権限がありません |
| 本当に0 | `0件` |

**この5つを混ぜない。** 混ぜると、繋いでいないのか壊れているのか本当に0なのかが分からなくなる。
