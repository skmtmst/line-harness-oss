## 1. A 流れ図（第1段階は見るだけ）

### 1-1. 達成すること

きっかけ → 条件 → 待ち → 動作 の並びを、箱と矢印で一目で読めるようにする。設定の欄を1つずつ開かなくても、どこで分かれ・どこで止まるかが分かる。

### 1-2. 範囲

- **第1段階は表示だけ。** 編集は今の設定画面のまま。箱を押すと、その設定の欄（例: シナリオのステップ編集 `xfYLn`）が開く
- 3機能で同じ部品を使う: シナリオ編集（`bV5Vs` に「一覧／流れ図」の切替）、オートメーションをつくる（`Rv8Jv` の右側）、友だち追加時の配信（`U3SI5` プレビューとテスト）
- 描くのは **公開版**。下書きに差分があるときは「下書きの変更あり」の印を箱に付け、下書きの形は描かない（公開版と下書きの取り違えを防ぐ。V6 の版の考え方と同じ）

### 1-3. 表示の決まり

| 要素 | 決まり |
|---|---|
| 箱の種類 | きっかけ・条件（分岐）・待ち・動作・終わり の5種。色は既存トークンだけ |
| 分岐 | 条件の箱から「満たす」「満たさない」の2本。行き先が「指定の通へ」なら矢印をその箱へ引く |
| 待ち | 「3日後 10:00」のように箱の中に書く。相対時刻は起点（登録日・予約日など）を併記 |
| 長さ | 30段を超えたら、分岐の無い連続部分を「◯通（まとめて表示）」に縮める。押すと展開 |
| 循環 | 公開前検査で止める（05 §3-8）。流れ図は循環を描かない |
| 未取得 | 取れない値は `—`、ラベルは 未取得／取得失敗／権限不足／未接続（共通基盤 §9） |

### 1-4. 状態

通常（3〜8段）、分岐あり、長い（縮めた状態）、下書きの変更あり、読込中、取得失敗、空（まだ段が無い）。

### 1-5. 除外

- 流れ図の上での編集（ドラッグで箱を足す・つなぐ）。第2段階で別に要件を立てる
- 実際に何人がどの箱を通ったかの重ね表示（実行台帳の集計口ができてから）

## 2. B 受信箱のキー操作

### 2-1. 達成すること

毎日たくさん返信する人が、マウスに持ち替えずに会話を回せる。

### 2-2. キー

| キー | 動作 | 効かないとき |
|---|---|---|
| J / K | 次の会話・前の会話へ | 入力欄・ダイアログの中 |
| E | 対応済みにする | 対応状態を変える権限が無い人（02 §11）。押しても何も起きず、キーの札も出さない |
| R | 返信欄へ移る | 返信できない会話（ブロック・未フォロー） |
| / | テンプレートを選ぶ窓を開く | 入力欄の中（`/` の文字として入る） |
| ? | キー操作の一覧を開く | 入力欄の中 |

- ⌥（Mac）/ Alt（Windows）を押している間だけ、各操作の横にキーの札を出す（参考: detail.design の Hold to Reveal Shortcut Hint）
- 日本語入力の変換中（`isComposing`）は、どのキーも受け取らない

### 2-3. 状態

札を出していない通常、⌥を押して札が出た状態、? の一覧の窓。

### 2-4. 除外

キー割り当ての変更（利用者ごとの設定）。

## 3. D 写真の連続審査

### 3-1. 達成すること

写真が多い日に、1枚ずつ大きく見ながら手早く審査できる。

### 3-2. 範囲

「写真を1枚ずつ見る」（`hHrz8`）は1枚表示と「前の写真／次の写真」まで既にある。足すのは次の3つだけ。

| キー | 動作 |
|---|---|
| A | 通す |
| R | 戻す（理由を選ぶ窓 `N2J629` を開く） |
| ← / → | 前後の写真 |

- 判定が**成功したら**、次の未審査の写真へ自動で進み、「通しました。次の写真です」と知らせる（`role="status"`）
- **失敗したら進まない。** 失敗の理由をその場に出す
- 未審査が無くなったら「審査待ちの写真はありません」の終わりの状態を出す
- **人の最終判断**の原則は変えない（22 §5）。AI の結果で自動判定しない

### 3-3. 状態

通常、判定して次へ進んだ直後（知らせ）、判定の失敗、未審査が無くなった終わり。

## 4. E 処理の進み・骨組み表示・保存結果の通知（共通部品）

### 4-1. 処理の進みの行

時間のかかる処理（一斉配信の送信、CSV取込、友だちの一括操作、クロス集計、アップロード）を同じ形の1行で見せる。

| 項目 | 決まり |
|---|---|
| 並べるもの | 対象件数・済み・失敗・経過秒・状態 |
| 状態 | 待ち／実行中／一部失敗／完了／停止 |
| 失敗 | 件数を押すと失敗の内訳へ。「もう一度」は失敗した分だけ（成功済みを再送しない。共通基盤 §6-2） |
| 未取得 | `—`（共通基盤 §9） |

今は一斉配信（`components/broadcasts/progress-bar.tsx`）とアップロードが別々の進みバーを持つ。部品ができたら置き換える。

### 4-2. 骨組み表示（スケルトン）

`ListState` の読込中に、表・カード・詳細の3種の骨組みを出す。読み込み後に表の高さが跳ねないようにする。今は全機能で「読み込み中」の文字か回転アイコンだけ。

### 4-3. 保存結果の通知（トースト）

| 種類 | 決まり |
|---|---|
| 成功 | 短く出して消える（約3秒）。`role="status"` |
| 失敗 | 消えずに残る。理由と「もう一度」。`role="alert"` |
| 位置 | 全画面で同じ場所 |

今は機能ごとに0〜40か所と、出し方がばらばら。部品ができたら順に寄せる。

### 4-4. 動き

動きは 200ms 以下で、状態の変化を伝えるときだけ。`prefers-reduced-motion` では止める。
