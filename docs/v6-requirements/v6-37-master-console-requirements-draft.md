## 3. 画面ごとの動き

### 37-1 運営ログイン（`InTGF`）

- `/ops` は統括コンソールのメニューから辿れない。直接 URL で入る
- **見た目は統括のログイン画面（musubo のログイン）にそろえる。** ロゴ・入力欄・ボタンの形を変えない
- 上から ロゴ「musubo」／「運営コンソール」／見出し「ログイン」／説明文／メールアドレス／パスワード（目のアイコン）／
  「パスワードを忘れた方はこちら」（右寄せ）／**ログイン**（緑の主ボタン）／「または」／**LINE でログイン**（白・枠線）
- 説明文は「メールアドレスとパスワードでログインします。LINE で登録した運営メンバーは LINE でログインしてください。」
- いちばん下に「運営メンバーの招待を受けた方は、招待メールのリンクから設定してください」。**新規登録の導線は出さない**
- **LINE でログイン**は `platform_admins` に登録された LINE ユーザーだけが通る。登録が無ければ入れない。
  既存の LINE ログイン（`apps/worker/src/routes/admin-auth.ts` の `/api/auth/line`）の仕組みを使う
- メール＋パスワードで入るときは **2 要素認証（6 桁）が必須**。LINE で入るときは省く（要確認）
- 検証環境と本番環境で、登録されるマスターは別々
- サイドメニューは出さない。環境帯だけ出す

### 37-2 ダッシュボード（`Xvofy`）

1. 期間の切り替え（今月・先月・今年）
2. 数値カード 4 枚: 今月の MRR（前月比）／契約中（プラン別内訳）／トライアル中／今月の解約（解約率）
3. **月ごとの売上（棒グラフ）** — 直近 6 か月。当月だけ濃い色にし、金額の吹き出しを乗せる。**目標線は置かない**
4. **プラン別の契約（円グラフ）** — ドーナツ。中央に契約先の総数。凡例に件数と割合。
   注記「トライアルは契約前です。月額の合計には入れていません。」
5. 要対応: 決済が失敗している契約先／トライアル期限が 3 日以内／LINE のトークン期限が近い店舗／未返信のお問い合わせ
6. お問い合わせ（チケット）の状況: 未対応／対応中／平均の初回返信／今月クローズ。
   さらに **契約者専用 LINE の登録（21 人 / 24 人）** と「未登録の3人へ案内」への導線
7. 上限に近い契約先の表: 契約先・プラン・配信通数・バナー生成・メディア容量・使用率

**売上の正本は Stripe**。musubo 側は表示用の写しとし、食い違ったら Stripe を正とする。

### 37-3 契約先アカウント（`X9f5jy`）

- 横断検索（統括名・メール・店舗名・LINE アカウント名）と状態の絞り込み
- 数値カード 4 枚: 契約中／トライアル中／今月の新規／要対応
- 表: 統括名（メール）・プラン・状態・契約日・トライアル期限・店舗数・権限者数・最終ログイン・操作
- 各行から「詳細」と「代理ログイン」。代理ログインのボタンは赤枠にして、通常操作と見分ける

### 37-4 契約先アカウント詳細（`vhwld`）

- 見出しに契約先名・プランの札・状態の札。右に「代理ログイン」と「操作」
- タブ: 概要／契約／店舗／権限者／使用量／サポート／監査（既定は概要）
- 概要に **契約者専用 LINE の登録状況**と「登録を案内する」ボタンを置く
- 店舗の表: 店舗（LINE 公式アカウント）・友だち数・今月の配信・接続状態・最終更新
- 「操作」から 停止／アーカイブ／トライアル延長／プラン変更／機能パック／上限の個別調整
- 停止とアーカイブは、**契約先の名前を手で入力**させ、理由を必須にする

### 37-5 代理ログイン中（`owKZi`）と確認（`Ve2FS` / `oVhwg`）

- 契約先アカウントの一覧・詳細から入る。統括の画面がそのまま開く
- 画面上部に環境帯と**赤い代理ログイン帯**が常時出る
- **既定は閲覧のみ**。書き込みは「書き込みに切り替える」＋**理由の入力必須**
- **時間制限は設けない**。「代理ログインを終える」で終了
- **友だちの氏名は「友だち#1041」のように伏せる**。会話は件数のみ。
  表示は「個人情報を表示する」＋理由の入力で一時的に解除し、終えると戻る
- 5-A の注意「解約・権限者の削除・LINE 公式アカウントの削除は、運営でも行えません」
- 5-B の注意「表示した記録は、日時・運営者・契約先・理由とともに監査ログに残ります」

### 37-6 お問い合わせ（チケット）（`IjIFa`）

画面は**左右 2 分割**。一覧を選ぶとその場で内容を読み、そのまま返信できる。別画面へ飛ばさない。

上部（左右で共通）

- 状態タブ: すべて／**新規**／対応中／待ち／解決済み／クローズ（それぞれ件数つき）
- 数値カード 4 枚: 未対応のチケット／平均の初回返信／解決率／平均の解決時間
- 検索、優先度の絞り込み、並び替え、「＋ チケットを作る」（運営から起票する場合）

左（幅 480）: チケット一覧

- 1 行に チケット番号・契約先・起票者・経過時間 ／ 件名 ／ 状態の札・優先度の札・**受付（管理画面／LINE）**
- 選んでいる行は淡い色で示す
- **相手のアイコンは出さない**（受付の多くが管理画面からで、画像を持たないため）

右（残り全幅）: 内容と返信

1. 見出し行: チケット番号・件名・**自動で付けた件名の印**・優先度の札・状態の札。右に「解決済みにする」「クローズする」
2. **問い合わせ元の帯**: 契約先／起票者／**受付**／プラン・契約状態／店舗数／LINE 登録／過去のチケット。
   右に「契約先を開く」「代理ログイン」。**返信する前に相手の状況が分かる**ことを狙う
3. やり取り: 契約先の発言は左、運営の返信は右。添付も出す
4. 返信欄と「返信する」。注記「返信は管理画面のお問い合わせ履歴に載り、登録メールに届きます。契約者専用 LINE にも通知します。」

**チケットが立つ・閉じる決まり**

1. 管理画面のお問い合わせ、または LINE のメッセージが届いたとき、
   **その契約先・その人の未クローズのチケットがあれば、そのチケットに足す**。無ければ新しく立てる（状態は「新規」）
2. 運営が返信すると「対応中」になる
3. 契約先の返事待ちにしたいときは「待ち」にする
4. 解決したら「解決済み」、確認が済んだら「クローズ」
5. **クローズしたあとに同じ人が送ったら、新しいチケットが立つ**
6. 優先度の既定は「中」。運営が変える

**件名の自動付与**

- 新しいチケットが立ったとき、**最初のメッセージから件名を自動で付ける**（20 字程度）
- 件名の横に「**自動で付けた件名**」の印を出す。鉛筆を押すと直せる
- 運営が直したら印を外し、直した人と日時を残す
- 付けられなかったときは「（件名なし）」とし、手で付けられるようにする

### 37-6-B AI が下書きを作成中（`XlTAd`）

押した直後の状態。**待っていることが分かる画面**を必ず見せる。

- 「AI で下書きを作る」のボタンが「**作成中…**」に変わり、灰色になって**押せなくなる**（二度押しを防ぐ）
- 返信欄の上に青い帯で「**AI が下書きを作っています。5〜15 秒ほどかかります。**」
- 帯の右に「**待たずに手で書く**」。押すと作成をやめて、空の返信欄で書き始められる
- 返信欄には、文章の代わりに灰色の線（読み込み中の目印）を出す

**時間の目安と決めごと**

- ふつうは **5〜15 秒**（材料を組み立てる 0.2 秒／AI が書き始めるまで 1〜3 秒／書き終えるまで 4〜12 秒）
- **10 秒を超えたら**「時間がかかっています。そのまま手で書くこともできます」を帯に足す
- **30 秒で打ち切る**。「うまく作れませんでした。もう一度試すか、手で書いてください」と出し、返信欄は空のまま使えるようにする
- 渡す材料が増えるほど遅くなるため、**musubo の機能情報はチケットに関係する範囲だけを渡す**（マニュアル全体を毎回渡さない）

### 37-6-A AI が作った返信の下書き（`b2uv3`）

返信欄の上の「**AI で下書きを作る**」を押すと、**musubo が契約中の AI を呼び、返信の下書きを作って返信欄に入れる**。
運営は画面から離れず、待つだけでよい。

- 返信欄の上に青い帯で「**AI が作った下書きです。内容を確かめて、必要なら直してから送ってください。**」と作成時刻
- 見出し行のボタンは「作り直す」「下書きを消す」
- 返信欄の下書きは**そのまま直せる**
- 送るのは「返信する」を押したときだけ。**自動では送らない**

**AI に渡す材料は 3 つだけ**

1. そのチケットのやり取り
2. その契約先の契約情報（プラン・契約状態・店舗数）
3. musubo の機能情報（マニュアル・ヘルプ）

**渡さないもの**: 契約先の友だちの個人情報、ほかの契約先の情報、秘密情報。

作成に失敗しても返信欄は空のまま使える。手で書く邪魔をしない。

### 37-7 お知らせ配信（`q2CokV`）

- 宛先: すべての契約先／プラン別／契約先を選ぶ。
  「15 件の契約先・24 人の権限者。うち契約者専用 LINE に登録済みの 21 人へ届きます」と出す
- 件名・本文・公開日時（予約）
- **送り方の既定は「契約者専用 LINE」＋「画面のお知らせ」**。メールは任意
- 配信済みの一覧: 件名・宛先・配信日時・LINE 既読
- LINE 未登録の権限者には届かない。配信結果にその理由を残す

### 37-8 監査ログ（`oEzZz`）

- 絞り込み: すべて／代理ログイン／個人情報の表示／契約先の停止／上限の変更
- 期間の指定と「CSV で書き出す」
- 表: 日時・運営者・契約先・操作・理由・IP
- **代理ログイン（書き込み）と個人情報を表示は赤**、契約先を停止とトライアル延長は橙、代理ログイン（閲覧）は無彩色

### 37-9 アカウントメニューを開く（`pxiUt`）

- 左下のログイン中アカウントを押すと、上に 300px のメニューが開く
- **メニューの幅はサイドメニュー（256px）の内側に収める。** はみ出させない
- 上段に 氏名・メール・権限の札（運営マスター）・2 要素認証の状態
- 項目: プロフィールを編集 ／ **メンバー管理** ／ 2 要素認証の設定 ／ ログアウト（赤）

### 37-10 メンバー管理（`POteo`）

- アカウントメニューから入る。**サイドメニューには出さない**
- タブ: 権限者／運営の情報
- 数値カード: 運営メンバー／2 要素認証／今月の代理ログイン／今月の個人情報の表示
- 注意帯「運営メンバーの追加と削除には、ほかの運営メンバーの承認が必要です。2 要素認証は必須です。」
- 表: 名前（自分には「（あなた）」）・メール・2 要素認証・状態・最終ログイン・操作

契約者専用 LINE（`@540qlkhn`）

- **運営専用の LINE 公式アカウントとして扱い、顧客テナントの `line_accounts` とは分ける**
- 受信は Webhook。署名検証・再送・重複処理は既存の LINE Webhook 基盤の方式に合わせる
- 送信は push message。送信の成否を記録する
- 同じメッセージが二重に届いても、チケットとメッセージが二重にならないこと（冪等）

AI（下書き）

- 使うモデルは **Gemini Flash**（2026-09-15 Masato の意向）。Google の Gemini API を musubo の Worker から呼ぶ
- 呼び出しの鍵は環境変数 `GEMINI_API_KEY`（Worker の secret）。値は画面にもログにも Git にも出さない
- 課金は API の利用量による（月額プランの一部ではない）。Flash は単価が低く、無料枠もある
- **無料枠は入力が Google のサービス改善に使われることがある**ため、契約先のやり取りを渡す本番では**有料枠（データを学習に使わない設定）**にする → 9 章で要確認
- 渡す材料の制限（友だちの個人情報・ほかの契約先・秘密情報を渡さない）はモデルに関係なく守る

既存の利用

- 認証: `admin-auth.ts` の LINE ログイン・TOTP・step-up
- 契約: `tenants` の `plan_key` / `plan_status` / `trial_ends_at` / `stripe_customer_id` / `stripe_subscription_id`（V6 36）
- 課金: Stripe。**Stripe 以外の契約は無い**ため手動請求の仕組みは作らない

## 5. 権限

| 操作 | 運営マスター | 統括のオーナー | 統括の管理者 |
|---|---|---|---|
| `/ops` に入る | 可 | 不可 | 不可 |
| 契約先の作成・停止 | 可 | 不可 | 不可 |
| 代理ログイン（閲覧） | 可 | 不可 | 不可 |
| 代理ログイン（書き込み・理由必須） | 可 | 不可 | 不可 |
| 個人情報の一時表示 | 可（理由必須） | ― | ― |
| チケットの返信・クローズ | 可 | 不可 | 不可 |
| お知らせの配信 | 可 | 不可 | 不可 |
| 運営メンバーの招待・変更 | 可（他の運営メンバーの承認が要る） | 不可 | 不可 |

`staff_members.role` の `owner` / `admin` とは別の軸として扱う。書き込み系 API は読み取り専用の権限を拒否する。

## 6. セキュリティ要件

1. `canManageTenants()` の「既定の統括の owner」判定を廃止し、`platform_admins` による明示判定に置き換える
2. 切り替えは **新しい判定を足す → マスター 3 名を登録 → 動作確認 → 旧判定を外す** の順で行う
3. LINE ログインでは、`platform_admins` に登録された LINE ユーザー ID だけを通す。
   登録が無い LINE アカウントは、たとえ契約者専用 LINE の友だちでも入れない
4. メール＋パスワードで入るときは 2 要素認証を必須とする
5. 代理ログイン中の操作は、通常の監査ログにも**運営の誰か**が分かる形で残す
6. 個人情報の表示は独立した権限として扱い、表示のたびに理由を記録する
7. 検証環境と本番環境で環境帯の色を変える
8. `/ops` の API はすべてサーバー側で権限を確認する。画面の出し分けに頼らない
9. 契約先 ID は必ず `tenants.id` と突合し、想定外の ID が混ざったら操作全体を実行しない
10. 契約者専用 LINE の Webhook は署名を検証する。**署名が合わないメッセージからチケットを作らない**
11. チケットの本文に個人情報が含まれることがあるため、チケットの閲覧も監査ログに残す
12. **AI へ渡す材料に、契約先の友だちの個人情報・ほかの契約先の情報・秘密情報を含めない**
13. AI へ渡した内容と、返ってきた下書きを、そのまま全文ログに出さない
14. AI の接続情報は環境変数で持ち、値を画面・ログ・Git に出さない
15. 返信は「返信する」を押したときだけ送る。**AI の下書きを自動送信する経路を作らない**

## 7. 合格条件

ログインと権限

1. `platform_admins` に登録された LINE アカウントで `/ops` にログインできる
2. 登録されていない LINE アカウントではログインできない（契約者専用 LINE の友だちでも入れない）
3. メール＋パスワードで入るときは、2 要素認証を通さないと入れない
4. 統括のオーナー・管理者で `/ops` の API を呼ぶと 403。データは変わらない
5. 読み取り専用の権限で書き込み系 API を呼ぶと 403

契約先

6. 契約先一覧に、検証 DB の `tenants` の件数と同じ数の行が出る
7. 契約先を 1 件停止すると `tenants.status` が `suspended` になり、監査ログが 1 件増える

代理ログイン

8. 代理ログインすると統括の画面が開き、赤い帯が常時出る
9. 閲覧のみの状態で書き込み API を呼ぶと 403。データは変わらない
10. 理由を入れて書き込みに切り替えると書き込める。`impersonation_sessions` に理由が記録される
11. 閲覧だけで終えた代理ログインは、**契約先側の履歴に出ない**
12. 書き込みをした代理ログインは、**契約先側の履歴に出る**
13. 代理ログイン中、友だちの氏名が「友だち#1041」の形で伏せられ、会話は件数のみ
14. 理由を入れて個人情報を表示すると氏名が出て、`pii_reveal_logs` が 1 件増える。終えると元に戻る

チケット

15. 管理画面のお問い合わせを送ると `ops_tickets` が 1 件増え、状態が「新規」・受付が「管理画面」になる
16. 契約者専用 LINE にメッセージを送ると、受付が「LINE」のチケットが立つ
17. 同じ人が続けて送ると、**チケットは増えず** `ops_ticket_messages` だけが増える
18. クローズしたあとに同じ人が送ると、**新しいチケットが 1 件立つ**
19. 返信すると状態が「対応中」になり、登録メールに届き、契約者専用 LINE に通知が飛ぶ
20. 同じ Webhook が二重に届いても、チケットもメッセージも二重にならない
21. 署名が合わない Webhook からはチケットが作られない
22. 状態タブの件数の合計が、すべての件数と一致する
23. 新しいチケットの**件名が自動で入り**、「自動で付けた件名」の印が出る。運営が直すと印が消える
24. チケットを選ぶと、同じ画面の右側に内容が出て、そのまま返信できる（別画面へ遷移しない）

AI の下書き

25. 「AI で下書きを作る」を押すと、すぐに「作成中…」に変わってボタンが押せなくなり、青い帯が出る
26. 検証環境で、押してから下書きが入るまで **15 秒以内**
27. 「待たずに手で書く」を押すと作成をやめ、空の返信欄で書き始められる
28. 30 秒を超えると打ち切られ、やり直すか手で書けることが画面に出る
29. 下書きが入ると「AI が作った下書きです」の帯と作成時刻が出る
30. AI へ渡した内容に、契約先の友だちの個人情報・ほかの契約先の情報・秘密情報が含まれない
31. 下書きが入っただけでは送られない。「返信する」を押して初めて送られる
32. AI の作成に失敗しても、返信欄は空のまま手で書ける
33. AI の接続情報が画面・ログに出ない

お知らせ

34. お知らせを配信すると、**LINE 登録済みの権限者にだけ届く**。未登録者には届かず、理由が配信結果に残る
35. 予約した日時より前には届かない

ダッシュボード

36. 棒グラフの 6 本が直近 6 か月に対応し、当月だけ濃い色になる。**目標線は無い**
37. 円グラフの 4 区分の件数の合計が、中央の総数と一致する

その他

38. 検証環境でもマスターコンソールが動き、環境帯の色が本番と違う
39. サイドメニューは 5 項目で、メンバー管理は左下のアカウントメニューからだけ開ける
40. 左下のアカウントメニューが、サイドメニューの幅からはみ出さない
41. 既存の統括コンソール・店舗の画面が今までどおり動く
42. 1440px・1920px で横スクロールが出ない。設計画像と実装画像の目視比較で一致
43. 型検査・ビルド・既存テストが通る
