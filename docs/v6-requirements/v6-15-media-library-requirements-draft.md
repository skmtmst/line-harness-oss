# V6 15 登録メディア 要件定義（実装照合版・下書き）

作成日: 2026-08-26
対象: V6「15 登録メディア」
対象範囲: 一覧、アップロード、詳細、プレビュー、使用先、差し替え、削除、容量、配信用派生ファイル

## 0. 結論と採点

V6を採用する。Lステップの登録メディア一覧より、使用先件数、予約中配信の警告、全使用先の一括差し替え、使用中削除の禁止が明確で、安全性と探しやすさで上回れる設計である。

ただし、そのまま実装すると危険または実現できない点が6つある。

1. V6の動画200MBは可能だが、現行のWorker経由base64アップロードでは通らない。ブラウザからR2へ直接アップロードする。
2. 「名前とURLは変わりません」のうち、管理用URLだけを固定する。LINEへ渡す実体URLは版ごとに変え、CDN・LINEの古いキャッシュを避ける。
3. 現行の使用先台帳は6時間ごとの本文検索で、最大500メディア・各参照先200件までである。削除判断の正本にはできないため、保存時に構造化参照を記録する。
4. 現行の`force=1`による使用中ファイルの削除を廃止する。代替へ差し替えるか、すべての使用先から外した後だけ削除できる。
5. MIMEはブラウザ申告と拡張子だけで判断しない。実ファイル形式、容量、寸法、時間、PDFの安全性を確認し、検査完了までは利用候補へ出さない。
6. 画像・動画・ファイルに加え、現行とLステップにある音声をV6へ残す。画像は利用先ごとのLINE制約に合う派生版を作る。

| 評価軸 | 現在 | 要件どおり実装後 |
|---|---:|---:|
| V6 UI・UX | 97 | 99 |
| Lステップ・Liny競争力 | 99 | 100 |
| 現行実装 | 70 | 98 |
| データ安全性 | 44 | 98 |
| 実現可能性 | 96 | 99 |
| 要件確定度 | 97 | 99 |

完全に不可能な画面はない。除外するのは、送信済みLINEメッセージ内の画像差し替え、使用中メディアの強制物理削除、URLを変えずにLINE側キャッシュまで必ず即時更新すること、任意形式のファイルをLINEメッセージとして直接送ること、秘密・個人情報を無期限の公開URLで配ること、ブラウザ申告だけによる安全判定である。

## 2. 達成すること

> 運用者が、配信や公開画面で使う素材を安全に登録し、どこで使われているかを理解してから差し替え・整理できる。

- 画像、動画、音声、PDFを複数まとめて登録する
- 各ファイルの検査、変換、進捗、失敗理由を1件ずつ確認する
- 名前、種類、フォルダ、登録者、日付、容量、寸法、時間で探す
- 全体・範囲別の使用容量と上限を確認する
- 配信、フォーム、リッチメニュー等から同じ選択部品で再利用する
- 使用先、状態、固定版、予約中・公開中を確認する
- 互換性を検査してから全使用先を別の素材へ差し替える
- 使用中は削除せず、アーカイブまたは差し替えへ案内する
- 実際にLINEへ送る形式・容量・縦横比・プレビューを自動で整える
- 公開素材と内部限定素材を分け、秘密・個人情報の公開を防ぐ

## 3. 用語を固定する

| 用語 | 意味 |
|---|---|
| メディア | 管理画面で再利用する素材の論理ID |
| 原本 | 運用者が登録した変換前ファイル |
| メディア版 | 差し替えごとに作られる変更不可の実体 |
| 派生ファイル | LINE画像、サムネイル、動画プレビュー等、用途別に作る実体 |
| 管理用URL | メディアIDを指す安定したURL。最新版の確認・ダウンロード用 |
| 配信用URL | 特定版・派生ファイルを指す変更不可URL |
| ライブ参照 | 実行時にメディアの公開最新版を使う参照 |
| 固定参照 | 指定したメディア版を使い続ける参照 |
| 使用先 | メディアIDまたは版を参照する定義・公開版・予約 |
| 検査中 | 保存済みだが形式・安全性・派生生成が未完了の状態 |
| 隔離 | 安全性または形式検査で利用不可になった状態 |
| アーカイブ | 新規選択を止め、実体と過去参照を残す状態 |

## 4. 画面とルート

| 画面 | ルート・状態 |
|---|---|
| 一覧 | `/contents` |
| 詳細・版履歴 | `/contents/{mediaId}` |
| アップロード | 一覧上の全面オーバーレイ |
| 差し替え | 詳細内または全面オーバーレイ |
| 使用先 | 詳細画面右欄。全件は`/contents/{mediaId}/usages` |
| 削除・差し替え確認 | 一覧上の全面オーバーレイ |

V6 15-1-B、15-1-Cは同じ一覧の状態であり、別ページを複製しない。戻る・閉じる後は起点のファイルへフォーカスを戻す。

## 5. 対応形式と利用制約

### 5-1. 登録形式

| 種類 | 受入形式 | 登録上限 | LINEでの利用 |
|---|---|---:|---|
| 画像 | JPEG、PNG、GIF、WebP | 10MB | 画像メッセージはJPEG/PNGのみ。GIF・WebPは派生版を作るかWeb用途限定 |
| 動画 | MP4 | 200MB | MP4、200MB以下。プレビューJPEG/PNGが必要 |
| 音声 | MP3、M4A | 200MB | duration必須 |
| ファイル | PDF | 20MB | LINEでは直接ファイル送信せず、リンクとして使う |

V6の「動画20分まで」はLINE APIの制約ではないため、ハード制限から外す。時間は表示し、長時間・大容量は読込時間の警告を出す。PDFは現行実装の20MBを残し、Lステップの10MBを上回る。ただし公開リンクになることを明示する。

### 5-2. 利用先別検査

- 画像メッセージ: 原本JPEG/PNG 10MB以下、プレビューJPEG/PNG 1MB以下、HTTPS
- 動画メッセージ: MP4 200MB以下、同じ縦横比のプレビューJPEG/PNG 1MB以下
- 音声メッセージ: MP3/M4A 200MB以下、durationを正確に持つ
- カルーセル・画像カルーセル: JPEG/PNG、縦横比・最大幅・容量を検査する
- リッチメニュー: LINE指定寸法・容量へ合わせる。勝手な拡大で画質を落とさない
- Flex・回答フォーム・Webページ: 各表示枠、代替テキスト、レスポンシブ表示を検査する
- PDF: HTTPSリンク、ダウンロード表示、公開範囲、期限を確認する

「登録できる」と「その場所で使える」を分ける。互換性がない素材は選択候補で無効にし、理由と直し方を出す。

## 6. アップロード

### 6-1. フロー

1. ファイル選択またはドラッグ
2. 件数、種類、申告容量をクライアントで事前確認
3. サーバがアップロードセッションとR2キーを発行
4. ブラウザからR2へ直接PUTまたはmultipart upload
5. ETag、容量、Content-Typeを付けて完了APIを呼ぶ
6. サーバがR2 HEAD、ファイルシグネチャ、メタデータを検査
7. 安全性検査と派生ファイル生成
8. `ready`になった素材だけ利用候補へ出す

200MB動画をJSON/base64へ変換し、Worker本文へ送らない。base64は容量を約3分の1増やし、メモリ負荷も高い。100MB超はCloudflareプランによりWorker到達前に413となるため、R2直接アップロードを正とする。

### 6-2. アップロードセッション

- 1回最大20件
- 各ファイルに`uploadId`、期限、対象アカウント、予定キー、最大容量、許可Content-Typeを持つ
- presigned URLは短い期限、1ファイル・1操作・1キーに限定する
- URLは秘密値としてログ・Slack・画面履歴へ残さない
- ブラウザOriginをR2 CORSで限定する
- 完了APIでETag、実容量、R2 object metadataを再検査する
- 同じハッシュの素材があれば、再登録せず既存利用を提案する
- 中断したmultipart uploadと孤児objectを期限後に掃除する

### 6-3. 進捗と失敗

V6の個別行を正本にする。

- 待機、アップロード中、検査中、変換中、完了、失敗、取消
- 進捗率、送信済み容量、推定残り時間
- 失敗理由と「この1件を再試行」
- 成功済みファイルは、別ファイル失敗時も失わない
- 画面を閉じても再開可能
- 上限超過、形式不正、通信切断、署名期限切れ、容量不足を分ける

## 7. ファイル検査と派生生成

### 7-1. 実ファイル検査

- MIME申告と拡張子だけでなくmagic bytesを確認する
- 画像の寸法・向き・アニメーション有無を実体から取得する
- 動画・音声のcodec、duration、縦横比を取得する
- PDFのページ数、暗号化、埋込スクリプト・添付を確認する
- 0byte、破損、途中送信、不一致は隔離する
- SHA-256等の内容ハッシュを保存する
- 検査前のファイルは公開しない

ブラウザから渡された`width`、`height`、`durationMs`を正本にしない。

### 7-2. 安全性

- SVG、HTML、JavaScript、実行ファイル、Office文書は初期版で受け付けない
- PDFはマルウェア検査完了まで隔離する
- EXIF位置情報・端末情報を表示し、公開派生版から削除する
- 公開配信URLに`X-Content-Type-Options: nosniff`を付ける
- PDF等は既定で`Content-Disposition: attachment`
- 内部確認用URLは認証または短期署名付きURLにする
- 公開URLへ顧客名、メールアドレス、元ファイル名等を含めない

### 7-3. 派生ファイル

必要なときだけ次を作る。

- 一覧サムネイル
- LINE画像原本用JPEG/PNG
- LINE画像プレビュー1MB以下
- カルーセル向け縦横比
- リッチメニュー向け指定寸法
- 動画プレビュー画像
- WebP等のWeb向け軽量版

自動変換が切抜きを伴う場合は、焦点位置とプレビュー確認を必須にする。元画像は保持し、再変換できるようにする。

## 8. 一覧・検索・容量

### 8-1. 一覧

カードに次を表示する。

- サムネイルまたは種類アイコン
- 表示名、拡張子、容量
- 画像寸法、動画・音声時間、PDFページ数
- 状態、登録者、登録日
- 使用先件数
- 公開・内部限定
- 現在版

ファイル名を途中改行せず省略し、`title`または詳細で全文を確認できるようにする。

### 8-2. 絞り込み・並び順

- すべて、画像、動画、音声、ファイル
- 未使用、使用中、予約中、公開中
- 上限に近い、検査中、失敗、アーカイブ
- フォルダ、登録者、登録日、容量範囲、寸法・時間
- 新しい順、古い順、容量が大きい順、使用数が多い順、名前順

検索対象は表示名、元ファイル名、メモ、タグ。検索0件とデータ0件を分ける。

### 8-3. 容量

- `organization_id`、`scope_type`、`scope_id`ごとに使用量と上限を持つ
- 原本、派生版、アーカイブ、アップロード途中を分けて表示する
- V6の`2.4GB / 10GB`を実集計で返す
- 80%、90%、100%で案内を変える
- 100%到達時は新規アップロードを止めるが、削除・差し替え・整理はできる
- 版保持期間とゴミ箱保持期間を容量計算へ含める
- R2全体容量を毎回一覧で走査せず、メタデータ台帳を集計する

## 9. 詳細・ダウンロード

- 原本の安全なプレビュー
- 種類、実寸、容量、時間、ページ数、codec
- 登録者、登録日、最新版作成者、変更理由
- 公開範囲、管理用URL、配信用URL
- 使用先と参照方法
- 版履歴
- 派生ファイルと各利用先適合状態
- ハッシュ、検査日時、検査状態

ダウンロードは権限を検査し、監査へ残す。内部限定素材は短期署名付きGETを発行する。公開素材のリンクコピー時は「URLを知る人が閲覧できる」ことを明示する。

## 10. 使用先台帳

### 10-1. 正規参照

新規保存はURL文字列ではなく、次を構造化して持つ。

- `media_id`
- `media_version_id`または`reference_mode=live`
- 利用場所のpath
- 利用目的
- 派生variant
- 代替テキスト

保存と同じ処理で`media_usages`を更新する。6時間ごとのLIKE検索は旧URL参照を拾う移行補助に限定する。

### 10-2. 使用先の種類

- テンプレート、一斉配信、シナリオ、リマインダ、自動応答
- リッチメニュー、回答フォーム、共通情報、予約、イベント、ウェビナー
- NEN配信、LINE通知、オートメーション、EC、外部連携
- 下書き、公開中、予約中、進行中、停止、アーカイブ済み
- ライブ参照、固定参照

現在の7種類だけで完了扱いにしない。上限500件・参照先200件による取りこぼしを削除判断に使わない。

## 11. 差し替えと版

### 11-1. 差し替え

差し替えは同じメディアIDへ新しい変更不可版を追加する。R2の既存キーを上書きしない。

1. 新ファイルをアップロード・隔離・検査する
2. 元版と種類・寸法・縦横比・容量・durationを比較する
3. 全使用先で互換性と変更後プレビューを計算する
4. 公開中・予約中・固定参照・ライブ参照を分ける
5. エラー0件で新しい版を公開する
6. ライブ参照だけを新しい版へ解決する
7. 固定参照は元版を維持する
8. 変更者、理由、影響件数を履歴へ残す

### 11-2. URL

- 管理用URLは同じメディアIDを指すため変わらない
- 配信用URLは`mediaVersionId`または内容ハッシュを含み、版ごとに変わる
- 配信用URLは`Cache-Control: public, max-age=31536000, immutable`
- 管理用URLは最新版へ302するか、認証画面を返し、immutableにしない

V6の「URLは変わりません」は管理用URLの説明へ限定する。同じ配信用URLのR2実体を上書きすると、CDNやLINE側に古い画像が残るため禁止する。

### 11-3. 予約中配信

14 共通情報と同じ規則を使う。

- 予約済み配信は固定参照を既定にする
- ライブ参照を明示選択した予約だけ、新版へ切り替わる
- 差し替え確認に、変更される予約と変更されない予約を分けて表示する
- 送信済みメッセージは変わらない

## 12. 削除・アーカイブ

### 12-1. 使用中

V6の削除禁止を正とする。

- 使用先1件以上は物理削除できない
- `force=1`をAPI・UIから廃止する
- 使用先を開く、別素材へ一括差し替え、アーカイブの3択を出す
- 影響台帳の最終更新が古い場合は再検査を完了するまで判断しない
- 権限外の使用先がある場合は件数だけ示し、管理者へ依頼させる

### 12-2. 未使用

- 未使用でも送信履歴・過去版がある場合はアーカイブ
- 物理削除は未使用、未公開、履歴なし、隔離中の未採用素材だけ
- 削除はDB行を先に消すのではなく、ジョブ状態を作り、R2削除・台帳確定を再開可能にする
- R2削除失敗は孤児object台帳へ残し、再試行する
- ゴミ箱保持期間と復元を持つ

## 14. API

| 操作 | API | 要点 |
|---|---|---|
| 一覧 | `GET /api/media` | cursor、検索、種類、状態、未使用、容量、範囲 |
| 詳細 | `GET /api/media/{id}` | 現版、派生、使用数、履歴、検査 |
| 容量 | `GET /api/media/quota` | 使用量、上限、内訳 |
| 開始 | `POST /api/media/upload-sessions` | 20件まで、署名付きURLまたはmultipart情報 |
| 完了 | `POST /api/media/upload-sessions/{id}/complete` | ETag・実体再検査、処理キュー |
| 取消 | `DELETE /api/media/upload-sessions/{id}` | multipart中止、孤児掃除 |
| 名前・フォルダ | `PATCH /api/media/{id}` | `If-Match`、範囲・権限 |
| 使用先 | `GET /api/media/{id}/usages` | 名前、状態、版、参照方法、遷移先 |
| 差し替えプレビュー | `POST /api/media/{id}/replacement-preview` | 全使用先互換性と変更前後 |
| 差し替え | `POST /api/media/{id}/versions` | previewToken、理由、新版公開 |
| 一括置換 | `POST /api/media/{id}/replace-usages` | 代替mediaId、previewToken、ジョブ |
| アーカイブ | `POST /api/media/{id}/archive` | 新規利用停止、履歴保持 |
| 削除 | `DELETE /api/media/{id}` | 未使用・未公開・履歴なしのみ |
| ダウンロード | `POST /api/media/{id}/download-url` | 権限、短期URL、監査 |

サーバ一覧は200件固定取得とクライアントページングをやめ、cursor paginationにする。使用数と次の状態を一覧APIで返し、各カードのN+1を避ける。

## 15. 権限・監査

- `media.read`
- `media.upload`
- `media.download`
- `media.rename`
- `media.replace`
- `media.archive`
- `media.delete`
- `media.quarantine.manage`
- `media.audit.read`

各権限にアカウント範囲を適用する。APIから権限外のファイル名、プレビュー、URL、使用先本文を返さない。

監査対象:

- アップロード開始・完了・失敗・隔離解除
- プレビュー、ダウンロード、公開URLコピー
- 名前・フォルダ・公開範囲変更
- 差し替え、公開版変更、使用先一括置換
- アーカイブ、復元、削除
- 容量上限変更

## 16. 状態・アクセシビリティ

画面状態:

- 読込中
- データ0件と作成導線
- 検索0件と条件解除
- APIエラーと再試行
- 権限不足
- 容量80%・90%・100%
- アップロード・検査・変換中
- 部分成功
- 形式不正・安全性失敗・隔離
- 競合更新
- 使用中で削除不可
- 差し替え互換性エラー

アクセシビリティ:

- ドラッグ以外にファイル選択を必須にする
- ファイル入力、個別進捗、失敗をスクリーンリーダーへ通知する

- モーダルはフォーカストラップ、Esc、復帰先を持つ
- サムネイルの管理用altはファイル名。配信時altは利用先ごとに設定する

- 200%拡大と1440px・1920pxで主要操作を失わない
- ファイル名は単語途中で改行せず、省略と全文確認を使う

## 19. 既存データ移行

### 19-1. 既存資産

新規構築と書かない。現行には次がある。

- `media`: 種類、名前、容量、寸法、duration、R2キー、フォルダ、登録者
- `media_usages`: 7種類の使用先
- R2保存と公開`/images/*`配信
- 画像・動画・音声・PDFアップロード
- MIME・拡張子・容量の基本検査
- フォルダ、検索、種類絞り、プレビュー、名前変更、使用先表示
- 6時間ごとの旧URL使用先スキャン

### 19-2. 移行手順

1. DB・R2バックアップ、DB行とR2 objectの相互照合
2. 孤児DB行、孤児object、重複ハッシュ、0byte、不正MIMEをdry-runで出す
3. 現行`media.id`を論理メディアIDとして維持する
4. 現行R2 objectを初版`media_versions`へ登録する
5. 実ファイルを非破壊で再検査し、メタデータとハッシュを補う
6. 現行URLを走査し、構造化使用先へ変換する
7. 旧URL読取を残したまま、新規保存だけID参照へ切り替える
8. 配信・フォーム等を機能ごとに新解決器へ切り替える
9. `force=1`削除を停止する
10. 未解決使用先0件、件数照合後に旧スキャンを補助へ降格する

### 19-3. 移行ゲート

- DB件数、R2件数、合計容量、種類別件数が一致
- 使用先台帳と旧スキャンの差を説明できる
- 予約中・公開中・進行中の全参照を抽出済み
- 既存公開URLが移行期間中も取得できる
- 画像、動画、音声、PDFを各1件以上実送信・実表示確認する
- ロールバック時に旧URL・旧DB行へ戻せる

## 23. 最終判断

V6の画面方向は正しい。残すべき差別化は、使用先、予約中警告、一括差し替え、使用中削除禁止である。

実装前に必ず直す要件は次の4点。

1. 200MB動画・音声はR2へ直接アップロードする
2. 管理URLと版ごとの配信用URLを分ける
3. 使用先を保存時に構造化し、強制削除を廃止する
4. 実ファイル検査・隔離・派生生成を行う

この4点を満たせば、Lステップの登録メディア機能を満たし、差し替え安全性、利用先の可視化、配信適合、監査で上回れる。
