# V6 36 統括アカウント・課金・お問い合わせ 要件定義（下書き）

作成日: 2026-09-12
対象: V6「36 統括アカウント」（統括コンソール /hq の左下アカウントメニューから入る画面と、フロントの会員登録）
対象範囲: アカウントメニュー、課金プラン、お問い合わせ、会員登録、メンバー管理
Pencil: `V6正本.pen` ★V6 36 系 5 画面。行は Y=224179（35 系の右）。

## 0. 結論

統括の「設定」タブを廃止し、Banas™ と同じく **左下のログイン中アカウント** から
プロフィール・メンバー管理・課金プラン・お問い合わせ・ログアウトへ入る。
会員登録（メール＋パスワード）で新しい統括が作られ、**1ヶ月の無料トライアル**のあと有料プラン 3 種（仮）に切り替わる。決済は Stripe（契約済み）。

`docs/v6-common-rules.md` §1-2 の「メニュー下端に何も置かない」は、統括の画面だけ例外とした（同日改訂）。

## 2. 達成すること

- 統括のどの画面からも、左下の自分の名前を押してアカウントメニューを開ける。トライアルの残り日数がそこに出る
- メンバー管理で、権限者の一覧・役割・担当店舗・状態・最終ログインを見て、招待・変更・再送できる（既存の `/hq/settings` の権限者機能をここへ移す。統括名の変更は「統括の情報」タブ）
- 課金プランで、いまの契約状態（トライアル中・期限・残り日数）と 3 つのプランを見て、Stripe Checkout でプランを選べる。支払い方法の管理は Stripe のカスタマーポータルへ
- お問い合わせを送れる。種類・件名・本文（必須）、関係する店舗・画像（任意）。控えが登録メールへ届き、過去の問い合わせと状態が見える
- 会員登録から統括名・名前・メール・パスワードで新しい統括を作り、確認メールのあとログインできる。登録日から 1 ヶ月はすべての機能が使える

## 3. 画面ごとの動き

### 36-1 アカウントメニュー（`qAvlC`）

- 左下ブロック: アバター（頭文字）、氏名、プランの札（無料トライアル／プラン名）、残り日数、上下矢印
- 押すと 300px のメニューが上に開く: 氏名・メール・プランと期限 ／ プロフィールを編集・メンバー管理・課金プラン・お問い合わせ ／ ログアウト（赤）
- メニューの外を押す・Esc で閉じる。項目は Tab で辿れる
- 統括のサイドメニューから「設定」を外す

### 36-2 課金プラン（`q7FP5k`）

- 契約状況の帯（黄）: 「無料トライアル中（期限・残り日数）」と、期限後の扱い。右に「支払い方法を管理」（Stripe ポータル）
- プラン 3 枚（仮）: ライト ¥9,800／スタンダード ¥29,800（おすすめ）／プロ ¥59,800。内容は LINE公式アカウント数・権限者数・配信通数・バナー生成の単位・登録メディア容量・ひな形配布・サポート
- 「このプランにする」→ Stripe Checkout（サブスクリプション）。戻り先で「手続き中」の帯を出し、Webhook 反映後に契約中へ変わる
- 契約中のプランは「利用中」の札。別プランは「変更する」。解約はポータル側
- 支払い履歴: 日付・内容・金額・状態・領収書リンク。無ければ空の文

### 36-3 お問い合わせ（`X6LZP`）

- 案内帯（返信先と目安）。フォーム: 種類（選択・必須）、件名（必須）、本文（必須・困っていること／期待する動き／起きた日時）、関係する店舗（任意）、画像（任意・3枚・5MB）
- 右: 送信者（統括・名前・メール・プラン）と、これまでの問い合わせ（件名・日付・状態）
- 下部追従バー: 左に控えの案内、中央に「内容をクリア」「送信する」
- 送信すると `support-inbox` の既存の受信箱へ入り、運営に通知される。送信者には控えメール

### 36-4 会員登録（`KYwCv`）

- 中央カード 520px: ロゴ、「無料で始める」、会社名・統括名、あなたの名前、メール、パスワード（8文字以上・英数）、確認、同意、主ボタン「無料で始める」、ログインへの導線、フッター（規約・プライバシー・特商法・お問い合わせ）
- 不一致・未入力はその項目の下に赤字。送信後は「確認メールを送りました」画面（別途）
- 登録で作られるもの: 統括（tenants）、オーナー権限者（staff_members）、トライアル期限（登録日＋30日）

### 36-5 メンバー管理（`CRL4w`）

- タブ: 権限者／統括の情報（統括名の変更）
- 右上「＋ 権限者を招待」（メール・役割・担当店舗）
- 数値カード帯: 権限者数（プラン上限）、招待中、閲覧のみ、担当店舗の割り当て
- 表: 名前（自分には「（あなた）」）、メール、役割の札、担当範囲、状態の札、最終ログイン、変更／再送

## 4. データと外部連携

- 認証: 既存の API キー＋Cookie セッションに、メール＋パスワード（ハッシュ）を併存させる。既存の権限者とログイン方法は変えない
- 統括: `tenants` に `trial_ends_at`、`plan_key`、`plan_status`、`stripe_customer_id`、`stripe_subscription_id` を追加（追加のみ）
- 課金: Stripe Checkout（subscription）、Customer Portal、Webhook（`checkout.session.completed` / `customer.subscription.updated` / `customer.subscription.deleted` / `invoice.paid`）。署名検証は既存の Stripe Webhook ルートの方式に合わせる
- お問い合わせ: 既存の support-inbox に「統括からの問い合わせ」として保存。メール送信は既存の送信経路
- 設定（秘密）: `STRIPE_SECRET_KEY`、`STRIPE_BILLING_WEBHOOK_SECRET`、価格 ID 3 つ（環境変数）

## 5. 権限

| 役割 | アカウントメニュー | メンバー管理 | 課金プラン | お問い合わせ |
|---|---|---|---|---|
| オーナー | 可 | 可 | 可 | 可 |
| 管理者 | 可 | 可（役割の昇格は不可） | 閲覧のみ | 可 |
| 担当者 | 可（プロフィールとお問い合わせのみ） | 不可 | 不可 | 可 |
| 閲覧のみ | 可（閲覧） | 閲覧 | 閲覧 | 可 |

## 6. 合格条件

1. 統括の全画面で左下にログイン中のアカウントが出て、メニューが開閉する。「設定」メニューが無い
2. メンバー管理で既存の権限者機能（追加・役割・担当店舗・状態）が今までどおり動く
3. 会員登録で新しい統括ができ、その統括でログインすると自分の統括だけが見える。トライアル期限が左下と課金プランに出る
4. Stripe Checkout（テストモード）でプランを選ぶと、Webhook 反映後に契約中になり、上限がプランの値に変わる
5. お問い合わせを送ると受信箱に入り、控えメールが届く
6. 1440px・1920px で横スクロールが出ない。設計画像と実装画像の目視比較で一致

## 7. 未決・要確認

- プランの価格と内容（仮置き）。Masato が決める
- トライアル終了後に配信を止めるか、閲覧のみにするか（設計は「配信と生成が止まり、データは90日保持」で仮置き）
- 会員登録の公開範囲（誰でも登録できるか、招待制か）
- 適格請求書の発行者と表記（Stripe の請求書設定）
