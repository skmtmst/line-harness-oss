# V6 25 オートメーション・共通アクション接続契約（カタログ正本）

更新日: 2026-09-03
位置づけ: 共通アクションのカタログと、V6の実行エンジンから既存処理・他機能の台帳を呼び出すときの境界を定める正本

## 0. この文書の扱い

- 共通アクションのカタログ（処理名、段、順番）はこの文書だけが持つ。`v6-shared-platform-requirements.md` §6-1 と `v6-25-automation-requirements-draft.md` §4-7 はカタログを再掲せず、段だけを引用する
- 処理名と順番は §1 の表のとおりに全文書で使う。略称や別名を作らない
- 任意のcode、SQL、JSON式を処理として実行しない。各処理は入力schema、権限、副作用、冪等性を持つadapterとして実装する（共通基盤 §6-1）
- きっかけ側の契約は `v6-25-automation-trigger-contract.md`、画面・API・移行は `v6-25-automation-requirements-draft.md` が持つ

## 2. 共通ルール

- 友だちと参照先は、実行時のLINE公式アカウントと一致するものだけを使う
- タグ、テンプレート、送信Webhook、対応マーク、通知定義は、`line_account_id` が明示された行だけを使う
- 既存行の所属は名前などから推測して移さない。所属が `NULL` の行はV6から使わない
- 外部処理には処理実行IDを冪等キーとして渡し、再実行で同じ結果を増やさない
- 再試行の回数・間隔は §6 の分類に従う。処理ごとに独自の回数を持たない
- 他機能の台帳（17、19、24、27）へは、その機能の公開APIまたはservice経由で追記する。台帳テーブルへ直接INSERTしない
- 処理は上から順に実行する。各処理は失敗時の動き（止める・次へ進む）を持ち、既定は「止める」
- 実行前・成功・失敗・スキップを処理ごとに実行台帳へ残し、友だち詳細のタイムラインから追える

## 6. 再試行

再試行の既定は共通基盤 §6-2 の1表（決定事項 D7）に従う。この文書に独自の回数を書かない。

| 分類 | この契約での該当 |
|---|---|
| 外部 API の一時失敗 | LINE送信、リッチメニュー切替、予約・カレンダー操作。`429` は `Retry-After` を優先 |
| 送信 Webhook（26） | 外部Webhookへ送る。26 のみの例外値を使う |
| 内部処理 | タグ、友だち情報、シナリオ、対応マーク、担当者、マイル、通知定義の解決、条件分岐。入力不備・権限不一致・宛先なしは再試行せず恒久失敗 |
| 手動再試行 | 実行台帳の `automation.run.retry`。新しい attempt を作り、成功済みの処理は再実行しない |

一時失敗は `retry_wait`、恒久失敗は `permanent_failed` として記録する。`failed` 一語で両者を混ぜない。

## 7. Webhookの扱い

- 任意URLは処理定義へ保存せず、登録済みWebhookのIDだけを参照する
- URL内の認証情報、localhost、内部向けホスト名、プライベート・リンクローカルIPは拒否する
- 10秒で打ち切り、`429` と `5xx` と接続失敗だけを実行エンジンへ再試行可能として返す
- `Idempotency-Key` を送る。ただし相手側がこのキーを処理しない場合の完全な一度だけ配送は保証しない

## 8. 処理結果の状態名

処理ごとの結果は横断レビュー §4 の実行状態を使う。

`queued / claimed / succeeded / skipped / retry_wait / permanent_failed / cancelled`

- `skipped` は skip reason を持つ。条件外は `condition`、runtime gate 拒否は gate の名前、宛先0人は `no_recipient`
- 機能固有の状態として `waiting`（「待つ」で停止中）を追加する
- 現行実装の `success / failed / skipped_condition` は移行時にこの名前へ寄せる（本体 §8）

## 9. この契約の対象外

- 所属が不明な既存タグ、テンプレート、Webhookの自動振り分け
- 作成・編集・公開のAPIと画面（本体が持つ）
- 受信イベントからV6実行を開始するきっかけと定期ジョブ（きっかけ接続契約が持つ）
- Webhook配送1件ごとの独立台帳（V6 26 外部連携で実装）
- 第2期・第3期の処理種別の最終確定。接続PRで確定し、この表を更新する
