### A. 一斉配信の二者承認

- **対象**
  - 宛先数が閾値以上の、即時送信と予約送信の両方。
  - 閾値は機能設定の値で、既定は 1,000 通。宛先数は送信を確定する時点の数で判定する。
- **権限**
  - 承認の権限キーは `broadcast.approve`。owner・admin は既定で持つ。
  - 承認する人は、依頼した人とは別の人でなければならない。自分の依頼は API で拒否する（403）。
- **状態と期限**
  - 状態は「承認待ち」を足す。
  - 予約時刻を過ぎても承認されなければ、送らずに「期限切れ」にする。
  - 差し戻しは理由が必須。依頼した人は、依頼を取り消すことと、もう一度知らせることができる。
- **1人運用**（有効な運用者が1人の組織）
  - 承認の代わりに、送る人数の手入力を必須にする。
  - 実際の宛先数と一致しなければ 409 を返す。
- **二重送信の防止**
  - 承認されてから既存の送信に渡す。渡すときは、状態の条件付き更新で二重送信を防ぐ。
- **合格**
  - 閾値未満は今までどおり送れる。
  - 閾値以上は承認が済むまで送られない。
  - 自己承認は 403 になる。
  - 期限を過ぎたら送られない。
  - 1人運用で人数が一致しなければ 409 になる。

### B. 危険なファイルの検査

- **対象**
  - ファイルを上げる口すべて。メディア・添付・写真の投稿・フォームの添付・友だち属性の画像/PDF など。
- **検査の順番**
  1. 中身の形（magic bytes）と、拡張子・MIME の一致
  2. 許可された形式か
  3. 大きさ・画素が上限内か
  4. 読めるか
  5. 危険な中身がないか
- **危険な中身の検査**
  - 差し替えられる作り（scanner の口）にする。
  - 既定は内蔵の簡易検査。次のものを見つけたら「しまう」。
    - 画像の後ろに付いたデータ
    - PDF の JavaScript・埋め込みファイル・起動の指示
    - Office のマクロ
    - 実行ファイルの印
  - 外部の検査サービスは、設定があるときだけ使う。
- **状態**
  - `pending` → `clean` ／ `rejected`（理由のコード）／ `quarantined`
  - clean になるまで、配信・公開・審査・LIFF に出さない。URL も返さない。
- **検査が止まっているとき**
  - 検査の仕組みが動かないときは pending のまま自動で再試行し、clean にしない。
- **しまったファイル**
  - 一覧は owner・admin だけが見られる。
  - 中身は開かない。
  - 消すことと、誤りだったので戻すこと（理由必須）ができる。
- **合格**
  - 名前だけ .jpg の別形式は rejected になる。
  - 実行ファイルの印を持つファイルは quarantined になる。
  - pending のファイルの URL は、どの口からも取れない。

### C. 一斉配信の宛先台帳・記録・10の状態（#816）

- **10の状態**
  - 主な流れ：下書き → 承認待ち → 予約済み → 送信準備 → 送信中 → 送信済み
  - 分かれ道：一部失敗・失敗・停止・期限切れ
- **宛先台帳**
  - 宛先ごとに、結果（届いた・失敗の理由・送る前）・時刻・LINE の要求 ID を残す。
  - 失敗の理由は人の言葉で出す（ブロック・友だちでない・一時的）。
  - 一時的な失敗だけを再送できる。
- **記録**
  - 作成・編集・承認の依頼・承認・差し戻し・予約・送信・停止・再送を残す。消せない。
- **既存の配信**
  - 完了済みの配信の宛先台帳は捏造しない。集約だけの旧配信として残す。
- **合格**
  - 送信の途中で止めると、まだの宛先には送られず、台帳に「送る前」が残る。
  - 再送は、一時的な失敗の宛先だけに送られる。

### D＋F. 写真の重複と報酬の決まりの版（#817）

- **重複の判定**
  - 完全に同じ写真は、中身の hash で「重複」とする。
  - 似ている写真は「注意」の札だけを付け、自動では却下しない。
- **前の投稿が採用済みのとき**
  - 前の投稿と並べて見せる。
  - 選べるのは「却下」か「報酬なしで採用」。
- **報酬の決まり**
  - 版を持つ（D の部品）。
  - 採用した時点の版を、付与の記録に写しとして持つ。
- **合格**
  - 同じ写真が2回採用されても、報酬は1回だけ。
  - 版を変えても、過去の付与は変わらない。

### H. 流入の広告費の取り込みとサイト計測の同意（#818）

- **広告費**
  - 広告の管理画面から毎日取り込む。取り込む口は、秘密を暗号化して保管している外部連携を使う。
  - 取り込めない日は「—」と最終取り込みの日時を出す。
  - 手入力も許す。手入力の分には「手入力」の札を付ける。
  - 1人あたりの費用 ＝ 費用 ÷ 友だち追加。
- **同意**
  - 同意の前は計測しない。
  - 管理画面には、同意した割合と、同意がなくて数えなかった件数を出す。
- **合格**
  - 同意していない閲覧は、1件も記録されない。

### I. Web 計測の公開口と取り消しの記録（#819）

- **公開口**
  - 許可したドメインからの成果だけを受け付ける。
  - 許可にないドメインから来た分は受け付けず、件数と最後の来た先だけを出す。
- **タグ**
  - サイトごとの ID を使い、鍵はタグに含めない。
- **取り消し**
  - 取り消しは理由付きで、記録を足す。元の成果は消さず、合計からは引く。
  - 取り消しの取り消しも同じ形で記録する。
- **合格**
  - 許可外ドメインの成果は数えない。
  - 取り消しても元の記録は残る。

### D＋E. テンプレートの版の履歴と参照表（#820）

- **版**
  - 版は D の部品で扱う。
  - 送った配信は、送った時の版を指したままにする。
- **参照表**
  - どの一斉配信・シナリオ・自動応答が、どの版を使っているかを出す。
  - 予約済み・送信中の配信で使っているテンプレートは消せない（409、画面には理由の文）。
- **合格**
  - 版を変えても、送信済みの配信の中身は変わらない。
  - 使用中は消せない。

### J. ウェビナーの離脱（#821）

- **heartbeat**
  - 再生中だけ、15秒ごとに送る。
  - 状態を区別する：再生・一時停止・隠れた・読み込み待ち・位置の移動・速度。
- **異常値の除外**
  - サーバーが受け取った時刻を基準にする。
  - 位置の進み方が経過時間の2倍を超える値は、異常として除外する。
- **視聴と離脱の定義**
  - 視聴開始 ＝ 有効な区間が合計30秒以上。
  - 離脱の位置 ＝ 最後の有効な区間の終わり。最後に報告された位置で決めつけない。
- **画面**
  - 見ていた人の割合の線を出す。申し込みボタンが出た時刻に、縦の線を引く。
- **合格**
  - 一時停止や隠れている時間は、視聴に数えない。
  - 異常値は除外される。

### K. リッチメニューの公開の手順と照合（#822）

- **公開の手順**
  1. 画像を上げる
  2. メニューを作る
  3. 友だちに割り当てる
  4. 前のメニューを片付ける
  - 途中で失敗したら、それまでの段を元に戻し、前のメニューのままにする。
- **照合**
  - 毎日と、画面を開いた時に照合する。
  - ずれの種類ごとに直し方を1つ決め、直したら記録に残す。
- **公開の記録**
  - 版・公開の実行・ページの実行を台帳に残す。
- **合格**
  - 割り当てに失敗しても、友だちの画面は前のメニューのまま。
  - ずれを直すと、記録が残る。

### G. アフィリエイトの成果の付け方と案件の決まり（#823）

- **成果の付け方**
  - 期間内の紹介のうち、最後に開いたリンクに付ける。
  - 自分の紹介には付けない。
  - 付けなかった紹介には、その理由を記録する。
- **案件の決まり**
  - 案件ごとに、報酬・数える期間（既定30日）・上限（案件全体 ／ 1人あたりの月）・受付の期間を持つ。版は D の部品で扱う。
  - 上限に達したら、受付を自動で止める。紹介した人の画面にもそれを出す。
- **合格**
  - 同じ成果に2人分は付かない。
  - 上限を超えて付与されない。

### L. ダッシュボードの数字の出どころ（#824）

- **数字の元**
  - 数字の元を、通知の台帳（`source` の欄・`delivery_id`）につなぐ。
  - 同じ失敗は1件として数え、送り直しは数えない。
- **画面**
  - 新しい画面は作らない。
  - カードの「i」から、出どころと、いつ時点の数字かを見せる。
- **合格**
  - 台帳の件数と、ダッシュボードの数字が一致する。

## 3. 作る順番と PR の分け方

1. 安全に関わるものを先に作る：A・B・V
2. 他の機能が使う共通部品を作る：D（版の部品。#820 と一緒に作る）
3. 残りは、同じファイルに触れないものから並べて進める（同時に4本まで）

- 1つの記号を1つの PR にする。
- PR には `docs/release-log/unreleased/` の1行を付ける。
- migration の適用と配備は、オーナーの承認を得てから行う。
