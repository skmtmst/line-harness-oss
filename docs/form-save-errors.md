# 保存が失敗した時の表示

入力欄のある失敗は、その欄へ理由を出します。`SaveErrorScope`・`SaveErrorField`・`useFormErrors` を使い、欄名を結び付けます。繰り返す欄は番号付きの名前を渡します。

- 赤い印、理由、`aria-describedby`、最初の欄への移動を共通部品で扱います。値と入力DOMを保ち、打ち直した欄の理由だけを消します。
- 背景と編集窓に同じ欄がある時は、編集中の窓だけへ出します。横並びの欄、ラジオ、選択群、日時、フォルダ、素材選択も同じ扱いです。
- 認証コードの自動消去では理由を消しません。畳んだ設定は開いてから該当欄へ移ります。
- 店舗・対象・読込世代が変わった古い応答は捨てます。その判定後に欄の理由を受けます。
- 未知の欄や入力欄のない失敗は、全体の知らせも残します。競合・権限・通信失敗と、保存後の後片付けも維持します。
- APIエラーの変換や共通の保存関数は `fields` を落としません。段階式の入力は、理由のある段へ移ります。

`apps/web/src/app/form-save-errors-contract.test.ts` が保存失敗の受け口を検査します。欄の結び付け・フォーカス・打ち直し・競合は動作試験で確かめます。見た目の合格は [見た目の決まり](v8-design-rules.md) に従って別に確かめます。
