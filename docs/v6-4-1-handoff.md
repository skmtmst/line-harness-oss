## 1. タグAPIの3項目 — **接続済み**

Codex が `GET /api/tags?withCounts=1` に足した3つを、画面へ繋いだ（PR #376）。

| 列 | 出るもの | 取れないとき |
|---|---|---|
| 自動付与のもと | `assignSource` → EC連携／LINE Login／回答フォーム／EC購入／手動／誕生日ルール | **`—`**（「手動」と書かない） |
| 使用先 | `usedIn` → 「配信3・フォーム1」 | **「未使用」**（`withCounts=1` で読んでいるので、無い＝0件） |
| 連動の「他N」 | `otherActionCount` → 灰色の札 | 出さない（0件のときサーバーが省く） |

**`—` と「未使用」を書き分けている。**
`assignSource` は「いまのデータから出どころを断定できるものだけ」返る仕様
（`friend_tags` に付与元が残っていないため、一般のタグを manual と推測しない）。
断定できなかったものは `—`。いっぽう `usedIn` は集計した上で0件なら省かれるので、
「未使用」と言い切ってよい。**この2つを同じ `—` にまとめない。**

### 2-1. 使用中のタグを消させない（PR #381 / #383）

`GET /api/tags/:id/delete-impact` を、削除の確認を開いたときに叩く。

| 状態 | 削除ボタン | 確認欄 | 出す言葉 |
|---|---|---|---|
| 読み込み中 | 押せない | 使えない | 影響を確認しています |
| 失敗 | 押せない | 使えない | 影響を確認できませんでした |
| `canDelete: false` | 押せない | 使えない | 使用中のため削除できません（N件から参照されています） |
| `canDelete: true` | タグ名を入れたら押せる | 使える | — |

- **失敗も「押せない」側に入れる。** 参照が取れなかったのを「0件」と読み違えて、
  使用中のタグを消させないため
- `references` の18項目は**0件のものを出さない**。取れていないときは `—`（「なし」＝0件と書き分ける）
- `friendCount` は「タグが外れます」と警告するだけで、**削除は止めない**
- サーバーの `DELETE` でも同じ依存関係を再計算する。APIを直接呼んでも、
  `canDelete: false` なら409で断る。画面側の停止も二重の守りとして残す

### CSVについて

設計どおり「CSVで一括登録」から、選択 `H374MR`、確認 `sfTEW`、
完了 `op1rh`、一部失敗 `QzRsJ` を同じ操作で通す。登録できる行だけを保存し、
入らなかった行は理由付きCSVで書き出せる。未取得と0件を混ぜず、同名タグを
黙って更新しない。

## 4. 画面を見る手順

**これが無いと、設計と比べられない。** ローカルで開くのに4つ要る（`v6-shell-contract.md` §10）。

```bash
# 1. 共有パッケージを建てる（無いと全ルート500）
pnpm --filter "@line-crm/shared" --filter "@line-crm/line-sdk" --filter "@line-harness/update-engine" build

# 2. Workerの代わり（ローカル専用・GET以外は405・固定データ）
pnpm qa:mock

# 3. 管理画面
pnpm qa:web

# 4. 画像で比べる（1440・1920）
pnpm qa:shot
```

- `scripts/visual-qa/mock-api.mjs` … 本番では起動しない。更新は必ず失敗する
- `scripts/visual-qa/fixtures.mjs` … **Pencil の絵に書いてある値そのまま**。
  タグ101件・フォルダ6つ・KPI 4枚。**6件だけで比べない**（桁あふれも折り返しも
  ページ送りも出ず、「一致した」と言えてしまう）
- `scripts/visual-qa/routes.mjs` … 見張るルート。いま**12ルート × 1440/1920 ＋ 4-1の4状態 × 2 = 32件**。
  `NOT_READY` は空（ダッシュボード・分析・一斉配信・リッチメニュー・
  オートメーションの5つを直して入れた）。
  増やすときは、そのルートが本当に描けることを手で1回確かめてから足す
- `scripts/visual-qa/api-shapes.mjs` … 配列で返る口を `api.ts` から読む。**手で並べない**

**初回は基準の画像が無いので全件「失敗」になる。** 撮り終えてから
もう一度走らせると通る。基準画像は `capture.spec.mjs-snapshots/` に入る。

### 見張っている4つ

1. **そのURLに居るか。** `AuthGuard` は `router.replace('/login')` で飛ばすので、
   エラーの文言はどこにも出ない。行き先のURLを見ないと、ログイン画面を
   撮って「通過」になる（実際に24件そうなった）
2. 描けているか（「画面を表示できませんでした」「店舗が選ばれていません」が出ていない）
3. **1440px と 1920px の両方で横スクロールが出ていないか**
4. 前回の画像と変わっていないか

### 違ってよい点の数は **0**

割合（`maxDiffPixelRatio`）にすると、縦に長い画面ほど甘くなる。
1920pxの1枚で 0.2% は約4,000点あり、**開発表示の丸い印（3,804点）が
丸ごと通った**。数に変えても120では「が」を「は」に変えた1文字（約70点）が
通ってしまう。乱数も時刻も使わず、開発表示は撮る瞬間に消す
（`screenshot.css`）ので、同じ絵はそっくり同じになる。**0で3回続けて通る**ことと、
**1文字変えると落ちる**ことの両方を確かめてある。

### 落ちたときに多いもの

**`◯◯.filter is not a function`** ／ **`undefined の ◯◯ が読めない`。**
モックの返す形の取り違え。配列で返る口は `api.ts` から自動で読んでいるので
**手で足さない**。足りないのは器のほう（`mock-api.mjs` の `SHAPES`）。
**推測で足さない。落ちた画面のコンソールを見て、その口の形だけを足す。**

## 6. 4状態（設計 ★V6 4-2-C `yKEdO`）

**ふつうの状態だけ合わせて「一致した」と言わない。** 4つを別々の画像で見張る。

| 状態 | 出るもの | 設計の部品 |
|---|---|---|
| 読込 | 輪 ＋「読み込んでいます」 | `sZE9Q` |
| 空（1件も無い） | 受け皿 ＋「まだタグがありません」 | `BDOJu` |
| 空（絞り込みに合わない） | 受け皿 ＋「条件に合うタグはありません」 | `BDOJu` |
| エラー | 赤い三角 ＋「表示できませんでした」 | `OLMp0` |
| 権限不足 | 錠 ＋「表示する権限がありません」 | **設計に部品が無い** |

- 共通部品は `components/shared/list-state.tsx`。高さ132・`$surface-pearl`・
  `$radius-md`・padding 24・gap 8・中央寄せ。**設計の実測値そのまま**
- **権限不足の絵は設計に無い。** 設計は「権限不足とエラーは今までどおり」と
  しか決めていない（`v6-design-review-handoff.md`）。`BDOJu` と同じ枠のまま
  絵と文言だけ変えている。**専用の絵が描かれたら合わせ直す**
- 403 は `error` と分ける。「壊れた」と出すと、直らない再読み込みを繰り返させる
- **中身を出せていないあいだは数を出さない。** フォルダの件数も、
  「1〜20 / 101件」も、ページ送りも `—` か非表示。0件と出すと消えたように見える
- 権限が無いときは「フォルダを追加」「＋ タグを追加」「CSVで一括登録」を出さない

画像は `tags-loading` / `tags-empty` / `tags-error` / `tags-forbidden` の
各1440・1920。差し替えは**ブラウザ側だけ**で、モックは触らない
（触ると他の画面の画像まで変わる）。

### 削除の確認（設計 `★ V6 4-1-F` `dKlkz`）

**本物を開いて撮る。** 作り物の絵を別ルートに置くと、実際に押したときの
画面とずれても誰も気づかない。影響は5行（付与人数・参照先・参照先（自動）・
連動の停止・積んだマイル）で、それぞれ「名前・値・結果」の3列。
**値が取れないときは `—`。0とは書かない。**
2026-08-26 まで「参照 3件」「自動付与の参照 1件」が**べた書き**だった。

**2枚撮る。**

| 画像 | 何を見る |
|---|---|
| `tags-delete` | 使用中で止まる絵（設計1行目・配信3/フォーム1から参照） |
| `tags-delete-ok` | 消せる絵（どこからも参照されていない） |

片方だけ見ていると、「押せないほうが正しい」のか「押せるべきなのに
押せない」のか分からない。画像だけでなく、**押せる／押せないも試験で見る**
（名前を入れると押せるようになるところまで）。
