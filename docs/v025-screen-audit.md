## 1. ダッシュボード（`EgKGw`）

**設計**: `Head → Alert → KPIs → 出荷予定 → Body(2カラム) → Bottom`

| 要素 | 実装 | 判定 |
|---|---|---|
| Head（期間チップ・再読み込み） | 実装済み | ○ |
| Alert | **「即時対応が必要です」の赤い帯が残っている** | × |
| KPIs 4枚 | 実装済み | ○ |
| 出荷予定 | 実装済み | ○ |
| Body 左：対応が必要な受信 | **無い**（内容は上の赤い帯の中） | × |
| Body 左：友だち数の推移 | 実装済み | ○ |
| Body 右：ケアが必要な子 | **無い** | × |
| Body 右：対応状況／今月の配信／直近の成果 | 実装済み | ○ |
| Bottom（友だち追加リンク） | 実装済み | ○ |

**直すこと**

1. 赤い帯（`SupportAlertPanel`）を左カラムの「対応が必要な受信」カードにする
2. 上部の Alert は「ケアが必要な子が◯頭います」にする（健康記録の連続検知が要る）

## 2. 受信箱（`nR2FI`）

**設計**: `Head → KPIs → Filters → Panes(360/862/320)`

| 要素 | 実装 | 判定 |
|---|---|---|
| Head | 実装済み | ○ |
| KPIs 4枚 | 実装済み。ただし4枚目が「メールの受信」（設計は平均の初回返信） | △ |
| Filters（チャネル／状態／表示） | チャネルをタブからチップに変更。状態は一覧の中 | ○ |
| Panes 一覧（360） | 幅を360に。**名前で検索**と**状態バッジ**を追加 | ○ |
| Panes トーク（862） | **「対応 ▾」「担当 ▾」を上部に追加**。入力欄のテンプレート選択は未 | △ |
| Panes 友だち詳細（320） | **幅320で常時表示に変更**。未選択時は案内を出す | ○ |

**残っていること**

1. 入力欄に「テンプレートを選択」
2. KPI 4枚目を平均の初回返信に（`107` で `first_replied_at` の列は用意済み。
   送信時に記録する処理と、平均を出す集計がまだ）
3. 右ペインの中身（マイル／★つき情報／リッチメニュー／実行型情報／フォーム回答）が
   設計どおりか未確認。`FriendInfoSidebar` の中を見ていない

## 3. 友だち（`P2guNv`）

**設計**: `Head → KPIs → Tabs → SearchBar → SavedChips → BulkBar → Table`

| 要素 | 実装 | 判定 |
|---|---|---|
| Head（マニュアル／CSVで書き出す／一括アクション） | 見出しのみ。**3つのボタンが無い** | △ |
| KPIs 4枚 | 実装済み | ○ |
| Tabs | **位置が違う**（Head の上にある）。件数バッジが無い。呼び名も違う（統合ユーザー／設計はアカウント横断の名寄せ） | × |
| SearchBar（詳細検索／保存した検索／並び順／表示件数） | 検索・タグ・対応マークのみ。**詳細検索と保存した検索が無い** | △ |
| SavedChips（保存済みの条件） | **無い** | × |
| BulkBar（選択時の一括操作6種） | **無い** | × |
| Table | 列順が違う（設計は名前が先）。**最終接触の列が無い**。★つきタグの列が無い | △ |

**直すこと**

1. タブを Head と KPI の下へ。件数バッジと呼び名
2. 検索行に詳細検索・保存した検索・表示件数
3. 保存済みチップの行
4. 一括操作バー（対応マークを変える／テンプレートを送る／シナリオを開始／タグを付ける・外す／友だち情報を書き換える／リマインダを開始）
5. 表の列順と最終接触

## この文書の使い方

画面を直すたびに、その行を更新する。**「○」にするのは骨格ではなく
中身まで合ったときだけ。** そうしないと、この表を見た人が
「もう合っている」と判断して次に進んでしまう。
