# Pen.dev V5/V6 基本設計の全面入替計画

作成日: 2026-08-24

対象: LINE Harness 管理画面全体

状態: **実装前の確認待ち**

## 1. 結論

個別ページを先に細かく直すのではなく、先に管理画面の基本設計をPen.devのV5/V6へ入れ替える。

この順番にすると、共通のメニュー、ページ枠、文字、色、カード、ボタン、表、入力、モーダル、読込中・空・失敗の表示が各ページへ同時に届く。その後のページ移行は、ページ固有の配置と機能差分へ集中できる。

ただし、基本設計を変えるだけで全ページが自動的に100%Pen.devどおりになるわけではない。現在は画面内へ直接書かれた色・角丸・影・寸法・ボタン・表が多く、共通部品を通っていない箇所には変更が届かないためである。

目標を次の2段階に分ける。

1. **基本設計の全面入替**: 共通部分をV5/V6へ統一し、既存ページ全体をPen.devに近い土台へ載せ替える。
2. **1ページずつの正確な移行**: Pen.dev画像、機能差分、状態を確認し、ページ固有の部分を一致させる。

ダッシュボードV5の詳細実装は、段階1が終わってから行う。

## 2. 設計の優先順位

1. 基本設計はV5を使う。
2. 対象部品または対象画面にV6がある場合だけ、その差をV6 variantとして使う。
3. V6に差がない部品はV5の共通部品を使う。
4. 見た目が似ていても意味や操作が違うものは、無理に1部品へまとめない。
5. Pencilの正本を先に変更し、その後コード契約へ写す。

V5とV6を別々のデザインシステムとして二重管理しない。V5を基本にし、確認できた差だけを名前付きvariantへ固定する。

## 3. 基本設計を替えると、どこまで自動で変わるか

| 変更する場所 | 自動的に変わる範囲 | 自動では変わらない範囲 |
|---|---|---|
| 色・文字・角丸・影のトークン | その変数を使う全ページ | `#fff`、`rounded-[18px]`、`shadow-[...]` 等の直書き |
| `AppShell` / `Sidebar` | 原則すべての管理画面 | ページ本体の独自余白・独自ヘッダー |
| 共通 `Button` | その部品を使う操作 | `<button className="...">` の直書き |
| 共通 `SummaryCard` / `Card` | その部品を使うカード | ページ内の独自カード枠 |
| 共通 `TableHeadRow` / `Th` | その部品を使う表 | 直書きの `<th>` と独自行 |
| 共通 `Field` / `Select` | その部品を使う入力 | 画面内の直接 `input` / `select` |
| 共通 `Dialog` / `Drawer` | その土台を使う重なり画面 | 画面内の `fixed inset-0` 直書き |
| 共通データ状態 | その部品を使う領域 | 「読み込み中…」等の画面別表示 |

このため、基本設計の実装と同時に、既存の直書きを安全に共通部品へ載せ替える工程が必要である。

## 4. 現在地

### 4-1. できていること

- V5/V6の変更トークン12件はコードへ反映済み。
- サマリーカード、標準ボタン、表見出し、ページ切替の4系統は契約済み。
- ビルド後CSSの照合、影響レポート、設計負債ゲートがある。
- Pen.devの再利用部品85件を確認済み。
- 画面移行の開始・完了チェックリストがある。

### 4-2. 基本設計として不足していること

Pen.devの再利用部品85件に対し、コード契約済みは4系統である。現在の主な設計負債基準は次である。

| 指標 | 現在 |
|---|---:|
| 任意値記法 | 1,482 |
| 解決できない `className` | 467 |
| 主要ボタン直書き | 154 |
| 副次ボタン直書き | 301 |
| `<th>` 直書き | 303 |

これらをすべて単純置換するのではない。意味とPen.dev部品が一致するものを共通部品へ移し、ページ固有の配置値だけを残す。

### 4-3. 既存の共通部品にも再設計が必要

コードには `Header`、`MergedTabs`、`Field`、`ConfirmDialog`、`ListToolbar`、`FolderPanel` などがある。しかし、Pencilの実Node ID、全状態、寸法、フォーカス、影響先が契約されていないものは、基本設計の移行済みとは扱わない。

既存部品を捨てて同じ機能を作り直すのではなく、機能を保ちながらV5/V6契約へ昇格させる。

## 5. 全面入替の対象

### 5-1. 画面の土台

| 分類 | Pen.dev候補 | 必要な状態 |
|---|---|---|
| 画面枠・正式共通メニュー | `J33xq` | 通常、選択、件数バッジ、権限非表示、アカウント切替、狭い幅 |
| ページヘッダー | ダッシュボード等の各Head | 題、説明、右操作、長い題、折返し |
| パンくず | `R098Z` | 先頭、中間、現在地、長い階層、省略 |
| ページ内タブ | `z9TQJ`、`VPn1F`、`ISA1Q` | 通常、選択、hover、focus、無効、件数 |

`AppShell` の `data-design-shell="v4-1920"`、V4を正本とするコメント・テスト・文書は、V5の正式共通設計へ更新する。

### 5-2. 表面と文字

| 分類 | 方針 |
|---|---|
| 本体背景 | `$canvas`、`$surface-pearl` 等の意味を固定 |
| カード | 枠、角丸、影、内側余白を共通 `Card` へ固定 |
| カード見出し | `t0jk8p` を候補に、題、補足、右操作、区切りを固定 |
| 文字 | 題、本文、ラベル、補足、数値、バッジをトークン化 |
| 状態バッジ | `crE5N`、`j9cdlp`、`hjekI`、`xRvDB` を意味別に固定 |
| アイコン操作 | `yujK7`、`K65Uhe`、`Ls12y`、`y0Ye5q` を説明ラベル込みで固定 |

カードごとに `rounded-[...]`、`shadow-[...]`、生の文字サイズを追加しない。

### 5-3. 操作部品

| 分類 | Pen.dev候補 | 必要な状態 |
|---|---|---|
| 標準ボタン | `nBRKk`、`uzNEC` | 契約済み。リンク、無効、処理中、focusを補強 |
| 入力欄 | `ytG7l` | ラベル、必須、説明、通常、読取専用、無効、エラー |
| 複数行入力 | `keKe3` | 文字数、高さ、エラー、リサイズ |
| プルダウン | `rpot9`、`Gfsb4`、`QB99A` | 閉、開、選択、未選択、無効、検索、キーボード |
| 検索 | `phlR1` | 入力、消去、検索中、0件 |
| その他操作メニュー | `H0V8EK` | 開閉、危険操作、外側クリック、focus復帰 |
| スイッチ | ダッシュボード編集等 | ON、OFF、無効、処理中、ラベル |

入力の見た目だけでなく、ラベル、説明、エラーの関連付けを部品APIで強制する。

### 5-4. 表と一覧

| 分類 | Pen.dev候補 | 方針 |
|---|---|---|
| 表見出し | `tPTMp` | 契約済み。`scope`既定とコントラスト判断を追加 |
| 表本体 | `AWHUI` 内候補 | 行高、セル余白、hover、選択、最終行、長文省略を固定 |
| 表示件数 | `niGPF` | 選択肢、選択中、無効、API連動を固定 |
| ページ切替 | `Blot6` | 契約済み。前後だけの画面も同じAPIへ寄せる |
| ツールバー | `n18zLK`、`eHPwj` | 検索、並び替え、件数、一括操作を固定 |
| フォルダ | `Pw4WX`、`CsGTC`、`hGpFq` | 選択、追加、編集、削除、件数を固定 |

表を使う画面の横スクロールを共通部品側で無条件に許可しない。1440px・1920pxでは列の優先順位、短縮、統合、非表示を先に使う。

### 5-5. 重なり画面と結果表示

| 分類 | Pen.dev候補 | 必要な状態 |
|---|---|---|
| 確認ダイアログ | `J6x4Q`、`H2S1T4` | 通常、重要、削除、処理中 |
| 右詳細パネル | `VJKAT` | 開閉、幅、未保存、保存、失敗 |
| 通知パネル | `z6TmF` | 閉、開、空、未読、失敗、分類 |
| 成功・失敗通知 | `ApbSZ`、`zPRvi`、`I5rKbM` | 成功、入力不備、処理失敗、消え方 |
| データ状態 | `BDOJu`、`sZE9Q`、`OLMp0` | 読込中、空、取得失敗、再試行 |

`Dialog` と `Drawer` の土台が、フォーカストラップ、Escape、背景操作禁止、閉じた後の復帰を持つ。画面ごとに同じ処理を書かない。

### 5-6. アクセシビリティと表示幅

- 全操作へ共通 `focus-visible` を出す。
- 状態を色だけで伝えない。
- アイコンだけの操作に名前を付ける。
- 表見出しへ `scope` を付ける。
- ダイアログ、ドロワー、メニューのキーボード操作を共通化する。
- 1440px・1920pxでページ全体と主要表の横スクロールを出さない。
- 短い文字列を単語途中で改行しない。
- 省略表示は全文確認手段を持つ。

Pen.devにfocus状態がない場合、コードだけで見た目を決めず、Pen.devの共通状態へ追加してから契約する。

## 6. 実装方法

### 6-1. 「丸ごと入替」を1つの巨大PRにしない

基本設計は全ページへ届くため、1本にすると原因の切り分けと画像確認ができない。目的は1つのまま、次の順で小さく統合する。

| 順番 | PR | 見た目への影響 |
|---:|---|---|
| B0 | 85部品の分類、Node ID、状態、props、影響先を契約へ追加 | なし |
| B1 | 画面枠、正式共通メニュー、ページヘッダー、パンくず、タブ | 全ページ |
| B2 | 文字、Card、CardHeader、StatusBadge、アイコン操作 | 共通部品利用箇所 |
| B3 | Field、Textarea、Select、Search、Switch | フォーム利用箇所 |
| B4 | Dialog、Drawer、操作メニュー、Notice、DataState | 重なり画面・結果表示 |
| B5 | 表本体、表示件数、ツールバー、フォルダ | 一覧画面 |
| B6 | 既存直書きの意味一致箇所を共通部品へ載せ替え | 対象ページ群 |
| B7 | 全代表画面の画像確認、負債基準締め、移行開始ゲート | なし |

B7を通過した後に、ダッシュボードV5、受信箱V6等を1画面ずつ移行する。

### 6-2. 既存ページへの載せ替え

自動変換できるもの:

- 同じ意味の主要・副次ボタン
- 同じ構造の表見出し
- 同じpropsで表せるカード
- 同じ入力状態を持つinput/select

目視判断が必要なもの:

- 同じ色でも意味が違う状態
- 業務上の主操作と副操作
- ページ固有のレイアウト幅・高さ
- 文字列値と数値カード
- 危険操作と通常確認
- 表の列統合・レスポンシブ非表示

ASTで候補を抽出しても、機械だけで置換しない。変換前後の意味、Pencil Node ID、影響ページを記録する。

### 6-3. 新しいPen.devルールの反映

Pen.devに新しいルールができた場合は、次の流れに固定する。

1. Pencilの正本で変更対象とNode IDを確認する。
2. V5共通か、V6差分か、画面専用か分類する。
3. トークンまたは共通部品契約を更新する。
4. `design:impact` で影響するルートを出す。
5. 共通部品を1回変更する。
6. 影響先の代表画面を同じ状態・同じ幅で比較する。
7. 直書きのため届かなかった箇所を一覧へ出し、対象画面の移行時に解消する。

変更要求には、「この部品を変えると、次の画面も変わる」を必ず添える。共通部品の変更なのに1画面だけ直す状態を作らない。

全ページを毎回同じ深さで確認する代わりに、基本設計の種類を代表する画面を固定する。

| `/friends` | 表、検索、プルダウン、詳細モーダル |
| `/tags` | フォルダ、タブ、表、追加・編集 |
| `/broadcasts` | V6表、KPI、状態バッジ |
| `/templates` | V6タブ、KPI、一覧 |
| `/reminders` | V6 KPI、一覧、操作 |
| `/analytics` | V6分析カード、タブ、長い内容 |

## 10. 基本設計後のページ移行

基本設計が終わると、各ページで残る作業は次へ絞られる。

- Pen.dev固有の列・カード・配置
- 現在機能とPen.devの機能差分
- 読込中、空、失敗、最大件数等のページ固有データ
- API・保存先・権限
- 同一状態の画像比較

最初のページは標準ダッシュボードV5とする。下書きは `docs/dashboard-v5-migration-requirements-2026-08-24.md` に残し、基本設計完了時の実装と照合してから承認版へ更新する。

## 11. 今回の範囲

今回作るのは、この全面入替の仕様と順番である。コードとPencilは変更しない。

利用者の確認後、B0から実装を開始する。基本設計を確認せずにダッシュボード本体へ進まない。
