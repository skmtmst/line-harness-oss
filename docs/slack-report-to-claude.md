# Slackでの完了報告の書き方（Claude宛て）

Slackで受けた依頼の報告は、この書式で、**依頼が来たスレッドへ返信**してください。

## 前提

報告を読むClaudeは、**リポジトリを自分で直接取得して確認します**。したがって、次は**書かないでください**。書いても使われません。

- 変更ファイルの一覧、差分、行数
- 実装の説明、設計の解説
- マイグレーションやテストの中身
- コミット履歴（マージSHAの1行を除く）

代わりに、**Claudeが自分では取得できないもの**だけを書いてください。

## 完了したとき

【報告】<依頼名> / 完了

■ 反映
- マージSHA:
- PR: #
- 配備: なし ／ Worker=<バージョンID> 管理画面=<URL>

■ 検査
- テスト・型検査・ビルド: 合格 ／ 一部失敗（失敗したものだけ列挙）

■ 依頼された確認の結果
- <確認項目1>: OK ／ NG（NGなら1行で内容）
- <確認項目2>: OK ／ NG

■ GitHub Actions
- <ワークフロー名>: <実行URL>
（実行していない場合は「なし」）

■ 指示になかった変更
- なし ／ <変更した内容と、そうした理由>

■ 未確認
- なし ／ <項目と、確認できなかった理由>

■ 判断が必要なこと
- なし ／ <何を決めてほしいか>

## 途中で止めたとき

**止めた報告のほうが重要です。** 次の4つを必ず書いてください。

【報告】<依頼名> / 途中で停止

■ どこで止めたか
- <手順の何番目か、どのファイル・どのコマンドか>

■ なぜ止めたか
- <事実と根拠。エラーの分類、公式ドキュメントのURLなど>
- 推測は「推測」と明記する

■ 現在の状態
- 作業ツリー: クリーン ／ <残っているもの>
- DB: 変更なし ／ <変更した内容>
- 配備: 実施なし ／ <実施した内容と戻したかどうか>

■ 判断が必要なこと
- <何を決めてほしいか。選択肢があれば並べる>

## 実施しなかったとき

【報告】<依頼名> / 未実施

■ 理由
■ 実施するために必要なもの

## 書いてはいけないもの

次は**いかなる場合も報告に含めないでください**。Slackは他の人も読みます。

- 顧客・友だちの氏名、LINEのユーザーID、メッセージ本文、電話番号、住所
- APIキー、トークン、チャネルシークレット、DBのパスワード、Webhook署名シークレット
- `.env` / `.dev.vars` の内容
- 署名付きURL（エクスポートのダウンロードURLなど）
- エクスポートしたデータの中身

件数・テーブル名・状態の分類だけを書いてください。

## 長さの目安

**完了報告は20行以内**を目安にしてください。それより長くなる場合は、たいてい「Claudeが自分で見られるもの」を書いています。

止めた報告は、長くなって構いません。**理由と根拠が一番大事です。**

## 宛先

- 依頼が来た**そのスレッド**へ返信する
- `#line-harness-指令塔` へは、**判断待ちと完了だけ**を流す
- 経過の途中報告は不要。**終わったときか、止まったときだけ**でよい
