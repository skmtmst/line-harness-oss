## 2. 作り方

- 画面は **型** に中身を入れて作る（ダッシュボード・一覧（フォルダの列あり／なし）・作る・詳細・受信箱・設定・分析）。型の外で、箱・余白・段を手で書かない。
- 部品は共通部品を使う。画面の中で同じものを手で書かない。部品の見た目を画面側で上書きしない（直すときは部品を直す）。
- 作る・編集の画面の保存の帯は、画面の下に追従。キャンセル・保存は中央、削除は左端。
- 一覧のフォルダは左の列、作るボタンはその列の上。作るボタンは列いっぱいの帯にせず、文字の幅・左寄せ（形は §6.4・B-151）。行の右端は「…」、ページ送りのある一覧は 10・20・50 件の切り替え。
- 見出しの下の説明は「？」に入れる。
- 合格の撮影は板の幅（1440・1152）。崩れの見張り（CI）は 1152・1440・1920。どの幅でもはみ出し・右端越えは 0。表だけの横送りも原則なし（09-30 の「長い表は表の中だけ横に送ってよい」はこの文書で置き換え）。
- V8 の画面の置き場は `apps/web/src/v8/<機能>/`。今の V8 ファイル（`app/**/*-v8.tsx`）で絵と 60% 以上合うものはそのファイルを直す。60% 未満・V8 なし・自前の枠だらけは `src/v8` に一から書く。`src/v8` で始めたものは続ける（2026-10-06）。書き方は `apps/web/src/v8/README.md`。
- 閲覧のみの人には押せないボタン（作る・追加・編集・削除など）を置かず隠す。絵が押せない形で描いていても隠す。閲覧のみの帯（「閲覧のみで見ています…」）は出す（2026-10-06）。
- 左にフォルダの列がある一覧は、表に「フォルダ」の列を置かず、名前の前にフォルダの色の丸を付ける。フォルダ列の無い一覧にも同じ丸を足してそろえる。丸には「フォルダ：〇〇」の読み上げ名と title。未分類は色の無い輪（2026-10-07）。色の無いフォルダも灰色にせず、名前から9色の1つを自動で出す（`folderDisplayColor`・`FolderDot`、`components/shared/folder-dot.tsx`）。フォルダを作る・編集する窓で「色なし」は選べない（B-126・B-147）。
- 表の中で1つを選ぶときは丸ボタン（radio）にしない。選ばれている行は札、ほかの行は「〇〇にする」の副ボタン。
- 作ってあるもの（テンプレート・回答フォーム・タグ・アカウント・シナリオ・リッチメニューなど）を選ぶ欄はプルダウンにせず、選ぶ窓を開く（§6.10・B-155）。プルダウンは件数・並び・絞り込み・種類のような選択肢だけに使う。
- プルダウンの開いた中身は共通部品 StFE7「選ぶ欄/開いた」（`components/shared/select-menu`。`Select` が使う）だけで描く。画面ごとに開いた一覧を手で描かない。白い地・薄い線・角丸 12・選んだ行は薄い地＋太字＋右端に ✓（緑の枠・左の ✓・緑の地にしない）。
- 選択肢に「並び：」「フォルダ：」などの頭を付けない。頭は閉じたボタンだけで、開いた中身では上の小さな見出し（「並び」）にする（全部が同じ頭・先頭の「〇〇：すべて」だけが頭のときは部品が自動で外す）。行は1行のまま折り返さず、幅はボタン以上・いちばん長い行に合わせる（2026-10-08 B-45）。
- ページの中に「← 〇〇へ」（戻るリンク・戻るボタン）を置かない。戻るはパンくずと下の帯の［キャンセル］だけ（2026-10-08 オーナー）。
- まとめて選んだときの操作は V8 の一括バー（下から出る白いバー：操作を選ぶ→確かめる→結果）。画面ごとに手で描かない。
- 並ぶカードは同じ高さ（高い方に合わせる）、ボタンの位置もそろえる。
- 物を作る・直す画面の「どのフォルダに入れるか」は共通部品 dLffh（FolderSelect）。開いた中身の下の「＋ 新しいフォルダを作る」から同じ板（iBuZH）で名前と色を入れて作り、作ったフォルダを選んで閉じる。作る権限がない人には「＋」を出さない。一覧の絞り込みには使わない（2026-10-08）
- 手順は型の共通部品 Steps だけで描く。置き場所は題のすぐ下（説明は「？」の中なので、題の下に説明の行は無い）・左寄せ・1行。済みの段だけ押して戻れる（q1xNMz・2026-10-08）
- 時刻の欄は共通の TimeField（打つ＋時と分の2列・YCOoR）。画面で時・分のプルダウンや type=time を組まない。分のきざみは minuteStep で渡す。高さはほかの欄と同じ 36（日付の欄と並ぶときも 36。2026-10-08 の「高さ40」は B-145 の 4・B-159 で置き換え）
- 本文の差し込みは共通部品 insert-text-field の緑の札で見せる。保存値は {{…}} の文字のまま（OVCot・2026-10-08）
- お客さまの画面（LIFF）の 28 枚も V8 のゴール（分母は管理画面 434＋LIFF 28＝462 枚）。決まりは `docs/v8-requirements/`。

### 6.6 言葉（B-146）

管理画面とお客さまの画面（LIFF）の両方。Pen をそろえてから、コードを Pen に合わせる。言葉を固定している試験も一緒に直す。

1. **消す操作は「削除する」**。目的語が付くなら「〇〇を削除する」。確かめの窓の題は「「〇〇」を削除しますか？」・主ボタン「削除する」。注の文は「削除しても、中の〇〇は未分類に残ります」。「消す」「削除」（する無し）は使わない（B-146）。
2. **作ったものを直す操作は「編集する」**。画面・窓の題は「〇〇を編集」。「直す」「編集」（ボタンで、する無し）は使わない。表の列名・履歴の「変更」は別の意味なので対象外（B-146）。
3. **ボタンの動きは「〜する」で終える**：保存する・複製する・公開する・追加する・送信する・配信する・確定する。「変える・配る・入る・止める・選ぶ」は「〜する」にしなくてよい（B-160 の ④）。目的語が付くものは今一番多い形のまま（「下書きを保存」「フォルダを追加」「〇〇を作る」「この版を公開」）。1つのボタンに同じ意味の言い方を混ぜない（「保存」「変更を保存」→「保存する」。既存を直す画面で区別が要るときだけ「変更を保存する」）（B-146）。
4. **複製は「複製する」**。「コピーする」は文字・URL を写す時だけ（B-146）。
5. **入力をやめる＝「キャンセル」、窓を閉じるだけ＝「閉じる」**。「やめる」は使わない（予約のキャンセル窓の「やめる」も「閉じる」）（B-146）。
6. **文末の「？」は全角**（B-146）。
7. **閲覧のみの帯**：「閲覧のみで見ています。変える操作はオーナーか管理者に頼んでください。」（統括の画面は「統括の管理者に頼んでください」）。403 の文と同じ頼む先にそろえる。言い回しを増やさない（B-146・B-159）。
8. **アカウント未選択の空の表示**：「LINE公式アカウントを選んでください」に1つ（B-146）。
9. **作るボタンは「〇〇を作る」**（「作成」「新規作成」「新しく作る」は使わない）。入れ物の中の項目なら「〇〇を追加」（B-146）。

### 6.17 選ぶ窓を使う範囲（2026-10-09 オーナー B-163）
- 複数を選べる欄と、選ぶ物が増えて長くなりうる欄（タグ・友だち情報欄・シナリオ・テンプレート・回答フォーム・スタッフ・予約メニュー・店舗・アカウント・セグメント・クーポン・リッチメニュー など）は全部、選ぶ窓（`EntityPickerDialog`／`EntityMultiPickerDialog`：フォルダで絞る・探す・件数・その場で作る）で選ぶ。欄は「〇〇を選ぶ」の副ボタン、選んだ後は札（色の丸＋名前）を並べて「変える」（B-155・B-163）。
- プルダウン（`Select`）のまま残すのは、数が決まっていて少ない選択（種類・やり方・並び・期間・件数・役割など 7 個まで）だけ（B-163）。
- 下に広がるチェックの並びで複数を選ばせる欄も、選ぶ窓にする（B-163）。
- 押されたときにあわせて行うこと（タグを付ける・スコアを足す）は押したらの共通部品の一部で、リッチメニュー・リッチメッセージ・カルーセル・質問・クーポン・リサーチ・自動応答・友だち追加で同じ形（B-162・B-164 採用：Pen V8.pen l3NXyz、タグの窓 BFXgZ）。
- 一覧の道具の段の絞り込みも、数が増えていく物（店舗・タグ・シナリオなど作った物）は選ぶ窓で選ぶ。状態・期間・種類など数の決まった物はプルダウンのまま（B-164）。
- 選ぶ窓の形は1つだけ：受信箱の「テンプレートを選ぶ」（幅 640）が正。左に「よく使う／すべて／フォルダ（色・件数）／未分類」、上に「〜で探す」、行は名前＋中身の見本、複数は行頭の番号かチェックと下の帯に選んだ数、下に［キャンセル］［主の操作］。タグ・アカウント・シナリオなどの窓もこの形の `EntityPickerDialog` 1つで作り、別の形の窓を新しく作らない（B-165）。

### 6.18 カードは1つの形だけ（2026-10-09 オーナー B-168）
- 中身のまとまりの箱（カード）は必ず共通のカードの形：`border: 1px solid var(--card-edge)`＋`box-shadow: var(--card-shadow)`、角丸 12（B-137・B-148・B-168）。
- 画面ごとに `box-shadow: var(--tpl-*-ring)`（内側の線）や `--color-hairline` の枠だけでカードを描かない。カードの中の入れ子の箱は影を重ねず、薄い地か線（B-168）。
- 数の並びは線の帯（B-153）で、カードにしない。
- 見張り：角丸がカードの値で、枠だけ・影なしの規則を新しく書くと CI の試験で落ちる。例外は試験の一覧に理由つきで書く（B-168）。Pen もカードは部品のカードだけを使う。

### 6.19 「行うこと」を足す所は1つの形（2026-10-09 オーナー B-169）
- ［＋ 行うことを足す］の副ボタン→種類のメニュー（テキスト・テンプレート・タグ・友だち情報・シナリオ・リマインダ など）→選ぶ物は選ぶ窓（§6.17・B-165）、テキストはその場の欄→選んだ後は行（印・種類・中身・並べ替えのつまみ・「…」）で並ぶ（B-169）。
- 枠の無い文字だけのボタンの並びや、押すと下に広がる欄にしない（B-169）。
- 回答フォーム・カルーセル・質問・自動応答・友だち追加・リッチメニューで同じ部品。回答フォームの「回答したときに付けるタグ」は「行うこと」のタグにまとめる（B-169）。

### 6.20 1回直せば全部に効く作り（2026-10-09 オーナー B-172）
- 型ごとに「持ち主」を1つにする。形と値を持つのは、コードでは共通部品（`components/shared`・`components/templates`）と `:root` の変数だけ、Pen では型ごとの部品1つだけ（B-172）。
- 画面は部品を置くだけ。画面の CSS で部品の見た目を上書きしない・同じ役目の部品を画面で作らない・色や大きさを直書きしない（B-172）。
- Pen の板は部品のインスタンスだけを使う。切り離し・見た目の上書きをしない。上書きしてよいのは文字・件数・データの違いだけ（B-172）。
- 型ごとの持ち主は型の対応表（`docs/v8-pattern-catalog.md`）に書く。点検の道具（`scripts/visual-qa/v8-pattern-audit.mjs`）と見張りの試験で、持ち主以外で形を作っている所を見つけて落とす（B-172）。
- 直すときは持ち主だけを直す。画面ごとに直したくなったら、それは型が足りない合図なので、対応表に型（または部品の変わり形）を足してから直す（B-172）。

### 6.21 決まって、絵の提案を描いている物（2026-10-09）
