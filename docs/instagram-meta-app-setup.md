# Instagram同時投稿のためのMetaアプリ準備手順

Googleビジネスの投稿をInstagramにも同時に出すには、Meta（Facebook）側に「アプリ」を1つ作る必要があります。
この文書は、**その作成をご本人が画面の順番どおりに進められるようにしたもの**です。

いまの検証環境（stg-admin.musubo.jp）は、この準備がまだ無いので
設定 → SNS連携 の Instagram に「**設定がありません**」と出ます。これは不具合ではなく、
「この環境にはMetaの設定がまだ無い」という正しい表示です。

## 誰が何をするか

| やること | 担当 |
| --- | --- |
| Metaにログインし、アプリを1つ作る | **ご本人** |
| Instagramをプロ（ビジネス／クリエイター）アカウントにする | **ご本人** |
| 折り返し先URLと権限の登録（Metaの画面での設定） | **ご本人**（下の手順4・5） |
| アプリIDとシークレットを検証環境へ入れる | **ご本人が貼り付け**（手順6。理由は後述） |
| 暗号化の鍵を作って検証環境へ入れる | こちら（値はお見せせず作ります） |
| 検証環境で「未接続」に変わったことの確認 | こちら |
| 実際の接続（Instagramにログインして接続）とその後の確認 | **ご本人の操作**＋こちらで結果確認 |

**シークレットだけはご本人に貼っていただきます。**
秘密の値を会話・ログ・リポジトリに出さない決まりのため、こちらが値を預かることができません。
貼る場所は決まっていて、名前も下に書いてあるので、作業は「コピーして貼る」だけです。

## 手順0：先に用意しておくもの（Metaのアプリを作る前に）

- **Instagramアカウントがプロアカウントであること**
  Instagramアプリ → 設定 → アカウントの種類とツール → プロアカウントに切り替える。
  ビジネスでもクリエイターでもどちらでも接続できます。**個人アカウントは接続できません。**

Facebookページは要りません。接続の処理はInstagramにログインするだけで終わり、
ページの一覧は見ません。

## 手順1：Metaの開発者サイトにログインする

<https://developers.facebook.com/> を開き、右上から**ご本人のFacebookアカウント**でログインします。
初回は開発者登録（電話番号の確認など）を求められます。案内どおり進めてください。

## 手順2：アプリを作る

「マイアプリ」→「アプリを作成」。

- **ユースケース**を選ぶ画面で「**Instagramの投稿を公開する**」を選びます。
- アプリ名は社内で分かるもの（例：`musubo連携（検証）`）で構いません。利用者には出ません。
  長い名前や商標に触れる名前は弾かれることがあります。弾かれたら短い名前に変えてください。
- **アプリの種類（ビジネス／消費者など）を選ぶ画面は、いまは出ません。**
  ユースケースを選んだ時点で決まります。出なくても間違いではありません。
- ビジネスポートフォリオ（Business Home）との連携を求められたら、
  **「ポートフォリオ無しで作成して後でつなぐ」で構いません。**
  この仕組みに必要なのはInstagramのプロアカウントだけで、ポートフォリオは要りません。

## 手順3：「InstagramログインによるAPI設定」を使う

アプリができると「**ユースケースをカスタマイズ**」という画面になります。
左メニューに、こう並んでいます。

```text
アクセス許可と機能
InstagramログインによるAPI設定   ← 既定でこちらが選ばれている。こちらを使う
API統合ヘルパー
FacebookログインによるAPI設定   ← 使わない
このユースケースにさらに追加
```

> **大事な分かれ道：** Instagramには接続方式が2つあります。
> この仕組みは「**Instagramに直接ログインする方式**」です。
> 既定で選ばれている「**InstagramログインによるAPI設定**」のままで合っています。
> 「FacebookログインによるAPI設定」へ切り替える必要はありません。

この画面で使うのは次の2つだけです。

- 「**Instagramビジネスログインを設定する**」（手順4の折り返し先URLを入れる場所）
- 「**Instagramアプリ ID**」と「**Instagram app secret**」（手順6で使う値）

**今回使わないもの**（触らなくて構いません）:

- 「アプリの設定 → ベーシック」にあるアプリ全体のIDとシークレット
  （DM受信を使うときに使う値です。いまの接続では読んでいません）
- 「アクセストークンを生成する」
- 「Webhooksを設定」（DM受信を使うときだけ。いまは止めてあります）

## 手順4：折り返し先のURLを登録する

Instagramにログインしたあと、画面がこの仕組みへ戻ってくるためのURLです。
**1文字でも違うとMetaが接続を拒否します。** コピーして貼ってください。

「Instagramビジネスログインを設定する」→「**ビジネスログインの設定**」→
「**OAuthリダイレクトURI**」に、次の1行を入れて保存します。

```text
https://stg-api.musubo.jp/api/instagram/oauth/callback
```

これは検証環境のURLです（`stg-` が付いています）。
本番用のURLは<./instagram-production-rollout.md>でご案内します。
**両方を残して並べて登録します**（片方を消す必要はありません）。

このURLはすでに検証環境側の設定に入っているため、**Meta側に同じものを登録するだけ**です。
`?` や `#` が付いたURL、`http://`（sの無いもの）は仕組みの側で弾くようにしてあります。

## 手順5：権限（できること）を2つ揃える

接続のときに、この仕組みは次の2つだけを求めます。

```text
instagram_business_basic
instagram_business_content_publish
```

**用途に入っていない権限を混ぜると、認可画面そのものが断られます。**
そのため求めるのはこの2つだけにしてあります（`apps/worker/src/services/instagram.ts` の
`INSTAGRAM_SCOPES`）。Facebookページ向けの `pages_*` は使いません。

- `instagram_business_content_publish` が**無いと接続そのものを保存しません**
  （「Instagramへの投稿が許可されていません」で止まります）。同時投稿のための権限です。
- `instagram_business_manage_messages` は将来のDM返信用です。
  いまはDM返信の口を止めてあるので、**求めていません**。
- **開発モードのままでも、アプリに役割（管理者・開発者・テスター）を持つご本人のアカウントなら接続できます。**
  検証環境での確認はこの状態で足ります。他の店舗のアカウントまで広げるにはMetaの審査が必要です
  （<./instagram-app-review.md>）。

## 手順6：アプリIDとシークレットを検証環境へ入れる

「InstagramログインによるAPI設定」の画面に、
「**Instagramアプリ ID**」と「**Instagram app secret**（表示するにはパスワード確認が必要）」があります。

> **アプリ全体のID（アプリの設定 → ベーシック）とは別の番号です。**
> 名前が似ているので、必ず「Instagram」と付いているほうの値を使ってください。

この2つを、Cloudflareの画面で次の名前で登録します。

| Cloudflareで入れる名前 | Metaのどこの値か |
| --- | --- |
| `INSTAGRAM_APP_ID` | InstagramログインによるAPI設定 → Instagramアプリ ID |
| `INSTAGRAM_APP_SECRET` | InstagramログインによるAPI設定 → Instagram app secret |

入れる場所：
Cloudflareダッシュボード → Workers & Pages → **nen-line-stg** → Settings →
Variables and Secrets →「Add」→ Type は「**Secret**」を選び、Name に上の名前、
Value にMetaからコピーした値を貼って Deploy。

> **名前は1文字も変えないでください。** 仕組みはこの名前でしか値を読みません。
> 値そのものはこの文書にも、やりとりにも書きません。

## 手順7：残りはこちらでやります

- `META_TOKEN_ENCRYPTION_KEY`（接続したあとのトークンを暗号化して預かるための鍵）は
  こちらで作って同じ場所へ登録します（検証環境は**登録済み**）。32バイトの乱数をbase64にしたものです。
  **Metaとは関係ない値なので、ご本人の操作は要りません。**
- 検証環境の設定には `META_REDIRECT_URI`（手順4のURL）と
  `META_GRAPH_API_VERSION`（いま `v24.0`）が**すでに入っています**。追加の操作は要りません。
- `META_WEBHOOK_VERIFY_TOKEN` はDM受信を使うときだけの値です。
  いまはDM返信の口を止めているので、**今回は不要**です。

### 設定の一覧（確認用・検証環境）

| 名前 | いまの状態 | 誰が入れるか |
| --- | --- | --- |
| `INSTAGRAM_APP_ID` | **登録済み** | ご本人（手順6） |
| `INSTAGRAM_APP_SECRET` | **登録済み** | ご本人（手順6） |
| `META_TOKEN_ENCRYPTION_KEY` | **登録済み** | こちら |
| `META_REDIRECT_URI` | **登録済み**（検証環境の設定ファイル） | — |
| `META_GRAPH_API_VERSION` | **登録済み**（`v24.0`） | — |
| `META_APP_SECRET` | 登録済み（いまは読んでいない） | DM受信を使うときだけ |
| `META_WEBHOOK_VERIFY_TOKEN` | 未登録 | 今回は不要 |

上の**5つが全部そろって、かつ形が正しいときだけ**
画面の表示が「設定がありません」から「未接続」へ変わります。
1つでも欠けていたり形が違うと、「設定がありません」のままです。

`META_APP_SECRET` と `META_WEBHOOK_VERIFY_TOKEN` は**DM受信（Webhook）の署名確認だけ**に
使う値です。いまの同時投稿の接続では読んでいません
（`apps/worker/src/routes/instagram.ts` のWebhook受信部分）。

形の決まり（こちらで確認します）:

- `META_GRAPH_API_VERSION` … `v` と数字2つ（`v24.0` のような形）
- `META_TOKEN_ENCRYPTION_KEY` … base64を戻すとちょうど32バイト
- `META_REDIRECT_URI` … `https://` で始まり、`?` も `#` も付かない

## 手順8：実際につなぐ（ご本人の操作）

手順6・7が終わると、画面の表示が変わります。

1. 検証環境の管理画面（<https://stg-admin.musubo.jp>）にログイン。
2. 設定 →**SNS連携**。Instagram の「いまの状態」が「**未接続**」になっていることを確認。
   （ここが「設定がありません」のままなら、値の登録が足りていません。こちらへお知らせください。）
3. ［**Instagramにログインして接続**］を押す。**Instagramのログイン画面**へ飛びます
   （Facebookのログイン画面ではありません）。
4. 権限の確認画面で、**チェックを外さずに**「許可」を押します。
   ここで `instagram_business_content_publish`（コンテンツの公開）の許可を外すと
   接続が保存されません。
5. 画面がSNS連携へ戻り、帯で結果が出ます。
   「いまの状態」が「**接続しています**」、「接続しているアカウント」に `@ユーザー名（ビジネス）` が出れば成功です。

このボタンは **オーナー／管理者**にだけ出ます。閲覧のみの権限では出ません。

## 手順9：同時投稿を確かめる（こちらで結果を確認します）

接続できると、Googleビジネスの投稿を作る画面に「**Instagramにも投稿する**」の区画が出ます
（接続していないあいだは、この区画は出ません）。

- 新しい投稿は「Instagramにも投稿する」が**はい**で始まります。
- 「はい」のときは**画像が1枚必要**です。無いまま保存しようとすると注意が出ます。
- Instagram用の文章は空のままでよく、空ならGoogleの本文をそのまま使います（上限2,200文字）。
- 投稿後、一覧の札が「Instagram済み」になれば同時投稿が通っています。
  失敗したときは「Instagram失敗・再試行」になり、行の「…」から再送できます。
  **Googleへの公開はそのまま残ります。**

画像の変換（PNG→JPEG）と公開用URLの用意は仕組みの側で行います。
この変換の実際の動きは、接続ができてから初めて確認できます（いまは接続が無いため確認できていません）。

## つながらないときの読み方

| 画面・メッセージ | 意味 | どうするか |
| --- | --- | --- |
| 「設定がありません」のまま | 5つの値のどれかが未登録か形が違う | こちらへお知らせください。名前と形を照合します |
| 「Instagramのビジネスアカウントが必要です」 | ログインしたアカウントがプロアカウントになっていない | 手順0をもう一度確認 |
| 「Instagramへの投稿が許可されていません」 | 許可画面で `instagram_business_content_publish` が外れた | もう一度［接続］を押し、権限を外さずに許可 |
| 折り返しでMetaがエラーを出す | 手順4のURLが1文字違う | 手順4のURLを貼り直す |
| 「認可が切れています」 | 預かっている許可の期限切れ | ［接続を確かめる］を押す。直らなければ接続し直す |

接続の許可は60日ほどで切れるため、［接続を確かめる］で延長できる作りにしてあります。

## 本番へ広げるとき

2026-10-12に、ご本人から「本番環境にも反映させたい」とのご指示をいただきました。
その判断をふまえ、**本番の設定ファイルへ `META_REDIRECT_URI` と `META_GRAPH_API_VERSION` を
追加済みです**（`apps/worker/wrangler.toml`）。折り返し先は
`https://api.musubo.jp/api/instagram/oauth/callback` です。

残りの手順は別の文書にまとめました。

- **本番へ広げる手順** … <./instagram-production-rollout.md>
  Meta側への本番URL追加（ご本人）、本番の秘密値3件、本番DBの移行、接続の確かめ方。
- **Metaのアプリレビューの準備** … <./instagram-app-review.md>
  他の店舗のアカウントまで広げるときに必要な審査の中身と、必要な資料。

アプリは**検証環境で使っている既存のアプリをそのまま使います**（2026-10-12 ご本人の判断）。
新しいアプリは作りません。アプリIDとシークレットも、いま登録済みのものと同じ値を
本番側にも登録する形になります。

### まだやっていないこと

- 他の店舗のアカウントまで広げるにはMetaの審査（アプリレビュー）が必要です。
  まずはご本人のアカウントで本番を動かし、審査は同時に出す方針です（2026-10-12）。
- DMの受信・返信はMetaの審査待ちのため、仕組みの側で止めてあります。
