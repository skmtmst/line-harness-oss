# 反映履歴の書き方

管理画面の **運用状態 → 更新履歴** に出るものの実体です。
`docs/change-log-design.md` の案Aをそのまま実装しています。

## いつ書くか

**PRを出すときに、変更した本人が `unreleased.md` に1行足します。**
リリース時にまとめて書くと、後から差分を読んで推測することになり、内容が薄くなります。

## 書き方

```markdown
---
version: 0.24.0
released: 2026-08-19 15:00
---

## 追加
- タグに親分類を付けられるようにした @kenta #142 2026-08-18 22:05

## 修正
- 予約した絞り込み配信が全員に届いていたのを直した @kenta #151 2026-08-19 10:22
```

- 見出しは **追加 / 変更 / 修正** の3つだけ
- 行末に付けられるのは3つ。**順番は問いません。どれも省略できます**
  - `@名前` … 担当（`kenta` / `masato`）
  - `#番号` … PR番号
  - `YYYY-MM-DD HH:MM` … いつ変えたか（**日本時間**。時刻は省いて日付だけでも可）
- **運用者の言葉で書きます。** テーブル名・関数名・ファイル名は書きません

> 「`friend_scenarios` の `status` を見るようにした」ではなく
> 「予約した絞り込み配信が全員に届いていたのを直した」と書きます。
> 読む人は、コードではなく画面を触っている人です。

## リリースするとき

1. `unreleased.md` を `<version>.md` に改名する
2. front-matter に `released: YYYY-MM-DD HH:MM` を入れる（配布した日時。日本時間）
3. 空の `unreleased.md` を作り直す

`unreleased.md` は画面上「次回反映予定」として、反映済みとは分けて出ます。

## PR番号は必須です

行を書く時点ではPR番号がまだ決まっていないので、**書き忘れやすい**。書式の上では
任意で、抜けていても組み立ては通ります。**通ってしまうから抜けます。**

抜けると、管理画面の 運用状態 → 更新履歴 に番号が出ず、**どの変更か辿れなく
なります。** 一晩で19行が番号なしのまま入りました。

PRを出したあとに、番号を入れてから push してください。`required-pr-gate` が、
足した行にそのPRの番号が入っているかを見ています。

```
- 変更した内容 @kenta #194 2026-08-20 08:15
```

`@名前` `#番号` `日付 時刻` の並び順は問いません。末尾から1つずつ剥がして読みます。
