# 反映履歴の書き方

管理画面の **運用状態 → 更新履歴** に出るものの実体です。
`docs/change-log-design.md` の案Aをそのまま実装しています。

## いつ書くか

**PRを出すときに、変更した本人が `unreleased.md` に1行足します。**
リリース時にまとめて書くと、後から差分を読んで推測することになり、内容が薄くなります。

## 書き方

```markdown
---
version: 0.24.0
released: 2026-08-19
---

## 追加
- タグに親分類を付けられるようにした @kenta #142

## 修正
- 予約した絞り込み配信が全員に届いていたのを直した @kenta #151
```

- 見出しは **追加 / 変更 / 修正** の3つだけ
- 行末の `@名前` が担当、`#番号` がPR番号。どちらも省略できます
- **運用者の言葉で書きます。** テーブル名・関数名・ファイル名は書きません

> 「`friend_scenarios` の `status` を見るようにした」ではなく
> 「予約した絞り込み配信が全員に届いていたのを直した」と書きます。
> 読む人は、コードではなく画面を触っている人です。

## リリースするとき

1. `unreleased.md` を `<version>.md` に改名する
2. front-matter に `released: YYYY-MM-DD` を入れる
3. 空の `unreleased.md` を作り直す

`unreleased.md` は画面上「次回反映予定」として、反映済みとは分けて出ます。
