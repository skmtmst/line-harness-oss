# 反映履歴の書き方

管理画面の **運用状態 → 更新履歴** に出るものの実体です。
`docs/change-log-design.md` の案Aをそのまま実装しています。

## いつ書くか

**PRを出すときに、変更した本人が `unreleased/<PR番号>-<担当>-<何の話か>.md` を1ファイル作り、1行以上足します。毎回必須です。例外はありません。**
リリース時にまとめて書くと、後から差分を読んで推測することになり、内容が薄くなります。
`unreleased.md` への新しい行の追加はできません（CIが落とします）。

## 書き方

```markdown
---
version: 0.24.0
released: 2026-08-19 15:00
---

## 追加
- タグに親分類を付けられるようにした @kenta #142 2026-08-18 22:05

## 修正
- 予約した絞り込み配信が全員に届いていたのを直した @kenta #151 2026-08-19 10:22
```

- 見出しは **追加 / 変更 / 修正** の3つだけ
- 行末には3つとも付けます。**順番は問いません**
  - `@名前` … 担当（`kenta` / `masato`）。書きます
  - `#番号` … 自分のPRの番号。必ず入れます（CIが落とします）
  - `YYYY-MM-DD HH:MM` … いつ変えたか。**日本時間**で必ず入れ、省略しません（運用指示です。CIは日時を見ません）
- **運用者の言葉で書きます。** テーブル名・関数名・ファイル名は書きません

> 「`friend_scenarios` の `status` を見るようにした」ではなく
> 「予約した絞り込み配信が全員に届いていたのを直した」と書きます。
> 読む人は、コードではなく画面を触っている人です。

## リリースするとき

版を切るときは、人が `unreleased.md` と `unreleased/` の各PRファイルの行をまとめ、1つの `<version>.md` に移します。

1. `<version>.md` を作り、front-matter に `version: <版>` と `released: YYYY-MM-DD HH:MM` を入れる（配布した日時。日本時間）
2. 移した行は `unreleased.md` と `unreleased/` の各PRファイルから取り除く

組み立て（`apps/web/scripts/build-release-log.mjs`）は `unreleased.md` と `unreleased/` の両方から拾い、画面上「次回反映予定」として反映済みとは分けて出します。

## PR番号は必須です

行を書く時点ではPR番号がまだ決まっていないので、**書き忘れやすい**。組み立て
（`apps/web/scripts/build-release-log.mjs`）は番号がなくても通ってしまうから、
**通ってしまうから抜けます。**

抜けると、管理画面の 運用状態 → 更新履歴 に番号が出ず、**どの変更か辿れなく
なります。** 一晩で19行が番号なしのまま入りました。

コードを変えるPRでは `required-pr-gate` が、足した行にそのPRの番号が入っているかを
見て、なければ落とします。**PRを出したあとに、番号を入れてから push してください。**

日時も運用指示として必須です（日本時間、省略なし）。担当も書きます。
CIは文書・ワークフローだけの変更や `[skip release-log]` では確認を飛ばしますが、
運用ルールとしては毎回書きます。例外はありません。

```
- 変更した内容 @kenta #194 2026-08-20 08:15
```

`@名前` `#番号` `日付 時刻` の並び順は問いません。末尾から1つずつ剥がして読みます。

## 書き足す場所（2026-08-20 から）

**`docs/release-log/unreleased/` の下に、PRごとの1ファイルを作ってください。**

```
docs/release-log/unreleased/198-kenta-auto-reply-all.md
```

ファイル名は `<PR番号>-<担当>-<何の話か>.md`。中身はこれまでと同じ書き方です。

```markdown
## 追加
- 自動応答で、キーワードを問わず全部のメッセージに応答できるようにした @kenta #198 2026-08-20 09:30
```

### なぜ変えたか

`unreleased.md` に全員が書き足す形だと、**全員が同じ場所（`## 追加` の直後）に行を
差し込むので、PRのたびに必ずぶつかります。** 一晩で9本のPRが全部ここで止まりました。
毎回手で解いていて、そのうち1回は**取り込みの目印がそのまま入って**しまいました。

1本ずつ別のファイルにすれば、ぶつかりようがありません。ファイル名の番号で並ぶので、
並び順を人が決めなくてよくなります。

`unreleased.md` はこれまでのぶんが入ったまま残ります。**新しい行はそちらに足さないで
ください。** 組み立てのときに両方から拾います。
