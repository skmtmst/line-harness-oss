## 2. 見ていない箇所と、そこで置いた想定

### 影響度：高（想定が外れると設計をやり直す可能性がある）

### A-1 と A-2 は突き合わせで解決した（2026-08-15 追記）

A-1（シナリオの分岐）と A-2（アクションの中身）は、**互いを突き合わせることで答えが出た**。実環境に触れずに、観察した事実と公開マニュアルの照合で確定している。

#### A-2 の答え：アクションは10種類

| # | アクション | 内容 |
|---|---|---|
| 1 | テキスト送信 | 直接入力したメッセージを送る |
| 2 | テンプレート送信 | 用意したテンプレートを送る（カルーセルのボタン対応） |
| 3 | タグ操作 | タグを付ける・外す |
| 4 | **友だち情報操作** | 友だち情報欄の値を追加・更新する |
| 5 | シナリオ操作 | シナリオ配信を開始する |
| 6 | **メニュー操作** | リッチメニューを切り替える |
| 7 | **リマインダ操作** | リマインダ配信を開始する |
| 8 | 対応マーク・表示操作 | 対応ステータスを変える |
| 9 | 通知 | スマートフォンへLINEで通知する |
| 10 | **予約操作** | 予約フォームを起動する |

**V2に足りなかったのは太字の4つ**（友だち情報操作 / メニュー操作 / リマインダ操作 / 予約操作）。`V2 7-1-1 ルールを作る` と `V2 4-5-1 自動応答編集` に追加済み。

特に **メニュー操作（リッチメニューの切り替え）** は、会員ランクや購入状態でメニューを出し分ける定番の使い方で、これが抜けていたのは設計上の穴だった。

なお **スケジュール設定（定期実行）はプロプラン以上限定**。`V2 7-1 オートメーション` に「毎日09:00 定期実行」を入れているが、Lステップでは上位プランの機能にあたる。

#### A-1 の答え：シナリオ内に条件分岐のUIは無い

Lステップのシナリオ編集画面で追加できるのは「**メッセージ**」と「**テンプレート**」の2つだけで、分岐を追加するボタンは存在しない。にもかかわらず一覧の説明文には「友だちの反応に応じて配信内容を分岐できます」とある。

この矛盾は、**分岐がシナリオの中ではなく外で実現されている**ことを意味する。

```
回答フォームの回答 / 自動応答のキーワード / カルーセルのボタン / 流入経路
  ↓ アクション（タグ操作）
タグが付く
  ↓ アクション（シナリオ操作）
別のシナリオを開始する
```

つまり **A-1 の答えは A-2 の中にあった。** 「シナリオ操作」というアクションが存在することで、間接的な分岐が成立している。

#### V2はここでLステップと分かれている

V2の `4-1-1 シナリオ編集` には、**シナリオの中に条件分岐ステップを置いている**（記録あり／なしで分岐し、各分岐の人数を表示）。これはLステップには無い形。

| | Lステップ | V2 |
|---|---|---|
| 分岐の置き場所 | シナリオの外（タグ経由で別シナリオへ） | シナリオの中（分岐ステップ） |
| 分岐の見え方 | 複数のシナリオに分かれるため、全体像が追いにくい | 1つのシナリオ内で流れと人数が見える |
| 実装コスト | 低い（既存機能の組み合わせ） | 高い（分岐の評価エンジンが要る） |

**この分岐はV2として維持することを勧める。** 離脱地点の可視化（SD-1）は、分岐がシナリオ内にあって初めて意味を持つため。ただし実装コストが上がることは認識しておく必要がある。

Lステップ方式（タグ経由）もV2で並行して使えるので、**両方を持つ**のが現実的。「シナリオ操作」アクションは上記のとおり追加済み。

## 4. 想定ではなく、別の根拠で作った部分

「Lステップを見ていないが、想定でもない」箇所。ここは確度が高いと考えてよいものです。

| 箇所 | 根拠 |
|---|---|
| リッチメニューのエリア制約（最大20個・2500×1686） | LINE Developers 公式ドキュメント |
| 開封数の集計方法と20人未満の制約 | LINE Developers 公式ドキュメント（検証済み） |
| 送信残枠・リプライ/プッシュ数の取得方法 | 同上 |
| 予約まわりの全画面 | **自社V1のデザインを移植**（トリミング・担当みさき・承認通知の文面まで） |
| 健康記録・ケアフラグ・EC連携・写真審査 | **自社のDBスキーマ**（`nen_health_logs` `nen_care_flags` `nen_ec_member_snapshots` `nen_photo_submissions`） |
| 出荷予定・QRコード・友だち追加リンク | **自社V1のダッシュボード**（実装済み機能） |
| 配信前チェック・離脱地点の名指し・使用箇所の明示 | **Lステップに無いV2独自の追加** |

**V2の67画面のうち、Lステップの実物を根拠にしているのは半分程度です。** 残りは自社V1、自社スキーマ、LINE公式仕様、そしてV2独自の判断で作っています。

## 5. 確認するには

| 方法 | 確認できること | コスト |
|---|---|---|
| **検証用のLステップアカウントを別途契約する** | A-1〜A-3、B-1〜B-7 のすべて。実環境を汚さずに作成ボタンを押せる | 月2,980円〜 |
| 上位プランで1か月だけ契約 | リッチメニュー、上位プラン限定機能 | プラン差額 |
| 同じシナリオを両方で組んで配信結果を突き合わせる | 画面に出ない挙動（配信順序・リトライ・重複排除・文字数の丸め） | 時間 |

**優先度としては A-1（シナリオの分岐設定）だけでも先に見ておく価値があります。** ここはV2の設計が最も薄く、かつ作り直しのコストが大きい箇所です。
