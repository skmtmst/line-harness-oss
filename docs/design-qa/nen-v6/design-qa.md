# P0：画面が数字について嘘をついている

## P0-1 「失敗 —／失敗の記録がありません」の隣に、失敗が1件出ている

`VLMGH-1440.png` の1枚に、両方が写っています。

- 帯：**失敗 `—`**、下に「失敗の記録がありません」
- 同じ画面の配信履歴タブ：「届きました／山田 太郎／試行：3回／**送信できませんでした**／ブロックされています」

帯の札は**そのまま書いてあります**（`nen-campaigns/page.tsx:344-347`）。

```tsx
<p className="text-ink-faint text-xs">失敗</p>
<p className="text-ink-faint mt-1 text-2xl font-bold">—</p>
<p className="text-ink-faint mt-0.5 text-xs">失敗の記録がありません</p>
```

`overview.jobs.failed` は**取れています**。`api.nenCampaigns.overview()` の型に
`jobs: { total; pending; sent; failed }` があり、`load()` で受け取って
`setOverview` まで済ませています。使っているのは `className="hidden"` を
付けた塊（`page.tsx:351`）だけで、**画面には出ません。**

これは未取得と0件の取り違えです。しかも向きが逆で、**取れている値を
「記録がありません」と言い切っています。** 運用の人は、ブロックされた
配信に気づけません。

- 数字 `—`（未取得）と、文「記録がありません」（実値0）が**同じ札の中で食い違って**います
- 実際の値は 6 です

**直し方：** `overview?.jobs.failed` を出す。`overview` がまだ無いあいだは
`—` と「読み込んでいます」。取得に失敗したら `—` と「取れませんでした」。
**「記録がありません」は、0 を受け取れたときだけ出す言葉です。**

## P0-2 誕生日配信が「発送完了から-3日後」と出る

`VLMGH-1440.png` の「ペットの誕生日」の行です。

```tsx
{setting.delayDays === 0 ? 'イベント発生後すぐ' : `発送完了から${setting.delayDays}日後 ${setting.deliveryTime}`}
```
（`page.tsx:384`）

`delayDays` が `-3` のとき、そのまま `発送完了から-3日後 10:00` になります。
2つ間違っています。

1. **起点が違う。** 誕生日配信の起点は誕生日で、発送完了ではありません
2. **負の数をそのまま出しています。** 「-3日後」は日本語として読めません

**#446 が入れた誕生日3日前配信が、その一覧で読めない形で出ています。**

**直し方：** `category`（`birthday`）と `triggerEvent`（`pet.birthday`）で
起点の言葉を変え、負のときは「◯日前」にする。

| 値 | いまの表示 | あるべき |
|---|---|---|
| `delayDays: -3`, `category: 'birthday'` | 発送完了から-3日後 10:00 | 誕生日の3日前 10:00 |
| `delayDays: 7`, `category: 'follow_up'` | 発送完了から7日後 20:00 | （このままでよい） |

## P0-3 配信履歴の日時が、生のUTCで出る

`WeXbL-1440.png` に `予定：2026-08-25T11:00:00.000Z` と出ています。

```tsx
<p className="text-gray-600">予定：{job.scheduledAt}</p>
```
（`page.tsx:462`）

`11:00Z` は**日本時間の20:00**です。運用の人はこれを11時と読みます。
**9時間ずれた時刻を見て、送る前に止められるかどうかを判断します。**

設計は `8/25 19:00 ／ 前田 さくら` です。

**直し方：** `Asia/Tokyo` で `M/D HH:mm` に整える。この画面の他の日時
（`sentAt`）も同じです。

## P0-4 読み込みに失敗した一覧が、0件だと言う

`i9sQP-error-1440.png` です。`/api/nen-campaigns/*` を 500 にして撮りました。

| 出ているもの | 実際 |
|---|---|
| 上の帯「フォロー配信の情報を読み込めませんでした。」 | 正しい |
| 配信ジョブ **0件** ／ 稼働中 **0** | 取れていない |
| 待機中 **0件** | 取れていない |
| NENコラム「**同期されたコラムはまだありません。**」 | 取れていない |

`load()` は `catch` で `settings` `jobs` を空配列のまま残します。札は
`settings.length` `jobs.length` を数えるので、**取れなかったことが 0 になります。**

**上の帯を読み飛ばした人には、この画面は「まだ何も無い」に見えます。**
新しく作ろうとして、実は既にあるものと二重になります。

設計はこの3つを別々に持っています（`i9sQP`）。

| 状態 | 設計の文 |
|---|---|
| 読込 | 読み込んでいます／このまま少しお待ちください。 |
| 空 | まだコラムがありません／売らない配信です。ここで信用がたまると、売る配信が届きやすくなります。／**コラムを書く** |
| 失敗 | **表示できませんでした**／再読み込みしても直らない場合はエラー報告へ。 |

実装の読込（「読み込み中...」）と空（「同期されたコラムはまだありません。」）は
出ます。**失敗だけが空と同じ絵になります。**

**直し方：** `load()` に読込・空・失敗の3状態を持たせ、失敗のときは札の数字を
`—`、一覧を「表示できませんでした」にする。`shared/list-state.tsx` が
`tags-page-v4.tsx` で使われているので、それに合わせられます。

## P1-2 きっかけが `ec.order.delivered` のまま

`HpKyF-1440.png` の「きっかけ」欄です。

```tsx
<p className="…">{setting.triggerEvent ?? '手動で送る'}</p>
```
（`edit/campaign-editor.tsx:298-301`）

## P1-3 編集画面が、誕生日配信の -3 を表せない

同じ画面の「何日後に送るか」は `min={0}`、覚え書きは「0 なら当日です。」、
プレビューは `きっかけの{merged.delayDays ?? 0}日後` です
（`campaign-editor.tsx:303-312`, `429`）。

**`pet_birthday` の `-3` を、この画面は入れることも読むこともできません。**
開いて保存すると、いくつになるか分かりません。

**P0-2 と同じ根です。** 一覧の表示だけでなく、編集の入れ物も
「◯日前」を持てるようにする必要があります。

## P1-4 画面の名前が、メニューの名前と違う

メニューと上の帯は「NEN配信」、見出しは「フォロー配信」です
（`VLMGH-1440.png`）。設計はどちらも「NEN配信」です。

押した名前と着いた先の名前が違うと、**着いた場所が合っているかを
確かめられません。**

## P1-5 押せない操作が、理由なしに3つ置いてある

見出しの右に「マニュアル」「並び替え」「フォルダを追加」があり、
**3つとも `disabled`** です。Playwright で確かめました。

さらに上の帯には**押せる「マニュアル」**があります。同じ名前が2つあって、
片方だけ押せます。

**直し方：** 使えないなら出さない。出すなら「まだ用意していません」と
理由を添える。

## P1-6 ペット・記念日に、設計の帯と表が無い

`q4lajm-1440.png` です。**クーポンの決めごととペットの一覧は在ります。**
無いのは次です。

| 設計 | 実装 |
|---|---|
| 帯4つ（登録864匹・友だち1,284人のうち62%／今月誕生日72匹／誕生日配信の開封94.6%「ふつうの配信の2倍以上」／クーポン利用38.2%） | 無い |
| 一覧の「次の配信」列（9/1 に誕生日クーポン／**送れません**） | 無い |
| 一覧の「これまでの配信」列（6回） | 無い |
| LINEプレビュー（ももちゃんには 9/1 にこう届きます） | 無い |
| 手を入れたほうがよいところ（誕生日が入っていない子 42匹／まだ登録していない人 420人） | 無い |
| つながる先（回答フォーム・友だち属性・テンプレート・コンバージョン） | 無い |

**「送れません」が出ないのがいちばん痛い**ところです。実装は
「誕生日未登録」と書きますが、**それが配信に効くことは書いていません。**
設計は次の配信の列に「送れません」と出して、手を打てるようにしています。
