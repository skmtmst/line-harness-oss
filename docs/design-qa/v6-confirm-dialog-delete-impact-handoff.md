# `H2S1T4` 削除確認：数えられていない影響のCodex向け引き継ぎ

## 何をした

ブラウザの `confirm()` を、共通の `components/shared/confirm-dialog`（設計 `J6x4Q` /
`H2S1T4`）へ移した画面：

- `/templates`（一覧）
- `/templates/detail`
- `/broadcasts`（一覧）
- `/webhooks`（受信・送信）
- `/pools`（プール本体／所属アカウントを外す）

どれも「何が止まり・何が残り・戻せるか」を本文で読ませ、二度押しを止め、失敗は
窓の中に運用者の言葉で出す（生のAPIエラーは出さない）形にしてある。

## 口が足りていないところ

画面だけでは埋められない。**API側で数えられるようになるまでは、確認窓に
「数えられていません」と断りを書いてある。0件と描いてはいない。**

### 1. テンプレートの使用箇所（`/templates`・`/templates/detail`）

`GET /api/templates/:id/usages` が返すのは自動応答とシナリオ配信だけ。
一斉配信・リマインダからの参照は数に入っていない。

そのため `usageCount === 0` は「どこからも使われていない」を意味しない。詳細画面の
確認窓には、その断りを本文の下に置いてある。一覧側は文言に含めていないので、
**参照元が揃ったら `templateDeleteDescription()`（`apps/web/src/app/templates/template-delete-message.ts`）
の0件の言い回しを見直すこと。**

欲しい形：`usages` の返しに `broadcasts` と `reminders` を足す。名前を引けない参照は
行を落とさず「名前を確認できない利用先」として残す。

### 2. 一斉配信の削除（`/broadcasts`）

確認窓に出せるのは、配信名・配信日時・送り先の条件まで。**対象人数は出せない。**
一覧の `ApiBroadcast` が人数を持っていないため。

一斉配信の最終確認（設計 `FpgxH`）は対象人数を並べてから決める形なので、削除の確認も
本来は「予約が取り消される＝何人に届かなくなるのか」を出したい。
一覧か個別に、予約時点の対象人数を返す口が要る。**数えられていない人数を `0人` と
描かないこと。** 未取得は `—` のままにする。

### 3. Webhookの削除（`/webhooks`）

「すでに受け取った記録は残ります」とだけ書いてある。**何件残るのかは出せない。**
受信・送信それぞれの件数を返す口が無い。

やり取りの記録（`/webhooks?tab=interactions`）は別途数えているので、Webhook単位の
件数を一覧の行に載せられるなら、確認窓にも出したい。

### 4. プールの削除（`/pools`）

「これまでの流入の記録は残ります」とだけ書いてある。**そのプールの公開URLから何人
入ったのかは出せない。** `GET /api/traffic-pools` が流入数を持っていない。

削除は取り消せないので、実際に使われている入口かどうかを数字で見せたい。
プールごとの流入数（累計・直近30日）が返るようになったら、確認窓の本文へ足す。

## 触っていないもの

`apps/worker` / `packages/db` / migration / API契約。上の4つはすべてCodex側の担当。
画面側は口が生えた時点で文言を差し替えるだけで済むようにしてある。
