# V6 機能4「友だち属性」設計寄せの引き継ぎ（Codex向け）

対象は `hqrOv`（タグ）、`rIhbN`（対応マーク）、`QKx8Q`（保存した検索）、
`sfTEW`（CSVで一括登録・取り込む内容の確認）、`XBkiQ`（保存した検索を編集）。

画面側は「いま取れている値だけで、設計に寄せられるところ」を直しました。
**この作業では `apps/worker` と `packages/db` を触っていません。** 口が要る
ところは `—` と理由で止めてあります。ここに、その口の中身を書きます。

## 1. 対応マークの「表示先」（`rIhbN`）

設計は、マークごとに**そのマークがどの画面に出るか**を並べます
（未対応＝受信箱・友だち一覧・ダッシュボード・配信・オートメーション、
保留＝受信箱・友だち一覧、というように**行ごとに違う**）。

`GET /api/support-marks` が返す `SupportMark` にはこれがありません。
そのため、いまは列の見出しを**中身に合わせて「使用先」に直し**、配信・
シナリオ・自動応答・保存検索・自動化からの参照数だけを出しています
（`components/friend-fields/mark-list.tsx` の `usageLabel`）。

口が付いたら「表示先」に戻します。

- 必要な入力: `lineAccountId`
- 返り値: 一覧の各要素に
  `surfaces: Array<'inbox' | 'friend_list' | 'friend_detail' | 'dashboard' | 'broadcast' | 'automation'>`
  - 取れないときは省略（`undefined`）。**空配列（＝どこにも出ない）と
    区別できるようにする。** 空配列を「未取得」に使わない。
- 状態番号: 200 / 401 / 403 / 500
- 副作用: なし（読み取りのみ）

## 2. 対応マークの「自動変更」（`rIhbN`）

設計は「受信時・期限超過」「担当者割当時」「手動・返信完了時」「条件一致時」
の4種類を出します。いまの `SupportMark` にあるのは `autoOnInbound`
（受信時）だけなので、それ以外は `—` のままです。

- 必要な入力: `lineAccountId`
- 返り値: `autoRules: Array<{ trigger: 'inbound' | 'overdue' | 'assigned' | 'replied' | 'condition'; label: string }>`
  - 省略は未取得、空配列は「自動変更なし」。
- 状態番号: 200 / 401 / 403 / 500
- 副作用: なし

**画面の「受信時に変更」の設定はいまの口のまま動きます。** 上の口は表示用の
読み取りで、既存の `autoOnInbound` の書き込みを置き換えるものではありません。

## 3. 帯の「未対応」「対応中」（`rIhbN`）

設計では、帯の「未対応23人／対応中19人」が下の表の同じ行の人数と一致します。
いまの実装は、この2枚だけ `GET /api/list-stats` の `marks.unanswered` /
`marks.inProgress`（＝**受信箱の対応状況**）から読んでいます。マークの
付与人数とは別の軸なので、同じ画面で数が食い違って見えます。

この作業では、**食い違いが確実に分かる2枚だけ**（マークの種類・使用中）を
一覧そのものから数えるように直しました。残る2枚は口の話です。

- 案: `list-stats` の `marks` に `byMark: Array<{ markId: string; friendCount: number }>`
  を足し、画面は表と同じ数を帯にも出す。
- または `GET /api/support-marks` の `friendCount` を帯の材料に使えるよう、
  帯の題を「未対応」ではなく既定マークの名前にする（設計の見直しが要る）。

どちらにするかは設計側の判断待ちです。**いまは数を作らず、受信箱の数だと
分かる副題（「全体の X%」「担当者あり」）を付けたままにしています。**

## 4. 保存した検索の「今月の呼び出し」（`QKx8Q`）

設計は84回。呼び出しの記録がどこにも無いので `—回`＋「呼び出し記録は未接続」
のままです（`components/friend-fields/saved-search-kpis.ts` に理由あり）。

- 必要な入力: `accountId`、期間（既定は今月・JST）
- 返り値: `{ calls: number | null; from: string; to: string }`
- 状態番号: 200 / 401 / 403 / 500
- 副作用: **書き込みが要ります。** 保存した検索で友だち一覧を開いたとき・
  配信やオートメーションが条件を評価したときに1件記録する。

## 5. 保存した検索の「更新者」（`QKx8Q`）

設計の一覧は「Kenta 8/20 19:20」と**誰がいつ直したか**を出します。
`SavedSearch` には `createdAt` しかないので、いまは日付だけです。

- 返り値: `updatedAt: string`、`updatedBy: { id: string; name: string } | null`
- 状態番号: 200 / 401 / 403 / 500
- 副作用: なし（保存時に記録する側は既存の更新処理へ）

## 6. 該当プレビューの内訳（`XBkiQ`）

設計は「LINE 15人・MAIL 3人」と経路の内訳を出します。いまは合計だけで、
副題は「保存済み条件で集計」にしてあります。内訳の口ができたら足します。

## 設計ゲートについて

`components/friend-fields/tag-csv-import-dialog.tsx` の
`unresolved-classname` を 51 → 55 に締め直しました。理由は、この窓が
CSSモジュールで組まれていて、`className={styles.x}` を数える仕組みが
member式を静的に読めないためです。**任意値記法（`arbitrary-value`）は
1218 か所のまま動かしていません**（`QKx8Q` のツールバーは
`w-[180px]` ではなく `w-40` / `w-36` の標準段で書きました）。
