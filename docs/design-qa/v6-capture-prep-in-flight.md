# Codexが実装中の機能の、撮影の下ごしらえ

**日付**：2026-08-30
**この文書はアプリを変更しない。** PRが来た瞬間に撮れるよう、道具だけ先に用意する。

## なぜ先に用意するか

1本のPRを撮るのに、こちらは **worktree作成 → 依存導入 → パッケージビルド → dev起動**
で5〜8分かかる。**撮影そのものは30秒。**準備が本体の10倍になっている。

さらに、固定データの穴が見つかるたびに撮影が止まる（`njLGA` でも
`{ success, data, limitations }` の形に気づくまで撮れなかった）。
**先に型を読んで固定データを作っておけば、この待ちが消える。**

## 使い回しの決めごと

- **同じ機能のPRは同じworktreeでheadだけ切り替える。**依存導入と
  パッケージビルドを作り直さない
- 起動は `NEXT_PUBLIC_API_URL=http://127.0.0.1:8788 pnpm --filter web dev -p <port>`
  （**`NEXT_PUBLIC_API_URL` が無いと `/analytics` などが500になる**）
- 撮影の宛先は **`VISUAL_QA_BASE`**。`BASE_URL` は効かない（既定の3101に当たる）
- **blobが同じなら撮り直さない。**`git rev-parse <head>:<file>` で比べる

## 1. `GqFTV` 16-1-H 支払いを確定する

**`njLGA`（#585）の直後に来る。** 決まっていることが多いので、いま作れる。

- **想定ルート**：`/conversions?tab=payment`（`njLGA` と同じ面の中の操作）
- **想定の口**：`GET /api/affiliate-payment-periods`
- **どちらも想定で正本ではない。** headが届いたら実装で確かめる

**固定データ**：`AFFILIATE_PAYMENT_PERIODS`（`fixtures.mjs`）。
決まったことをそのまま形にしてある。

- **締め済みの期間は変更しない** → `status: 'closed'` の行は金額が動かない
- **返品は次の未締め期間へマイナス調整** → `adjustments` に負の `amount` を持ち、
  **どの締め済み期間の返品か**を `originPeriodId` で指す
- 締める前は `approvedReward`、締めたあとは `closedAmount`。
  **`njLGA` と同じく「未払い残高」とは書かない**

場合分けは **締め済み1・未締め1・調整あり1・調整なし1**。
0件は `AFFILIATE_PAYMENT_PERIODS_EMPTY`。

**撮る状態**：通常・読込・0件・取得失敗・**締め済みだけ**・**未締めだけ**。

**必ず見ること**（`njLGA` の受入条件から引き継ぐ）

- 締め済みの行の金額が、あとから動かないこと
- 返品が**締め済みの期間を書き換えず**、次の未締め期間にマイナスで出ること
- **取得失敗を0円にしない**（`njLGA` でここがP0だった。**同じ帯を使うなら同じ穴が出る**）
- 実値0は `0円`
- 振込先・振込CSVを作らない

## 2. `ymXJK` 21-1-E コラムを書く

- **想定ルート**：`/nen-campaigns`（コラムのタブの中）
- **想定の口**：`POST /api/nen-campaigns/columns`
- **列は推測ではない**——`nen_columns`（`bootstrap.sql:1458`）そのまま

**決まっていること：V6は外部記事リンク方式。本文をDBに持たない。**
よって `article_url` は必ず埋まり、本文の列は増やさない。いまの取り込み口
（EC-CUBEからの署名付きWebhook `verifyEccubeSignature`）と同じ形で、
管理画面からも作れるようにするだけ。

**固定データ**：`NEN_COLUMN_DRAFT`（`fixtures.mjs`）。
場合分けは **公開済み・下書き・画像なし・公開日未取得**。
`publishedAt: null` を入れてあるので、**今日の日付で埋めていないか**が見られる。

**必ず見ること**

- 本文を書く欄が**無い**こと（外部記事リンク方式なので、あったら設計と違う）
- `article_url` が必須で、空のまま保存できないこと
- 公開日が未取得のとき `—`（今日の日付で埋めない）
- 日時が日本時間で出ること（`formatNenJobDateTime` と同じ扱い）

## 3. 削除確認の束（#574 #575 #580 #581 #438）

画面は既に台帳にあり（`UIaM7` `szXsT` `yPkWe` `gBp2J` `YfTfJ`）、
固定データも揃っている。**headが来たら `--only` で撮るだけ。**

**必ず見ること**（束として共通）

- 消す前に**何がどれだけ影響を受けるか**を数で出すこと
- 使用中のものを**そのまま物理削除しない**こと
- 取得できないときに**0件として出さない**こと
- `force` のような**抜け道を画面から押せない**こと
