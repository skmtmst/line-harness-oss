## 未実装10枚の中身

### 開いた状態を出せなかったもの（3枚）→ 直しました

`YZaDK` `L35UOV` `IYjvu` は「プルダウンを開いた状態」ですが、実装は素の
セレクトで、**開いた中身がブラウザ任せのため画像に写りませんでした。**
素のセレクトのままでは永久に見比べられないので、専用の部品を作りました
（`components/chats/inbox-dropdown.tsx`）。

**共通の `Select`（`Gfsb4`）は使えません。** 設計は作りが違います。

- 担当者（`lJ1CF`）… 選択肢の上に**名前で絞る入力欄**がある。担当が増える
  ほど縦に伸びるので、探す手段が要る
- 対応マーク（`k6lHgo`）… 1件ずつに**色の丸と色付きの札**が付く。文字だけ
  だと、一覧の札と目で結びつかない

一覧の担当者絞り込みも同じ部品へ寄せました。色を直に書いた素のセレクト
だったので、実測値の直書きが4つ減っています。

**設計側の抜け**: `k6lHgo` の選択肢は 未対応・対応中・対応済 の3つで、
**「保留」がありません。** 一覧の絞り込みタブには保留があるので、
設計の描き落としと思われます。実装は4つ出しています。

### 絞り込みパネル（1枚）→ 作りました

**先に書いた「開く入口が無い」は誤りでした。** 開く操作は `<details>` /
`<summary>` で作られていて、ボタンとして探していたため見つけられません
でした。撮り方の側の見落としです。

ただし中身は違いました。実装は208pxの小箱に**対応状態だけ**。設計
（`bXyEA`）は420pxのパネルに 対応マーク・担当者・受信経路・期限・
メッセージ種別・未読だけ表示 の6項目です。**箱が小さいと、置ける条件の数が
先に決まってしまいます。** 設計どおりのパネルに置き換えました。

**繋がっていない条件は、押せない形で出しています。** 「期限」と「表示する
メッセージ種別」は絞り込める口がまだありません。押せるのに何も起きない操作は
無いより悪い（効いたつもりで読み違える）ので、`disabled` と「まだ絞り込め
ません」を添えてあります。設計では両方とも押せる形なので、**そこは差として
残ります。**

### テンプレートの置き場（2枚）→ 直しました

**「フォルダの区分が無い」と書いたのは誤りでした。** 置き場を選ぶ仕組みは
前からあり、**固定データが空でひな形が1枚も無かった**ので、選ぶものが出て
いなかっただけです。設計の件数（未分類3・お問い合わせ8・予約5・EC4＝20枚）を
入れました。

選ぶ形は素の `<select>` だったので、**開いた中身が画像に写りません**でした。
設計（`esGzX`）の 検索欄＋すべてのフォルダ＋置き場ごとの件数 に合わせて
部品へ替えています。**件数を出すのが要点です。** ひな形が20枚あるとき、
どこに何枚あるかが分からないと「予約」を開くべきか決められません。

置き場の行には `フォルダ ◯◯` という名前を付けました。分類のチップにも
「予約」があり、**どちらを指しているか読み上げでも試験でも分かりません**でした。

### 名前を付けて保存する流れ（4枚）→ 直しました

**「この条件を保存が無い」と書いたのも誤りでした。** 名前の入力欄と保存
ボタンは、保存した検索のパネルの中に**直接**並んでいました。

ただし設計（`Ln4zS`）は560pxのモーダルです。**インラインの入力欄には、
何を保存しようとしているのかが書いていません。** 絞り込みを変えたつもりで
前の条件を保存してしまいます。設計は名前と「保存する条件」を並べて見せて
から保存させます。

エラーは**空と重複で文を変えます。**「保存できません」だけだと、名前を
書けばいいのか別の名前にすればいいのかが分かりません。

| | 出る文 |
|---|---|
| 空のまま押した | 検索名を入力してください |
| すでにある名前 | 同じ名前の検索がすでにあります。別の名前にしてください |

字数は「8 / 40文字」と出します。**残り字数だけだと上限が分かりません。**

エラーと完了の設計（`mxpHZ` `xIbXt` `WtxZM`）は参照ノードで、**文言を
読み取れませんでした。** 上の文はこちらで決めたものです。設計に文言がある
なら差し替えます。

## 固定データについて

空で返していたあいだ、受信箱は**会話が1件も出ず**「チャットを選択して
ください」だけの画面でした。設計と並べても「差が無い」とは言えません。

途中で3回落としました。**どれも、こちらの返事の形が違っただけです。**

| 何が起きたか | 原因 |
|---|---|
| 会話を開くと画面ごと「もう一度試す」になる | `/api/friends/:id/mileage` が `summary` を返さず、`summary.programName` で落ちていた |
| 同上 | `/api/friends/:id` が一覧の形（`{items,total}`）で、`friend.tags.length` で落ちていた |
| 同上 | `/api/chats/:id` が同じく一覧の形で、`friendName.charAt(0)` で落ちていた |

**仕組みがこれを見逃していました。** 撮影は成功扱いのまま、落ちた画面の絵を
残していたので、`capture-screens.mjs` に「画面を表示できませんでした」などの
文言を見る検査を足しました。

吹き出しの向きは `incoming` / `outgoing` です。`inbound` / `outbound` と
書くと、画面はどれも受信側として描きます。

## 撮り方で直したこと

**日本時間で撮るようにしました。** 撮る機械の時計帯のままだと、設計の
「14:16」が「12:16」になります。設計は日本時間で描かれているので、
合わせないと時刻の入る画面すべてが「差がある」ように見えます。

**1枚目で止めないようにしました。** 17枚ある機能で最初の1枚が撮れないたびに
止まると、残り16枚の状態が分からないまま直しに入ることになります。撮れな
かったものをためて、最後にまとめて出します。黙って飛ばすことはしません。

## 撮り方でもう1つ直したこと

`capture.spec.mjs` の**ダッシュボードにも時計の固定が要りました。**
「6日前」は今日から数えるので、日をまたいだ翌朝に「7日前」へ変わり、
基準画像が赤くなりました。実際に一度そうなっています。
