# `byqIW` フォルダ作成・編集の引き継ぎ（Codex 向け）

設計Node `byqIW`（`/tags/folders/new`）を実測へ合わせた際に、**API側で埋めたい穴**だけを残します。
画面は既存の口だけで動いており、この引き継ぎが入るまで壊れません。

## いま使っている口（変更不要）

| 用途 | 口 | Web側 |
|---|---|---|
| 作成（タグ） | `POST /api/tag-groups` | `api.tagGroups.create({ name, color })` |
| 更新（タグ） | `PATCH /api/tag-groups/:id` | `api.tagGroups.update(id, { name, color })` |
| 作成（友だち情報欄） | `POST /api/folders` | `api.folders.create({ kind: 'friend_field', name, color })` |
| 編集時の読み込み | `GET /api/tag-groups` | `api.tagGroups.list()` |

## 足りない口

### 1. フォルダ1件を読む口がない

編集（`?id=`）で開くと、**全フォルダを一覧で取ってから `find` で1件を選んで**います。
件数が増えるほど、1件直すために全件を運ぶことになります。

- 欲しい口：`GET /api/tag-groups/:id`
- 返り値：`ApiResponse<TagGroup>`（`id` / `name` / `color` / `sortOrder`）
- 状態番号：`200`、`403` 見る権限なし、`404` 見つからない
- 副作用：なし（読み取りのみ）

**いまは404と403を区別できません。** 一覧が空で返ってきたのか、権限で弾かれたのか、
消えた後なのかが同じ「読み込めませんでした」に潰れています。画面側は
`ApiError.status === 403` を `見る権限がありません` に振り分ける枝だけ先に用意してあるので、
上の口が入れば `404` を「このフォルダは削除されています」に分けられます。

### 2. `PATCH /api/tag-groups/:id` の同時更新

2人が同じフォルダを開いて保存すると、**後勝ちで黙って上書き**されます。
`409` と現在値を返してもらえれば、画面側で「別の人が変更しました」を出して描き直せます。

- 欲しい状態番号：`409`（`code: 'conflict'`、`data` に現在の `TagGroup`）
- 副作用：なし（保存しない）

## 画面側で決めた言葉（口が入っても変えない）

| 状態 | 画面の言葉 |
|---|---|
| 読込中 | 読み込んでいます |
| 取得失敗 | 読み込めませんでした ＋「再読み込み」 |
| 権限不足（見る） | 見る権限がありません |
| 権限不足（保存） | 操作する権限がありません |
| 名前が空 | フォルダ名を入力すると保存できます |

保存ボタンは、**読み込めていないあいだと権限が無いあいだは押せません。**
止めている理由は必ず本文にも出しています（押せない見た目だけにしない）。
