  調整元ID   入力なし

# P1：失敗すると `API error: 405` と生で出る

書き込みの口を405で返したとき、窓の中にこう出ます。

```
API error: 405
```

窓は開いたままで、「入力に戻る」も残ります。**入力が消えないのは
正しい**のですが、**文字が運用の人に読めません。**

#420 の `yKEdO` で挙げた「`API error: 500` が生で出る」と同じ形です。

**推奨（Node `vz0Ji`／`/mileage/friends/detail`／P1）：**
数字は残してよいので、その前に何が起きたかと次の手を書く。
たとえば「マイルを動かせませんでした（405）。時間をおいて、
もう一度お試しください。」

| 設計 | 実装 |

| だれの欄に**ランク**（ゴールド） | 名前と残高だけ |

| 減らす「残高から引きます。**足りないときは 0 で止まります。**」 | 「残高から引きます」 |

## `mock-api.mjs` の前検査を直しました（**実装の不具合ではありません**）

はじめ `Failed to fetch` と出て、実装が生のエラーを出しているように
見えました。**こちらの `Access-Control-Allow-Headers` が足りず、
ブラウザが前検査で弾いていた**だけでした。

`Idempotency-Key` を足したらまだ落ち、次は `X-Confirm-Irreversible` でした。
**数え上げるとまた漏れる**ので、`Access-Control-Request-Headers` を
そのまま返す形にしました。通すのは前検査だけで、**書き込みそのものは
これまでどおり405に落ちます。**

直したあとに出たのが上のP1（`API error: 405`）です。
**前検査を直さなければ、実装の不具合として誤って報告していました。**
