# `uNBlA` 共通情報「変える前に影響を見る」：口の引き継ぎ

## 正本と範囲

- Node: `uNBlA`（V6 14-1-B）
- ルート: `/contents/vars/edit?id=...`（正規URLは `/contents/vars/{varId}/impact` の予定）
- 要件: `docs/v6-requirements/v6-14-common-information-requirements-draft.md` 7章
- この引き継ぎは**画面側で埋められなかった節**だけを書く。埋まった分は実装済み。

## いま画面が読んでいる口

`GET /api/common-vars/:id/delete-impact?accountId=:accountId`

名前は削除向けだが、返るのは使用先台帳そのものである。編集画面はここから
次を読んで「影響確認」の節を描いている。

- `blockingTotal` … 保存するとすぐ変わる場所の数
- `historicalTotal` … 送信済みで**変わらない**場所の数
- `items[]` … 種類・名前・状態・導線・`currentPreview`（いまの文）
- `unavailableReferences[]` … 所属を確定できず名前を出せない使用先の件数と理由
- `checkedAt` … いつ時点で確かめたか

403は「見る権限がありません」、503は「読み込めませんでした」＋再読み込みで出す。
**未取得を0か所として描いていない。**

## まだ無い口

### 1. 変更後の文と文字数の検査

要件 7-2 の `POST /api/common-vars/:id/impact-preview` が無い。画面はこの節を
`—`＋「まだ繋がっていません。変更後の文と文字数の検査が接続されると表示されます。」
で出している。

必要なのは次である。

- 下書きの値を渡して、使用先ごとの**変更後の文**を返す
- 媒体別の文字数・バイト数・URL・altTextの検査結果
- 空になる箇所、必須値の欠落
- 予約中配信・公開中フォームのうち、ライブ参照で実際に変わるものの内訳
- `previewToken`、対象版、使用先集合のハッシュ

`currentPreview` の文字列を画面側で置換して「変更後の文」を作ってはいけない。
現在値がたまたま本文に自然に現れている場合に、差し込みでない箇所まで
書き換えた絵を出してしまう。**取れない値を作らないこと。**

### 2. 使用中の直接保存を止める

要件 6-2 は「使用先が1件以上なら、保存ではなく影響を確認へ進む」としている。
いまは `impact-preview` が無く、止めると編集そのものができなくなるため、
**保存は押せるまま**にして影響確認の節を先に出すだけにした。

`impact-preview` が入った時点で、使用先1件以上のときは保存を
`BlockedAction` に置き換え、影響確認を通した `previewToken` がある場合だけ
押せるようにする。

### 3. 版・変更理由・履歴

要件 6-3 の追記型履歴（版番号、変更前後、変更理由、担当者）と 6-2 の
楽観ロック（409で差分表示）が無い。いまの `PATCH /api/common-vars/:id` は
`expectedVersion` を受けないので、後勝ちで上書きされる。画面は409を
「ほかの人が先に保存しました」と言える形にしてあるが、Workerが409を
返す口はまだ無い。

## 画面の受入条件（この画面で守っていること）

1. 影響確認の節は**必ず出す**。読めないときも節ごと消さない。
2. `—` と `0か所` を混ぜない。0か所は「どこにも差し込まれていません」と書く。
3. 送信済みは「すぐ変わる」に混ぜない。「変わりません」と明記する。
4. 名前を出せない使用先も件数と理由を残す。内部IDは出さない。
5. 保存の失敗は理由を運用者の言葉で出す。`API error: 500` のような内部文は出さない。
6. 権限不足（403）は「操作する権限がありません」。読み込み失敗と分ける。
