# 機能5（シナリオ配信）— 口が足りずに画面へ出せていないもの

対象：`bV5Vs` `xfYLn` `r6Gzsu` `EvVO5` `g2UNV`
枝：`codex/kenta-v6-feature5-design-fit`
書いた人：@kenta 2026-09-02

設計には数や口があるが、**取ってくる先が無い**ものを並べる。画面側は
`—`＋「まだ繋がっていません。○○が接続されると表示されます。」で止めてある。
数を作らないので、口が付いたときに画面を直せばそのまま出る。

## 1. 新規開始予定の人数（`EvVO5`）

設計は開始条件の面に「一致 124人／すでに購読中 8人／新規開始予定 116人」を出す。

- **一致** … `POST /api/segments/count` で数えている（実装済み）。
- **すでに購読中** … シナリオの集計（`activeNow`）から出している（実装済み）。
- **新規開始予定** … **口が無い**。`—` にしてある。

**一致から購読中を引いてはいけない。** 購読中の人がいま条件に一致している
とは限らないので、引き算だと画面にだけ在る数になる。

欲しい口：条件と、そのシナリオの購読状態の**重なり**を数えるもの。
たとえば `POST /api/scenarios/:id/start-preview` が
`{ matched, alreadySubscribed, newlyStarting }` を返す形。

## 2. 開始のきっかけ 4種（`EvVO5`）

設計は6種（友だち追加／タグ追加／フォーム回答／予約確定／手動開始／API・Webhook）。
実装が受け取れるのは `friend_add` と `tag_added` の2つだけ。残り4つは押せない
形で並べ、理由を本文に書いてある。

欲しい口：`POST /api/scenarios/:id/triggers` が
`form_answered` `booking_fixed` `manual` `api` の `kind` を受け取ること。

## 3. 「初回のみ／毎回」の開始（`EvVO5`）

設計は「同じ友だちは初回のみ開始」「条件を満たすたびに開始」を選ばせる。
**保存先の列が無い**（`scenarios` に相当する列が無い）。

2つとも押せない選択肢になるので、**画面には出していない**。片方も動かない
切り替えを置くと、押して何も起きない面が増える。列が付いたら足す。

欲しいもの：`scenarios.restart_mode`（`first_only` / `every_time`）と、
`GET/PATCH /api/scenarios/:id` での読み書き。

## 4. 1通ごとのテスト送信結果（`g2UNV`）

設計は送った結果を1通ずつ確かめる。
`POST /api/scenarios/:id/test-send` が返すのは **送った合計だけ**（`{ sent }`）。
合計から1通ずつの成否を作ると、落ちた通が成功に見える。

画面は「送る内容」を1通ずつ並べたうえで、結果の桁を `—` にしてある。

欲しい口：`{ sent, results: [{ stepId, ok, error }] }` の形。

## 5. 配信前チェック（`xfYLn`）

設計は右の柱に4行（配信対象が設定されています／配信日時が設定されています／
テスト送信が未完了です／送信枠を超えていません）。

- 前の2つは画面の値から出せる（「設定内容」の段に出してある）。
- **テスト送信の済み／未済**を持つ場所が無い。
- **残りの送信枠**を返す口が無い。

4行のうち2行だけ出すと「全部確認できた」と読めてしまうので、
チェックの行そのものを `—` にして理由を書いてある。

欲しい口：`GET /api/scenarios/:id/preflight` が
`{ testSentAt, quotaRemaining }` を返す形。

## 6. 台帳（`scripts/visual-qa/screens.mjs`）の注記が実物と違うところ

最新の `origin/codex/development` で読んだ結果。

- `bV5Vs` の注記は「#625 で①`afterSend` を『次へ進む』に②配信対象の列を追加
  ③警告を帯へ④見出し7個を共通 `Th` へ（直書き 7 → 0）」と書いてあるが、
  **development にはどれも入っていなかった**（`direct-th` は 7 のまま、
  警告は見出しの説明文の中、`配信後` は `—`、配信対象の桁は無し）。
  このPRで4つとも入れた。
- `g2UNV` の注記は「`W98zZQ`（リマインダのテスト送信）が
  『本番の登録は増えません／配信予定は作りません』の断りを既に持っている」と
  書いてあるが、**その文字列はリポジトリのどこにも無い**。
  リマインダ画面にテスト送信そのものが無い。今回はシナリオ側に文言を起こした。
- `g2UNV` の注記は「実装は一括で送るところまで」と書いてあるが、
  テスト送信の窓は**前から送信先を選べる**。足りないのは
  「送る前に何が送られるか」と「1通ずつの結果」のほう。
