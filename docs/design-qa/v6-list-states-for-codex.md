# 一覧の状態（空・読込・エラー）— Codexへの引き継ぎ

設計は**どの一覧にも**「読み込んでいます／まだ〜がありません／表示できませんでした」の
3枚を並べています。**18枚ぶんの設計**がこれにあたります。

撮る仕組みを足して、18画面すべての実際の状態を撮りました。結果は下のとおりです。

## 結論

**共通部品（`components/shared/list-state.tsx`）は在るのに、
使っているのは友だち属性の「タグ」タブだけです。**

そのため**ほとんどの一覧で、読み込みに失敗しているのに「ありません」と出ます。**
共通部品の覚え書きに、まさにその理由が書いてあります。

> 一覧はどれも `items.length === 0` だけを見て「ありません」と出していた。
> 読み込みに失敗したときも同じ文が出るので、運用する人からは
> **「登録したものが消えた」ように見える**

## 実際に見えているもの（抜粋）

| 画面 | 読み込み失敗のときに出るもの |
|---|---|
| ウェビナー（`zCQXe`） | **「ウェビナーがまだありません」＋「最初のウェビナーを作成」**。さらに `API error: 500` の生の文字 |
| オートメーション（`Vdbv5`） | 「オートメーションがありません。「新規ルール」から作成してください。」 |
| テンプレート（`NKyoA`） | 「該当するテンプレートがありません」 |
| 友だち情報欄（`yKEdO`） | 「項目がまだありません。「項目を追加」から作ってください。」 |

**「最初のウェビナーを作成」は、押すと二重に作ります。** 元のデータは
消えていないのに、消えたように見えて作り直す形です。

リマインダ（`dC0yg`）は**言い分けられています**（帯が `—`「取得できませんでした」、
本体が「いまは読み込めていません。上の案内をご覧ください。」）。
ただし共通部品は使っていません。

## 推奨する直しかた

`components/shared/list-state.tsx` を各一覧へ入れて、
**loading / empty / error を3方向に分けます。**

```tsx
{loading ? (
  <ListState kind="loading" />
) : error ? (
  <ListState
    kind="error"
    title="ウェビナーを読み込めませんでした"
    description="通信が切れているか、サーバーが応答していません。少し待ってから開き直してください。"
  />
) : rows.length === 0 ? (
  <ListState kind="empty" title="…がまだありません" description="…" action={…} />
) : (
  …一覧…
)}
```

**エラーのときは `action`（作る導線）を渡さない。** 渡すと二重に作らせます。

## 撮り方（直したあとの確かめかた）

```bash
node scripts/visual-qa/capture-screens.mjs --feature N --impl
```

`states` を持つ行は `<node>-loading-<幅>.png` `<node>-empty-<幅>.png`
`<node>-error-<幅>.png` の3枚が出ます。**どの状態が出ているかを名前で
言えるか**も一緒に出ます（`empty→empty` なら合格、`empty→—` は
共通部品を使っていない）。

いまは18画面すべてが `→—` です。
