## いま「リッチメッセージ」と呼ばれているもの

一覧のタブ「リッチメッセージ」は、テンプレートではなく
**配信素材（`broadcast_message_assets` の `kind: 'rich_message'`）** を出しています。
描いているのは `apps/web/src/components/broadcasts/broadcast-asset-manager.tsx`
で、作成はタブの中の折りたたみフォームです。

| | いまの配信素材 | 設計 `j9ixI` |
|---|---|---|
| 面の分け方 | 無し（画像1枚） | **6型**から選ぶ |
| 面ごとの動き | タップ時に開くURLを1つ | **面ごと**にアクション（URL・テンプレート・タグ付与など） |
| 画面の型 | タブの中の折りたたみフォーム | E型（パンくず＋編集本体＋右390pxプレビュー＋下部追従バー） |
| LINEプレビュー | 無し | 右390pxに `NLsw4` |
| 使う場所 | 無し | 「使う場所」カード（全作成画面に置く決まり） |
| リッチメニューとの違い | 書いていない | 併記する |

つまり **設計の `j9ixI` は、いまの素材フォームの置き換えではなく別物** です。
素材フォームを `j9ixI` の見た目に寄せるだけでは、面の分割も面ごとの動きも
入りません。

## 作るのに要る口

### 1. 面の分割と面ごとの動きを保存する

いまの `POST /api/broadcast-message-assets` の `payload` は
`{ imageUrl, actionUrl }` だけです。**面を持てません。**

```ts
/** kind: 'rich_message' の payload。 */
interface RichMessagePayload {
  /** 面の分け方。設計の6型。 */
  layout: 'full' | 'split2v' | 'split2h' | 'split3' | 'split4' | 'split6'
  imageUrl: string
  /** 面の数は layout で決まる。足りない・多いは 400 で止める。 */
  areas: {
    /** 面の番号（左上から）。 */
    index: number
    action:
      | { type: 'none' }
      | { type: 'url'; url: string }
      | { type: 'template'; templateId: string }
      | { type: 'tag'; tagId: string }
  }[]
}
```

| 決めること | 提案 |
|---|---|
| 画像の寸法 | LINEのリッチメッセージは 1040×1040（正方形）か 1040×520。**入れた瞬間に検査して止める** |
| 面と layout の整合 | `areas.length` が `layout` の面数と違えば 400（`rich_message_areas_mismatch`） |
| 面の座標 | `layout` から決まるので保存しない。画面と配信側で同じ表から引く |

### 2. 使う場所を逆から引く

設計は「使う場所」カードを全作成画面に置き、`＋ 使う場所をここから追加する`
で逆向きにも繋げます。テンプレートには `GET /api/templates/:id/usages` が
ありますが、**配信素材には同じ口がありません。**

```
GET /api/broadcast-message-assets/:id/usages?lineAccountId=:accountId
```

返すのは、引用している一斉配信・シナリオ・自動応答の 種別／名前／状態／`href`。
**取得失敗を0件として描かないでください。** 読込中・0件・取得失敗を分けます。

### 3. 削除の前に使用先を見る

いまの削除は素の `confirm()` から `DELETE` を投げるだけです。共通情報
（`yPkWe`）・回答フォーム（`gBp2J`）と同じく、削除前の影響確認が要ります。

```
GET /api/broadcast-message-assets/:id/delete-impact?lineAccountId=:accountId
```

### 状態番号（3つの口に共通）

| 番号 | とき | 画面の出しかた |
|---|---|---|
| 200 | 読めた（0件でも200） | 0件は `0件` と書く |
| 400 | 面の数・画像の寸法・URLが合わない | 入力の誤りとして、その欄に出す |
| 403 | そのアカウントを扱う権限が無い | 「操作する権限がありません」 |
| 409 | 確認したあとに使われ始めた | 窓を閉じず、最新の影響へ差し替える |
| 503 | 使用先を読み切れなかった | **0件扱いにしない。** 削除を止める |

### 副作用

- 画像は `POST /api/broadcast-message-assets/upload` に載ります。**先に上げた
  画像を、保存せずに離れたときに消す口がありません。** 迷子の画像が残ります。
- 作成・更新は配信側から即座に引用できるようになります。**下書きの状態が
  ありません。** 設計の追従バーには「下書きに保存」があるので、
  `status: 'draft' | 'published'` が要ります。

## この版でやったこと（`/templates` 一覧側）

1. 一覧の面に `data-design-node="W7LBc"` を付けた（タブ `kcmGB`・作成 `FuBeQ` は既に有り）
2. 読込中・取得失敗・**権限不足**・初回空・絞り込み0件の5つを言い分けた。
   以前は4つとも「該当するテンプレートがありません」の1文で、読み込みに
   失敗したときも、登録したものが消えたように見えていた
3. 読み込めていないあいだ「テンプレートを作る」を押せる形で置かず、理由を本文に出した
4. 案内帯が「送信数を確認できます」と書いていたのを直した。テンプレート別の
   送信集計は繋がっていないので、表では `—` のままになる
