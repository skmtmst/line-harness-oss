## 未取得と0件が分かれています

- 金額を持たない成果地点は「**金額なし**」（`資料ダウンロード`）
- 使われていないものは「**どこからも使われていません**」。これは
  `usedIn` が**空配列**のとき。型の覚え書きに
  「理由が無いときも空配列を返す。省略は『未取得』と区別するため
  使わない」とあり、**省略できない形で決まっています**
- 止めたものは操作の列が「過去実績を保持」になり、押せる操作が消えます

# `GUxsj` レポート — P1

実装はこれだけです。

```
成果地点（CV）名  種別      CV数  金額
体験申込フォームの送信  申込・登録  386   ¥1,158,000
定期便の申込          購入       42    ¥126,000
資料ダウンロード      URLクリック  58    —
旧キャンペーンの申込   申込・登録   0    —
合計                                ¥1,284,000
```

**金額の無いものが `—`、成果0件が `0` と分かれています。** そこは正しい形です。

設計にあって実装に無いもの：

| 設計 | 効き |
|---|---|
| 帯4つに**前の30日との比較**（486件／前の30日 412件、+18%） | **増えたのか減ったのかが分からない。** 数字だけでは判断できない |
| 「いちばん伸びた +62% 体験申込」 | どこに手を入れるかの当たりが付かない |
| 日ごとの棒グラフ＋「8/13 に伸びているのは一斉配信『夏のご案内』を出した日です」 | **何をしたから増えたのか**が分からない |
| 表の「前の30日」「増減」「**いちばん多い経路**」 | 経路が分からないと、次にどこへ出すか決められない |
| 「この画面をCSVで書き出す」 | 無い |

**推奨：** まず「前の30日」と「増減」の2列。比べる相手が無い数字は、
高いのか低いのか言えません。

# `d8d3Mz` 削除確認 — 未実装 → 要修正

**#444 で窓が入りました。** 実装側に `data-design-node="d8d3Mz"` の印まで
付いています（`conversions/page.tsx:383`）。前はブラウザの `confirm()` で、
撮ることもできませんでした。

| 設計 | 実装 |
|---|---|
| 「『体験申込フォームの送信』を**削除**しますか？」 | 「『…』の**計測を停止**しますか？」 |
| 「3か所から呼ばれています。消すと、その3か所が同時に動かなくなります。」 | 「新しい成果は数えなくなります。過去の成果・金額・分析結果は削除しません。」 |
| 使っている場所に **［案件を開く］［自動応答を開く］［分析を開く］** | 場所は並ぶが**開くボタンが無い** |
| 「これまでに数えた486件の記録も一緒に消えます。」 | 「**そのまま残るもの**／過去の成果 128件・金額 ¥384,000」 |
| **3択**（数えるのをやめる（おすすめ）／別の成果地点に差し替えてから削除する／このまま削除する） | **停止だけ。削除の道が無い** |

## これは差というより、決め直しだと思います

設計は「削除」を主にして、いちばん安全な「数えるのをやめる」を
おすすめとして並べています。実装は**削除の道をなくし、停止だけ**に
しました。成果地点を消すと過去の数字と分析が消えるので、
**実装のほうが安全です。** 文言もそう書いています。

ただし設計の3択のうち「**別の成果地点に差し替えてから削除する**」は、
間違えて作ったものを片づける道です。停止だけだと、
**使わない成果地点が増え続けます**（一覧の「どこからも使われていない」が
まさにそれを数える札です）。

**Codexへ：** 削除をなくす決めでよいか、確認をお願いします。
なくすなら、「どこからも使われていない」札の先に片づける道が要ります。
