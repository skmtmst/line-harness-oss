# V6 シナリオ（送信後アクション・1通目設定）の引き継ぎ

対象は `hz9ti`（送信後のアクションを設定）と `kk8dz`（1通目設定）です。
画面側は設計へ寄せましたが、**読む口・書く口が無いために作らなかったもの**が
3つあります。作れる形になるまで、画面には出しません。空欄だけ置くと、
書いたものが保存されずに消えたように見えます。

## 1. アクションの共通設定（アクション名・フォルダ）

設計 `hz9ti` の2段目は「アクション名（h40）」と「フォルダ（w300 h40）」です。

現在の `scenario_actions` には名前もフォルダもありません。`ScenarioAction`
（`apps/web/src/lib/api.ts`）が持つのは `hook` / `stepId` / `choiceIndex` /
`sortOrder` / `actionType` / `config` / `condition` / `repeatOnRefire` だけです。

要るもの:

- `scenario_actions` に名前を持たせるのか、**hookごとのまとまり**に名前を
  持たせるのかの判断。設計の「アクション名」は窓に1つなので、後者に見えます。
  その場合は入れ物にあたる行が新しく要ります
- フォルダは既存のフォルダ機構（`kind`）に `scenario_action` を足すのか、
  別に持つのか
- `GET`/`PUT` の口。名前だけ先に足しても、一覧側に出す場所が無ければ
  付けた名前を誰も読みません。**どこで読むのかまで決めてから**足してください

## 2. 動作の種別が8つ

設計は4×2で8つ並びます。実装の `ScenarioActionType` は5つです。

- `tag` タグ操作
- `friend_field` 友だち情報操作
- `support_mark` 対応マーク操作
- `scenario` シナリオ操作
- `common_var` 共通情報操作

残り3つが何かは設計の実測からは決まりません。押しても何も作れない札を
3つ増やしても、できることは増えないので並べていません。種別を足すときは
`packages/shared` の型、worker の `services/scenario-actions.ts`、
画面の `ACTION_KINDS` と `ActionConfigEditor` の4つが揃って初めて足せます。

## 3. 「発動2回目以降も各動作を実行」の置き場所

設計はセクションに1つ、実装は動作ごとに1つです。**実装のままにしました。**

`repeatOnRefire` は `scenario_actions` の行ごとの列です。セクションに1つへ
まとめると、動作ごとに違う値を持てなくなり、まとめた側を押した瞬間に
既にある設定を黙って上書きします。「タグは付け直すが、加算はもう一度
足したくない」が書けなくなります。

セクションに1つへ寄せるなら、先に**どちらが正本か**を決めてください。
まとめる側を正本にするなら列を `scenarios` へ移す必要があり、それは
進行中の購読にも効く変更なので、版の固定と一緒に決めるべきものです。

## 4. 1通目の本文の上限

`kk8dz` の「52 / 5,000」は出しました。上限はLINEのテキストメッセージの
5,000字で、超えたときは保存操作を押せなくしています
（`apps/web/src/components/scenarios/char-counter.tsx`）。

画面側でしか見ていないので、APIにも同じ上限の検査があると安全です。
いまは `POST /api/scenarios/{id}/steps` が長さを見ていません。
