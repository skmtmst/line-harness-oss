## 種類が1つ足りない（`NNDMR`）

設計のタブは6本です。実装は5本で、**「質問」だけがありません。**

| 設計 | 実装 |
|---|---|
| メッセージ / カルーセル / リッチメッセージ / **質問** / クーポン / リサーチ | メッセージ / カルーセル / リッチメッセージ / クーポン / リサーチ |

「質問」は、文のあとにボタンを2つ出して、押された選択肢ごとに
**タグを付ける・シナリオを開始する・フォームを開く**を分ける道具です。
「はい、続けます／いったん止めたい」の受け止めがこれにあたります。

いまは同じことをするなら、カルーセルのボタンで代用するか、自動応答で
キーワードを待つかになります。どちらも**押した人が誰かを取りこぼします。**

## クーポンとリサーチは、名前とURLしか作れない（`hsBtl`・`J3GxEZ`）

| 設計のクーポン | 実装 |
|---|---|
| 画像（1029×1029） | 無い |
| 使える期間（開始・終了） | 無い |
| 使い方のご案内（お客さまに見える） | 「特典内容・利用条件」の自由記入 |
| 使える回数（1人1回／何回でも） | 無い |
| だれに見えるか（友だちだけ／リンクを知っている人／誰でも） | 無い |
| 抽選（当たる確率・当選人数の上限） | 無い |
| クーポンコード | 無い |
| 使われたときに実行すること | 無い |

実装の入力欄は **名前・特典内容の自由記入・クーポンを開くURL の3つ**です
（`broadcast-asset-manager.tsx:76`）。つまり**クーポンそのものは作れず、
どこか別で作ったクーポンのURLを貼るだけ**です。

「使える期間」「1人1回」「当選人数の上限」は、決めておかないと運用で
効いてきます。抽選の上限が無いまま配ると、全員に当たります。

リサーチも同じで、**質問を1問も作れません**（説明とURLだけ）。
設計は10問まで、種類（1つだけ選ぶ／いくつでも／自由に書く）と
答えの残し先（友だち情報欄・タグ）まで決めます。

## フォルダを作れない（`CzndJ`）

左の縦帯は**テンプレートの `category` という文字から自動で生えているだけ**で、
`/api/folders` を一度も呼んでいません（`grep api.folders` が0件）。
つまり **作る・名前を変える・消すのどれもできません。**

設計は「フォルダを追加」を持ち、こう書いています：
「フォルダはアカウントで1組。上のタブは種類の絞り込みで、フォルダは増えません。」
つまり**種類とフォルダは別のもの**として設計されています。
実装はそこが一緒になっています。

ほかの一覧（リマインダ・自動応答）は共通の `FolderPanel` と `/api/folders` を
使っています。**テンプレートだけが別の作り**です。
