# `g89Tc` 一括削除の選択を、画面を動かして確かめた（#559 head `7922c002`）

**絵では分からないところなので、DOMと通信を見ました。**
「選べません」の断りは `title`（当てたときに出る吹き出し）なので、
撮った絵には写りません。

固定データは3つの状態を持ちます。

| id | ファイル | `usageCount` | 意味 |
|---|---|---|---|
| `media-1` `media-2` `media-4` | 夏の定番セット.jpg ほか | 3 / 1 / 2 | 使用中 |
| `media-3` | 店内のようす.mp4 | **0** | 数えて0 |
| `media-5` | メニュー表.pdf | **0** | 数えて0 |
| `media-6` | 定期便パンフ.jpg | **無し** | まだ数えていない |

## 見たこと

| 確認項目 | 結果 |
|---|---|
| 未取得のメディアを選べない | ✓ チェック欄が `disabled`。`title="使用先を確認できないため選べません"` |
| 使用中も選べない | ✓ 3枚とも `disabled`。`title="使用先から外すまで削除できません"` |
| 「全てのメディアを選択」で0件の2件だけ | ✓ ボタンが **「選択したメディアを削除（2）」** になる |
| 未取得が削除APIへ送られない | ✓ 送られたのは **`DELETE /api/media/media-3`** と **`DELETE /api/media/media-5`** の2本だけ。`media-6` は送られない |

**#559 の前（`888e80f9`）は3件選ばれていました。**
チェック欄が `disabled={(item.usageCount ?? 0) > 0}` で `undefined` が
`0` に潰れていたためです。いまは `isKnownUnused()`
（`usageCount === 0` だけを真とする）に替わっています。

**二重に止めています。** 選べなくするだけでなく、`removeSelected()` でも
選択に未取得が混ざっていたら送信前に外し、
「使用先を確認できないメディアは削除できません。状態を読み直して確認してください。」
と出します（`contents/page.tsx:210-216`）。画面の状態が古いまま押されても
消えません。
