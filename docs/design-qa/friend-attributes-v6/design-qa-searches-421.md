## 未取得と0件が分かれています

**「なし」（サーバーが0件と確かめた）と「—」（確かめられなかった）が、
同じ列で読み分けられます。**

削除の押せない理由も分かれています（`saved-search-list.tsx` の `title`）。

| 状態 | 出る理由 |
|---|---|
| `lineAccountId` が無い | 管理者が対象アカウントを割り当てるまで変更できません |
| `usedIn` が未取得 | **使用先を確認できないため削除できません** |
| `usedIn` が1件以上 | 使用中のため削除できません（N件） |

**「確認できないから消させない」は正しい向きです。** 分からないときに
消せてしまうのが、前回のP0でした。

参照の仕方まで日本語で出ます（`mode: 'live'` →「条件を自動反映」、
`'fixed'` →「固定した条件」）。**設計より詳しい**ところです。

## P1-1：条件の要約が読めない

一覧に出ているのはこれです。

```
・eq mark-1
・includes tag-0
・between [object Object]
・next_delivery eq 2026-09-01
```

設計はこうです。

```
タグ VIP / 未契約・AND
対応マーク未対応 AND 担当者なし
最終返信60日以上 AND 有効友だち
```

原因は `describeOne`（`saved-search-list.tsx:18-28`）です。

```ts
const label = o.label ?? o.field ?? o.key ?? o.type
```

**`kind` を見ていません。** 型（`SavedSearchCondition`）が持っているのは
`kind` で、`field` も `type` もありません。だから主語が落ち、
`op` と `value` だけが残ります。

`value` が `{ from, to }` のときは `String()` を通って
**`[object Object]`** になります。

### 直せる形が、同じPRの中にあります

#421 は `saved-search-utils.ts` に **`describeSavedCondition`** を
入れています。`kind` ごとに日本語にし、タグはIDから名前を引きます。

```ts
if (condition.kind === 'tag') return `タグ ${…}「${value || '未指定'}」`
```

**ところがこれは、編集画面の `<span className="hidden">` の中でしか
呼ばれていません**（`tags/searches/edit/page.tsx:376`）。
組み立てた文を、そのまま隠しています。

**直し方：** `saved-search-list.tsx` の `describeOne` を捨て、
`describeSavedCondition(condition, tags)` を使う。タグ一覧は
`api.tags.list()` で取れます。

## P1-3：対応マークとシナリオが、IDの手入力

値の欄が種類ごとに分かれています（`edit/page.tsx:102-124`）。

| 種類 | 値の入れ方 |
|---|---|
| タグ | **選ぶ**（名前が出る） |
| 対応状態 | **選ぶ** |
| 友だち状態 | **選ぶ** |
| 友だち追加日 | 日付を2つ |
| 友だち情報 | 項目名＋値の手入力（項目名も選べない） |

対応マークとシナリオの値は**内部のID**です。運用の人は `mark-1` を
知りません。タグと同じように選ばせる必要があります。

# 固定データ

`SAVED_SEARCHES` を**型（`SavedSearch`）に照らして書き直しました。**

- 条件は `{ kind, key, op, value }`。前は `{ field, op, value }` で、
  画面の当てはめが `o.field` の逃げ道を通っていたため、
  **書き方が間違っていることに気づけませんでした**
- 対応マークの `kind` は **`mark`**。`support_mark` と書いていて、
  編集画面の種類が「タグ」に落ちていました。**実装のせいに見えましたが、
  こちらの書き間違いです。** 直したら「対応マーク」と出ました
- `usedIn` `canDelete` `matchCount` は**わざと混ぜて**あります
  （2件／0件／未取得／1件、および 38人／`null`＋理由／12人／`null`＋理由／7人）

## 撮った絵の中で、こちらの都合で違うところ

**該当プレビューの「231人」**は、こちらの固定データの都合です。
編集画面は `/api/friends?savedSearchId=ss-1&limit=1` の総数を読みますが、
**こちらの口は `savedSearchId` で絞っていません。** 一覧の「38人」と
食い違って見えますが、**実装の不具合ではありません。**
