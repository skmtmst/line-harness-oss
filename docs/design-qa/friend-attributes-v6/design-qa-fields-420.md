### 未取得と0件が、絵で分かれました

**空のとき `0件 / 使用中 0件 / 0人 / 0件 / 0件`、失敗のとき
`—件 / —人 / —件 / —件`** です。同じ画面の同じ場所で、
**取れて0だったのか、取れなかったのかが読み分けられます。**

`data-list-state` も3つに分かれました。前回は3つとも `—`（印そのものが
無い）で、機械では見分けられませんでした。

## 見出しの「＋ 項目を追加」について

失敗のときも、見出しの右に緑の「＋ 項目を追加」が残ります。
**これは設計どおりです。** 設計 `yKEdO` も見出しに置いています。

一覧の上にあるもう1つの「＋ 項目を追加」は `status === 'ready'` で
囲まれており（`field-list.tsx:119`）、失敗のときは出ません。
**誘いの文（「最初の項目を作ってください」）も出ません。**

## 残っているもの

### P1：`API error: 500` が生で出る

```tsx
description={error || '友だち情報欄を読み込めませんでした。'}
```

`error` には `ApiError` の `message`（`API error: 500`）が入るので、
**用意してある日本語は一度も出ません。**

設計は「表示できませんでした／**再読み込みしても直らない場合は
エラー報告へ。**」です。見出しは合っていますが、下の1行が
運用の人には読めない形になっています。

**直し方：** `500` などの数字は残してよいので、その前に何をすればよいかを
書く。設計の1行をそのまま使えます。

# 固定データを直しました

**「使用中 undefined件」と撮れていたのは、こちらの固定データの
形違いでした。実装の不具合ではありません。**

帯は `/api/friend-fields-stats`（枝ではなく**ハイフン**）という別の口から
来ます。こちらの当てはめが無く、一覧の既定（`{items,total,page,limit}`）が
返っていたので、`summary.inUse` が `undefined` でした。

- `FRIEND_FIELD_SUMMARY` を型（`FriendFieldListSummary`）どおりに足しました
- `formLinks` は `null` にして、**未取得の道が通ることを撮ります**
- `FRIEND_FIELDS` に `usageCount` を足しました。**型のとおり
  `?withUsage=1` のときだけ付けます**（いつも付けると、付かない側の道を
  一度も撮らないまま合格にしてしまいます）
- 空のときの当てはめ（`EMPTY_BODIES`）にも、この口を足しました。
  空の一覧なら繋がっているフォームも本当に0件なので、`formLinks` は
  `null` ではなく **`0`** を返します

final result: **前回のP0は解決。残り P1 1件（`API error: 500` が生で出る）**
