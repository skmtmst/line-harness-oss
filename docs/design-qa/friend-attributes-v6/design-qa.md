## 撮り方

| | 出どころ |
|---|---|
| 設計 | Pencil `pencil-new.pen` の実ノードを `html-css` で書き出し、Chromium で実寸描画（幅1920、ノードの高さ） |
| 実装 | 実ルートを操作して撮影（作り物の検証ルートは使っていません） |

Pencil の `png` 書き出しは壊れていて、砂嵐になります。`html-css` を経由します。

`fullPage` は `position: fixed` を最初のビューポート位置に焼き込むので、
ドロワー・ダイアログは**設計の高さでビューポートを開いて**撮っています。
`fullPage` で撮ると、ドロワーが途中から始まる誤った絵になります。

## P0：動きが設計と食い違う

### `ee0sk` 編集画面が逆のことを書いている

右下の黄色い枠に「**新規作成の保存では**、既存の友だちへの送信・マイル付与は
行われません」と出ます。`mode` の分岐が無く、編集画面でも同じ文が出ます
（`apps/web/src/components/friend-fields/tag-editor-v4.tsx`）。

**遡及反映をONにして保存すれば、実際に付与されます。** その確認ダイアログ
（`VjXGX`）がある画面で、付与されないと書いている状態です。

設計はここが「**取り消せない操作です** / さかのぼって積んだマイルは自動では
戻せません。人数と金額を確認ダイアログで確かめてから保存してください。」

同じ理由で「この設定で起きること」も、設計では編集時に「この**変更**で起きる
こと」へ変わり、中身も編集向けの4項目になります。実装は作成時と同じ3項目です。

### `zGZMA` 削除後の行き先が違う

| | |
|---|---|
| 設計 | この対応マークを使用している3人は、削除後に「**未対応**」へ変更されます |
| 実装 | 19人の対応マークが「**未設定**」へ戻ります |

設計は**初期値のマークへ寄せる**、実装は**未設定にする**。未設定になった友だちは
受信箱・友だち一覧の対応マーク絞り込みから漏れます。どちらが正かは API 側の
話なので、実装前に決めてください。

見た目も違います。実装は見出しと本文をまとめてピンクの帯に入れていますが、
設計は白地に黒い見出し＋灰色の本文で、赤いのは「削除する」ボタンだけです。
幅も設計560pxに対し実装845pxで、1.5倍あります。
