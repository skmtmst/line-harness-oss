## 作ったもの

席予約では、公開中の同じ店舗のコースを選び、その所要時間で空き・在庫・全卓の占有・閉店時刻を確認する。仮押さえ・確定・変更にも同じコースを渡し、予約時のコース名・アレルゲンを既存の写しへ残す。安全の判定はしない。客が卓を選ぶ操作は作らず、既存の配席を使う。コースや営業時間の改版、古い予約版、二重予約は拒否する。

入口は既存のLIFFの `?page=restaurant&token=...`。`apps/liff` と配備されるWorker clientの両方で同じ画面を開く。旧 `/restaurant/reserve/:token` も通る。Workerで初期化済みのLIFF SDKを共用画面へ渡し、本人名・認証・LINEへ戻る操作までつなげた。

回答フォームの `booking.kind` は、人の予約が `people`（省略時も従来どおり）、席の予約が `seats`。人は従来のメニュー・担当の予約口、席は既存の仮押さえ・確定の口を使う。Workerのフォーム入口では、予約ブロックを持つフォームだけ共用画面へ渡し、通常のフォームの既存入口を保つ。

席は送信済み回答と、その回答の公開版を本人・アカウント・回答キーで照合してから作る。本文で別店舗・コースを差し替えられない。回答の保存後に席だけ失敗した場合、回答は残し、同じキーで席だけ再試行する。期限切れの仮押さえは同じ予約を取り直し、確定済み・取消済みの回答の再試行で別予約を作らない。試し回答から実予約は作らない。

満席・休業の時刻では、同じ組織の同じ組に属し、紹介元・先の両方が許可した店舗だけ案内する。確認済みの座標から距離を計算し、設定距離・同人数・同時刻の空き・予約入口・機能の有効状態を再確認する。店名・距離・空き・入口だけを返し、顧客情報は渡さない。移動先はその店舗のLIFFで本人確認と友だち追加を行い、コースも移動先で選ぶ。同名コースを勝手に対応付けない。

紹介先での確定と紹介の受諾は同じ書込で保存し、途中のDB失敗では両方戻す。来店案内は飲食2の既存イベントから飲食3の共通フォローへ渡す。仮押さえで送信せず、固定の案内文・直接送信・別の予約台帳は増やさない。変更・取消・人のキャンセル待ち・席待ちの既存経路を保つ。

## APIの受け渡し

管理APIは既存のアカウント・組織指定と店舗の可視範囲を守る。更新はowner/admin、閲覧のみの更新は403。組の一覧はowner/admin/staffで、全参加店を読める組だけ返す。系列の設定で店舗やLINEアカウントの閲覧権限は広げない。

| 口 | 入力・結果 |
| --- | --- |
| GET `/api/liff/restaurant/courses` | storeId。同じ店舗の公開コース・所要時間・料金・登録アレルゲン、timezone |
| GET `/api/liff/restaurant/availability` | 既存のstoreId/date/guestCountにcourseIdを追加。所要時間を含む空き |
| POST `/api/liff/restaurant/holds` | 既存入力にcourseIdを追加。既存の卓・在庫・版で仮押さえ |
| POST `/api/liff/restaurant/reservations/:id/confirm` | 既存のexpectedVersion、任意referralId。既存の結果イベントと同じ書込 |
| GET / POST `/api/liff/restaurant/referrals` | storeId/date/guestCount/startsAt、任意courseId。POSTはtargetStoreIdも指定し、案内先のLIFF URLを返す |
| POST `/api/liff/restaurant/form-booking` | formId/blockId/submissionKey。保存済み公開版の席予約ブロックから既存予約へ渡す |
| GET / POST `/api/restaurant-test/store-groups` | 組の一覧／nameとmembersで作成。各memberはstoreId/referralEnabled/maxDistance（km） |
| PATCH `/api/restaurant-test/store-groups/:id/members/:storeId` | referralEnabled/maxDistance。参加許可・案内距離の変更 |
| PUT `/api/restaurant-test/stores/:id/referral-location` | latitude/longitude/confirmed:true。確認した座標を登録 |

客用APIはLIFF ID tokenを検証し、本文の本人IDを採用しない。追加した8操作はOpenAPIと権限の網羅検査にも登録した。
