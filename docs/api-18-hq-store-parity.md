## 足したAPI

- テンプレート一覧：今月の実送信通数、新しい版が未配布のひな形数、現在版。日本時間の当月、テスト送信を除き、再配布しても重複計上しない。
- `GET /api/hq/templates/:id/versions`：版番号、作成者、日時、現在版、未配布かを返す。`is_draft` は「その版の成功配布がない」の意味。店の公開・下書き状態とは別。
- `GET /api/hq/templates/:id/versions/compare?from=1&to=2`：両方の定義と変更の有無。
- `POST /api/hq/templates/:id/versions/:version/restore`：`expectedRevision` 必須。過去版を書き換えず、新しい現在版として保存する。
- `GET /api/hq/templates/:id/received-versions`：店ごとの最新成功配布版と現在版との差。
- `GET /api/hq/templates?kind=tag` と `GET /api/hq/templates/attribute-kind-counts`：タグの種類別一覧・件数、配布先の付与人数、手動付与可否・付け方。配る口は既存の preflight/distribute を使用。
- リッチメニュー一覧：順、誰に出すか、配布先の押された数。定義の `displayOrder` と `displayAudience: all|store` を配布へ引き継ぐ。配布先は下書きのまま。
- 一括配信：フォルダ CRUD、社内メモ、シナリオ購読・詳細条件・除くタグ・保存した配信条件、複数吹き出し・計測設定を保存して店の配信へ引き継ぐ。
- `GET /api/hq/broadcasts/approvals/candidates`、`GET /:id/approval`、`POST /:id/approval-request|approve|reject|approval-cancel`（前置きは `/api/hq/broadcasts`）：店と同じ承認状態の形、別人承認、承認時の本人確認、人数変更時の再承認。1人運用は送信時の `confirmedRecipientCount` 必須。
- `POST /api/hq/broadcasts/:id/test-send`：`accountId` 指定。その店の設定済みテスト宛先に全吹き出しを送る。
- 配信詳細：店別の送信・開封・クリック・反応人数。`GET /api/hq/broadcasts/:id/export.csv`、`GET /:id/targets/:accountId/recipients`、`GET /:id/activity`。

共有の `BroadcastDefinitionInput`・吹き出し・条件・承認状態を店と統括で使用。タグ・シナリオ・保存条件は、選んだ店の同名資源へ解決する。条件不足は送信を止める。作成・変更・配布は統括全体のオーナー／管理者、閲覧のみはGETだけ。店側のAPIで統括配信の承認を変更できない。

## 未対応・画面側への注意

- 友だち情報欄・対応マークのひな形と配布は未実装。現在の表に店・統括の所属がなく、安全な店別配布には既存API全体の所属設計が必要。件数は `null` と理由を返し、0件とは表示しない。保存した検索のひな形配布も追加していない。
- 詳細条件のうち、友だち情報欄・対応マーク・回答フォーム履歴・担当者・個別友だちID・分析対象ID・配信クリック履歴は未対応として拒否する。保存条件は `segment_v1` のみ。店で決める後処理と複数アカウント重複除外も指定できない。
- リッチメニューの対象は「全員」または「配布先で店が決める」。統括で複雑な対象条件を指定する口は追加していない。
- 別資産として配るクーポン等は送信ログとの対応がなく、今月送信数を `null` とする。合計にこの種が含まれる場合も `null`。通常のメッセージひな形は実通数を返す。
- 開封・クリックは店の配信計測が取得済みのときだけ値を返す。未取得は `null`。反応は「送信済み宛先のうち、配信日時以降に受信記録がある人数」で、返信の原因を断定する値ではない。

## 店に結びつくテンプレート欄の調査

- 差し込みの文字は統括の本文に保存できる。実際の値は配布先の友だち・店の共通情報で解決する。各店の変数・情報欄の定義は店が用意する。
- カードと質問のフォーム／シナリオ参照は既存の同名参照解決を使用できる。配布先に同名の参照先が一意に必要。
- 「使われたとき／答え終わったとき」の共通アクション結び付けは、統括のひな形定義と配布処理に含まれていない。配布先で店が決める。
- カルーセルの動作JSONは保存可能だが、一般の動作で参照するタグ・情報欄・対応マーク等を店ごとに解決する処理は追加していない。カードで対応済みのシナリオ参照を除き、店固有IDを統括から持ち回らず、配布先で店が決める。
