# V8の画面を確かめる手順

見た目の決まりは[正本](v8-design-rules.md)、型の持ち主は[対応表](v8-pattern-catalog.md)、機能の動きは[要件の索引](v6-requirements/v6-requirements-master-index.md)と[追加要件](v8-requirements/README.md)。この文書は作業の順を説明する。合否の基準を別に作らない。

1. 対象の板とURL・状態・役割を一致させる。Pencilの書き出しは司令塔の `~/lh-work/design/v8/html/` と `pencil-texts/`。別画面や隠れた層を見本にしない。
2. 現在の動き（保存、公開、停止、権限、別店、失敗、読み直し、入力と焦点）を一覧にする。画面は `apps/web/src/v8/`、共通の型と部品を使う。
3. 実装を直し、関連の試験・型・ビルドを実行する。全試験やビルドは `~/lh-work/tools/hq/heavy.sh` を通す。同じ作業場所の開発サーバーとビルドを同時に走らせない。
4. 1152・1440で同じ状態を開き、切れ・重なり・横はみ出し・折り返し・色を画像と実操作で確かめる。CIの崩れ検査は1920も含む。未到達は未計測として残す。
5. 画像のSHA・実装のSHA・URL・役割・状態・幅を記録する。文字位置の比較だけで操作や安全の合格にしない。正式記録は司令塔が `PASSED.tsv` と `SWITCH-READINESS.md` へ反映する。
6. 試験の故障対照は、一時的な不具合が落ちることと復元後の成功を別に確認する。動き・権限・崩れを守る試験を消さない。旧V7の見た目や文言だけの固定試験はV8へ移す際に整理する。

管理画面はV8に固定する。公開条件と残る旧分岐の整理は[切り替えの要件](v8-requirements/v8-switch.md)を参照する。古い道具名・行数凍結・許可一覧への追加を日々の手順として複製しない。現在の命令は `pnpm run`、各アプリの `package.json`、[開発ガイド](development.md)から確かめる。
