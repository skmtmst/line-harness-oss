# V8 画面を Pencil の絵に 90% 以上で合わせる手順（使い回せる直し方）

2026-10-06 司令塔。自動応答の作る①〜⑤を 24〜52% → 90〜100% にしたときのやり方をまとめた。次の画面でもこの順にやる。

## 0. 道具
| 道具 | 使い方 | 何がわかる |
|---|---|---|
| 開発サーバー | preview `v8w-mock`（8781）＋ `v8w-web`（3181）。作業場所 `~/lh-work/lh-v8w`（本線から切った作業用） | 保存すると数秒で画面が変わる |
| `zsh ~/lh-work/tools/hq/m8.sh 板,板` | 開発サーバーで撮って Pencil の座標と比べる（20〜60秒） | 板ごとの「合う%」と `design/v8/overlay/pages-v8w/<板>-delta.md` |
| `MEASURE_SERVER=1 zsh ~/lh-work/tools/hq/measure.sh <名前> 板` | `~/lh-work/lh-pages-<名前>` を開発サーバーで撮る。**出荷の枝そのもの**を測るときに使う（`ln -sfn <枝の作業場所> ~/lh-work/lh-pages-<名前>`） | 出す物が本当に合っているか |
| `design/v8/pencil-texts/<板>.tsv` | 絵の文字の x・y・幅・高さ | 正しい位置 |
| `design/v8/html/<板>.html` | 絵の HTML 書き出し。**寸法（padding・gap・font-size・色）を読むのに使う**。位置は崩れるので使わない | 正しい寸法 |
| `lh-spacing/scripts/peek.mjs`（`PORT_WEB=3181`） | 撮影と同じ条件で開き、エラー・送った API と返事を出す | 「撮れない」「落ちる」の原因 |
| `lh-spacing/scripts/cards.mjs`・`tpl-dig.mjs` | 箱の位置・高さ・余白を測る | どの箱がずれの元か |

## 1. 進め方（1画面ずつ）
1. `m8.sh` で今の点を測る。撮れないなら先に原因（下の §4）
2. 実装と絵の画像を並べて目で見て、**作りの違い**（並び・横並びか縦か・箱が1つか2つか）を先に直す。位置の数字はそのあと
3. `delta.md` の表を**上から**読む。
   - 縦（dy）だけ同じ数ずれて下へ続く → その上に足りない／余計な物が1つある（行を直さず、それを足す・消す）
   - 行ごとに 1px ずつ増える → 行の高さか行の間が違う。**絵の行の間隔＝（次の行の y − この行の y）**を TSV から出し、高さ＋間に合わせる
   - 横（dx）が少しずつ増える → 並ぶ札・ボタンの幅か間（印の大きさ・文字の大きさ・間）
4. 寸法は `html/<板>.html` の `data-pencil-name` の style から読む（`padding`・`gap`・`font-size`・`line-height`・`outline`・`border-radius`・`background-color`）
5. 直すたびに `m8.sh`。**同じファイルの合格済みの画面も一緒に測る**（例：作る②を直すときは①も）
6. 90% 以上 → 画像を目で見る（切れ・重なり・折り返し・印・色）→ PASSED.tsv
7. 出荷：本線から枝を切り、画面のファイルは丸ごと（本線で後から変わっていないか `git log` で確かめる）、共通の型・変数・見本データは差分で当てる → 出荷の枝そのものを measure.sh で測る → 試験は**単独で回して結果を見てから**コミット → PR

## 2. 使い回せる直し方
| 症状 | 直し方 | 例 |
|---|---|---|
| 画面ごとに欄の間・題の行の高さが違う | 共通の class（`.field` `.label`）を変えない。**その手順のカードにだけ** class を足して効かせる（`.stepTrigger .field`） | 作る②の値を共通に入れたら①が 98→54% に落ちた |
| 絵に無いが機能がある欄 | 消さない。**空いている場所に小さく**（題の行の右・別の欄の横・「ほかの〇〇」で開く）／**足りないときだけ出す** | 受け取る場所・祝日・種類の残り4つ・関門 |
| 値が長くて2行になり下がずれる | 値は1行（`white-space: nowrap; text-overflow: ellipsis`）＋ `title` で全文 | 作る⑤の設定の確認 |
| あとで出る結果で下が動く | 先に場所を取る（`min-height: 2行`） | 作る④の「試した結果」 |
| 絵では1行の文字が、実装では印＋文字・変数＋文字に分かれて見つからない | `{`いまの順番：${x}`}` のように**1つの文字列**で書く | いまの順番・「〇〇」より前へ |
| 札・選ぶボタン | 選んだ札は墨の地に白い字（`.pickChip`）、切り替えは灰の地に選んだ所だけ白（`.seg`/`.segBtn`） | 作る②③ |
| 行に「何をするか」と操作を並べる | `components/auto-replies/inline-action-rows-v8.tsx` の形（1行・番号・「どれを」・失敗したら・…）。中身の編集は「…」から開く | 作る③ |
| 右の列の「設定内容」 | `components/templates/create-parts.tsx` の `CreateSummaryCard`・`CreatePreviewNote`・`CreateStarterCards` | 作る①②④・リマインダを作る① |
| 例の文に当たるかを見せる | いまの言葉と合い方で判定して「当たる／当たらない」（実際に動く判定にする） | 作る②の右の列 |

## 3. 値は変数に
画面の CSS に数字を書かない（見張りの試験に当たる）。`apps/web/src/app/globals.css` の `[data-theme="v8"]` に `--tpl-*` を足して使う。足した主なもの：`--tpl-chip-h` `--tpl-chip-pad` `--tpl-body-*` `--tpl-rule-row-gap` `--tpl-summary-*` `--tpl-action-row-*` `--tpl-count-num-*` `--tpl-conflict-desc-lh`。

## 4. 「撮れない」「点が変」のときに疑う所
| 症状 | 原因だったもの | 直し方 |
|---|---|---|
| 「画面を表示できませんでした」 | 見本の返事が `{success, data:{success, data}}` と二重に包まれていた | mock-api の該当の口は素の値を返す（外側で包む） |
| `theme=なし` で撮れない | 上と同じ（落ちて V8 にならない）。`peek.mjs` で PAGEERROR を見る | 落ちる原因を直す |
| 手順②以降が全部①で撮られる | 撮影の URL が同じ | `?id=<下書き>&step=…`（自動応答）・`/reminders/edit?id=…&stage=…`（リマインダ） |
| 飲食店の画面が /hq に飛ぶ | `NEXT_PUBLIC_RESTAURANT_TEST_ENABLED=true` が無い | 測る道具に入れた |
| データの名前が違うだけで点が下がる | データの文字は合格の対象外。ただし下書き・重なりなど**画面の形が変わるデータ**は見本に足す（`ar-new` のように一覧に出ない ID で） | fixtures.mjs・mock-api.mjs |
| 「⌘K」「？」が無い言葉に出る | 絵の隠し層（HTML 書き出しに無い）。測る道具で自動で外すようにした | 追いかけない |
| 合格した画面の点が後で下がる | 別の PR が共通部品を変えた（例：選ぶカードの○を消した・スマホの見出しの基本を消した） | 本線の `git log -- <部品>` を見る。決めがぶつかるならオーナーに聞く |

## 5. 出荷で止まらないために
- v7 の画面・v7 の試験は消さない（本番を切り替える日まで）
- 見張りの試験（design-debt・direct-values・screen-css-budget・size-scale-contract・design-impact・src/v8 の境界）を通す。Tailwind の `gap-3.5` などは型の変数へ。共通 Button を新しく使ったら `design/design-impact-baseline.txt` に1行挿す
- 試験は1つの命令にコミットとつなげない。CSS のコメントに `#数字` を書かない（色コードの見張りに当たる）
- 試験を足したら、わざと壊して落ちるか確かめる（押していない試験は何も見ていない）
