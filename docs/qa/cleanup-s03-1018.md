## 変更の契約

- JSON APIのHTTP失敗を `{success:false,error:{code,message,requestId,fieldErrors}}` に統一する。既存のHTTP状態・機械コードの大小文字・復旧用データ・Cookie・Retry-Afterを保つ。コードなしの応答だけ共通の既定を使う。[番号と契約](../error-codes.md)を参照。
- APIのpath/method・登録順・成功の本文とデータを変更しない。JSON-RPC、HTML文書、WebSocketの101は各プロトコルを保つ。書換えた本文のContent-Length/Encoding/ETagを引き継がず、キャッシュは禁止する。元のprivate指定も保つ。
- HTTP/cron/queueの各メッセージ/emailの入口でサーバー側のUUIDを作る。応答のX-Request-ID、ログ、外部通信、LINE低層通信、既存監査欄へ渡す。入力ヘッダーを番号の正本にしない。
- ログは時刻・レベル・固定イベント名・依頼番号・実行番号・実行種別・状態と所要時間の数値だけ。例外や本文、URL、認証値、顧客情報を記録しない。既存の監査の伏せ方も保つ。
- A06のcall stateの保存情報を再開時に引き継ぐ。cronの実行番号はその実行の番号として分け、元の依頼番号は保持する。
- S01の未処理エラーの追跡番号は、応答・ログ・既存通知を同じ番号に接続する。S01全体の代替実装はしない。
- 管理画面・LIFF・埋込み画面・SDKで共通失敗を読む。旧形式も読める。権限、別店舗、CSRF、待機、項目別の理由、競合時の再読込、結果不明時の自動再送停止を保つ。画面の型・CSS・余白は変更しない。
- 予約系route/serviceは非予約の移行後に変更し、A07の業務判定・冪等性・補償・台帳の意味を変更しない。
