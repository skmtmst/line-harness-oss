# 実ブラウザ検査を必須CIへ入れる案

司令塔が採用を決めるまで、workflowは変更しない。

既存の`web-checks`の実ビルドとChromiumを利用し、受信箱9・共通情報5・処理中24を最初に足す。その後、列車34で書き換えた友だち3・ルートとタグ/CSV50を同じ入口へまとめる。新しいworkflowは作らない。

呼出し案：`pnpm exec playwright test --config scripts/visual-qa/browser-behavior.config.mjs`。`VISUAL_QA_BASE`と`TEST_WEB_URL`を既存のローカル配信先へ、`VISUAL_QA_MOCK`をそのジョブ専用の見本APIへ渡す。1worker、再試行0、画像更新なし。終了1は必須失敗にし、traceと失敗画像を既存の成果物保存へ追加する。

旧画像なし27件はV6/V7の画像を新設せず、動きと画面合わせを分けた。P039〜P062の24件はURL・ログインへの誤移動・エラー・はみ出し・描画を実ルートで維持。残りの画像なし分を含む状態/CSV検査は状態・入力・結果を維持。色・間隔・折返し・重なりは既存`v8-screen-guard`の3幅と画面合わせで担当する。見た目の合格はこの操作検査の成功から推定しない。

P089〜P091は未対応の要求/選択解除、API候補から保存検索を選んで適用、表示列の変更前/確定後/再読込をV8で確認。タグの旧削除は現在の行メニューから保管の窓を開く操作へ。参照があるだけで押せないという古い前提は使わず、サーバーの拒否を見本で返し、入力と行を保持することを確認する。保管成功、影響の読み取り、名前未入力/不一致時の停止、版と影響の票の送信も残す。

個人の情報・外部送信・実環境・DBへの変更は行わない。91ケースのうち処理中24は3つのブラウザ設定で同じ8ケースを繰り返している数で、24種類の固有動作とは呼ばない。
