# 本体の行数を増やさない検査

新しい本体は400行まで、既存の400行超は保存した行数まで。判定は空行・コメント込みの論理行数で、LF/CRLF/末尾改行の有無で変わらない。

リポジトリ全体の追跡済み`.ts`/`.tsx`を対象とし、手元では未追跡の追加予定も確認する。`.test`/`.spec`、試験・fixture・test-utilsの専用フォルダ、`.d.ts`と実行内容のない型宣言は別。型のファイルに実行内容を足すと本体へ戻る。生成物の除外登録は現在0。「generated」という名前やコメントでは除外しない。

基準は列車34の認証/予約修正済み`8e57d715cd`の本体437本。初期採番の時点を固定し、そのGit treeから現在も所属と上限を検証する。通常PRでは本線の記録とも比較し、追加・上限の増加・消した行の再登録は通さない。巨大なファイルの改名も新規400行として止まる。見た目の例外許可とは別の記録であり、見た目の検査を緩めない。

削った後は `node apps/web/scripts/v8-guard/code-size.mjs --base <本線SHA> --lower-baseline` で記録も下げられる。400行以下・削除・型宣言だけになったものは記録から外す。命令は上限を上げたり新しい行を足したりしない。

調査案の433/432/430は、母集団と拡張子の異なる以前の値。今回の対象は全リポジトリ・TS/TSXのみ・型宣言と試験補助を分けた2,528本で、437本が400行超。主要5領域のsrcだけを使った調査案の数字へ混ぜない。分布の全数・最大50処理は `train34-code-size-distribution.json`。

関数・部品の上限は今回は止めない。構文木で本体と引数型を含む全体を分けて数えた。無名のコールバックも含み、部品の候補はTSXの大文字名なので、React部品の確定数ではない。

追加案は調査案と同じ：普通の新しい処理は本体80行で相談、120行を停止の案。React部品は120行で相談、200行を停止の案。既存の長い処理は長さを記録して増加を止める案。採用前に名前と親の役割を追う方法、誤検出、レビュー時間を確認する。今回はファイルの400行と既存凍結だけをCIへ接続した。
