# M11：削除の小窓を同じ役目の共通部品へ

1. 目的：リマインダの削除前に、消えるものと代わりに一時停止できることを読み合わせる。実行中の禁止・失敗・一覧から外れた対象の禁止は保つ。
2. 見立て：幅720の直指定、操作段を通さないfooter、中央寄せoverlayの3つが原因。幅を480、上位置を絵の260、操作をDialogActionsへ渡すと幅/上/左操作の指摘が0になる予想。
3. 一番安い確かめ方：SheetDialogとu8sKNの接続・固定絵の窓のstyleを比較。VsSyuは480/260、u8sKNは480/280。同じ部品でも上位置は板別に指定する。

やった事：VsSyuだけ幅480・上260、dangerの注意帯はNotice.soft、操作はDialogActions.start、削除ボタンはidleの幅。RwVo5の720/中央操作とwarning帯は保つ。
結果：関連32件・接続最終14件・型/lint・長さ/新規ソース固定0、3幅の実寸対照3・本番ビルド成功。3板9条件はF1〜F10/崩れ/右端/例外/更新0。
理由：以前の「専用の窓だから720」を絵と同じ役目の共通部品に照合していなかった。生画像は既存撮影係のものを参照し、新撮影はしない。
次に変える事：幅と上位置を別々に見張り、操作段の左右を測る。動いている対象と停止中の対象を撮影係へ明示し、代替操作の有無を別幅の不具合へ読み替えない。

対照試験の診断：既存の入力窓を削除窓へ変えて即座に測ると、scanのtop16の後にcomputed top280となる旧寸法が混ざった。CSSのliteral改行だけでは解消しなかった。独立した短い削除窓を描き、寸法が到達した条件を待つ形へ変更。3幅で正常0、720幅/中央操作/上320の各故障1、復元0。しきい値・許可は変更しない。初回ログguard-control〜4とguard-diagnoseを保持。

最終結果：8fe6926c28の3板9条件でF1〜F10/崩れ/右端/例外/更新0、実幅Vs480/上260/削除84。比較u8とRwも0、本番ビルド成功。左右と正式合格は撮影係/司令塔の仕事。
