# V6 22-1-B 公開中の写真と掲載先（`J3Wxl8`）画面引き継ぎ

## 正本

- Node: `J3Wxl8`
- 想定ルート: `/nen-members?tab=published`
- 読み口: `GET /api/nen-members/photo-publications?accountId=...`
- 判定の上限: `structure_match_data_pending`

採用完了と公開中は同じ状態ではありません。既存の採用写真を自動で公開せず、
`nen_photo_publications` に記録されたものだけを一覧に出します。

## 画面で使える値

- 公開中の写真数
- 使用中の掲載先の種類数
- 最も見られた写真（全掲載先の数を取得できた写真だけ）
- 公開同意を記録済みの写真数
- 掲載先別の件数（リッチメニュー／コラム／回答フォーム／サイト）
- 写真ごとのキャプション、公開日、ペット名の公開状態、掲載先、表示回数

`displayCount: 0` は実値の0回、`displayCount: null` は未取得です。
同じ写真の掲載先に1つでも未取得がある場合、`totalDisplayCount` も `null` です。
取れた分だけを合計して少ない数に見せてはいけません。

## 画面で作らないもの

- 投稿者名: 名前の公開同意を記録する口がまだありません。`submitter` は常に未取得です。
- 原画像: 画面で表示しません。`publicImage.state === 'ready'` の公開用派生画像だけ表示できます。
- 表示回数の推測: 未取得を0回にしません。
- 「使う場所」の更新と「外す」: 配布先の書き込み・取り外し処理が未接続です。

`capabilities.canChangePlacement` と `canWithdraw` はどちらも `false` です。
押しても何も起きないボタンは置かず、未接続の理由を表示してください。

## 必須状態

1. 読込中
2. 通常
3. 取得できた0件
4. 取得失敗
5. 権限不足

失敗や権限不足では「公開中の写真はありません」と書かず、値は `—` にします。
取得できた0件だけ、0件と表示できます。

## 撮影と契約テスト

- 通常・空・失敗の固定データは `PHOTO_PUBLICATIONS` と読み口を使います。
- 開閉する詳細がある場合は押し口に `data-qa-open="J3Wxl8"` を付けます。
- 1440px・1920pxでページ全体と一覧の横スクロール0を確認します。
- `undefined` / `NaN` / `Invalid Date` / 内部ID / 原画像URL / 内部エラーを本文に出しません。
- 画面実装と契約テストが入っても、公開・掲載先更新の書き口と実績カウンタの接続が終わるまで `match` にしません。
