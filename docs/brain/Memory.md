## 配備と速度確認の手順（作業報告からの移記・2026-10-11）

- 通常の検証配備の成功記録は、固定したrun IDの成功とheadSha、本線のSHA、Workerの `/admin/version`・health、管理画面の `/version.json` の完全SHAが一致した後だけ。設定再配備は各元コードのSHAと照合し、unknown・短縮・不一致・HTTP失敗・異常healthを成功にしない。確認の再GETは最大15回、再配備はしない。司令塔の外部道具への反映状況も確認する。
- D1未適用確認は本線を明示した `migrate-d1.yml --ref codex/development` の `operation=migrate, environment=staging, mode=dry-run` を使用する。台帳の有無と適用済み一覧はSELECTだけで取得し、台帳がなくても作らない。起動したrun IDの成功と `COUNT:` を確認し、不明を0件にしない。applyは別途承認した個別ファイルだけ。
- 速度は応答2,000件と描画行数を別に確認し、窓表示の行数を2,000行と誤認しない。読込中・エラー・欠測・未完了は成功にしない。固定目標と悪化予算は `docs/v8-speed-rules.md` の表に従う。元の2,000件目標1,000/50ms、PERF-01のタグ表示1,000ms/2,000件の長い処理65ms、列車17の4目標をそれぞれ維持する。正式の入口は `pnpm qa:speed`。ブラウザlongtaskの0msは50ms以上の通知がない意味。既存の予算チェック合格だけで固定目標達成としない。標準画面の通信待ち・測定回数・基準を変えず、前後を同じ環境で比較し、手元の合格をCI解消の証明にしない。
