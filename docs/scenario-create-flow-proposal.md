# シナリオ作成の3段目「ステップの作成」— 案

2026-08-18。**絵をもらっていないところの提案。決めるのはこれから。**

配信方式の選択（2段目）の絵に、こういう段組みが描かれている。

```
✓ シナリオ情報 ── ② 配信方式の選択 ── ③ ステップの作成
```

1段目と2段目は決まった。**3段目の絵が無い。** ここをどうするかの案。

---

## いまどうなっているか

「時刻で作成」を押すと、いまは既存の編集画面（`/scenarios/detail`）へ送っている。
そこには段組みの帯が無いので、**3段目に着いた感じがしない。** 押した人から見ると
「作成の途中だったはずが、急に編集画面に放り出された」形になる。

作られたシナリオは次の状態になっている。

| | |
|---|---|
| 名前 | `新しいシナリオ` |
| 開始のきっかけ | 友だち追加時 |
| 配信方式 | 2段目で選んだもの |
| 通 | 0通 |
| 状態 | 配信可 |

**名前が仮のまま**なのが、いちばん引っかかる。1段目の画面が無いので聞く場所が無い。

---

## 案A — 3段目も専用の画面にする（おすすめ）

`/scenarios/first-step?id=` を作る。2段目と同じ見た目で、段組みの帯を出す。

```
✓ シナリオ情報 ── ✓ 配信方式の選択 ── ③ ステップの作成
```

出すもの:

| | |
|---|---|
| シナリオ名 | **ここで決める。** 仮の名前が入った入力欄を最初から出す |
| 1通目 | タイミングと本文だけ。2通目以降は編集画面で足す |
| 送る先 | 「友だち追加時」など、開始のきっかけを選ぶ |
| 進む | 「作成して編集へ →」で `/scenarios/detail` へ |
| 逃げ道 | 「あとで決める」で通0のまま編集画面へ |

**良いところ。** 段組みが最後まで途切れない。仮の名前のまま残らない。
1通目を書かせると、0通のシナリオが増えない（0通は配信できないので、
作ったまま忘れられていることが多い）。

**悪いところ。** 画面が1枚増える。編集画面と入力欄が二重になるので、
片方だけ直す変更が起きると、ずれていく。

---

## 案B — 編集画面に段組みの帯だけ足す

画面は増やさず、`/scenarios/detail` に「作成の途中から来たとき」だけ帯を出す
（`?from=create` のような印で判断する）。

**良いところ。** 画面が増えない。入力欄が二重にならない。

**悪いところ。** 名前が仮のままになる。編集画面の「シナリオ名」の札から
直せるが、**直さずに閉じる人が必ず出る。** `新しいシナリオ` が並ぶことになる。

---

## 案C — 2段目で名前も聞く

3段目を作らず、配信方式の選択の画面に名前の入力欄を足して、
「時刻で作成」を押した時点で名前も確定する。

**良いところ。** 画面が増えず、仮の名前も残らない。

**悪いところ。** **絵と違う。** いただいた絵に名前の入力欄は無い。
それに、緑の帯が「◯◯を作成しました」と言っているのに、同じ画面で
名前を入れるのはつじつまが合わない。

---

## こちらの推し

**案A。** ただし1通目の入力は「あとで決める」で飛ばせるようにする。

理由は2つ。

1. **仮の名前が残るのがいちばん困る。** 一覧に `新しいシナリオ` が並ぶと、
   どれがどれか分からなくなる。あとから直せる、では直らない
2. **段組みを出しておいて2段で終わるのは、約束を破っている。** 3つ書いたら
   3つ目まで連れて行く

案Bの「入力欄が二重になる」問題は、1通目の入力欄を編集画面と同じ部品に
すれば避けられる（`renderStepForm` を切り出して両方から使う）。

---

## 決めてほしいこと

| | |
|---|---|
| A / B / C のどれにするか | |
| 案Aなら、1通目の入力は必須にするか、飛ばせるようにするか | |
| 仮の名前を `新しいシナリオ` のままにするか、日付を足すか（`新しいシナリオ 8/18`） | |

**絵があるなら、それがいちばん早いです。** 上の案は絵が無いところを埋めるための
たたき台で、絵をいただければそちらに合わせます。
