# 外部送信の二重送信防止

## 対象

- 受信箱から送るLINEの1対1返信
- 友だち詳細から送るLINEメッセージ
- 受信箱から送る問い合わせメールの返信

## 仕様

管理画面は送信操作ごとにUUIDの `Idempotency-Key` を作ります。通信が切れて同じ内容を再試行するときは同じキーを使い、送信に成功した次の操作では新しいキーを使います。

Workerは外部サービスへ送る前に、キー・宛先・本文の組み合わせを予約します。

- 完了済みの同じ操作は外部へ再送せず、最初の結果を返します。
- 同じキーで宛先や本文を変えた要求は拒否します。
- LINEは同じキーを `X-Line-Retry-Key` にも渡し、Workerの保存前に通信が切れてもLINE側で二重配信を止めます。
- メールは上流に同等の保証がないため、結果が確定していないキーを再送しません。画面には履歴確認を案内します。

送信ログと予約の完了更新は同じDBバッチで保存します。外部送信後にDB保存が失敗した場合も、同じキーのメールを自動で送り直さないことを優先します。
