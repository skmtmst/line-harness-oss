# Lステップのシナリオ配信 — 実機調査と実装との差分

2026-08-19。Lステップ本番アカウント（meauty渋谷店）に管理者でログインし、
シナリオ配信まわりを実機で確認した記録です。

**確認方法**：既存の「名称未設定」シナリオ（購読者0人・一時停止）と新規登録画面を開いて
項目を読み取りました。登録・削除・送信は一切していません。値を入れた画面はすべて
保存せずに離脱しています。

この文書の目的は、**Lステップができることを正確に書き出し、うちの実装と突き合わせること**です。
どれを作るかの判断はここではしません。

---

## 1. いちばん大きい構造の違い

**Lステップのシナリオは「開始条件」を持ちません。**

シナリオ編集画面にあるのは シナリオ名 / フォルダ / 状態（配信可・停止） / 対象の絞り込み の4つだけで、
「いつ始まるか」を決める欄がどこにもありません。画面にはこう書かれています。

> 構築したシナリオは、アクションなどで呼び出すことができます。
> ※作成しただけでは配信されません。

つまり購読の開始は**シナリオの外**から呼びます。友だち追加時設定、アクション、
質問の選択肢、回答フォームなど、呼ぶ側が「このシナリオを購読させる」と指定する形です。

うちは `scenarios.trigger_type` に `friend_add` / `tag_added` / `manual` を持たせ、
**シナリオ1本につき入口1つ**に縛っています。同じ流れを別の入口からも流したい場合、
今の作りではシナリオを複製するしかありません。

ここは見た目の話ではなく、データの持ち方の話です。あとから変えると
`friend_scenarios` の作られ方まで波及するので、**差分の中でいちばん重い**と考えています。

## 2. 画面ごとの中身

### 2-1. シナリオ一覧

左にフォルダペイン、右に表。

| 列 | 中身 |
| --- | --- |
| （ドラッグ） | 行の並べ替え |
| （チェック） | 複数選択 |
| シナリオ名 | リンク |
| 配信方式 | 時刻 / 経過時間 |
| 購読中 | 人数。0人のときは「配信を始める方法はこちら」への導線が出る |
| 読了済 | 人数 |
| 終了後 | 最終コンテンツ配信後の処理（例：一時停止） |
| 登録日 | 日付 |
| 状態 | ●配信可 / 停止 |
| ⋮ | コピー / 削除 |

上部に 新しいフォルダ / 新しいシナリオ / 並び替え / 検索。

**うちとの差**：「終了後」の列がありません（そもそも機能が無い）。
「購読中が0人のとき、始め方への導線を出す」のは素直に効く導線だと思います。

### 2-2. 配信方式の選択

カード2枚（時刻で指定＝赤枠、経過時間で指定＝青枠）。それぞれに
説明2行 ＋ **具体例の図** ＋ 注意書き ＋ CTA（時刻で作成／経過時間で作成）。
**この画面では名前を入れません。**

**うちとの差**：ほぼ同じものを作れています。具体例の2人の並べ方も、
注意書き（「購読開始時刻が最初の配信時刻を過ぎている場合、翌日の配信時刻から」
「購読開始時刻によっては夜間の配信となる場合があります」）も一致しています。
違うのは、うちはこの画面に名前欄を置いていること。

### 2-3. シナリオ編集

見出しに4項目が横並び、それぞれに小さな編集ボタン。

- シナリオ名［編集］
- シナリオフォルダ［編集］
- 状態［変更］→ 配信可 / 停止
- **対象の絞り込み［設定］→ 条件ビルダー（§3）**

その下がコンテンツ表。

| 列 | 中身 |
| --- | --- |
| （チェック） | 複数選択 |
| タイプ | 💬メッセージ など |
| 日数 | 1日後 |
| 時刻 | 20:00 1通目 |
| 本文 | テンプレート名バッジ＋本文の頭＋補足（例「(送信後一時停止)」） |
| 操作 | 編集 / 挿入 / コピー / プレビュー / 別窓 / テスト |
| 到達人数 | 0人 |
| （削除） | 赤ボタン |

表の上に 一括プレビュー / 一括テスト。表の下に メッセージを追加 / テンプレートを追加。
その下に **最終コンテンツ配信後の処理［編集］**、最後に コピー / 削除。

**うちとの差**：表の形と 挿入・複製・プレビュー・到達人数 は作れています。
無いのは **1通ごとのテスト送信**（一括テストは「準備中」のまま）と
**最終コンテンツ配信後の処理**。

### 2-4. メッセージ登録

3つの節に分かれています。

**① 配信タイミング**

- 時刻指定 → ［N］日後 ［HH:MM］ ［N］通目 ＋ □開始当日
- 購読開始直後 → ［N］通目 のみ

**② 配信対象の絞り込み**（＝先日いただいた3択はここ）

- シナリオ購読中の全員に配信する
- タグで絞り込んで配信する → タグ選択2段
- 詳細条件で絞り込んで配信する → ［絞り込み］で条件ビルダー

**③ 配信内容の設定**

- メッセージのみ / アクションのみ / メッセージ ＋ アクション

メッセージ種別は**9タブ**：テキスト / スタンプ / 画像 / 質問 / カルーセル / 位置情報 / 紹介 / 音声 / 動画。

テキストの場合の周辺：

- 本文 0/22500、約4,500文字を超えると複数メッセージに分割
- 差し込み：名前 / 友だち情報▾ / 共通情報▾ / 回答フォーム▾ / 配信日▾ / その他 / 絵文字
- ツール：PDFアップロード
- URL設定：URL読み込み／□このメッセージではURLを短縮しない／サイト名・訪問時の表（クリック計測）
- 公式アイコンで送信（変更不可）
- □テンプレートとして保存
- **メッセージ送信後**：シナリオを一時停止しない / する
- ボタン：登録 / 下書き保存 / テスト送信

**差し込みの中身**

- 配信日▾ … 8書式（M月D日(W) / YYYY年M月D日(W) / M月D日 / YYYY年M月D日 とスラッシュ区切り版）
- その他 … 「配信日から［目標日］までの日数」「配信日から［N］日後の日付（書式指定）」

カウントダウンを本文に差し込めるのが効いています。

**うちとの差**：種別が text / image / flex の3つ。差し込みなし。URL短縮・クリック計測は
一斉配信には `trackLinks` があるがシナリオには無い。下書き・テスト送信なし。
**「メッセージ送信後：一時停止する」は `afterSend` として実装済み**で、これは一致しています。

## 3. 条件ビルダー（3か所で共用）

同じ部品が **シナリオ全体 / 1通ごと / アクション1つごと** の3か所に出ます。
ここがLステップの背骨です。

- 「すべて満たす」必要がある条件（and条件）のグループ
- ＋「いずれか1つ以上を満たす」必要がある条件（or条件）を追加 ＝ **入れ子のORグループ**
- 右上に［カスタム検索からコピー］＝保存済み検索を条件の初期値として流用

絞り込み項目は**15種**。

| 項目 | 演算子・中身 |
| --- | --- |
| 名前 | LINE登録名 / 本名 / システム表示名 のどれから探すか。半角スペース区切りでOR |
| 個別メモ | テキスト |
| ステータスメッセージ | テキスト |
| 友だち登録日 | 日付範囲 |
| 対応マーク | 8種から複数選択／いずれかに一致 |
| タグ | いずれか1つ以上を含む / 全て含む / 1つ以上含む人を除外 / 全て含む人を除外（＋タグフォルダで指定） |
| 友だち情報 | 完全一致 / 部分一致 / 登録あり / 登録なし / 完全一致除外 / 部分一致除外 / ≧ / ＞ / ≦ / ＜ |
| シナリオ | シナリオ指定 |
| イベント予約 | 予約済み / キャンセル済み / 保留中 / 否認中 ×（を検索 / 以外を検索） |
| カレンダー予約 | いずれかで〜予約をしたことがある人 |
| 共通情報 | ＝ / ≧ / ＞ / ≦ / ＜ |
| リマインダ | 現在設定中 / 1度でも設定したことがある / 現在設定していない / 1度も設定したことがない |
| 回答フォーム | に回答した人 |
| 最終反応日 | 日付範囲 |
| その他 | 反応状態：指定しない / 返信・ボタン応答あり / 返信あり / ボタン応答のみ / 返信・応答なし |

シナリオ全体のときだけ、上に **配信対象 ☑表示中の友だち ☑非表示にした友だち** が付きます。

**対応マークの8種**（色つき）：未対応 / 対応済み / 未返信（マガジンコメント） /
未返信（重要度低） / 要対応（質問） / 要対応（トラブル） / 要対応（クロージング） / 要対応（クレーム）

**うちとの差**：`advanced-search-dialog.tsx` が近いものですが、
項目が6種、ORグループなし、シナリオからは呼べません。

## 4. アクション（6種）

「アクション設定」の中身。動作を積み重ねる形で、各行が番号付きカードになっています。

各カードに：ドラッグ / 「N. 種別」 / ［条件ON・OFF］ / ↑ / ↓ / 🗑
全体に：☑発動2回目以降も各動作を実行する

| 種別 | できること |
| --- | --- |
| タグ操作 | タグを追加 / タグをはずす（□タグフォルダで指定） |
| 友だち情報操作 | ［欄］に［定数］を ←代入 / ＋加算 / －減算 / X消去 する |
| リマインダ操作 | リマインダを開始 / キャンセル |
| 対応マーク・表示操作 | 対応マーク（8種 or 変更しない）＋ 表示状態（変更しない…） |
| イベント予約操作 | イベントを予約 / 予約をキャンセル（予約枠を選択）※通数を消費する場合あり |
| 共通情報操作 | ［共通情報］に［定数］を ＋加算 / －減算 する |

**条件ON/OFF が1アクションごとに付く**のが重要です。
「タグAが付いている人にだけこのタグを足す」が1画面で書けます。

**うちとの差**：`scenario_steps.on_reach_tag_id`（到達したらタグを1つ付ける）だけ。
はずす・友だち情報の書き込み・対応マーク変更・条件付き実行、いずれもありません。

## 5. 質問メッセージ ＝ 分岐の実体

一覧の説明文にある「友だちの反応に応じて配信内容を分岐できます」は、
**質問タブ**のことです。

メッセージ側：

- 前文（テキストメッセージで流れます）0/4500・差し込み対応・短縮URL対応
- 質問文 0/160
- PC版・通知欄での代替テキスト 0/400
- 質問の回答は：1つのみタップ可能 / 両方タップ可能

選択肢ごと（選択肢1・2）：

| 欄 | 中身 |
| --- | --- |
| 選択肢N | 0/20（10文字超で途切れる注意書き） |
| 選択後の挙動 | 何もしない / URLを開く / 電話をかける / LINEアカウントを友だち追加 / メールを送る / 回答フォームを開く / **シナリオを移動・停止** |
| ユーザーメッセージ | 0/60。押したとき友だちの発言として送る文。□使用しない |
| 選択時返信 | 種別＋返信テキスト 0/4500 |
| **二度押し時返信** | 種別＋テキスト。既定は「すでに押されています！」 |
| 選択時追加タグ | タグ |
| 選択時はずすタグ | タグ |
| 友だち情報欄 | ＋セットする値 0/100（既存の値は上書き） |
| シナリオ操作 | 「シナリオを移動・停止」を選んだときだけ出る。移動先シナリオ ＋ 購読の仕方：(新規)最初から／(再開)友だち読んだところから / 指定したタイミングから始める |

**二度押し時返信**が独立して用意されているのは、実運用で効くところだと思います。

**うちとの差**：質問メッセージも分岐もありません。

## 6. 最終コンテンツ配信後の処理

シナリオの最後まで配り終えた人をどうするか。

- シナリオの変更：一時停止 / **1つ前のシナリオを再開** / **別のシナリオへ移動**
- その他のアクション：アクション設定（§4と同じ部品）

「1つ前のシナリオを再開」があるので、**シナリオを一時的に割り込ませて戻す**という
使い方が成立します。質問の「シナリオを移動・停止」と対になっています。

**うちとの差**：ありません。最後まで行ったら `completed` で終わりです。

## 8. 所感

作る順を決めるための材料として、3つに分けて書いておきます。

**A. 見た目を寄せるだけで済むもの**
一覧の「終了後」列、購読0人のときの導線、1通ごとのテスト送信。
既にある部品の組み替えで届きます。

**B. 受け皿はあるが繋がっていないもの**
1通ごとの配信対象は `buildSegmentQuery` と `segment_conditions` が既にあり、
条件ビルダーも `advanced-search-dialog.tsx` が下敷きになります。
**条件ビルダーを1つの部品に切り出して3か所から呼ぶ**形にすると、
シナリオ全体・1通ごと・アクションが同時に片付きます。Lステップがまさにその作りです。

**C. 設計から要るもの**
アクション（テーブルが要る）、質問メッセージ（分岐で `friend_scenarios` の進み方が変わる）、
最終配信後の処理（シナリオ間の遷移）、そして `trigger_type` をやめて外から呼ぶ形にすること。
この4つは互いに絡んでいて、**バラバラに足すと後で作り直しになります**。

順番としては B → C、C の中では「アクションのテーブル」を先に置くのが素直だと見ています。
質問の選択肢も最終配信後の処理も、結局アクションを呼ぶ器だからです。
