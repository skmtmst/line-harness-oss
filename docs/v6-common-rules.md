## 0. この文書の使いかた

**「V6のとおりに作って」と言われたときに、迷わず手が動く状態にする。**
そして **この文書だけで、1機能ぶんの仕様書が最後まで書ける** ようにする。

正本の順位はこれ。上が勝つ。

1. **Pencil の ★V6** — 見た目の正本。寸法・色・文字はここが決める
2. **この文書** — 画面の骨組みと、どの部品を使うか
3. **`apps/web/src/components/shared/`** — 実際に使う受け皿
4. **`v5-parts-contract.test.ts`** — 1 と 3 がずれたら落ちる見張り

**設計を変えるときは Pencil を先に直す。** コードだけ直すと、次に絵を見た人が元に戻す。

**ユーザーの直しは尊重する。** 消えているものは不具合ではなく、わざと消されたことがある。
復活させる前に、消えた理由を疑う。

## 1. 画面の骨組み

**260枚すべてがこの入れ物。ここから外れる画面を作らない。**

```
画面（1920 × 1080・横並び）
├ 共通メニュー ref J33xq（幅256・上から下まで）
├ 右側（縦・fill/fill）
│   ├ 共通トップバー ref cBSCb（幅fill・高さ56）
│   └ ○○ メイン（幅fill・高さfill・padding [14,40,32,40]）
│        └ 帯を縦に積む
└ オーバーレイ（layoutPosition:"absolute"・x0 y0・画面と同じ大きさ）
```

### 1-1. 共通トップバー `cBSCb`

**画面ごとに作り直さない。参照（ref）で入れて、画面名だけ上書きする。**

| 左から | 中身 | 画面ごとに変えるか |
|---|---|---|
| 1 | **画面名**（`$size-title` 20 / 700） | **`Y6lRn` の文字だけ上書きする** |
| 2 | **マニュアル**（画面名のすぐ横） | 変えない |
| — | あき（fill_container） | — |
| 3 | `LINEアカウント` ＋ 切替プルダウン | 変えない |
| 4 | 区切り線 | — |
| 5 | 権限バッジ（統括）＋ ログイン中の人 | 変えない |
| 6 | 区切り線 | — |
| 7 | ログアウト | 変えない |

地色は `$surface-chrome` `#EBEDF1`。白いサイドメニューとも、本文の地（`$canvas-parchment`）とも
別の色にして、**アプリの枠**であることを見せる。下端に `$hairline` の線。

決めごと。

- **画面のタイトルを本文に置かない。** バーの画面名がタイトル
- **説明文（サブタイトル）を置かない。** 説明が要るなら案内帯（§2-3）に書く
- **マニュアルを画面の中に置かない。** バーに1つだけ

### 1-2. 共通メニュー `J33xq`

上から。

1. **このアカウント** — アイコン ＋ 会社名 ＋ `Ver. 2.6.4`（枠も影も付けない）
2. **区切り線**
3. **メニュー** — 区分見出し（配信／コンテンツ／成果と分析／自動化／予約／専用機能／設定）で分ける

**下端に何も置かない。** 名前・権限・ログアウトはバーにある。

### 1-3. 画面の型は5つだけ

**6つ目を作らない。**

| 型 | 見分け方 | 帯の並び（上から） |
|---|---|---|
| **L 一覧** | タブか作成操作＋表 | 1行目 → 数値カード帯 → **案内帯** → 一覧操作 → 一覧（検索行／絞り込み行／表／フッター） |
| **B ボード** | タブ＋カード | 1行目 → 数値カード帯 → **案内帯** → 本体 |
| **E 作成・編集** | 下部追従バーがある | パンくずと操作 → 編集本体（設定内容＋右390px） → 下部追従バー |
| **D 詳細** | 1件を見る | パンくずと操作 → 数値カード帯 → 本体（左＋右390px） → 下部追従バー |
| **M モーダル** | 暗幕がある | 下敷き（L か B）＋ 全面オーバーレイ（`$scrim`・中央そろえ）＋ モーダル |

### 1-4. 操作だけの行を作らない

**ヘッダー操作だけの行は置かない。本文の1行目に寄せる。**

| 本文の1行目 | 操作の置き場所 |
|---|---|
| タブ行 | タブの右端。あき枠（fill_container）で押し出す。操作枠は `height:"fill_container"` ＋ `alignItems:"center"` |
| パンくず行 | パンくずの右端。パンくずが ref 単体の画面は `パンくずと操作` で包む |
| 緑・黄の案内帯 | 帯の右端。**帯は短いまま**、同じ行に置く |
| 作成操作・一覧上部操作 | その行の右端 |
| 受信箱の対応状況バー | **バーの外**、同じ行の右端 |

### 1-5. 作る・足すは左、それ以外は右

同じ行の中で、

- **左** … `フォルダを追加` `＋◯◯を作成` など、**新しく作るもの**
- **右** … `CSVで書き出す` `まとめて操作` `表示切替` など、**すでにあるものを扱うもの**

### 1-6. 下部追従バー

**保存・実行・削除は、下部追従バーにしか置かない。**
本文の途中に保存ボタンを置くと、長い画面で「どこで保存されるのか」が分からなくなる。

見た目は 白地 `$canvas` ／ 角丸 `$radius-tile` ／ 枠線 `$hairline` ／ 高さ72 ／ 左右余白20。

並べかたは **削除だけ左、それ以外はぜんぶ中央**。

| 置くもの | 位置 |
|---|---|
| 削除（赤） | 左端 |
| 状態文・件数（「下書きです」「18件中…」） | 左端 |
| キャンセル・戻る・コピー・保存・有効化・一時停止・設定を編集 | **中央** |

組みかたは3つ並べる。

```
下部追従バー（justifyContent: center）
├ 左のがわ（width: fill_container）… 削除ボタン／状態文。無ければ枠ごと置かない
├ ボタンの組（width: fit_content）  … ここが画面の中央に来る
└ あき（width: fill_container）
```

**ボタンの組を `fill_container` にしない。** 横いっぱいに広がって左寄せに見える。

### 1-7. オーバーレイ

暗幕とモーダルを別々に置かない。**全面1枚の枠にまとめる。**

**Pencil（絵）**

```
オーバーレイ（layoutPosition:"absolute", x:0, y:0, 1920×画面の高さ,
              fill:"$scrim", justifyContent:"center", alignItems:"center"）
└ モーダル
```

`layout:"none"`（子をx/yで置く）の画面を作らない。**必ず横並びの入れ物にする。**

**コード（実装）**

**1920px を書かない。** 絵の 1920 は「画面いっぱい」を絵で表すための数字で、寸法の指定ではない。

```css
.overlay {
  position: fixed;
  inset: 0;              /* ← 幅も高さも書かない */
  background: var(--color-scrim);
  display: flex;
  justify-content: center;
  align-items: center;
}
```

固定幅にすると、1920 より狭い画面で暗幕が右にはみ出し、横スクロールが出る。

### 1-8. 幅・余白・高さ

**幅も、絵の数字をそのまま書かない。** 1920 は絵を描くための基準で、実装は可変にする。

| | 決めごと |
|---|---|
| **Pencil（絵）** | 1920px で描く。サイドメニュー256 → 本体1664 → 中身1584 |
| **コード（実装）** | サイドメニューだけ固定（256px）。本体は残り全部（`flex: 1`）。中身は `max-width: var(--container-shell)`（104rem）で頭打ちにして中央寄せ。**`width: 1664px` と書かない** |

- 本体の左右余白は 40px。**中身が使える幅は 1584px**（`--container-shell` = 104rem）
- 右カラムは **390px 固定**。420 や 430 を作らない
- 部品は**幅を持たない**。幅は画面ごとに違うので呼び出し側が `className` で渡す
- **本体の上余白は 14px**（全画面）。下は 32px（一覧）／28px（作成）
- 帯と帯の間は 18px（一覧）／16px（作成）
- カードの中は 16px（つながる先・気をつけること）／18px（ふつうのカード）

#### 画面の高さ

**これは Pencil のルール。コードにそのまま持ち込まない。**

| | 決めごと |
|---|---|
| **Pencil（絵）** | 画面の枠は 1920×1080 が基本。**中身が少なくても 1080 より小さくしない。** 1080 は画面そのものの大きさで、下の余りは地であって無駄な空白ではない。1080 を超える画面（長い一覧・受信箱・作成の途中）だけ、中身に合わせて詰める |
| **コード（実装）** | **`min-height: 100vh` を基本にする。`height: 1080px` と書かない。** 1080px 固定にすると、縦がそれより短いPCで**中身が無いのに縦スクロールが出る** |

下部追従バーも同じ。絵では本文の最後の帯として置いてあるが、
実装では `position: sticky; bottom: 0` で、**画面が短いときだけ本文に重なる**形にする。

## 2. 書きかたの決めごと

### 2-1. ボタン名は「行き先か、実行した結果」が名前だけで分かる

| 用途 | 使う形 | 例 |
|---|---|---|
| 別画面を開く | `{対象}を見る` / `{対象}を開く` | `中身を見る` → `配信結果を見る` |
| 次工程へ進む | `{次工程名}へ` | `次へ` → `送信設定へ` |
| 確認画面を開く | `{対象}を確認` | `確認` → `公開内容を確認` |
| 保存する | `{対象}を保存` | `保存` → `機能設定を保存` |
| 試す | `{対象}をテスト` | `テスト実行` → `友だち追加時配信をテスト` |
| 実行する | `{対象}を送信・公開・停止・復旧` | `実行する` → `配信を緊急停止` |
| 行内操作 | `編集` / `削除` を許す | 対象が同じ行で明白なときだけ。読み上げ名には対象名を含める |
| ページ送り | `前へ` / `次へ` を許す | ページ送り欄だけの例外 |

### 2-2. プルダウンは、選んだ値だけで何の設定か分かる

1. 直前か上に、`並び順` `表示件数` `期間` `状態` など**目的名を必ず出す**
2. `20件` ではなく `20件表示`、`新しい順` ではなく `追加日が新しい順`
3. ラベルが見えていても、`label` との関連付けか `aria-label` を必須にする
4. **使えないプルダウンを完成画面に置かない**。実装するまで隠すか、いま使える固定条件を文章で出す
5. 検索・並び順・期間・表示件数を1行に詰め込んで、一覧を横スクロールさせない。狭いときは2段に折る
6. タブの切り替えは `?tab=` のまま。共有・再読込・戻るに強い。
   `<Link>` にしない（push になって履歴が積まれ、ブラウザバックで一覧まで戻れなくなる）

### 2-3. 案内帯は1画面に1本

同じことを2つの形で言わない。帯・注記・ツールチップのどれか1つにする。
色は意味で決める。

| 色 | 使うとき |
|---|---|
| 緑 `$accent-soft` | いまの状態のお知らせ（「作成しただけでは配信されません」） |
| 黄 `$status-warn-soft` ＋ 文字 `$status-warn-deep` | 気をつけてほしいこと |
| 赤 `$status-danger-soft` | 止まっている・失敗している |
| 青 `$status-info-soft` | 決めごとの説明（「過去の結果は書き換わりません」） |

### 2-4. 空の状態は2種類だけ

| 状況 | 見せかた |
|---|---|
| **新しく作れる一覧が、まだ空** | `fRgeK` まだありません（作成導線つき）。**ボタン名に対象を必ず含める**（`シナリオを作る`） |
| **絞り込み・検索の結果が0件／履歴が空** | `BDOJu` データがありません。作成導線は付けない |

読み込み中は `sZE9Q`、失敗は `OLMp0`。**この4つ以外を作らない。**

### 2-5. 右390カラムの並び

上から「その画面の固有カード」→ **`つながる先`** → **`気をつけること`** の順で終える。

- `つながる先` は「相手の機能名」と「ひとこと」だけ。呼び出し先は遷移表にあるものだけ
- `気をつけること` は見出し＋説明の2行組。3つまで

### 2-6. 文章

- **ひらがなを優先する。** 「全て」ではなく「すべて」
- 画面に出る言葉に、DBの列名・内部用語を出さない（`friends.unfollow_count` `inline` `silent rule` など）
- 数字には単位を付ける。`231` ではなく `231件`
- 敬体（です・ます）。ただしラベルと見出しは体言止め

### 2-7. 用語表

**設計画像が正本。** 迷ったら `docs/design-reference/` を数えて、多いほうに合わせる。
この表は数えた結果を固定したもので、実装・要件書・判定のメモもここへそろえる。

## 3. 色と大きさ（トークン）

`apps/web/src/app/globals.css` が置き場所。**部品はここの `var()` しか使わない。**

### 3-1. 色

| 役割 | 名前 | 値 |
|---|---|---|
| 本文の地 | `--color-canvas-parchment` | `#f5f5f7` |
| カード・入力の地 | `--color-canvas` | `#ffffff` |
| **アプリの枠（トップバー）** | `--color-surface-chrome` | `#ebedf1` |
| うっすらした地 | `--color-surface-pearl` | `#fafafc` |
| 線 | `--color-hairline` | `#dadde2` |
| カードの中の線 | `--color-divider-soft` | `#f0f0f0` |
| 文字 | `--color-ink` `#1d1d1f` / `--color-ink-secondary` `#4a5565` / `--color-ink-faint` `#6e7781` | |
| 緑 | `--color-accent` `#06c755` / `--color-accent-soft` `#e8f8ee` / `--color-accent-deep` `#087a3e` | |
| 状態 | `--color-status-info` `#175cd3` / `--color-status-warn` `#f5c56b` ＋ `-deep` `#a15c00` / `--color-status-danger` `#e5484d` ＋ それぞれ `-soft` | |
| 暗幕 | `--color-scrim` | `#11182755` |

**緑（accent）は「オン・正常・主要な1つ」にだけ使う。** タグの色分けには使わない
（`tag-purple` `tag-indigo` がある）。

注意色は「地・線・文字」で3つある。`#fff7e6` の地に `#f5c56b` の文字は読めないので、
**文字は必ず `--color-status-warn-deep`**。

**状態色はいま2系統ある。** `status-*`（V6で足したもの）と `danger/warning/info`（既存）が並存している。
新しく作る画面と共通部品は **`status-*` だけ**を使う。既存の4組は移行が済んだ画面から消す。

### 3-2. 角丸

| 名前 | 値 | 使うところ |
|---|---|---|
| `--radius-tiny` | 3px | アイコンボタンの当たり |
| `--radius-mini` | 6px | 行の中の小さなボタン |
| `--radius-control` | 8px | ボタン・入力欄・プルダウン |
| `--radius-tile` | 10px | 数値カード・一覧表の外枠・**追従バー** |
| `--radius-card` | 12px | ふつうのカード |
| `--radius-section` | 18px | 区分カードの外枠 |
| `--radius-pill` | 9999px | 印・スイッチ |

**`--radius-md` という名前は使わない。** Tailwind標準の `rounded-md` は6pxで、
上書きすると既存83か所が黙って10pxになる。

### 3-3. 文字の大きさ

`nano 10 / micro 11 / caption 12 / label 13 / body 14 / lead 16 / heading 18 / title 20 / metric 22 / display 30`。
**この10段階以外を使わない。**

Pencil 側の対応は `$size-nano` … `$size-display`。

## 5. 部品の書き方

### 5-1. 見た目はCSSモジュールに置く

Tailwindの任意値記法（`rounded-[14px]` `border-[#DADDE2]`）は、規格外の値が
普通のクラスと同じ見た目になる。3系統に割れた原因がこれ。
CSSなら Pencil のノード属性と1対1で並び、コメントに設計値をそのまま書ける。

**ページ側はTailwindのままでよい。** 部品の境界だけCSSにする。

### 5-2. 部品は幅を持たない

設計でも `width` は指定されていない。幅は画面ごとに違うので、
`className="w-full"` のように呼び出し側から渡す。

例外はプルダウン（`rpot9` 176px / `niGPF` 128px）と右カラム（390px）。
これは設計が値を持っているので部品が持つ。上書きしたいときは `className` で渡す。

### 5-3. 生の色とローカル変数を作らない

友だち属性V3のCSSモジュールは `--v3-accent: #08c654` を持ち、
Pencilとも `globals.css` とも違う3つ目の色系統になっていた。
**部品の中で色を定義しない。** `globals.css` の `var()` だけを使う。

やむを得ない例外は1つだけ。プルダウンの矢印は data URI の中なので `var()` が使えない。
ここは契約テストがトークンと突き合わせている。

### 5-4. 呼び出し側の `className` は最後に置く

```ts
const classes = [styles.button, styles[variant], className].filter(Boolean).join(' ')
```

最後に置かないと、画面ごとの上書きが効かない。

### 5-5. `className="hidden"` で隠さない

部品は `display: inline-flex` などを自分で持っている。Tailwind の `.hidden` と
同じ強さなので、**書いた順で勝ち負けが決まってしまう**。
隠したいときは**そもそも描かない**（条件分岐で `null` を返す）。

### 5-6. 押せる部品には `:focus-visible` を入れる

最初の3部品はフォーカス指定が0件だった。キーボードだけで操作する人が
いまどこにいるか分からなくなる。押せる部品には必ず入れる。

## 7. 仕様書のひな形（1機能ぶん）

**1機能＝1つの仕様書。** 32機能あるので32本になる。
この見出しをそのまま埋めれば、実装に渡せる仕様書になる。
**空欄を残したまま実装へ渡さない。** 埋まらない欄は「決めていない」と書いて、決める人を書く。

### 7-0. 表紙

| 欄 | 書くこと |
|---|---|
| 機能番号・名前 | `17 マイル` のように、遷移表と同じ番号 |
| 正本の画面 | Pencil の画面名と Node ID を全部（例 `★ V6 17-1 マイル・友だちの残高（1920）` `s98Vfw`） |
| 実装のルート | `/mileage` のような実際のURL。`?tab=` も書く |
| いまの状態 | 良好／要改善／要修正／一部未完了／重大（実装照合監査の判定を引く） |
| この版で変えないもの | 触らない範囲を先に書く。これが無いと関係ない場所が壊れる |

### 7-1. 画面の一覧

Pencil の1枚＝1行。

| 画面名 | Node ID | 型（L/B/E/D/M） | 何をする画面か | 呼び出し元 | 行き先 |
|---|---|---|---|---|---|

### 7-2. 画面ごとの中身

**1枚につき1節。** 上から順に、帯ごとに書く。

1. **バーの画面名** — 何と出すか
2. **1行目** — タブ／パンくず／案内帯のどれか。右に置く操作
3. **数値カード帯** — カードごとに「ラベル／値の出どころ／注記／取れないときの見せかた」
4. **案内帯** — 出す条件と文言。出さない条件も書く
5. **本体** — 表なら列の一覧（列名／出どころ／並び替えの可否／幅）、カードなら項目
6. **右390カラム** — 固有カード → つながる先 → 気をつけること
7. **下部追従バー** — 左（削除・状態文）／中央（ボタン）を分けて書く

### 7-3. 状態

**代表状態をぜんぶ書く。** 絵が無い状態も文章で書く。

### 7-4. 操作と、押したあと

| ボタン名 | 置き場所 | 押すと何が起きるか | 確認は要るか | 失敗したときの戻りかた |
|---|---|---|---|---|

- **確認が要るのは「取り消せない操作」だけ。** 削除・送信・公開・緊急停止
- 確認は `H2S1T4` 重要操作確認。標準の `confirm()` を使わない

### 7-8. 版と履歴（作ったものを使い回す機能だけ）

- **公開しても、いまの利用先は変わらない。** 使う場所ごとに「新しい版に更新」を押したときだけ切り替わる
- **動き始めたものは、その版のまま終わる**
- **公開ずみの版を上書きしない。** 前の版へ戻すのではなく「この版をもとに新しい版を作る」
- 過去の実行記録は書き換わらない

### 7-9. 除外するもの

**やらないことを書く。** 書かないと「できるはず」と読まれる。
例：取れない数字を0で見せない／推測値で欠けを埋めない／相関を因果と書かない。
