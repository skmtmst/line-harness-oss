# Pen.dev移管 4画面実証ゲート

作成日: 2026-08-24

対象: ダッシュボード、受信箱、友だち、友だち属性

## 結論

設計台帳と共通部品があるだけでは「Pen.devから正確に移せる」とは証明できない。性質の違う4画面を固定し、基本設計が同時に届くことと、画面全体を正確に作れることを二段階で確認する。

| 画面 | 採用版 | Pencil Node ID | 確認できること |
|---|---|---|---|
| ダッシュボード `/` | V5 | `fJ2hc` | 共通画面枠、複合ヘッダー、カード、表、期間操作 |
| 受信箱 `/chats` | V6 | `WQhu3` | V6差分、3ペイン、入力、通知、長い画面 |
| 友だち `/friends` | V5 | `FG391` | 共通タブ、検索、KPI、表、モーダル、一括操作 |
| 友だち属性 `/tags` | V5 | `PbCvb` | 分割タブ、フォルダ、一覧、作成・編集・削除 |

「友だち属性V3」は通常メニューから外す。比較用URLと過去の比較資料は削除せず、通常利用者の入口には出さない。

## 第1段階: B1 共通土台の伝播確認

B1では4画面本体を完成移行しない。次の共通部分が、画面ごとの直書きではなく1つの変更から届くことを確認する。

- `J33xq` 正式共通メニューと256px画面枠
- `RWNQP`から共通化した高さ76px・見出し30pxのページヘッダー
- `VPn1F` / `ISA1Q` の下線タブ
- `z9TQJ` の分割タブ
- `R098Z` のパンくず
- 権限非表示、アカウント切替、件数バッジ、URL連動、ブラウザバックを維持

### B1合格条件

- [x] 4画面が同じ共通画面枠を通る
- [x] 4画面が同じ共通Headerを使う
- [x] 友だちと友だち属性が同じTabs APIを使う
- [x] タグ編集が共通Breadcrumbを使う
- [x] V5実ノードの値をビルド後CSSで照合する
- [x] 「友だち属性V3」を通常メニューから外す
- [ ] 1440px・1920pxの同一データ状態で4画面を画像比較する

最後の画像比較は、共通表示部品が揃っていないB1時点では「画面全体一致」の判定に使わない。B1ではヘッダー、メニュー、タブ、パンくずの領域だけを判定する。

## 第2段階: B2〜B5後の移管リハーサル

Card、入力、Select、Dialog、Drawer、DataState、表本体まで揃った時点で、4画面を実際のPen.dev移管と同じ手順で仕上げる。B6で全画面へ大量展開する前に行う。

### 画面全体の合格条件

- [ ] 1920pxの設計画像と、同じ状態・同じ幅の実装画像がある
- [ ] 1440pxで主要情報と操作が横スクロールなしで見える
- [ ] 位置、寸法、文字、色、余白、枠、角丸、影が一致する
- [ ] 読込中、空、失敗、長文、最大件数、無効、処理中を確認した
- [ ] 現在動いている機能とデータの意味を失っていない
- [ ] V6がある受信箱だけV6差分を使い、他3画面はV5を使う
- [ ] 画面で見つけた反復要素を、直書きせず共通部品へ昇格した
- [ ] 共通部品変更後、`design:impact`の全利用画面を再確認した

## この実証で判断すること

4画面が通れば、全画面への展開を始められる。通らない場合は、ページ固有の修正を増やさず、足りなかった共通部品・状態・ルールをB2〜B5へ戻して直す。

この順番により、同じ問題を各ページで繰り返し修正することを防ぐ。
