# G-9 共通メッセージ作成部品の引き継ぎ（2026-10-09）

統括の一括配信③と店の一斉配信③は、`components/shared/message-composer.tsx` を使う。差し込み候補、LINEアカウント、使えない種類だけ呼び出し側から渡す。API・DB・Pencilは変更していない。

- 12種類のタブ、番号・種類・要約・上下移動・削除、カード内の余白20、5通上限、テンプレート選択・保存の入口を共通化した。
- スタンプは高さ40の切り替えと基本スタンプ一覧を共通化した。選んだスタンプは緑の枠。番号の直接入力も残した。
- 画像・動画・音声は既存の登録メディアとアップロードを使う。形式・容量を確かめ、失敗やアカウント変更で元の内容を置き換えない。音声は再生・停止・再生位置を表示する。
- カルーセル・リッチメッセージ・リッチビデオは既存のテンプレート編集部品を広い引き出しで使う。引用したテンプレートを直接更新せず、その吹き出しを直す。テンプレートも保存するときは別のものを作る。
- 店のカルーセル引用ではボタンの動き・押せる回数も読み込み、再編集で失わない。保存の途中で失敗した場合は作成済みのIDを使って再試行する。
- LINEの見本には全吹き出しを渡す。カルーセルの見本は実際のカードとボタンから作る。編集の引き出しを開閉しても親画面の題を維持する。

### 標準測定で比較状態をそろえられなかった板

GKgRk・Z6Hx5oは撮影自体は成功するが、標準の撮影操作が画面外の「開いて直す」を押すと、背面のスクロール位置が変わる。座標表はスクロール前の背面も含むため、隠れている背面の文字を数える測定では約600pxのずれになる。また、同じ文を背面と引き出しから混ぜて対応付ける。編集部分の見比べはできたが、標準の全体測定は合格と扱っていない。製品のスクロールを測定のために変えたり、外部の測る道具・Pencilを変更したりしていない。

### 絵との差と司令塔への確認事項

- 基本スタンプの見本は絵の絵文字ではなく、実際に送れるLINEスタンプを表示する。「絵文字」を別のスタンプパッケージとして作ることはしていない。
- スマホ内の画像・アカウント名・本文・カード数は見本データによって変わる。左メニューのデータ差は担当外。
- 配信後のアクションや右の見本の既存共通部品に残る位置差は、今回の吹き出し部品の変更で無理に上書きしていない。統括で配信後のアクションを設定する口は未対応。
- `measure.sh` が画像のメタデータへ記録するSHAは道具側の作業場所のSHA。実装を測った土台は上記SHAであり、wrapperが出す作業場所の版と未コミット差分数も確認した。

## APIの追加が必要なもの

今回は画面の担当なので、以下のためにWorkerやDBは変更していない。

1. 統括で登録メディアを選び、音声ファイルをアップロードする機能。音声のURL・長さの直接入力は既存機能として残した。
2. 統括からリッチビデオを作成・保存・配布する機能。使えない理由をタブに表示し、送れない内容を作らせない。
3. 店の新しいリッチビデオを、テンプレート保存なしで作る機能。既存動画の通知・見終わった後のリンクだけを直す場合は、元の画像の組を使って保存なしで挿入できる。新しい動画は保存のチェックを求める。
4. 店のカルーセルで「動きを実行する」をテンプレート保存なしで使う機能。現行の動きはテンプレートIDを参照するため、保存を求める。統括への配布では店舗のIDへの置換も必要。
5. リッチメッセージから「動きを実行する」を送る配信変換。現在の変換で受けられない内容は挿入前に止め、編集を残す。
6. 複数の吹き出しをひとまとめにテンプレートへ保存する機能。上部の保存は現行APIに合わせて1通目を対象にし、確認窓で「ほかの吹き出しは含まない」と説明する。各作成済みカードからも個別保存できる。

質問・紹介など、以前から送れない種類の制限も解除していない。統括と店で機能をそろえる次のAPI担当の依頼に含める。
