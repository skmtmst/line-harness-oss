# 設計を決めないといけないところ（v0.25.0）

V2設計どおりに作れなかった箇所の一覧。

実装は止めずに進めている。**設計にある数字を出す仕組みが無いとき、
数字を捏造せず、意味の近い別の数を出すか「—」にしている。**
どちらを選んだかと、設計どおりにするなら何が要るかをここに書く。

- 更新: 2026-08-16
- 対象: `docs/design-node-ids.md` の V2 85画面

## まとめ：根っこは5つ

個別に見ると19件あるが、原因は5つに集約される。

### A. 送信の出どころを記録していない（6-2 / 7-1 / 8-2）— **誤り。028 で既にあった**

`messages_log` は 028 の時点で `source` を持っている。

  user / broadcast / scenario / auto_reply / reminder / manual

さらに 038 で `template_id_at_send`（送信時に使ったテンプレート）もある。

**「記録していない」は私の思い込みだった。** 実物を確かめず決めつけていた。

したがって次はすべて**読み出しを書くだけ**で済み、解決した。

  テンプレートの「今月の送信」  template_id_at_send IS NOT NULL で絞る
  シナリオの「今週の配信」      source = 'scenario'
  リマインダの「今月の配信」    source = 'reminder'
  プッシュ数 / リプライ数       source IN ('auto_reply','manual') が応答

108 で origin_kind / origin_id を足してしまった。検証環境に入っており、
追加のみのポリシーで消せない。**どこからも読み書きしない。**

### B. 初回返信の時間を記録していない（1-1 / 2-1）— **107 で解決済み**

受信してから最初に返すまでの時間。`chats` に `first_replied_at` を足し、
送信時に「まだ入っていなければ入れる」だけでよい。

### C. 短縮URLとテンプレートが紐づいていない（6-1）— **110 で列を用意した**

`tracked_links` はテンプレート本文から自動生成されるが、どのテンプレート由来かを
持っていない。クリック率をテンプレート単位で出すにはこれが要る。

### D. 友だち情報欄に型が無い（8-1）— **誤り。099 で既に入っていた**

`friend_fields` は 099 の時点で `type`（text / textarea / number / date /
select / multi_select / checkbox / url / tel / email）と `is_starred` を
持っている。

**「型が無い」は私の思い込みだった。** 突き合わせ表を書いたときに実物を
確かめず、そう決めつけた。109 を足そうとして migrate.ts に止められ、
実物を見て気づいた。

したがって 8-1（リマインダの「起点になる項目」）と 18-2（情報欄の「種別」列）は、
**列を足す必要が無い**。`type = 'date'` の項目を数え、`type` をそのまま
出せばよい。読み出しを書くだけ。

109 はどの環境にも当たっていない。何もしないファイルとして残してある。

### E. 「いつ変わったか」を残していない（9-2 / 10-2 / 10-3）— **110 で表を用意した**

対応マークも保存した検索も、いまの値しか持っていない。設計は
「過去7日」「今月の呼び出し」のように期間で切って見せる。

個別に履歴表を足すより、汎用の操作記録を1つ持つほうがよい。
`login_audit`（103）と同じ形で、対象・種類・日時を残す。
